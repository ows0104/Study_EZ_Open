# 수용 기준

1. 유지보수 자동화의 깨진 이름/지시문을 정상 UTF-8로 복구한다. 저장소의 현행 feedback-loop 규칙과
   기존 사람 승인 범위를 보존한다. 매시간·기존 대상 채팅·현재 상태·알림 설정은 유지한다.
   완료된 coverage 조사 항목은 P3a 해결 기록을 가리킨다. 새 자동화를 중복 생성하지 않는다.
2. 사이트/출제/연결/공유/Spotter 각 영역의 실제 코드·설정·자산 입력을 검증 범위로 정의한다.
   Spotter 소스, 시간표 입력, 의존성 잠금 변경을 누락하지 않는다. 비밀값은 기록하지 않는다.
   관련 없는 영역의 변경으로 모든 검사가 무효가 되는 비용을 줄이되, 공유 계약은 생산자/소비자를 함께 묶는다.
3. 테스트/리뷰를 코드 및 intent/spec/plan/검사 목록에 묶는다. 설계 변경 후 구현만 재승인해도
   옛 검사·리뷰가 그대로 유효해지지 않아야 한다. 검사 중 설계가 바뀌어도 실패 처리한다.
4. 배포 후보의 정확한 파일/버전/환경 참조와 검증을 연결한다. 보관 검사만 통과한 change를
   사이트 전체 릴리스 근거로 사용하지 않는다. 웹과 서버 모두 승인 확인 경로를 명확히 한다.
   배포 후 실제 버전·health·핵심 학습 동작 검사 결과·복원 기준을 영속 기록한다.
5. incident 조사/승인대기/해결/관측복구와 후속 change 링크를 구별해 저장한다. 복구 알림만 출력하고
   조사 폴더가 영구 미완료로 남지 않게 한다. 제보 ledger는 기술 사건과 연결하되 기존 승인 체계를 유지한다.
6. 승인 없는 구현/배포를 막는 기존 동작, 최신 실패 우선, 중복 사건 방지, unknown 구분은 보존한다.

## 구현 세부 계약

근거 버전 2는 영역별 입력과 plan 지문을 함께 기록한다. 구형 기록은 보존하되 현재 근거로 자동 승격하지 않는다.
배포 후보 설정은 대상·health URL·읽기 전용 핵심 학습 검사·복원 기준을 포함한다. 웹은 후보 artifact를 사용하는
배포 명령과 실제 버전 조회 명령을 명시한다. 서버는 기존 프로젝트/리전/서비스와 일치해야 한다.
운영 배포 없이 원격 명령 대역으로 서버/웹 성공·실패·사후검사·종료까지 검사한다.
검사 묶음은 workflow(이전4결함 및 신규전체흐름 포함), contracts(공유계약/패키징/무승인배포차단)다.
자동화는 같은 항목을 복구한 뒤 저장된 UTF-8 지시문과 일정/상태/대상 일치를 별도 확인한다.
