읽는 경로는 검사 723개와 표본으로 확인했지만 **빌드 한 편을 끝까지 돌려 본 적이 없다.**

## 먼저 — **밤에 저절로 도는 것이 없다**

내가 세션 중에 「오늘 04:00 예습과 21:30 쓸기가 새 모양으로 처음 돈다」고 두 번 적었다.
**틀렸다.** 확인한 것은 이렇다.

- `runner/agent.py` 머리가 스스로 적고 있다 — *"`04:00 예습 빌드` + `06:00 쓸기`로
  돌던 것을 여기로 옮겼다"*. **크론은 걷어냈다.**
- 예약 작업에 남은 것은 `\StudyEZ Agent` 하나이고 트리거가 로그온이다.
  **마지막 실행이 2026-09-10 09:48, 결과 `-1073741510`**(강제 종료).
- `runs/agent.lock` 은 09-14 09:08 에 찍힌 죽은 pid 다(36556 — 지금 없다).
  90초가 지난 표시는 죽은 것으로 보므로(`agent.LOCK_STALE`) **막지는 않는다.**

그래서 아침에 **저절로 만들어져 있는 것은 없다.** 확인하려면 한 편을 손으로 돌려야 한다.
빌드는 이제 사람이 누른 일감(관리 화면)이나 손으로 친 명령으로만 시작된다.

## 아침에 돌렸다 (2026-09-15 10:08~10:30) — ①②③ 닫힘, ④ 남음

**빌드 한 편을 끝까지 돌렸고 거기서 버그 둘이 나왔다.** 둘 다 이 배치 변경이 낳은
것이고 검사 723개가 다 통과하는 동안 숨어 있었다.

                         경계 넘는 import 0 · 검사 723개 통과
    ②  한 편 끝까지    ✓  두 번째에. 첫 번째는 죽었다 (아래)
    ③  나가는지        ✓  문지기가 `c021` 로 막는다. 배치 문제가 아니다
    ④  예습 한 편      —  **아직 안 돌렸다.** 30분 · 약 $12

### 버그 ① — 갈아 끼우기가 옛 판을 못 찾는다 (`2835b02`)

`--revise` 는 옛 판의 `prep.json` 과 카드를 읽어야 성립하는데 **이번 판이 빈 폴더**다.
그래서 「옛 판의 산출물이 없다」로 읽고 통째로 만들기로 내려가고, 거기서 `assemble` 이
없는 `revise.json` 을 받아 죽는다. **종료 코드는 0 이었다**(루트 CLAUDE.md 함정 ①).

안 죽었더라도 통째로 다시 만들면 **복습 이력이 죽는다**. 그것이 `--revise` 가 있는
이유다. 고친 뒤 `260831_02` 는 **89장 중 82장을 그대로 들고** 2.3분·$2.1 에 끝났다
(같은 편 통째로: 34.9분·$12.69).

### 버그 ② — 복습 빌드가 `slides/` 를 지운다 (`96030b2`)

`_slides` 가 `media` 를 `PRE`(예습) 자리에서 찾는다. 옛 모양에서는 갈래와 상관없이
같은 폴더라 값이 같았는데, 판을 가르고 나서는 **복습을 구우면서 예습 판을 뒤지는 것**이
되고 못 찾으면 `slides/` 를 지운다. `slides/` 는 **서버가 읽는 강의 것**이다.

`260831_02` 가 89장을 굽고 슬라이드 23장을 잃었다. **`publish --dry-run` 은 그것을
정상으로 찍었다** — 올릴 미디어가 0개인 것은 검문 조건이 아니다. `runner promote` 로
되살렸다. 다른 편도 훑어 봤는데 같은 꼴은 없었다(`media` 는 있는데 `slides/` 가 없는
편 1개 = `260911_03`, 그것은 `run.meta.json` 자체가 없어 계약이 안 돈 편이다).

### ②를 다시 돌릴 때 알아 둘 것

**죽은 판 폴더가 「제일 새 판」이 된다.** 전략 판정까지 갔다 죽으면 `run.config.json` 이
이미 쓰여 있어서 카드가 없는 그 폴더가 `work_dir` 의 ③에 걸린다. `deck.revise_from` 은
카드가 있는 판만 옛 판으로 주도록 해 뒀지만, **`publish`·`deck.source_pdf` 는 그대로다.**
죽은 판은 지우고 다시 돌리는 편이 낫다.

## 아침에 이 순서로

### ① 읽는 쪽이 성한지 — 30초, 공짜

```bash
python -m runner watch
```

**맞으면 이렇게 나온다** — 「만들 강의 2편」(`260831_02`·`260907_01`, 둘 다 v2 갱신)과
밀린 것 9편. 새벽 01:00 에 그렇게 나왔다.

**틀렸으면 이렇게 보인다** — 만들 강의가 갑자기 100편 넘게 잡힌다. 그건 접힌 편의
`prep.json` 을 못 찾아 「만든 적이 없다」로 읽은 것이다. 그때는 ⑤로 간다.

```bash
python scripts/map_numbers.py --check     # 경계 넘는 import 0 이어야 한다
python -m pytest -q                       # 723개
```

### ② 한 편을 끝까지 — 30분 · 약 $12

**이것이 아직 아무도 안 해 본 자리다.** 새 판 폴더에 쓰고, 덱을 강의 폴더로 올리고,
계약이 어느 판으로 만들었는지 적는 길 전체다.

```bash
python -m runner watch 기생충학 --run-id 260831_02 --build
```

끝나고 볼 것 넷:

```bash
ls runs/260831_02                      # 루트에 main/ 과 강의 것만 (prep.json 이 있으면 틀렸다)
ls runs/260831_02/main                 # 판 폴더 둘 — 옛 판 + 오늘 것
python -c "import json;print(json.load(open('runs/260831_02/run.meta.json',encoding='utf-8'))['attempt'])"
python scripts/attempts.py 260831_02   # 시도가 나란히 서고 컷 칸이 채워졌는지
```

| 봐야 할 것 | 맞으면 |
|---|---|
| `runs/260831_02/` 루트 | `main/` · `*.apkg` · `run.meta.json` · `slides/` · `source.json` 뿐 |
| `runs/260831_02/main/` | 판이 둘. 오늘 것이 `260915-####` |
| `run.meta.json` 의 `attempt` | `{"kind": "main", "version": "260915-####", "cards_sha256": …}` |
| `attempts.py` 표 | 오늘 판에 **컷 260908-0130** 이 찍힌다 |

`attempt` 가 `null` 이면 **올리기가 안 돌았다** — `deck.contract` 가 `promote` 를 먼저
부르는지 본다. 컷 칸이 비어 있으면 족보가 안 붙은 것이고, 이유는
`runs/260831_02/main/<판>/jokbo.used.json` 의 `why_not` 에 적혀 있다.

### ③ 나가는지 — 1분

```bash
python -m runner publish --run-id 260831_02 --dry-run
python -m runner publish --run-id 260831_02
```

문지기가 막으면 사유가 한 줄로 찍힌다. **「사람이 고른 시도가 이 자리에 없다」가 뜨면**
`CHOSEN.json` 과 올라간 판이 다른 것이니 `python -m runner promote 260831_02` 로 맞춘다.
지금은 `CHOSEN.json` 이 있는 편이 하나도 없어서 이 줄은 안 떠야 한다.

### ④ 예습 쪽도 한 편 — 30분

복습과 예습은 **다른 작업 폴더**를 쓴다(`main/<판>` vs `prequiz/<판>`). 예습은 아직
새 길로 한 번도 안 돌았다.

```bash
python -m runner prequeue --dry-run          # 무엇이 준비됐는지
python -m runner prequeue <과목> --run-id <올해 run_id> --build
ls runs/<작년 run_id>/prequiz                # 판 폴더가 섰나
```

**예습 산출물은 작년 편 폴더에 앉는다** — `pre_target.json` 이 올해 어느 강의인지 안다.
그 파일과 `preview.md` 는 강의 것이라 판 폴더로 안 들어간다(들어가 있으면 틀렸다).

### ⑤ 틀렸을 때 — 되돌리는 길 둘

**새 실행만 옛 자리로 돌린다** (접어 놓은 것은 그대로 읽힌다):

```python
# runner/runlayout.py
WRITES_ATTEMPT_DIRS = False
```

`runlayout.find` 가 판 폴더를 먼저 보므로 이미 접힌 편은 그대로 돈다. 다만 그 뒤에
새 실행이 강의 폴더로 쓰면 **그 산출물이 판 폴더에 가려 조용히 무시된다** — 되돌린
뒤에는 `python scripts/migrate_attempts.py --all --apply` 를 한 번 더 돌려 접어라.

**족보 컷 이름을 되돌린다:**

```bash
mv runs/_materials runs/_jokbo      # deck.subject_dir 이 옛 이름도 본다
```

컷이 `_jokbo/<과목>/<판>/` 이 되지만 `cutmark.resolve` 가 `current` 를 따라가므로
그대로 읽힌다.

**통째로 되돌리려면** `git revert cae085e cbef761 862054e` — 다만 **파일은 안 돌아온다.**
접은 것을 펴는 스크립트는 없다(필요하면 그때 만든다).

## 에이전트는 아침 확인에 필요 없다

빌드는 이제 사람이 누른 일감이나 손으로 친 명령으로만 시작되고, 위 ①~④ 는 전부
직접 명령이다. 에이전트가 하는 일은 둘뿐이다 — 관리 화면이 만든 일감을 집어 오는
것과 10분마다 `publish` 쓸기.

**띄워도 새로 나갈 것이 거의 없다.** `published.json` 의 기록과 지금 파일을 전부
맞대 봤다(2,245개).

    그대로 2,060 · 달라졌다 170 · 없는 것 15 · **오늘 새벽 이후 만져진 것 0개**

달라진 170개는 09-03·09-08 재생성분이고 문지기나 `_owns` 에 걸려 있다. **이행이
재업로드를 유발하지 않는다** — 강의 것은 안 움직였다. 처음 dry-run 이 「3,019개 ·
8,214MB」라고 찍은 것은 **계획 총량**이고 올릴 것이 아니다.

순서는 **손으로 한 편 → 그 다음 에이전트**다. 거꾸로 하면 에이전트가 잡은 편에서 새
길을 처음 확인하게 되고, 그러면 로그를 뒤져야 한다 — `agent.py` 가 크론을 걷어낸
이유가 바로 그것이었다.

    python -m runner agent --once      붙는지만
    python -m runner agent             계속

`agent.py` 는 안 고쳤고, 에이전트는 `subprocess` 로 매번 새 프로세스를 띄우므로
코드가 낡을 자리가 없다.
