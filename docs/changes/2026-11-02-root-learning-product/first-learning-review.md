# 콜린성 뿌리 첫 범위와 한 문제의 학습 흐름 — 검토안

2026-11-02. 사용자의 “한번 해봐”에 따라 첫 범위와 학습 동작을 검토할 수 있게 구체화했다. **제품 동작 제안이며 Build 승인·콘텐츠 검수·실제 학습 기록이 아니다.** 기존 합의는 상위 learner-journey Spec을 따른다. 이 문서의 제안을 채택하기 전에는 합의된 Spec으로 취급하지 않는다.

후속 상태: 자료·목적지에 대한 명시적 사용자 승인 후 [단회 CLI 대조](content-comparison-review.md)를 완료했다. 아래는 그 결과를 연결한 사용자 검토안이다. 초기 실행 실패·승인 거절의 이력은 5절에 보존하며 현재 대조 미실행 상태로 읽지 않는다.

## 1. 첫 범위 제안과 확인 수준

첫 적용은 콜린성 약리학(1), `261002_01`의 강의별 뿌리다. 먼저 큰 구조를 살펴보고 준비된 과제를 풀며 각 위치의 상태를 확인하는 흐름을 완성한다. 세부 약물·반응식·용량까지 모두 첫 뿌리 과제로 넣지는 않는다. 첫 제품에서 다루지 않은 세부도 올해 시험 범위에서 제외됐다는 뜻은 아니다.

수신한 트리의 다음 제목을 **탐색 묶음 후보**로 유지한다. 단회 CLI 대조도 다섯 묶음의 활용을 권고했으며, 원본 물리 4쪽의 다섯 학습목표와 각 묶음의 학습목표 분모는 구별한다.

| 지도에서 찾을 묶음 | 수신 트리의 질문·역할 | 첫 제품에서의 처리 제안 |
|---|---|---|
| 작용 표적 | 어디에서 어떤 수용체에 작용하는가 | 지도와 첫 과제의 위치 예시로 사용 |
| 약물의 작용 방식 | 직접작용과 간접작용 | 실제 목표·기존 과제 연결을 대조 후 확정 |
| 장기별 반응 | 수용체 활성화와 반응 | 세부 반응을 일괄 성공시키는 묶음 평가를 피함 |
| 임상적 활용 | 반응을 활용하는 목적 | 작용 방식 등 다른 위치의 같은 목표를 참조할 수 있게 설계 |
| 과도한 활성화 | 중독과 치료 표적의 구별 | 관련 과제·필수 방향의 실제 범위를 대조 후 확정 |

**다섯 묶음을 목표 5개로 저장하지 않는다.** CLI 대조에서 답 경계·필수 방향 후보·원본 쪽·기존 과제의 충분/부분/미준비를 담은 목표 후보 15개를 제시했다. 분포·장기 반응 등 여러 관계가 들어간 후보는 더 나눠야 하므로 15도 최종 목표 수가 아니다. 실제 분할·필수 방향의 채택은 아직 확정하지 않았다. 포인트에 별도로 나온 신경전달 억제 지점은 근거 강도와 기존 과제 부족을 확인할 범위 항목으로 남긴다.

첫 사용자 검토에는 기존 `LNK001`을 그대로 사용한 아래 동작 예시를 제안한다. 선택 이유는 두 항목을 회상하는 기존 list 문항으로 평가·부분 회상·저장 과정을 설명할 수 있기 때문이다. CLI 대조도 이 예시를 권고했으며 첫 짧은 경로 후보는 **LNK001 → Q002 → Q005 → Q047 → Q036 → Q068 → Q063 → Q060**이다. 이 8문항은 제품 경험을 살필 경로이며 전체 뿌리의 완료 조건이나 검증된 선수관계가 아니다. 각 후보의 원본 근거와 실제 질문 범위는 대조 결과 표를 따른다.

## 2. 실제 기존 문항으로 보는 화면

기존 은행에서 읽은 `LNK001`, 원래 형식 `list`, 회상 방향 `direct`를 사용한다. 새 발문·정답·해설은 작성하지 않았다.

질문:

> Acetylcholine 수용체를 나누는 두 주요 수용체 계열은?

정답:

> Nicotinic receptor
>
> Muscarinic receptor

기존 문항의 원본 참조는 `S1: p.4 목표 1; p.5; p.7`이다. 이는 은행에 저장된 locator이며 이번 작업에서 PDF의 물리쪽과 대조 완료한 번호가 아니다. 기존 문항에 explanation이 비어 있으므로 해설이 있는 것처럼 새 의학 설명을 채우지 않는다.

### A. 질문 화면

경로는 `콜린성 약리학(1) / 작용 표적 / 현재 질문`으로 표시한다. 지도상의 정답 계열명·정답 개수를 부가 노출하는 목록은 풀이 시작부터 펼쳐놓지 않는다. 기존 질문이 스스로 제공하는 단서는 그대로 유지한다.

- 질문 아래에 “두 항목을 머릿속으로 떠올려보세요.”를 표시한다. 매번 텍스트 입력을 요구하지 않는다.
- 주 행동: **떠올린 뒤 정답 확인**. 이 행동은 사용자가 회상 시도 후 확인한다고 명시하는 입력이다. 시스템이 실제 사고 과정을 감지했다는 뜻이 아니다.
- 보조 행동: **답만 보기**. 시도하지 않은 열람을 별도로 기록한다.
- **지금은 넘기기**는 평가하지 않은 보류다. 실패·첫 학습으로 바꾸지 않는다.

### B. 정답 확인과 평가

회상 시도 후 확인했다면 원문 정답 두 줄을 보여주고 다음 세 평가를 제안한다.

| 평가 버튼 후보 | 이 문항에서 사용자가 판단할 기준 | 저장할 의미 |
|---|---|---|
| 못 떠올림 | 필요한 두 항목을 온전히 떠올리지 못함 | 시도·답 확인 사실은 남고 해당 방향은 보완 필요 |
| 도움 받아 떠올림 | 선지·지도·자료 등 답 단서의 도움으로 두 항목을 떠올림 | 도움 받은 평가. 도움 없는 회상 성공으로 처리하지 않음 |
| 스스로 떠올림 | 답을 보기 전에 두 항목을 도움 없이 떠올림 | 해당 방향의 도움 없는 회상 평가 |

두 항목 중 하나만 기억한 경우 전체 과제를 ‘스스로 떠올림’으로 기록하지 않도록 안내한다. 이 list를 자동으로 두 목표로 나누거나 한 번의 평가로 다른 문항·관련 방향까지 성공시키지 않는다.

**채택 전 해결할 표시 차이:** 위 초기안은 일부만 기억한 경우를 ‘못 떠올림’에 두었으나 CLI 검토는 부분 회상도 중간 평가 후보에 포함했다. 중간 상태에 포함한다면 버튼을 **일부만·도움 받아 떠올림**으로 표현하는 안을 권고한다. 부분 회상과 도움 사용은 서로 다른 사실이므로 중간 평가를 선택했다고 도움을 열었다는 기록을 만들어서는 안 된다. 이 구분은 실제 기록 필드·문구와 함께 확정하며, 현재 구현 기본값으로 처리하지 않는다.

답 단서를 담은 지도 내용을 펼치는 행동은 도움 열람으로 표시한다. 그 상태에서 ‘스스로 떠올림’을 누르면 도움 없이 떠올렸다는 평가와 충돌함을 알리고, 중간 평가로 바꾸거나 해당 단서를 회상 후 열었다는 사용자의 명시적 정정을 받는 안이다. 클릭만으로 몰래 높은 등급을 낮추거나 도움 사실을 지우지 않는다. 도움 시점의 구체 입력은 Spec 채택 시 확정한다.

‘답만 보기’로 진입한 경우 회상 평가 버튼 대신 **다음 질문**을 보여주는 안이다. 열람한 정답을 즉시 재현한 것을 도움 없는 회상으로 평가하지 않는다. 이 과제를 다시 공부할 수는 있지만 같은 날 반복을 의무로 만들지 않는다.

### C. 다음 질문·취소·종료

평가를 선택하면 추가 ‘다음’ 버튼 없이 다음 질문으로 이동한다. 질문 준비 중이어도 앞 문제를 다시 평가하게 만들지 않는다. 서버에 접수되기 전 상태는 **저장 중**으로 표시하고 완료 막대와 오늘 결과를 확정하지 않는다.

직전 평가 취소는 평가 취소 사건을 추가해 원래 상태를 재계산한다. 회상 시도·답 확인 사실은 남긴다. 취소 후 직전 질문의 답 확인 단계로 돌아가 평가를 다시 고를 수 있게 하는 안이다. 기록된 첫 학습 사실 자체가 잘못됐을 때는 별도 ‘학습 기록 정정’ 동작이 필요하며 단순 평가 취소와 섞지 않는다.

마지막 과제에서는 ‘오늘 결과를 저장 중’ 상태를 거쳐 모든 저장이 확인되면 오늘 결과를 보여준다. 사용자가 중간에 종료해도 확정된 기록은 남고, 이후 같은 질문·확인/평가 단계로 재개한다. 경로 종료·오늘 분량 완료·전체 범위 첫 학습 완료를 각각 구별한다.

## 3. 구현 가능한 상태 전이 제안

아래 사건 이름은 설명용이며 API 계약의 최종 이름은 아니다. 서버 시각·콘텐츠 판·사용자·세션 판과 함께 기록하는 구조를 제안한다.

| 현재 상태 | 사용자 행동 또는 응답 | 기록과 다음 상태 |
|---|---|---|
| 질문 중 | 지도 탐색·접기·펼치기 | 탐색 상태만 변경. 학습 사건 없음. 답 단서 열람은 별도 도움 표시 |
| 질문 중 | 떠올린 뒤 정답 확인 | 시도+답 확인 요청을 고유 요청 ID로 전송. 답 수신 후 평가 전. 첫 학습은 서버 확인 시 확정 |
| 질문 중 | 답만 보기 | 열람만 기록, 첫 학습 없음. 답을 보여주되 회상 성공 평가로 연결하지 않음 |
| 질문 중 | 지금은 넘기기 | 보류 후 다음 과제. 첫 학습·실패 평가 없음 |
| 평가 전 | 세 평가 중 하나 | 로컬에 요청 보관 후 다음 질문. 서버 확인 전에는 임시 표시 |
| 평가 전 | 종료 또는 새로고침 | 확인 단계와 확정된 시도 사실 유지. 재개 후 평가 가능 |
| 평가 전 | 평가 보류 | 첫 학습 사실은 유지, 해당 방향은 미평가로 남기고 다음 과제 |
| 저장 중 | 서버 확인 | 확정 위치·방향 상태·목표 집계를 서버 결과에 맞춤 |
| 저장 중 | 응답 끊김 | 같은 요청 ID로 접수 여부를 대조. 평가를 새 사건으로 중복 생성하지 않음 |
| 저장 중 | 명시적 실패 또는 로컬 보관 불가 | 새 평가 누적을 멈추고 해당 과제·미확인 요청·재시도 동작 유지 |
| 확정 평가 후 | 직전 평가 취소 | 서버에 취소 사건 기록, 해당 평가 전 상태로 재계산. 시도+답 확인은 유지 |
| 어느 단계든 | 다른 탭이 먼저 상태 변경 | 오래된 revision을 덮어쓰지 않고 재동기화. 사용자의 미확인 입력은 충돌 확인까지 보존 |
| 어느 단계든 | 계정 전환 | 이전 계정의 미확인 요청을 다른 계정으로 보내거나 보여주지 않음 |

질문 중 상태와 정답 수신을 기다리는 상태도 구별한다. 답을 받지 못한 네트워크 오류를 첫 학습 완료로 추정하지 않는다. 서버가 먼저 접수한 요청의 결과가 끊겼다면 재시도로 확정 여부를 대조한다.

## 4. 이 예시로 확인할 학습 변화

강의 전체 목표 수나 회상률을 만들지 않고 한 과제의 사실만 비교한다.

| 예시 행동 | 시도·답 확인 사실 | 해당 방향 평가 | 목표 전체의 회상 가능 여부 |
|---|---|---|---|
| 질문만 봄 | 없음 | 미평가 | 이 행동으로 판단하지 않음 |
| 답만 보기 | 없음 | 미평가 | 이 행동으로 판단하지 않음 |
| 시도·답 확인 후 틀림 | 있음 | 보완 필요 | 완료로 승격하지 않음 |
| 시도·답 확인 후 도움 없는 회상 평가 | 있음 | 도움 없는 회상 기록 | 실제 목표의 필수 방향과 유효기간이 확정돼야 판정 가능 |
| 평가 전 보류 | 있음 | 미평가 | 완료로 승격하지 않음 |
| 직전 평가 취소 | 있음 | 취소한 평가 이전 상태 | 남은 유효 사건과 필수 방향으로 재계산 |

오늘 결과에는 확정된 새 첫 학습 범위·회상 변화·중요 잔여를 표시한다. 이 예시에서 저장이 완료된 과제 수 1을 강의 목표 1개 전체의 회상 완료와 동일시하지 않는다. 실제 목표 연결과 필수 방향이 확정된 콘텐츠로 통합 검사해야 한다.

## 5. 남은 범위 대조와 이번 작업의 증거
