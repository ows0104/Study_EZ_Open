# 완료 작성 초안의 구조 실패를 기존 보완 예산으로 복구 — 배포 준비

## 코드 리뷰·검증 결과
명시적 완료 작성 수용 복구를 구현했다. 실제 NativeJson 파일·완료 영수증·사용량·원본·입력·원래 실패/소비를 확인하고 두 경로를 제공한다. brief-repair는 failed generate를 유지한 채 남은1회를 선소비하여 구조만 모델 보완하고 BANK/crop/임상충돌은 원문과 같아야 한다. acceptance-recheck는 실제 범위(label/included/excluded)가 같은 완료 보완의 검토 설명 교정을 전체 계약으로 재검증한다. 검토 설명의 변경도 derived와 이유가 필요하다. 이전 실패는 불변 증명에 남고 예산은 초기화하지 않는다.

recovery-contract13개, 기존 계약/생성/NativeJson 회귀239개 및 격리 서버 root_generation/root_pipeline_v2/root_preservation 각1개 통과. 최초 제한 환경의 서버 검사는 소켓 제한으로 정지해 소유 프로세스만 종료했고, 같은 검사를 정상 로컬 환경에서 다시 통과했다. API/DB/저장소는 합성이며 운영 자료를 사용하지 않았다. 테스트가 생성한 웹 프롬프트 줄바꿈 차이는 원복했다. 실제 강의 복구 검증은 아직 완료로 세지 않는다.

## 배포 대상 버전·순서·데이터 변경
별도 codex/root-authoring-recovery 로컬 후보다. CNS가 실행되었던 기존 작업 공간의 코드는 바꾸지 않는다. 명시 복구 명령은 모델/서버를 호출하지 않고 실제 원문 검증과 복구 증명만 작성한다. 원래 ledger는 복구 증명에 그대로 보존하며 새 실행 지문으로 연결한다. 실제 심내막염/CNS 실험에 적용하고 원본/독립 정답 검수를 마친 후 로컬 앱에서 확인한다. 운영 배포·548 재개·기존 은행·학습 기록·권한 변경은 없다.

## 배포 후 확인·롤백·필요한 사람 승인
사용자 구체 복구 승인과 기존 자료 전송/최대3회 보완 승인을 적용한다. 데이터/원본/실패/사용량은 되돌리거나 지우지 않는다. 코드 복원 시에도 이미 소비한 모델 호출·보완 횟수는 보존한다. 실제 복구의 결과/남은 지적/풀이 확인은 후속 기록에 추가한다. 운영 공개는 별도 중요 승인 범위다.
