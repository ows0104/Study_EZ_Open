# Implementation Plan

1. 변경 목록·작업 기록·Git 원격과 기존 제외 정책을 조사한다.
2. 생성 자료/캐시의 제외 규칙을 보강하고 소스·정책·검토 문서를 경로별로 선별한다.
3. root/server/web 검사를 실행하고 발견된 확실한 기술 문제만 필요한 범위에서 고친다. publication 검사로 스테이징 목록·비밀/대용량/충돌 표시를 점검한다.
4. 구조·파이프라인, 학습 기능, 자료/작업 기록 등 관련 변경끼리 커밋한다. 공유 파일의 의존성이 강하면 함께 커밋한다.
5. 사용자 명시 승인 범위로 현재 원격 브랜치에 일반 push한다. 원격 앞섬이 있으면 보존한 상태에서 통합하고 충돌 여부를 확인한다. force push·클라우드 배포는 하지 않는다.

현재 사용자 발언은 전체 다른 세션 변경의 검토·필요 정리·커밋·push를 포함한다. 기존 요청 범위의 동일 승인을 반복 요청하지 않는다. 생성 자료와 사용자 파일을 삭제하지 않는다.
