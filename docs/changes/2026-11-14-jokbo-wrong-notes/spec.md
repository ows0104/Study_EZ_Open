# 족보 오답노트 (2026-11-14)

## 의도

사용자: 「족보에는 오답노트 기능도 있어야 해. 좌측 메뉴에 오답노트 메뉴를 추가해줘. 들어가면 amgi에서 봤던 거랑
비슷한 오답노트 페이지를 우선 구현해줘. 족보 오답을 각 강의별로 보기에는 너무 빠듯하니까 그냥 amgi처럼 하나에 모아줘.」
PR을 올리고 CI가 통과하면 병합까지 한다.

## 동작

- 좌측 메뉴 학습 칸에 **오답노트**(`/wrong-notes`). 족보 문항을 강의 구분 없이 한 화면에 모은다.
- 담기는 길 두 가지.
  - 족보 퀴즈에서 틀리면 서버가 **상 틀림**을 붙인다. 맞혀도 표시는 떼지 않는다(사람이 뗀다).
  - 답을 연 뒤 **상 틀림 · 중 좁혀서 · 하 헷갈림**으로 직접 담거나 바꾸고, 켜진 것을 다시 누르면 뗀다.
    amgi 족보 오답노트의 상·중·하 손표시를 그대로 따랐다. amgi는 종이로 풀어 자동 채점이 없었지만
    StudyEZ는 사이트에서 채점하므로 틀린 문제는 자동으로 담는다.
- 오답노트 화면(amgi `PastExamWrong`과 같은 구성).
  - **풀기 / 정답 보기** 토글(이 기기에 기억). 풀기는 답을 가리고, 선지를 고르면 채점한다(틀리면 다시 상 틀림).
    「답 보기」로 그냥 열 수도 있고 「답 전부 보기」로 한 번에 연다. 정답 보기는 정답·선지별 해설·해설이 펴져 있다.
  - 상·중·하로 거른다(수 표시).
  - 목록은 들어올 때 한 번 세운다. 표시를 떼거나 바꿔도 줄이 남는다(「뗌」, 「지금 중」). 다음에 들어오면 뗀 것은 빠진다.
  - 순서: 상 → 중 → 하, 그 안은 강의 날짜 → 족보에 실린 순서. 카드마다 강의(누르면 그 강의 족보 퀴즈)·연도·교수·번호·틀린 횟수.
  - 족보가 관리자 전용으로 돌아갔거나 다시 빌드해 문항이 사라졌으면 「볼 수 없는 문제 N」으로만 센다.

## 저장

새 표 `jokbo_mark` (사람 × 족보 문항 한 줄, RLS). 족보 문서는 그대로 R2.

| 칼럼 | 뜻 |
|---|---|
| user_id, item_id | 키. item_id는 족보 원천 id(`pe_2023_12_030`) — 다시 빌드해도 그대로. 합쳐진 사본 id면 대표 문항으로 찾는다 |
| event_id | 시간표 칸 |
| band | high · mid · low · NULL |
| wrong_count, right_count, last_result, answered_at | 족보 퀴즈·오답노트에서 푼 기록 |
| marked_at, updated_at | 표시 시각 |

API(모두 본인 것만, 족보를 볼 수 있는 사람만 쓰기):

- `GET /api/jokbo/marks[?eventId=]`
- `POST /api/jokbo/events/{eventId}/items/{itemId}/answer` `{result: correct|wrong|ungraded}`
- `PUT /api/jokbo/events/{eventId}/items/{itemId}/mark` `{band: high|mid|low|null}`
- `GET /api/jokbo/wrong-notes` — 표시 붙은 문항 + 강의·교수·서명 그림 URL

쓰기마다 족보 문서를 R2에서 읽지 않도록 프로세스 안에 60초 둔다(올리면 바로 비운다).

이용현황: `jokbo_answer` 「족보 퀴즈 풀이」(문항). 한 줄 = 푼 족보 문항, 시각은 마지막으로 푼 때.
강의 상세는 그 칸에 이어진 강의 줄에, 없으면 칸 id 줄에 붙는다.

## 배포 순서

운영 DB에 `jokbo_mark` 표를 먼저 만든다 — `create_table.py`(이 표 하나만 create_all, RLS 확인). 운영 자격 정보는 사용자가 넣고 실행한다.
표 없이 병합하면 오답노트·이용현황 API가 500이므로 표 확인 뒤에 master 병합 → API → 웹.

## 하지 않은 것

- 복습 퀴즈식 간격·채점 기록은 아직 없다(사용자 결정 대기). 푼 횟수와 마지막 결과만 남긴다.
- 문항별 내 노트(amgi의 「내 노트」)는 넣지 않았다.
