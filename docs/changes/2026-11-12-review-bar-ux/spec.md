# 복습바·로딩 속도·풀이 바·Ctrl+Z — 설계

## 요구사항과 수용 기준

### 속도 — 측정한 원인

운영 DB를 읽기 전용 트랜잭션으로 읽어 로컬에서 잰 결과(학습 기록이 가장 많은 두 계정, 공개 Main-Quiz 23편):

- CPU의 95%가 `state.replay_tasks`가 부를 때마다 다시 하는 `task_fingerprints(doc)`(문항마다 canonical JSON + SHA-256)다.
  23편 요약에 161번, 22,743문항을 다시 해시했다(로컬 CPU 23.3 s 중 21.2 s).
  지문은 **이전 판의 이벤트**를 이번 판 문항에 잇는 데만 쓴다.
- 문서 한 편이 JSON 6–11 MB(23편 96 MB)이고 그중 92 %가 문항 그림 `stimuli`다. 학습 상태·학습률·계획 계산은
  `stimuli`를 읽지 않는다. 캘린더 주 요청의 시간은 거의 전부 이 문서를 DB에서 읽는 데 든다.
- Cloud Run 메모리는 512 MiB라 원본 문서를 담아 둘 수 없다.

### 수용 기준

- S1 `replay_tasks`는 이전 판 이벤트가 실제로 있을 때만 지문을 계산한다. 결과는 같다.
- S2 학습률·목록 요약 계산은 「가벼운 문서」를 쓴다: 원본에서 문항 `stimuli`만 뺀 사본 + 원본으로 계산한 지문.
  (강의, 판, digest)마다 인스턴스 메모리에 한 번 만들고 다음 요청부터는 digest만 읽는다.
  문항을 화면에 그리는 경로(풀이·지도·관리자)는 원본을 그대로 쓴다.
- S3 `GET /api/root-learning`은 한 강의의 요약이 실패하면 그 강의만 빼고(로그 남김) 나머지를 돌려준다.
- 공개 23편 × 상위 두 계정의 실제 데이터에서 원본/가벼운 문서의 요약·계획·문항 진행·학습률·범위가 같다.
- W1 캘린더: 목록 요청과 주 학습률 요청을 동시에 보낸다.
- W2 강의 목록: `study-progress` 8강의 묶음을 최대 3개 동시에, 창 포커스 재읽기는 60초에 한 번.
- W3 복습 막대 색·테두리, 시험 밖 갈래의 빈 막대 숨김.
- W4 풀이: 스페이스는 버튼·링크에 포커스가 없으면 언제나 쪽 스크롤을 막는다(누르고 있어도).
  아래 바는 처음부터 화면 아래 16px에 붙어 있고 스크롤 끝에서도 같은 자리다.
- W5 풀이: Z·Ctrl+Z·⌘+Z가 되돌린다. 버튼에 포커스가 있어도, 한글 입력 상태(KeyZ)여도. 입력칸 안에서는 브라우저 기본 동작.

## 책임·입출력 계약·오류 상태

- API 응답 모양은 바뀌지 않는다. `/api/root-learning`은 실패한 강의를 목록에서 뺄 뿐이다(웹은 시간표의 `mastery`로 대신 그린다).
- 가벼운 문서 캐시는 프로세스 메모리, 최대 32편 LRU, 잠금으로 보호. 키에 digest가 들어 있어 판이 바뀌면 새로 만든다.
  RootContent 행은 넣기만 하고 고치지 않는다(코드 전체에서 `document` 갱신 없음).

## 호환성과 데이터 보존

- DB 스키마·학습 기록·문항·판·공개 범위를 바꾸지 않는다. 쓰기 없음.
- 학습률 정의(`score.py`)·복습일 계산(`state.py`)의 결과를 바꾸지 않는다(지문 계산 시점만 늦춘다).
