# 콜린성 약리학(1) 뿌리 시범 검토 — 설계

## 요구사항과 수용 기준

상태: 원본과 기존 산출물의 식별을 마친 시범 검토 설계. 사용자 동의 후 실행 경로 비교를 우선 요청받아
분석 실행은 시작하지 않았다. 현재 비교와 기능별 권고는 [execution-strategy.md](execution-strategy.md)를 따른다.
제품 구현·운영 반영은 승인 범위에 포함하지 않는다.

### 결과물

1. 원본 전체를 살펴 고른 뿌리/큰 구조 후보. 분류·순서·목적·핵심 질문 등의 역할과 실제 근거 쪽을 제시한다.
2. 별도 원본 전용 추출로 만든 뿌리 관련 출제 포인트와 족보 근거. 목록 밖 누락 가능성·합본 족보의 범위 불확실성도 기록한다.
3. 뿌리/포인트 ↔ 실제 기존 문제 ID의 대조표. 실제로 묻는 관계·방향과 충분/부분/미충족/불명확을 구별한다.
4. 뿌리에서 큰 가지로 진입하는 제안 순서와 처음 몇 지점의 학습 흐름. 없는 뿌리 질문은 별도 검토 초안으로만 제시하고 운영 문제에 추가하지 않는다.
5. 사용자가 읽을 `review.md`: 뿌리의 선정 이유, 기존 문제가 맡는 역할, 부족한 연결, 검토 질문을 간결하게 정리한다.

### 선정·대조 원칙

- 독립 뿌리·포인트 추출 입력에는 기존 은행·문항 색인·옛 개념도를 넣지 않는다. 원본과 교수별 범위 근거만 사용한다.
- 뿌리 추출과 출제 포인트 추출은 서로의 결과를 정답으로 전제하지 않는 별도 입력으로 작성한 뒤 대조한다.
- 족보의 (1)·(2) 범위는 올해 (1) 필기와 근거를 대조한다. (2) 내용을 (1)의 누락으로 일괄 판정하거나 합본 전체를 (1) 범위로 삼지 않는다.
- 완성된 기존 문항 목록에서 새 트리의 전체 범위를 역으로 정의하지 않는다. 기존 69문항을 모두 뿌리 질문으로 간주하지 않는다.
- 문항이 연결돼 있다는 것과 해당 관계·방향을 실제로 물었다는 것을 구별한다. 원본 근거가 부족하면 보류 사유를 남긴다.
- 기존 문항·정답·해설·검수 판정은 읽기만 한다. 새 검토 초안이 기존 내용의 수정이나 의학 검수 통과를 뜻하지 않는다.
- 이번 실행은 강의별 뿌리 검토이며 전체 세부 Tree·강의 간 연결·전 강의 재출제를 만들지 않는다.
- 도출한 뿌리가 옳다는 판정은 아직 미실행이며, 사용자에게 원본 근거와 초안을 제시한 뒤 검토한다.

## 책임·입출력 계약·오류 상태

입력 경로와 확인한 지문은 [sources.md](sources.md)를 따른다. `response-resume.json`은 로컬 참조본의
연결 근거이며 운영 서버의 현재 은행을 확인했다는 증거가 아니다.

계획 승인 후 로컬 전용 작업 폴더 `work/concept-tree-cholinergic-20261029/`에 실행 입력 목록·원본 지문,
원본 읽기용 텍스트/이미지·문서 쪽 대응, 원본 전용 CLI 결과와 대조 결과를 새로 보관하는 안이다.
원본의 그림·표·필기를 텍스트만으로 판단하지 않으며 필요한 지면을 함께 확인한다.

2026-10-31 역할 배치: 원본 기반 출제 포인트·뿌리 후보 작성은 사용자가 수동 전송하는 별도 일반
ChatGPT 웹 대화에서 수행한다. 기존 69문항은 재사용한다. Codex CLI는 원본 대조·의미 연결을 맡고,
현재 에이전트는 실행 연결·산출물 확인·사용자용 검토 안내를 맡는다. 구체 흐름은 [pipeline.md](pipeline.md)를 따른다.
기존 생성기·문제은행·공용 프롬프트는 수정하지 않는다.
프로젝트의 기본 모델 설정을 사용하고 별도 모델을 임의 지정하지 않는다.

2026-10-31 첫 웹 결과의 파일 계약과 회수 절차는 [next-step.md](next-step.md),
[roots-request.md](roots-request.md), [points-request.md](points-request.md)를 따른다.
2026-11-01 사용자 지시에 따라 첫 요청은 기존 문제를 보지 않고 필기·족보에서 강의 전체 구조를 추출하도록 한다.
참고 대화를 풀어쓴 intent를 바탕으로 사용자가 요청문 재작성을 요청했다. 현재 요청문은 큰 구조에서 세부로
이어지는 지도, 학습 목표에 따른 묶음과 강의의 흐름, 소속·연결 이유·유사 개념의 차이, 무조건 연결하지 않기를 담는다.
추천 알고리즘·반복·자기평가·문제 생성 지시를 추출 요청에 넣지 않는다.
처음부터 질문/답·근거·깊이·파일명·메타데이터 등 출력 형식을 강제하지 않고 나온 결과를 함께 검토한다.
이 간단한 요청 자체가 뿌리의 대표성·원본 근거·범위 확인을 보장하지는 않는다. 후속 검토에서 이를 확인하고,
파일 전달이 필요하면 별도로 요청한다. 첫 출력이 세부 트리를 포함해도 이번 제품 적용 범위를 확대하지 않는다.
식별·참조 정리는 회수 후 수행하며 완료 문구만으로 수신/내용 검증을 대신하지 않는다.
사용자의 후속 요청으로 포인트 요청문도 “위 필기와 족보를 보고 출제 포인트를 추출해줘.” 한 문장으로 바꿨다.
포인트 결과의 형식·깊이·파일명·메타데이터를 처음부터 강제하지 않고 결과를 함께 검토한다.
첫 요청에서 나온 세부 포인트를 모두 구현·재출제하는 것으로 범위를 확대하지 않는다.
뿌리/포인트 결과는 기존 bank-response에 넣지 않는다.
현행 문제은행 수신기의 지원을 가정하지 않으며, 첫 회수는 사용자 수동 파일 전달이다.
처음 받은 파일의 구조·바이트 지문 확인과 bridge 자동 회수·의학적 타당성 검증을 구분한다.

원본 누락·지문 불일치·불완전 출력·범위 혼동·CLI 실패는 해당 상태와 미실행 부분을 남긴다.
완료 산출물과 원문을 보존해 중복 저작을 피하며, 실패를 통과로 바꾸거나 기존 수정/검수 횟수를 초기화하지 않는다.
기존 raw 포인트 파일이 있다는 이유로 독립 추출 완료로 판단하지 않는다.

## 호환성과 데이터 보존

- PDF·족보 조각·기존 은행·출제 포인트·검수/재개 기록은 변경하지 않는다.
- 기존 ID·개인 편집·제외 상태·학습 기록을 새 초안에 자동 승계하거나 초기화하지 않는다.
- 로컬 참조 은행은 현재 바이트 지문으로 고정하고 실행 후 동일성을 확인한다. 서버·DB는 조회하거나 변경하지 않는다.
- 새 파일은 작업 전용 폴더에만 추가한다. 저장소의 다른 미커밋 변경을 되돌리거나 커밋하지 않는다.
- 웹 자동 전송·재출제·러너 업로드·운영 게시·기존 자료 이동/삭제는 이 계획에 포함하지 않는다.
