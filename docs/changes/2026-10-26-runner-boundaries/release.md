대상: P3b 러너 경계 정리. 현재 코드 지문 `bb7ce1390317f34c4b429b3016b06ff4c557b90b1630326f0409f850298846c4`.
CLI/HTTP/상태 파일/재시도 정책은 유지하며 DB 마이그레이션은 없다.
검사: 러너 477개, 공용 계약·개발 도구 14개, 14가지 차등 재현과 CLI/import 검사 통과.

검토: agent 실행/중단/잠금은 유지하고 상태 판정만 분리했다. bank 입력 확인 순서와
재개·수정 상한을 유지했다. 이미지 확인 뒤 은행을 올리는 순서 및 실패 보고가 동일하다.
transport는 게시 정책에 의존하지 않는다. 기존 caller import는 호환 이름으로 유지한다.
sources의 PDF fallback은 기존 publish planner에 의존하며 import 초기화만 지연한다.

현재 저장소에는 다른 미커밋 작업도 있다. 이 변경을 포함한 전체 작업 트리를 자동으로
배포 승인 대상으로 삼지 않는다. 운영 적용 시 후보 포함 범위와 실행 중 러너를 먼저 확인하고
정지/교체가 필요한 경우 그 작업 단위 및 복원 기준을 정한 후 중요한 승인을 받는다.
이번에는 실제 agent 실행·재시작·일감 claim·모델 출제·운영 업로드·커밋/푸시를 하지 않았다.

복원: work/runner-originals와 runner-apply-manifest.json의 전후 해시를 대조해 이번 코드만 복원.
기존 runs와 사용자 변경은 덮어쓰지 않는다. 재개/ledger 데이터 형식은 같으므로 데이터 이전 없음.
