첨부한 강의자료와 족보로 의대 시험 대비 문제은행을 만들어줘.
강의: {{title}}

1. 교수 강조·학습목표·족보를 참고해 출제 포인트를 먼저 정리해라.
2. 이를 바탕으로 Concept Map → Retrieval Plan → Question Bank를 작성해라.
3. 아래 문항 품질 원칙을 적용하고, 문항 수와 형식은 각 포인트의 학습 가치에 맞게 판단해라.
4. 각 포인트와 문제에 원본 근거를 남겨라. PDF는 실제 쪽 번호를 써라. 외부 의학지식도 사용하되 자료에 없거나 다른 내용은 EXT로 표시해라. 출처가 충돌하면 한 문항으로 합치고 차이·선택한 답·판단 근거를 설명해라.
5. 완성본을 검토해 누락·오류·중복을 수정해라. 정답이나 범위를 확정할 수 없는 내용은 불확실한 것으로 남겨라.

문항 품질 원칙

아래 원칙은 최초 출제와 CLI의 문항 설계 검토·수정·보강에 공통으로 적용한다.

### 1. 인출 목표와 형식

- 한 문항은 하나의 의미 있는 인출·판단 목표를 중심으로 만든다. 독립적인 요구를 「쓰고, 구별하고, 설명하라」로 합치지 않는다. 여러 목표가 섞이면 목표별로 나누거나 요구를 좁힌다.
- 같은 축의 비교·대응이나 함께 기억할 가치가 있는 관계는 묶을 수 있다. 하나의 기전·과정이 여러 단계라는 이유만으로 쪼개지 않는다. 함께 묶을 학습 가치와 개별 인출의 필요성을 판단한다.
- Basic(단답형)은 용어·수치·짧은 관계로 쓰고 전체 설명을 요구하지 않는다. 긴 서술이 필요하면 목표를 좁히거나 적합한 형식으로 바꾼다. 서술형 답을 불릿으로 나눈 것만으로 단답형이 되지는 않는다.
- List는 하나의 축에 속하고 답의 범위가 정해진 항목을 나열할 때 쓴다. 서로 다른 축의 질문을 List로 합치지 않는다. 대응은 Matching, 과정의 순서는 Sequence 등 목표에 맞는 형식을 선택한다.

Basic 예시 — 여러 독립 요구를 한 서술형으로 묶지 않는다.
✗ Vancomycin의 결합 서열을 쓰고, 직접 결합 대상과 두 효소의 이름을 포함해 세포벽 합성 억제 과정을 설명하라.
✓ Vancomycin이 결합하는 세포벽 전구체의 말단 서열은? (Basic)
✓ Vancomycin은 세포벽 합성 효소와 전구체 기질 중 어디에 직접 결합하는가? (Basic)
✓ Vancomycin의 전구체 결합으로 기질 접근이 차단되는 두 효소는? (같은 축의 List)
기전의 연결 자체를 시험할 필요가 있으면 별도 목표로 설계한다. 각 기초 지식은 실제 자료에서 확인한다.

### 2. 발문과 정답 단서

- 질문만으로 답의 범위가 결정돼야 한다. 필요한 조건·범주·분류 기준·답할 변수를 명시한다. 수송의 이동 방향과 양·속도의 증감처럼 다른 질문 축을 구별한다. 서로 다른 답이 자연스럽게 가능하면 범위를 명확히 한다.
- 발문은 간결하게 쓴다. 범위 결정에 불필요한 설명이나 답의 구성 항목을 미리 나열하지 않는다. 무엇을 묻는지 세우는 데 필요한 조건은 남긴다.
- 출처 대신 지식 자체를 묻는다. 「강의에서 제시한」·「족보에서」로 답의 범위를 한정하지 않는다. 필요한 내용상 조건을 발문에 쓰고 출처 정보는 source_refs·exam_rationale에 둔다.
- 정답의 의미를 발문에 노출하지 않는다. 동의어·약어 풀이·반대말·문장 다른 위치의 같은 답도 확인한다. 평가하려는 지식을 알려 주는 단서는 제거하고 실제 판단에 필요한 조건은 보존한다.
- 해당 의학 지식을 알아야 풀리는 문항을 만든다. 일반 추론·산술·제시된 범위 비교만으로 끝나면 정답에 필요한 의학 지식을 인출·적용하도록 다시 설계한다. 그런 계산·비교가 다른 의학적 판단의 중간 단계이면 사용할 수 있다.

### 3. 정답과 해설

- answer_units에는 실제 인출 대상의 최소 채점 단위만 둔다. 발문에 이미 있는 사실, 같은 의미의 반복, 부연을 별도 채점 항목으로 세지 않는다. 질문이 요구하는 지식과 정답 단위를 대조한다. OX의 근거·정정 설명을 answer_units에 저장하는 CLI 계약은 유지한다.
- 채점은 핵심 개념·관계·필요한 조건의 의미를 기준으로 한다. 의미가 같은 동의어·허용되는 약어·표기·어순 차이는 정답으로 인정한다. 정확한 명칭·수치·서열 자체가 목표이면 그 정확성은 요구한다. 필요한 조건이나 관계가 빠지거나 작용 방향이 바뀐 답은 동등한 답으로 보지 않는다. 정답 검토와 자기채점 기준도 이 원칙을 따른다.
- 배경·부연은 해설에 둔다. 인과 자체가 인출 목표이면 정답에 남긴다. 길이를 줄이려고 필요한 관계·조건을 잘라 의미를 훼손하지 않는다. 해설 작성은 기존 웹·CLI 역할 분담을 따른다.

### 4. Cloze

- 각 학습 목표에 적합한 문항 형식을 검토한다. 문맥이 답의 역할·관계를 명확히 하고, 핵심 개념을 가려 인출하는 데 적합한 목표에는 Cloze를 활용한다. 형식 변경만으로 같은 목표의 문항을 중복 추가하지 않는다. Cloze가 0문항이면 적합한 목표가 없다고 판단한 이유를 짧게 기록한다.
- Cloze의 빈칸에는 핵심 개념을 둔다. 약물·표적·기전·효과·수치 등 학습할 지식을 가린다. 조사·곁말·문맥만으로 채워지는 말을 비우지 않는다. 실체 없는 단계 번호·기호는 해당 실체와 함께 가린다.
- Cloze의 남는 문장은 각 빈칸이 무엇을 묻는지 알려줘야 하며, 정답 자체를 알려줘서는 안 된다. 학습할 지식을 몰라도 남은 문장의 동의어·반대말·문법·상식만으로 답을 알아낼 수 있는 빈칸은 고친다. 빈칸을 [ ]로 바꿔 읽고 요구 대상은 명확한지, 정답을 인출해야 하는지 확인한다.
- Cloze는 정답의 의미 있는 덩어리를 가린다. 답의 일부를 남겨 나머지를 짐작하게 하지 않는다. 각 빈칸의 경계와 answer_units를 함께 확인한다.
- 단순 나열은 같은 축의 List로 만들고, 문맥이 각 항목의 역할·관계를 구별해 줄 때 Cloze를 쓴다.
- 빈칸은 하나 이상 두되 개수의 고정 상한은 두지 않는다. 같은 학습 목표에서 함께 인출할 가치와 풀이·채점 부담을 기준으로 수를 정한다. 수를 맞추려고 필요한 지식을 빼거나 억지로 분할하지 않는다. 독립 목표가 섞이거나 부담이 과하면 목표별로 나눈다.

예시 1 — 남은 문장만으로 정답을 알아낼 수 없는가? 가상의 지역에서 겨울 강수량이 가장 많다는 자료가 있는 경우:
✗ 이 지역은 여름과 겨울 중 {{c1}}이 여름보다 강수량이 많다. → 이 지역을 몰라도 남은 문장만으로 겨울이라고 답할 수 있다.
✓ 이 지역에서 강수량이 가장 많은 계절은 {{c1}}이다. → 계절을 묻는다는 점은 분명하고, 답하려면 해당 지역의 지식이 필요하다.
answer_units: 겨울

예시 2 — 빈칸이 무엇을 묻는지 알 수 있는가?
✗ 이 도시는 {{c1}}이다. → 위치·산업·인구·기후 중 무엇을 묻는지 알 수 없다.
✓ 이 도시의 주된 산업은 {{c1}}이다. → 주된 산업을 묻는다는 점은 분명하고, 산업의 이름 자체는 가려져 있다.
answer_units: 관광업

예시 3 — 빈칸이 여럿이어도 각 자리의 질문 축이 분명한가?
✗ A종은 {{c1}}이고 B종은 {{c1}}이다. → 생김새·서식지·번식 방식 중 무엇을 비교하는지 알 수 없다.
✓ A종의 잎 모양은 {{c1}}이고 B종의 잎 모양은 {{c1}}이다. → 두 빈칸 모두 각 종의 잎 모양을 묻는다. 같은 축의 비교이므로 함께 인출할 수 있다.
answer_units: 넓고 둥근 모양<br>좁고 길쭉한 모양

질문 축은 빈칸에서 답할 대상·특성·비교 기준이다. 축을 남기는 것과 정답을 노출하는 것을 구별한다.
예시 1–3은 가상의 내용이며 실제 문항은 첨부 자료에 근거한다.

예시 4 — 단일 빈칸: 두 현상을 연결하는 공통 원인을 인출한다. 기타항생제 자료로 독립 CLI 검수를 통과한 예시:
question: Tetracycline의 소화관 내 금속 양이온 결합에 따른 흡수 저하와 치아·뼈의 칼슘 결합에 따른 침착은 공통적으로 {{c1}}이라는 화학적 성질에서 비롯된다.
answer: Tetracycline의 소화관 내 금속 양이온 결합에 따른 흡수 저하와 치아·뼈의 칼슘 결합에 따른 침착은 공통적으로 킬레이트 형성이라는 화학적 성질에서 비롯된다.
answer_units: 킬레이트 형성
→ 빈칸은 두 현상의 공통 화학적 성질을 묻는다. 핵심 개념 전체를 가렸으며, 남은 문장에는 그 결합 방식의 명칭이나 동의어가 없다.

예시 5 — 복수 빈칸: 같은 학습 목표의 변화 전후를 함께 인출한다. 기타항생제 자료로 독립 CLI 검수를 통과한 예시:
question: VanA·VanB 유전자군에 의한 vancomycin 내성에서는 세포벽 전구체의 말단 서열이 {{c1}}에서 {{c1}}으로 바뀐다.
answer: VanA·VanB 유전자군에 의한 vancomycin 내성에서는 세포벽 전구체의 말단 서열이 D-Ala-D-Ala에서 D-Ala-D-Lac으로 바뀐다.
answer_units: D-Ala-D-Ala<br>D-Ala-D-Lac
→ 첫 빈칸은 변화 전, 둘째 빈칸은 변화 후의 말단 서열을 묻는다. 두 서열 전체를 가려 공통 잔기로 답을 추측할 단서를 없앴다. 같은 {{c1}} 표기여도 각 답은 등장 순서대로 대응한다.

### 5. 보기와 난이도

- 객관식을 적절히 활용한다. 먼저 답을 인출하는 기억 확인형은 recall_first, 선지를 비교·판별하는 과정이 목표인 구별·판단형은 comparison이다. 두 유형 모두 실제 선지와 정답을 작성한다.
- 난이도는 비교·기전·조건 적용에서 만든다. 모호한 표현·긴 답·불필요한 요구로 어렵게 만들지 않는다. 쉬운 기초 인출 문항도 학습 가치가 있으면 허용한다.
- 객관식 오답은 실제 혼동·오개념에 근거하고 같은 판단 축의 보기를 만든다. 억지 오답·이중 부정·표현상의 정답 단서를 피한다. 객관식·OX·보기 풀에서 「반드시·항상·모든·절대」 같은 과도한 단정이나 일부러 부자연스럽게 만든 문구만으로 정오가 드러나지 않게 한다. 이 단어들을 일괄 금지하지는 않는다. 내용상 필요한 한정어는 유지하되 참·거짓 모두 자연스럽고 지식으로 판별할 수 있게 쓴다. 보기 길이·정답 위치도 단서가 되지 않게 한다.

예시 1 — recall_first (기억 확인형, format=mcq)
question: Vancomycin이 결합하는 세포벽 전구체의 말단 서열은?
options: A: D-Ala-D-Lac<br>B: D-Ala-D-Ala<br>C: L-Ala-D-Ala<br>D: D-Ala-L-Ala<br>E: L-Ala-L-Ala
correct_option_ids: B
answer: B: D-Ala-D-Ala
분류 이유: 선지 없이도 특정 서열을 먼저 인출할 수 있다. 선지는 인출한 답을 확인하는 역할을 한다.

예시 2 — comparison (구별·판단형, format=mcq)
question: β-lactam계 항생제와 Vancomycin의 직접 결합 대상을 올바르게 연결한 것은?
options: A: β-lactam → 전구체 기질; Vancomycin → 전구체 기질<br>B: β-lactam → 전구체 기질; Vancomycin → 효소(PBP)<br>C: β-lactam → 효소(PBP); Vancomycin → 전구체 기질<br>D: β-lactam → 효소(PBP); Vancomycin → 효소(PBP)<br>E: β-lactam → 효소(DNA gyrase); Vancomycin → 전구체 기질
correct_option_ids: C
answer: C: β-lactam → 효소(PBP); Vancomycin → 전구체 기질
분류 이유: 두 약물의 효소·기질 결합 차이를 후보별 연결과 비교해 판별하는 것이 목표다. 선지 없이 답을 말할 수도 있다는 사실만으로 recall_first로 분류하지 않는다.

mcq_mode는 학습 목표를 기준으로 판단한다. 「다음 중」이라는 문구, 보기 수, 난이도만으로 정하지 않는다.
위 예시는 유형 구분을 위한 것이며 실제 출제는 첨부 자료와 출제 포인트에 근거한다.

### 6. 문항 구성과 학습 계획

- 통합·List·Matching 문항으로 묶어도 따로 인출할 가치가 있는 기초 사실의 문항을 생략하지 않는다. 개별 인출이 실제로 필요한 포인트를 보존하되 묶인 문항마다 기초 문항을 기계적으로 추가하지 않는다.
- 반복 문항에는 추가 학습 목표가 있어야 한다. 역방향·객관식·OX라는 형식 차이만으로 늘리지 않는다. 같은 인출·판단의 중복은 통합하고 별도 비교·적용 목표가 있는 문항은 보존한다.
- 선택한 범위의 독립 포인트와 필요한 회상 방향을 충분히 문항화한다.
- prerequisites에는 실제로 필요한 기초 question_id만 연결한다. 기전·구별·통합·순서 문항에서 필요한 기초 인출과 연결을 확인한다. 같은 개념이거나 앞선 문항이라는 이유만으로 연결하지 않는다.
- 중요도와 난이도는 독립적으로 판단한다. Core는 시험 전에 반드시 인출·판단할 핵심이며, 중요한 기전·비교·적용도 Core일 수 있다. Advanced는 Core를 익힌 뒤 추가로 풀 가치가 있는 확장·심화, Optional은 선택한 범위 안의 낮은 우선순위다. 형식·회상 방향·답 길이·난이도만으로 tier를 자동 지정하지 않는다.

### 7. 최종 문항별 검수

최종 문항마다 아래 세 항목을 확인하고, 확인된 위반을 수정한다. 정정한 문항·선지·정답도 다시 대조한다.
- 출처로 범위 한정: 「강의에서 제시한」 같은 표현 대신 답의 범위를 결정하는 내용상 조건을 명시했는가?
- 정답 노출: 평가하려는 지식을 발문에서 이미 제공했는가? 실제 판단에 필요한 조건은 보존한다.
- 보기의 비대칭: 정답에만 조건·설명이 집중돼 길이나 구성이 단서가 되는가? 모든 보기를 같은 판단 축과 비슷한 상세도로 작성한다.
단어를 일괄 삭제하거나 선지 길이를 숫자로 맞추지 않는다. 의미를 보고 수정하며, 필요한 조건·관계와 정답의 정확성을 보존한다.

출력 형식

전체 결과는 파일 링크 대신 이 대화 본문에 Markdown 표로 출력해라.

첨부 자료의 ID와 파일 이름은 다음과 같다. 이 ID를 source_refs에 사용한다.
{{sources}}
다음 이름의 Markdown 표를 출력한다. 각 표의 열 순서는 아래와 같다.
배열 항목은 <br>로 구분한다. 셀 본문의 |는 &#124;로 쓰고 한 행에 실제 줄바꿈을 넣지 않는다.

0. Exam Point Plan
point_id | point | source_refs
포인트 ID는 P001…로 지정한다.
각 포인트에는 무엇을 인출·구별·적용해야 하는지 구체적으로 적어라.

1. Concept Map
concept_id | title | graph_title | core_facts | importance | importance_rationale | concept_difficulty | tier | exam_signal_strength | related_concepts | source_refs
importance·concept_difficulty는 1–5, tier는 Core / Advanced / Optional, exam_signal_strength는 low / medium / high다.
graph_title은 개념을 구분할 수 있는 짧은 이름이다. core_facts·related_concepts는 ;로 구분한다.

2. Retrieval Plan
concept_id | directions | repetition_budget | target_mastery
directions는 direct / reverse / mechanism / discrimination / integration / sequence / trap 중 필요한 것을 선택한다.
repetition_budget는 1–100, target_mastery는 0.1–1이다.

3. Question Bank

3.1 Questions
question_id | concept_id | tier | importance | item_difficulty | format | retrieval_direction | mcq_mode | question | answer | answer_units | prerequisites | source_refs | exam_rationale | conflict_id
importance·item_difficulty는 1–5다. format은 basic / cloze / list / ox / mcq / multi_select / matching / sequence다.
mcq_mode는 recall_first / comparison이며 다른 형식은 none이다. exam_rationale에 관련 point_id와 출제 이유를 적는다.
cloze의 빈칸은 모두 {{c1}}로 표시한다. answer_units는 빈칸 등장 순서대로 하나씩 대응시키고, answer에는 정답을 채운 문장을 쓴다.
basic의 answer와 answer_units는 같은 짧은 정답 단위다. ox의 answer는 O 또는 X다.
해설은 CLI에서 작성하므로 웹에서는 정답과 핵심 채점 단위만 출력한다.
integration에는 실제 필요한 기초 question_id를 prerequisites로 연결한다. 빈 prerequisites·conflict_id는 —로 쓴다.

3.2 Choice Details
question_id | options | correct_option_ids
options는 A: 내용<br>B: 내용…으로 쓴다. mcq는 정답 1개, multi_select는 해당하는 정답을 모두 적는다.

3.3 Matching Details
question_id | matching_left | matching_right | answer_pairs
왼쪽은 1. 항목…, 오른쪽은 A. 항목…으로 쓰고 정답 짝은 1. 왼쪽 - B. 오른쪽처럼 적는다.

3.4 Sequence Details
question_id | sequence_items | correct_order
항목에 A: 내용…처럼 ID를 붙이고 correct_order에 ID를 순서대로 적는다.

같은 판단의 보기 조합을 바꿀 가치가 있으면 선택적으로 다음 두 표를 작성한다.
3.5 Option Pools: question_id | pool_id | select_count | correct_when
3.6 Option Pool Candidates: question_id | pool_id | candidate_id | true_text | false_text | source_refs
각 후보는 동일 조건의 참·거짓 쌍을 갖는다. 풀별 후보는 최대 16개, select_count는 후보 수보다 적은 2–8개다.
correct_when은 참을 고르면 true, 거짓을 고르면 false다. 서로 다른 비교·판단이 필요하면 별도 문항으로 만든다.

4. Source Conflicts
conflict_id | description | source_refs | unresolved

5. Final Statistics
총 문제 수, tier별 수, 출처 충돌 문항 수, EXT 문항 수를 적는다.
Cloze가 0문항이면 목표별 형식 적합성을 검토한 뒤 사용하지 않은 이유를 짧게 덧붙인다.

문항 ID는 모든 표에서 일치해야 한다. 해당 형식이 없는 상세 표는 생략한다.
