# Implementation Plan
1. codex/root-tier-transport의 커밋된 복구 후보(원래 authoring recovery 포함)를 현재 새 브랜치에 보존 통합한다. 관련 회귀를 실행한다.
2. 신규 병렬 실행/원본 그림 목록 모듈과 독립 map/points/bank 지침을 추가한다. 기존 source-assessment/2 통합·독립 검수·수정3회/증거 검증을 재사용한다. 직접 그림 추출 선택과 범위·원본/출력 해시를 검증한다.
3. 명시적인 병렬 요청을 러너/서버 입력·관리자 버튼에 연결하고 구형 요청은 보존한다. 러너 status의 등록 작업/하위작업 상태를 추가해 실제 프로세스와 완료 증거를 읽는다. 브라우저/관리화면/DB 변경은 필요한 최소 범위이며 UI 담당의 셸·캘린더는 수정하지 않는다.
4. parallel-regression: 독립 입력/동시실행/완료 캐시/실패 보존/그림 원본/지문/중복 차단. source-regression: 기존 계약·생성기·복구. runner-regression: 상태·실패·완료와 연결. pilot-evidence: 지정 PDF·실제 모델 영수증·병렬 시각·그림·최종 검수/격리 등록 실제 결과 확인. 실패/미실행을 성공과 구분한다.
5. 사용자 지정 올해 필기 한 강의를 실제 OpenAI Codex CLI로 전송해1회 시범한다. 기존 소스 폴더 읽기 전용, 별도 runs 산출물, 기존 운영 은행/학습 미변경. 콘텐츠 공급자 제한은 중단·보존하고 전송경로를 바꿔 우회하지 않는다. 원본·문항 내용은 사람이 임의 교정하지 않고 기존 CLI 상한을 따른다. 검사/리뷰/PR 후 운영 배포는 별도 기록한다.
사용자 현재 승인(2026-11-06): “응, 기존 복구 변경은 보존하면서 네가 이어서 맡아줘. 문제은행·개념도·출제포인트를 CLI에서 병렬로 돌리고 러너에 각각 진행도가 보이게 해줘. 감염과면역 강의 하나로 이미지 문제까지 포함해서 한번 진행해봐.” 지정 파일과 추후 실험 구분을 적용한다.
