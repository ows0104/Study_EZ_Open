# 구현과 사용

관리자는 강의 패널의 「Concept map·포인트 자동출제」 또는 뿌리 학습 화면에서 지도/포인트를 붙여 넣거나 MD·TXT·JSON 파일로 불러온다. 출제 범위·시험일·개인 시범 여부를 정하고 「자동출제·검수 후 게시」를 누른다. 강의에 올해 원본이 등록되어 있어야 한다.

흐름: 입력과 등록 원본 사본 고정 → 기존 bank 큐 → 러너의 명시적 분기 → learning-brief/1 정규화 → BANK 생성 → 원본/방향 대조와 독립 의학 검수 → 필요시 최대 3회 수정/재검수 → 방향 전체를 시험하는 과제 어댑터 → 서버 재검증 → 불변 RootContent와 활성 설정을 한 번에 게시.

제공 포인트는 독립 추출로 인증하지 않는다. 포인트·목표·미준비 방향을 보존하며 여러 부분 문항을 합쳐 방향 완료로 만들지 않는다. 지도는 계층·목표별 회상 방향과 포인트별 confirmed/partial/missing/unknown 집계를 표시한다. 학생의 지도 열람은 기존 도움 노출 정책을 따른다.

원본 대조·정답 검수를 모두 마친 뒤 남은 wrong/doubt/범위 지적은 실제 판정 그대로 보존해 관리자 결과와 학생의 답 공개 후 주석에 표시한다. 구조가 깨지거나 검수가 누락되면 게시하지 않는다. 답 공개 후 출제 당시 원본 사본 링크를 제공한다. 원본·활성 판·공개 범위 변경, 취소·중지 상태는 게시를 차단한다.

기존 QuizBank·개인 수정·제외·학습 기록은 변경하지 않는다. 새 판은 동일성 승계를 자동 부여하지 않는다. 기본 개인 시범이며 관리자가 학생 공개를 명시적으로 선택할 수 있다. 전체 뿌리 기능 설정이 꺼져 있으면 저장 완료와 실제 접근 불가를 구분한다. 새 요청/게시 완료 사건은 이용현황 카탈로그에서 별도로 센다.

## 실행·재개

일반 러너가 실행 중이면 기존 bank 작업을 집어 처리한다. 서버는 생성기/모델을 import하지 않는다. 실제 생성은 `python -m quizbank.connection_generate --packet ... --out ...` 하위 프로세스다.
같은 원문·원본·강의 제목은 기존 작업 ID로 합쳐지고, 「같은 입력·남은 횟수로 재개」도 같은 폴더를 사용한다. `runs/_root-generation/<generation-id>/`에 인증정보 없는 입력, 원본 사본, material, 각 단계 JSON/사용량, ledger, 최종 결과와 게시 응답을 보존한다.
ledger는 모델 호출 전에 started와 수정 소비를 기록한다. 완료된 같은 입력/모델/코드의 결과만 지문 확인 후 재사용한다. failed/started, 누락된 기록, 변경된 산출물·코드는 보류한다. 재개 버튼은 불명확 모델 호출을 다시 허용하거나 상한을 초기화하지 않는다. 출력 폴더 삭제로 복구하지 않는다.

## 검증과 현재 한계

`server/.venv/Scripts/python.exe scripts/check_connection_generation.py --check <contract|generation|runner|server|ui|web-types|web-build|root-regression>`
UI 검사는 격리 DB/저장소와 합성 PDF, 실제 HTTP 러너·생성기 하위 프로세스를 사용하되 모델 어댑터만 합성 응답으로 바꾼다. 실제 의학 출제 품질이나 실제 모델의 입력 해석 성공을 인증하지 않는다. 이번 작업에서 실강의 모델 전송·운영 DB 변경·운영 배포는 실행하지 않았다.
