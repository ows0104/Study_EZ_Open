# 모아풀기 시작 화면 선택지 — 설계

#219(`docs/changes/2026-11-18-main-quiz-batch`) 위에 쌓는다. 바뀌는 곳만 적는다.

## 요구사항과 수용 기준
- R1 문항 분류: 강의마다 준비된(available) 과제를 강의 목록 칸과 같은 단위로 셋으로 나눈다.
  - 미열람: 시도·평가 기록 없음(`question_progress`의 unseen).
  - 복습 대상: 평가했고 `effectiveDue ≤ 오늘`이며 오늘 평가하지 않았다. 또는 시도는 했지만 평가가 없고 오늘 건드리지 않았다.
  - 나중: 나머지 본 문항(복습일이 아직이거나 오늘 이미 푼 것).
  단위는 root-generation/4 판이면 과제 하나, 그 전 판이면 방향마다 계획이 내는 과제 하나다.
- R2 고르기: 강의의 과제 = 그 강의에 고른 중요도 ∩ (복습 대상 ∪ (기존 학습률 무시면 나중) ∪ (미열람 문항 보기면 미열람)).
  두 체크는 따로 계산한다. 기본값은 둘 다 끔.
- R3 중요도: 시작 화면에 전체 칩(Essential·Core·Important·Optional, 각 칩에 고른 강의들의 현재 조건 문항 수 합).
  기본은 넷 다 켬. 전체 칩을 누르면 모든 강의에 그 값이 적용된다(강의별로 바꾼 값을 덮어씀).
  「강의별 ▾」를 펴면 강의 줄마다 같은 칩이 보이고 그 강의만 바뀐다. 강의마다 다르면 전체 칩은 「일부」 모양이다.
  전체 칩은 마지막 하나를 끌 수 없다. 강의별 칩은 모두 끌 수 있고 그러면 그 강의는 0문항이다.
  이 선택은 강의 하나 화면의 중요도(과목별 저장값)를 바꾸지 않는다.
- R4 순서: 「순서대로」 = 강의 번호 순(강의 목록 순서)으로 한 강의를 끝낸 뒤 다음 강의. 강의 안은 판 문서의 과제 순서.
  「섞어서」 = 강의 사이도 무작위로 번갈아 내고, 강의 안 순서도 무작위. 강의 안 무작위는 선행 문항이 뒤 문항보다 앞에 오게 둔다.
  강의 사이 무작위는 회차 ID·위치로 정해 새로고침해도 같은 순서다.
- R5 수: 강의 줄마다 그 강의의 문항 수, 시작 단추에 합계. 선택을 바꾸면 서버를 다시 부르지 않고 바로 바뀐다. 0문항 강의는 흐리게, 흐름에서 빠진다.
- R6 시작·재개: 시작하면 강의마다 모아풀기 회차를 연다. 같은 학습일·같은 조건(중요도·두 체크·순서)의 안 끝난 모아풀기 회차가 있으면 그것을 잇는다.
  그 경우 강의 줄 수는 남은 수, 단추는 「모아풀기 재개」.
- R7 분리: 모아풀기 회차는 강의 하나 화면의 「오늘 학습」 흐름이 아니다(이어 풀기·칩 재계획·더 풀기에 잡히지 않는다).
  모아풀기에서 한 평가는 같은 이벤트라 강의 화면의 오늘 추천·복습일·학습률에 그대로 반영된다.
- R8 화면: 기존 #219의 풀이·되돌리기·마침 화면 그대로. 주관식/객관식 선택 유지. 설명 문장을 새로 넣지 않는다(라벨·숫자만).

## 책임·입출력 계약·오류 상태
- 새 `GET /api/root-learning/lectures/{subject}/{run_id}/mix` (읽기 전용):
  `{revision, title, counts: {<tier>: {unseen, due, later}}, open: [{sessionId, options, left}]}`.
  `open`은 오늘 학습일의 안 끝난 모아풀기 회차. 공개 범위·정책 없음은 기존 overview와 같은 404/409.
- 새 `POST /api/root-learning/lectures/{subject}/{run_id}/mix-sessions`
  `{requestId, tiers: [1–4개], unseen: bool, ignoreSchedule: bool, order: 'ordered'|'random'}` → `{sessionId, version, count}`.
  같은 requestId 재요청은 같은 결과(기존 start와 같은 멱등 규칙). 고른 과제가 없으면 409. 0칩 강의는 웹이 요청하지 않는다.
  회차는 기존 `root_session` 행이며 `state.mix = {tiers, unseen, ignoreSchedule, order}`로 표시한다.
  무작위 순서의 seed는 requestId(새로 시작할 때마다 새 순서, 같은 회차를 이을 때는 저장된 순서).
- 풀이·미리 받기·되돌리기·지도는 기존 `sessions/{id}` 경로 그대로.
- `today_stream`은 `state.mix`가 있는 회차를 건너뛴다.

## 호환성과 데이터 보존
- DB 스키마·migration·프롬프트·생성기 변경 없음. 새 행은 기존 `root_session`·`root_event`(kind='start') 형식이다.
- 학습 이벤트 형식·복습일·학습률 계산·강의 목록 집계는 그대로다.
- 옛 서버(롤백)는 `state.mix` 회차를 오늘 흐름으로 볼 수 있다(그 회차를 이어 풀게 될 뿐, 기록은 그대로).
- 강의 하나 화면의 중요도 저장값(kind='focus')은 쓰지 않는다.
- #219의 「오늘 추천 목록을 섞는」 동작은 이 선택지로 바뀐다(기본값 = 복습 대상만, 전체 중요도).
