# Bridge 파일 수신 점검 결과

2026-10-31 KST. 제품 코드·패키지·은행·운영 환경 변경 없이 조사했다.

## 결론

파일 수신·검증·원문 보존은 구현되어 있고 과거 정상 수신 근거도 있다. 현재 로컬 검사도 통과한다.
그러나 최신 자동 다운로드 회수가 지금 설치된 확장과 운영 사이트에서 성공하는지는 미확인이다.
현행 소스와 로컬 다운로드 ZIP의 버전 차이가 있으므로 “파일 수신이 항상 자동으로 잘 된다”고 결론 내릴 수 없다.

## 확인한 경로

1. 프롬프트 1.78은 모든 강의의 확정본을 실제 UTF-8 MD 파일로 받도록 한다.
   bridge/bank-file.js의 required도 모든 강의에 1.78부터 파일 필수를 적용한다.
   bridge/CLAUDE.md와 artifact-contract.md의 중추신경계 1.76 설명은 도입 시점이며 전체 최신 범위를 망라하지 않는다.
2. 자동 수집은 답변에 노출된 직접 다운로드 주소를 읽거나, 실제 파일 카드의 다운로드 동작으로 나온 바이트를 회수한다.
   sandbox 링크를 읽을 수 없으면 직접 파일 선택 경로를 제공한다.
3. 파일의 강의·과목·프롬프트 판·문항 수·ID·정답 참조·완료 표식을 검사하고 실제 UTF-8 바이트의 SHA256을 계산한다.
   서버와 러너도 검증하며 raw.md와 response-file.json으로 보존한다.
4. 파일 생성이 완전한지와 전송이 손실 없는지는 별개다. 파일 헤더와 본문이 함께 일부 범위를 빠뜨렸다면
   구조 검사가 그것만으로 강의 전체의 의학적 누락을 발견할 수는 없다. 원본 기반 포인트 대조는 계속 필요하다.

## 기존 수신 이력

실제 강의 경로 `runs/[강의 ID]/bank/[시도]/response-file.json` 10건을 찾아 연결된 raw.md와 대조했다.
테스트에서 새로 생성된 임시 기록은 제외했다. 아래 6개 강의이며 중복 시도도 있으므로 10건을 10회 독립 전송 성공으로 해석하지 않는다.

| 강의 ID | 파일 문항 수 | 저장된 원문 크기 |
|---|---:|---:|
| 261006_03 | 68 | 48,087 bytes |
| 261012_02 | 115 | 78,441 bytes |
| 261012_03 | 110 | 76,799 bytes |
| 261019_01 | 189 | 136,326 bytes |
| 261019_02 | 122 | 91,139 bytes |
| 261019_03 | 100 | 65,216 bytes |

10건 모두 바이트 수·SHA256·문항 수가 기록과 일치하며 현재의 순수 파일 계약 검사도 통과했다.
이는 파일 방식으로 원문이 보존된 근거다. 이 메타데이터만으로 자동 회수와 수동 파일 선택을 구분하거나,
이번의 최신 다운로드 버튼 회수 기능이 운영에서 사용되었다고 판정할 수 없다.
행별 결과는 [receipts.json](receipts.json)에 있다.

## 버전 차이

| 대상 | 확인 결과 |
|---|---|
| 로컬 bridge 소스 | manifest·protocol 1.3.20. bank-download.js와 실제 다운로드 요청 경로 있음 |
| 로컬 `web/public/studyez-extension.zip` | 1.3.19. bank-file.js는 소스와 같지만 bank-download.js와 새 다운로드 요청 경로는 없음. 직접 파일 선택은 있음 |
| 로컬 스토어 제출 ZIP `1.3.6` | 파일 회수에 필요한 최신 구성 없음. 실제 스토어 게시/설치 버전의 증거는 아님 |
| 실제 설치된 확장·운영 사이트/서버 | 이번 조사에서 버전과 왕복 동작 미확인 |

따라서 로컬 다운로드 ZIP을 기준으로 설치했다면 최신 파일 카드 자동 회수 경로가 포함되지 않았을
가능성을 확인해야 한다. 설치본이 1.3.19라고 단정하거나 운영 배포가 실패했다고 추정하지 않는다.
이번에 패키지를 재생성하거나 확장을 갱신하지 않았다.

## 실제 실행 검사

| 검사 | 결과 |
|---|---|
| Node: bank_file·bank_download·link_recovery | 62개 통과, 생략 없음. 모의 브라우저/확장 환경 |
| pytest: tests/bridge + tests/runner/test_bank.py, autosend 제외 | 35개 통과, autosend 1개 제외. 해당 Node 파일 검사들은 위 명령으로 별도 실행 |
| Node: web/tests/bank-bridge.test.cjs | 5개 통과. 서버 저장 성공 이후 확인·실패 시 미확인 처리 |
| 격리 서버: bank_file_storage | 통과. 임시 SQLite/로컬 저장소에서 잘못된 파일 거절·중복 접수·원문 및 학습 기록 보존 |
| 격리 서버: bank_markdown_file | 미완료. 시작 후 결과를 반환하지 않아 중단. HTTP 왕복 통과 근거로 사용하지 않음 |
| 실제 Chrome: web/tests/bank-file.test.cjs | 실행 환경의 localhost 접근 거절 `ERR_NETWORK_ACCESS_DENIED`로 화면 진입 실패. 파일 UI 자체의 실패로 단정하지 않음 |

첫 Python 검사들은 기본 임시 폴더 생성/SQLite 접근 문제와 출력 인코딩 문제로 실패했다.
임시 폴더를 저장소 내 별도 진단 경로로 지정하고 UTF-8 출력으로 재실행해 위 결과를 얻었다.
서버 설정은 테스트 파일이 import 전에 지정하는 임시 DB를 사용했으며 server/.env를 읽지 않았다.
HTTP 검사와 임시 Vite 서버는 종료했다. 모델·운영 API·게시 작업은 실행하지 않았다.

실제 출력·종료 코드는 [test-results.json](test-results.json), 조사한 소스의 지문은
[source-fingerprints.json](source-fingerprints.json)에 기록했다. 소스 지문은 진단 후 스냅샷이며 출시 후보가 아니다.
변경 기록은 development.py로 생성했고 build check는 구현 승인 없음으로 false다.
제품 구현 승인을 만들어 검사 근거로 쓰거나 이 조사를 배포 승인으로 처리하지 않았다.

## 다음 판단

파일 방식은 유지할 근거가 있다. 웹 작업 세 종류로 확대하기 전에 다음을 검증할 계획을 세운다.

- 설치된 확장·다운로드 패키지·웹의 요구 버전을 맞춰 확인한다.
- 완성 파일 하나의 내용 지문·문항 수가 수집 전후 일치하는지 확인하고, 자동 회수/직접 선택을 구별한다.
- 화면의 파일 발견·파일 검증·서버 저장 확인을 구별한다. 확장 보관 확인을 서버 저장 완료로 보지 않는다.
- 전송 실패 후 같은 원문으로 재전달하고 성공한 결과를 보존하는지 확인한다.
- 실제 운영의 기존 파일 저장 버튼은 검수·게시 작업을 만들 수 있다. 다음 실험은 공개·은행 교체 없이 확인할
  격리 경로를 구체화한 뒤 진행한다. 이번 조사에서 새 운영 전달 실험을 실행하지 않았다.

발견한 버전 차이·실제 환경 미검증·세 종류 작업 계약은 구현 계획에 반영할 사항이다.
코드 수정과 운영 반영은 이번 조사에 포함하지 않는다.
