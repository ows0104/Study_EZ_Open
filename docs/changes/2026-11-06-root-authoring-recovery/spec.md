# 완료 작성 초안의 구조 실패를 기존 보완 예산으로 복구 — 설계

## 요구사항과 수용 기준
최초 normalize가 완료되고 generate가 실제 모델 완료 후 AUTHOR 형식은 맞지만 brief 구조 수용에서 실패한 실행에 한해 복구한다. 두 단계 외의 실행/다른 복구/결과가 없어야 한다. 모델·입력·원본·NativeJson 파일·사용량·실패 원문을 검증한다. source-only/제공 Map 입력을 구분하며 독립 추출로 재인증하지 않는다.

## 책임·입출력 계약·오류 상태
복구 명령 자체는 모델을 호출하지 않는다. 실패 ledger·작성 원문·이전/현재 실행지문·실제 구조 지적을 불변 증명으로 보존한다. 기존 generate는 failed로 남고 다음 repair-1이 실제 보완 호출이다. 이전 최초 지도 교정 소비가 있으면 유지하고 다음1회를 추가 소비한다. 검수 round0은 작성 수용 실패로 실행되지 않았음을 명시하며, 복구 후 source-1/medical-1부터 필요한 전체 검수를 수행한다. 추가 지적의 repair-2 등은 남은 총3회 안에서만 진행한다.

## 호환성과 데이터 보존
구조 복구에서는 BANK·원본 그림 crop·임상 충돌 사실을 원문 그대로 보존한다. 모델은 brief 구조만 교정하며 정상 문항 원문을 재작성하지 않는다. 수정 brief는 전체 검사·원래 포인트/범위 보존·derived와 변경 이유를 충족해야 한다. 최종 manifest는 실패와 원문, 복구 증명, 실제 수정·검수 단계를 모두 연결하고 서버 공용 검증도 같은 기준을 적용한다. 기존 복구 없는 결과는 계속 수용한다.

CNS의 완료 repair-1도 원본 검수 지적대로 scope.reviewed/limitations의 잘못된 자료 설명만 고쳤다가 전체 scope 불변 검사에 실패했다. 실제 범위인 label/included/excluded와 원본/포인트/제외 판단은 고정하고 reviewed/limitations/outside_list_review는 이유 있는 파생 교정을 허용한다. 이 현재 계약을 이미 충족하는 완료 보완은 추가 모델 호출 없이 명시적 수용 재검증할 수 있다. 같은 지문/실패/실제 원문 증명은 유지하며 이미 소비된 보완 횟수를 그대로 적용한다. 임의 범위 확대나 실패를 자동 성공으로 덮는 복구는 제공하지 않는다.
