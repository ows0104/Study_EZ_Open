# 러너 창 흐름 순서 — 배포 준비

## 코드 리뷰·검증 결과
- `runner/desktop.py`: 한 표를 네 구역으로 나눔. `sections()`가 서버 `tasks` 행을 상태로 분류·정렬(대기열은 서버 `waiting` 순서,
  완료·실패는 실패 → 취소 → 완료, 같은 묶음은 날짜 최근 먼저). 상태 라벨 규칙은 `state_label()`로 옮기기만 함.
  버튼 활성 판정(`allowed`)은 기존 조건 그대로, 구역이 버튼 종류만 줄임. 실행 중 카드마다 중지·취소(같은 runId의 실행 행이 하나일 때만).
  완료·실패 행을 고르면 `status.tail()`로 로그 끝 40줄. 선택은 창 전체에서 하나.
- `runner/status_window.py`: 빈 훅 `build_before_jobs`·`card_controls`만 추가. 읽기 전용 상태 창 모양은 그대로.
- 접힌 구역은 패널째 숨김(Tk가 마지막 자식이 빠진 프레임 크기를 유지해 빈 칸이 남던 것을 확인 후 수정).
- 검사: `pytest tests/runner` 통과(바로가기 설치기 1개는 worktree에 .venv가 없어 생기는 기존 결함, 제외). 새 검사 5개.
- 실제 `runs/`·운영 조회(읽기)로 자동 시작을 끄고 창을 띄워 확인(2026-11-14 02:14): 시작할 수 있는 강의 97(시작 가능 0 · 자료 대기 96 · 보류·중지 1) 접힘/펼침,
  대기열 0, 실행 중 0, 완료 64 · 실패 3(실패 먼저), 실패 행 선택 시 로그 표시.
- 남은 점: DPI 인식을 켠 캡처에서는 표 행 높이 27이 글자보다 작다(기존 값, 이번 변경 아님). 실제 창은 기존과 같은 배율로 뜬다.
