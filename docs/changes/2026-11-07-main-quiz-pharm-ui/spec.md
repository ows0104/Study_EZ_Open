# Main-Quiz 약리 블럭 UI 복원 — 설계

## 요구사항과 수용 기준
1. 약리 블럭의 기존 풀이처럼 문제 카드, 상단 개념지도·쉬기, 하단 되돌리기·답 보기/평가를 배치한다. 학습 화면의 관리/검수/자료판 안내와 보조 기능은 접는다. 중요한 저장 실패는 계속 표시한다.
2. 직접 답을 쓰는 입력 UI를 제거한다. 이전에 보관된 초안과 서버 응답 원문은 지우지 않는다. 객관식 선지 선택과 문항 그림은 유지한다.
3. Space/Enter로 답을 열면 하단에 Again(1)·Hard(2)·Good(3)·Easy(4)를 표시한다. 클릭과 숫자 키가 같은 동작을 실행하며 저장 중 중복 요청을 막는다. 도움 노출만으로 Good/Easy 버튼을 비활성화하지 않는다. 사용자 평가와 독립 회상 여부는 별도로 보존하며 지도를 본 사실을 거짓으로 지우지 않는다.
4. 네 평가값을 구분하여 저장한다. 신규 평가의 네 단계 처리와 도움 정보의 처리를 명시적으로 구현하고, 기존 세 단계 사건·고정 회차·요청 재시도는 원래 의미로 유지한다. 과거 평가를 덮어쓰거나 재계산하여 저장하지 않는다.
5. 답을 확인한 뒤 해당 문제의 실제 참고 슬라이드/쪽을 화면에서 볼 수 있다. 원본 파일명과 PDF 쪽수를 표시하고 확대/원본 열기를 제공한다. 현재 원본으로 과거 출제 원본을 잘못 대체하지 않는다. 페이지 근거가 없는 문제는 임의 쪽을 선택하지 않고 자료 부재를 표시한다.
6. 개념지도를 열면 개념 노드와 관계선, 현재 학습 현황을 함께 표시한다. 노드를 선택하여 관련 내용을 확인하고 현재 문제로 돌아올 수 있다. 모바일에서도 읽을 수 있어야 한다.

## 책임·입출력 계약·오류 상태
RootLearning/RootSolve/RootToday/RootMap이 기존 Quiz Bank의 화면 구성과 스타일을 재사용한다. 새 자료의 학습 목록·기록은 기존 Root API를 유지한다.
슬라이드 문제의 직접 원인은 content.answer가 항상 slides:[]를 반환하는 것이다. generation의 원본 보존본(source_records)과 문항/대조 근거의 source_id·쪽을 대조하여 정답 응답에 표시용 근거를 연결한다. 실제 존재하는 이미지가 있으면 사용하고 PDF만 있으면 해당 쪽을 화면에 렌더링한다. 서명 URL로 자료를 읽으며 공개 저장소나 로컬 경로를 노출하지 않는다.
현재 3번 비활성화는 답 입력 여부가 아니라 RootSolve와 서버 act의 도움 노출/attempted 제한이다. 기존 사건 의미를 보존하는 호환 평가 필드를 도입하여 새 4단계 자기평가를 받는다. 저장 실패·충돌·그림 로딩 실패·학습일 경계는 계속 방어한다.

## 호환성과 데이터 보존
문제은행·문항 ID·문제 내용·검수 판정·원본 PDF·생성 횟수·개인 수정·제외·학습 사건을 변경/삭제/재출제하지 않는다. 기존 약리 은행은 기존 엔진과 네 단계 동작을 유지한다. 새 자료에만 호환 평가 입력과 표시를 적용한다. DB 스키마/권한/공개 대상 변경은 이 범위에 포함하지 않는다.
