# Map와 독립 출제포인트 추출 지침 정리

## 문제와 사용자 효과
지도는 고정 트리일 필요가 없다. 최종적으로 문항 구조·누락·학습 순서를 대조하는 데 쓰지만, Map 추출 지시문에는 그 최종 용도를 넣지 않고 원본의 개념·분류·관계·흐름 구성에 집중한다.

## 범위와 성공 기준
원본 전용 Map과 포인트 요청문 및 읽기 쉬운 출력 형식을 작성한다. 실행 코드·모델 호출·출제 재개·배포는 포함하지 않는다.

## 근거·미정 사항
사용자 2026-11-06: “Map은 그렇게 정리해줘. 필요하다면 이전 프롬프트의 형식을 참고해도 될듯. 더 좋은 형식이 있으면 그걸로 가고. 출제포인트는 이전 프롬프트를 우리의 철학에 맞게 해줘.”

후속 교정: “Map을 뽑을때의 프롬프트는 문제와는 무관하게 강의와 족보에서 개념 Map으로 만드는데 집중하는게 좋을듯.” 이는 동일 작성 범위의 명확화다.

표현 교정: “부정문이 상당히 많은데, 심각한게 아니면 차라리 방향성을 제시해주거나 빼는게 나을듯?” 원하는 구조·결과를 직접 안내하고 반복 금지문을 줄인다. 범위·근거·불확실성의 의미는 보존한다.

출력 구체화 승인: “어 이걸 정하자. 각각 어떤 형식이 좋을지 생각해서 구체적으로 프롬프트를 작성해줘.” 두 추출 결과의 JSON 구조·필드 설명·합성 예시·스키마를 작성하고 로컬에서 형식 검증한다. 자동 생성기 연결은 포함하지 않는다.

후속 간소화: 사용자가 과도한 수집 항목 축소에 “좋아”라고 동의하고, 예전 Exam Point Plan/Concept Map/Retrieval Plan 요청을 참고용으로 제공했다. 목표·핵심 내용·관계·근거의 간결한 표현을 참고한다. 기존 tier(Core/Advanced/Optional), EXT 범위 확장, Markdown 본문 전달, 포인트→Map→문항의 종속 순서는 가져오지 않는다. Map과 포인트는 원본에서 각각 추출하고 JSON 파일로 받는 방향을 유지한다.
