# Main-Quiz 풀이 지연 제거 — 설계

## 요구사항과 수용 기준
1. `GET /api/root-learning/sessions/{id}/prepare?start=&count=`(기본 현재 위치·4, 최대 8) — 읽기 전용.
   회차의 고정 과제 목록에서 `start`부터 `count`개 위치의 `{position, taskId, blocked, task}`를 돌려준다.
   `task`는 `{id, question, answer, helped}`이며 `question`·`answer`는 `/sessions/{id}`가 답 열람 뒤 주는 것과 같다.
   준비되지 않은 과제는 `task: null`과 `blocked` 사유. 학습일이 지난 회차는 `frames: []`.
   이벤트·세션 상태·버전을 바꾸지 않는다(검사: 행 수·세션 상태 불변).
2. 웹은 이 프레임으로 Space(열람)·1–4(평가)·보류·Z(직전 평가 취소)를 즉시 그린다. 이벤트는 `version`을 하나씩
   올려 순서대로 보낸다. 프레임이 아직 없으면 예전처럼 저장을 확인한 뒤 세션을 읽는다.
   지도 보기·회차 시작은 예전처럼 확인 후 그린다.
3. 저장 표시는 한 요청이 2.5 s 넘게 확인되지 않을 때만 「저장 확인 중…」으로 보인다.
4. 참고 PDF는 API 범위 요청만으로 읽는다(첫 512 KB로 크기를 알고 이후 필요한 범위만). 열린 문서는 20분 유지하고,
   앞으로 나올 답의 첫 참고 슬라이드를 미리 그려 둔다(최근 16장).
5. 서버 `read_source`는 (강의, 활성 판, 원본) 별로 원본 기록·파일 크기를 기억해, 범위 요청마다
   판 문서 JSON·생성 기록·R2 HEAD를 다시 읽지 않는다. 권한 확인(`allowed`)은 매번 한다.

## 책임·입출력 계약·오류 상태
- 서버가 여전히 유일한 기록 주체다. 화면의 미리 그린 상태는 표시용이며 다음 이벤트의 `version`이 맞지 않으면
  서버가 409로 거절한다.
- 저장 대기열(`useRootStudyWrites`): 요청마다 보내기 전에 localStorage에 보관, 확인 뒤 삭제.
  응답 유실(네트워크·5xx)은 대기열을 멈추고 「같은 요청 다시 저장」으로 같은 요청을 같은 순서로 다시 보낸다(서버는
  같은 requestId·같은 본문에 이전 결과를 돌려준다). 409는 거절된 요청과 그 뒤에 쌓인 요청을 보내지 않고
  충돌로 보존한다(`unsent: true`). 기존의 「보관 응답 확인 후 서버 기록 불러오기」로 서버 상태를 다시 읽는다.
- 회차 마지막 평가 뒤 완료 화면은 모든 저장이 확인될 때까지 「마지막 저장과 미확인 요청을 확인 중」을 보이고,
  확인 뒤 서버의 요약을 읽어 그린다.

## 호환성과 데이터 보존
- 새 경로 하나 추가(`test_route_contract.py` 갱신). 기존 경로·응답 형식 불변. DB 스키마 변경 없음.
- 이전 페이지가 남긴 보관 요청(`seq` 없음)도 그대로 읽어 순서대로(생성 순) 재시도한다.
- 미리 받은 답은 화면 메모리에만 있고 열람으로 기록되지 않는다(Quiz Bank `/prepare`와 같은 수준의 노출).
- 미리 그린 화면의 「도움 노출」 표시는 서버 계산의 근사다(지도·선지 열람 안내 문구에만 쓰임). 기록되는 값은 서버가 계산한다.
