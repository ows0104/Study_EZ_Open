# 족보 모아풀기 — 설계

## 요구사항과 수용 기준
- R1 고르기: 강의 목록에서 Main-Quiz가 열렸거나 족보가 있는 행에 체크가 있다. 족보 유무는 새 읽기 경로(R7)로 목록이 한 번 묻는다.
  행·제목·▶는 지금처럼 바로 그리고, 족보만 있는 행의 체크는 요약을 받은 뒤 나타난다.
- R2 막대: 고른 강의가 있으면 막대에 「복습퀴즈 모아풀기」(고른 것 중 Main-Quiz 강의만 `/study/mix`로)와
  「족보 모아풀기」(고른 것 중 족보 있는 시간표 칸만 `/study/jokbo-mix?e=…`로). 해당 강의가 없으면 그 단추는 꺼진다.
- R3 시작 화면: 머리 「족보 모아풀기 · N개 강의」. 범위 칩 「같은 교수만」·「다른 교수까지」(각 칩에 고른 강의들의 그 범위 문항 수 합).
  전체 칩을 누르면 모든 강의에 적용, 「강의별 ⌄」를 펴면 강의 줄마다 같은 두 칩. 강의마다 다르면 전체 칩은 「일부」.
  같은 교수 문항이 없는 강의는 「같은 교수만」을 고를 수 없어 「다른 교수까지」로 남는다(강의 하나 화면과 같다).
  기본값: 강의마다 강의 하나 화면의 기본(같은 교수 문항이 있으면 같은 교수만). 「다른 교수까지」는 다른 교수 연도 전부.
- R4 순서: 「모아풀기」 = 강의 안 순서(강의 하나 화면의 pickItems: 같은 교수 → 다른 교수 최신 연도, 변형 묶음은 이어서)를 지키고,
  강의의 k번째(n개 중) 묶음을 전체의 (k+½)/n 자리에 둔다 — 강의마다 문항 수가 달라도 처음부터 끝까지 고르게 섞인다. 같으면 강의 순서.
  「섞어풀기」 = 강의 사이·안 모두 무작위. 변형 묶음은 쪼개지 않는다. 기본은 모아풀기.
- R5 풀이·끝: 강의 하나 족보의 풀이 화면(답 고르기·바로 채점·해설·모르겠음/주의/괜찮음·Z·끝 화면·다시 풀기·이 문제만 다시 풀기) 그대로.
  머리줄에 지금 문항의 강의 제목, 진행은 전체(`족보 k / N`). 채점·표시 기록은 그 문항의 시간표 칸으로 간다.
- R6 회독: 시작 화면에서 고른 범위 전부를 끝 화면까지 풀면 그 범위에 든 강의마다 1회독(기존 `POST /jokbo/events/{id}/rounds`).
  일부만 다시 푼 판은 세지 않는다.
- R7 화면 문구는 라벨·숫자만. 설명 문장을 넣지 않는다.

## 책임·입출력 계약·오류 상태
- 새 `POST /api/jokbo/summaries` `{eventIds: [1–200개]}` → `{summaries: [JokboSummary…]}`(읽기 전용).
  족보가 없거나 이 사람에게 안 보이는(관리자만) 칸은 빠진다. 문서 읽기는 기존 60초 캐시를 쓰고 칸들을 나란히 읽는다.
- 시작 화면은 칸마다 기존 `GET /api/jokbo/events/{id}`·`GET /api/jokbo/marks?eventId=`를 읽는다. 404 칸은 「족보 없음」으로 빠진다.
- 채점·표시·회독은 기존 경로 그대로(`…/items/{item}/answer`·`…/mark`·`…/rounds`). 문항 ID는 칸 안에서만 유일하므로 화면은 (칸, ID)로 구분한다.
- 시작 화면 선택은 저장하지 않는다(새로 열면 기본값).

## 호환성과 데이터 보존
- DB·스키마·족보 문서·R2 변경 없음. 기록 형식(jokbo_mark·jokbo_round)은 강의 하나 화면과 같다.
- 강의 하나 족보 화면은 동작이 같다. 풀이 화면 컴포넌트를 여러 강의에 쓰도록 props만 일반화한다.
- 「복습퀴즈 모아풀기」는 지금 「모아풀기」와 같은 동작이다(이름만 바뀜).
