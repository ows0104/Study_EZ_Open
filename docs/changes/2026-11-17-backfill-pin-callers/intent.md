## 원인 (재현으로 확정)

실패한 두 판의 generation 폴더를 복사해(`C:\sez\rp\a`·`b`) 저장된 단계 출력으로 조립까지 다시 돌렸다.
모델 호출과 운영 쓰기는 없다.

**261106_06 — 공개 문항이 새 목표로 옮겨졌다.**

```
안 이어짐: Q110  자리 D011 → DQ020 · 문항 달라진 칸 [] · 지문 같음
승계 161 / 162
```

어제 job 646(261102_02)과 같은 일이다. 그 고침인 PR #206은 자리를 고정하는 함수
(`generation_v4.keep_published`)와 결과 검증 쪽(`_settled_places`)만 넣었다. 커밋 메시지는
「보강이 settledPlaces로 그 지도를 넘기고」라고 적었지만 **넘기는 호출이 커밋에 없다.**
`connection_presuppose.run`은 `settled_places` 없이 `v4.assemble`을 부르고, 기록에 `settledPlaces`도
남기지 않는다. `origin/master`와 모든 worktree를 찾아도 이 이름을 쓰는 호출부가 없다.
그래서 고정은 운영에서 한 번도 작동하지 않았다.

**261105_03 — 공개 문항 둘이 새 목표에서 중복으로 묶였다.**

```
빠짐: Q075 (자리 U060_1)
중복 묶음: Q075 → Q025 남김 · 목표 DQ017
  Q075 | Shigella의 Shiga toxin은 어떤 작용으로 혈성 설사를 유발하는가?
  Q025 | Shiga toxin은 어떤 세포 기능을 억제하여 세포 사멸과 혈변을 유발하는가?
```

새 존재 목표 DQ017의 범위 판정이 공개 문항 Q025와 Q075를 같은 문항으로 적었고,
조립(`merged_duplicates`)이 Q075의 과제를 뺐다. 공개판에서는 둘 다 과제였다.
보강의 계약은 「공개된 문항·과제는 그대로」이므로 검사가 거절했다.

## 고침

1. `connection_presuppose.run`이 공개판 과제의 자리(문항 → 목표)를 `settled_places`로 조립에 넘기고,
   같은 값을 기록 `presupposeOnly.settledPlaces`에 남긴다. 서버의 결과 검증은 이미 이 칸을 읽는다(#206).
2. `merged_duplicates(..., held=)`: 공개판에서 과제였던 문항은 중복으로 빼지 않는다.
   - 공개 문항끼리 묶이면 둘 다 남는다(공개판과 같은 상태).
   - 공개 문항과 새 문항이 묶이면 새 문항이 빠진다. 전에는 중요도가 높은 쪽이 남아
     공개 문항이 빠질 수 있었고, 그때는 강의 전체가 거절됐다.
   - 공개판이 이미 중복으로 뺀 문항은 `held`가 아니다. 빠진 채로 둔다.

`held`는 `settled_places`가 있을 때만 채워진다. 첫 출제, 중복 재판정, 재배치, 그리고 이미 올라간
보강판(기록에 `settledPlaces`가 없다)의 검증은 결과가 달라지지 않는다.

두 검사(「과제가 빠졌습니다」·「같은 문항으로 이을 수 없는 것」)는 그대로 둔다. 풀지 않았다.

## 바꾸지 않는 것

- 프롬프트·DB·서버 API. 서버는 계약(`studyez_contracts`)만 같이 배포된다.
- 새 문항의 배치와 문항 내용.
- Q025·Q075가 실제로 비슷한 문항이라는 사실. 공개판에 이미 둘 다 있었고, 이번 보강이 정리할 일이 아니다.
  줄이려면 공개판 중복 재판정(duplicates-only/1)이 따로 있다.
