# 선지: 사진 문항 그림 전달·작성·검토 기준 완화 — 설계

## 요구사항과 수용 기준
- 그림:
  - 묶음에 `stimuli`가 있는 문항이 있으면, 작성·검토 작업 폴더에 `images/<question_id>-<n>-<sha12>.png`를 쓴다.
  - input.json의 그 문항에 `images`(상대 경로 목록)를 넣고, 같은 파일을 모델 호출에 첨부한다(`studyez_llm.codex.run(images=)`).
  - 그림 없는 묶음의 호출은 지금과 같다.
- 작성 기준(`write.md`):
  - 판단 기준은 이 강의다. 강의를 공부한 학생이 강의 내용으로 틀렸다고 가릴 수 있으면 좋은 오답이다.
  - 질문에 없는 조건을 상상해 「정답이 될 수도 있다」며 버리지 않는다.
  - 다음은 그대로 쓰지 않는다: 정답의 다른 이름·상하위·부분, 질문의 조건 그대로에서 정답인 것, 목록에 실제로 속하는 항목(강의가 적지 않았을 뿐인 경우 포함).
  - 「다른 답도 있을 수 있다」만으로 건너뛰지 않는다. 강의가 든 것과 분명히 다른 실제 개념을 찾는다.
  - 사진 문항은 그림을 보고 쓴다.
- 검토 기준(`review.md`):
  - 「조건·분류 기준·교과서에 따라 옳다」는 「질문과 이 강의의 맥락에서 옳다」로 좁힌다.
  - 「확신할 수 없다」는 「강의 내용과 현재 의학으로도 답인지 아닌지 가릴 수 없다」로 좁힌다.
  - 질문에 없는 조건(다른 나라·지역·드문 예외·특수 환자군)을 끌어와 빼지 않는다고 명시한다.
  - 검토 입력에 `lecture_facts`(같은 강의 다른 문항의 짧은 정답, `same_lecture_pool`)와 그림을 준다.
    쓴 쪽의 출처·근거·이유는 지금처럼 주지 않는다.
- 검토 기록의 정책 이름: `mcq-medical/2` → `mcq-medical/3`.

## 책임·입출력 계약·오류 상태
- 계약(`studyez_contracts/roots/mcq.py`)·서버·웹은 바꾸지 않는다. asset 모양(`root-mcq/2`)도 그대로다.
- 그림 파일 이름에 sha가 들어 있어, 그림이 바뀌면 입력 지문이 바뀌고 캐시를 다시 쓰지 않는다.
- 그림을 못 쓰는 경우(base64가 깨짐)에는 그 그림만 빼고 진행한다. 계약 검사(`validate_images`)를 지난 판이라 드물다.

## 호환성과 데이터 보존
- 다시 만들면 그 판의 `mcq/<revision>.json`과 업로드 asset이 바뀐다.
  - 학습 기록은 선지에 묶여 있지 않다. 같은 날 본 선지 조합만 바뀐다.
  - 옛 결과는 러너 폴더에 `v2-<revision>.json`으로 남겨 되돌릴 수 있게 한다(수동 복사).
- 프롬프트가 바뀌어 기존 묶음 캐시(`output.json`의 입력 지문)는 맞지 않는다. 다시 만들면 모델을 다시 부른다.
