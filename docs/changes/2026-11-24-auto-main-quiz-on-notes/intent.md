# 필기 업로드 시 Main-Quiz 자동 요청 · 러너 자동 시작 15초

## 문제와 사용자 효과
- 사용자 2026-11-24: 「복습필기가 올라오면 러너가 자동으로 Main-Quiz를 진행했으면 좋겠어. 그리고 시작 1분 좀 길어서 15초로 해도 될듯.」
- 지금은 올해 필기가 올라와도 Main-Quiz는 관리자가 강의마다 「Main Quiz 만들기」를 눌러야 시작한다.
  - 서버의 업로드 완료 자리(`complete_uploads` → `_auto_main_job`)는 2026-10-16부터 아무것도 하지 않는다.
- 러너 창은 연 뒤 60초 동안 선택이 없으면 준비된 작업을 등록한다. 이 대기가 길다.

## 범위와 성공 기준
- 올해 필기(`notes_current`)가 **처음** 등록된 강의에 Main-Quiz 요청(새 구조 2, map-tree/3, CLI 원본)이 자동으로 선다.
  러너가 그 일감을 집어 지금의 버튼 요청과 같은 길로 출제·게시한다.
- 러너 창의 자동 시작 대기는 15초다.

### 사용자 결정(2026-11-24, 이 세션의 질문에 대한 답)
- 공개 범위: 「학생에게 바로 공개」. 검증을 통과하면 버튼 기본값과 같이 학생에게 공개된다.
- 제외 강의: 「필기가 올라오면 일단 만들기 시작하자.」
  - TBL·블럭 첫 수업을 따로 빼지 않는다.
  - 질문은 「실습·CBL·PBL은 기존 규칙으로 이미 빠진다」를 전제로 했다. 이 기존 규칙(`auto_review_excluded`)은 그대로 둔다(내 해석).
- 대상 시점: 「새로 올라온 필기만」. 이미 필기가 있는 강의는 지금처럼 버튼으로 만든다.

## 근거·미정 사항
- `docs/development/README.md` 「사람에게 묻는 것」: Main-Quiz map-tree 요청은 강의마다 누르는 버튼이 자료 전송·공개의 승인이었다(2026-11-09).
  이번 결정으로 **첫 필기 업로드의 자동 요청**이 그 승인을 대신한다. 공개된 판의 교체는 여전히 따로 묻는다.
- 자동 요청은 기존 자동 일감 하루 상한(`JOB_AUTO_DAILY_CAP` 12, 예습과 함께 셈)을 따른다. 넘으면 보류로 선다.
- 족보는 필기와 같은 업로드에 실려 온 것만 원본(S2)에 든다. 족보가 나중에 붙는 강의는 필기만으로 출제된다.
- 범위 밖: 이미 필기가 있는 강의의 일괄 채우기, TBL 판별, 공개된 판 교체, 필기 교체 시 재출제.
