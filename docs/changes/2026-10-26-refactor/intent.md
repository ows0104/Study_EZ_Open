# StudyEZ 리팩토링 의도

작성: 2026-10-26 (Asia/Seoul) · 상태: 제안 초안 / 구현 승인 전

## 해결할 문제

사이트를 유지보수할 때 AI가 읽는 코드·문서·과거 기록의 범위와 재탐색 시간을 줄인다. 동시에 다음 출제 방식으로 교체하기 쉬운 경계를 만든다. 이번 구조 정리와 이후 출제 정책 변경을 별도 작업으로 진행한다.

사용자가 원하는 방향:
- 사이트, 문제출제, 둘의 연결부를 나누고 관련 영역만 읽어 작업한다.
- StudyEZ 본 서비스와 독립적인 기능은 별도로 관리한다.
- 불필요한 작업 사본·과거 자료는 확인 후 복구 가능하게 보관한다.
- 26필기와 족보에서 Concept Tree, 족보 경향, 출제 포인트를 각각 추출하고, 문항 생성과 누락 확인을 거친다.
- Concept Tree의 뿌리부터 탐색하는 경험으로 문제를 제시한다.
- Plan → Design → Build → Test → Deploy → Maintain을 반복한다. 구현 계획과 중요한 운영 변경은 사람이 승인한다.

## 제안하는 이번 범위

1. 현재 코드·운영 경로·보존 자료를 식별한다.
2. 작업별 읽기 지도, 짧은 공통 안내, 과업별 intent/spec/plan을 정립한다.
3. 공유 검증 계약과 출제 프롬프트의 소유권을 명확히 한다.
4. 현재 동작을 유지하면서 사이트·출제·연결부를 단계적으로 모듈화한다.
5. Spotter는 별도 앱으로 관리하고, 예습·기존 학습 기록은 현재 이용 경로를 유지한다.
6. 새로운 출제·학습 엔진은 별도 명세와 시범 강의로 검증한 후 전환한다.

## 성공 기준

- 화면 수정은 출제 코드·강의 원문을 읽거나 모델 출제를 실행하지 않고 완료할 수 있다.
- 출제 단계 수정은 사이트 구현 전체를 읽지 않고 계약·해당 단계·검사만으로 검증할 수 있다.
- 계약 변경은 생산자·소비자·호환성 검사 위치가 한 지도에서 드러난다.
- 보관 항목에는 출처·보관 이유·해시·복원 방법·남아 있는 참조가 기록된다.
- 기존 URL, 접근 권한, 문제은행, 개인 수정, 제외 문항, 학습 기록을 보존한다.
- 실제 유지보수 과제에서 읽은 파일 수·입력 토큰·소요 시간·재작업을 측정해 전후 비교한다. 절감률은 측정 전 약속하지 않는다.

## 현재 결정과 미정 사항

권고: 하나의 저장소 안에서 경계를 먼저 정리하고 현재 웹/API/로컬 러너 배포 구성을 유지한다. 별도 저장소나 서비스 증설은 실제 독립 배포 필요가 확인된 뒤 판단한다.

미정: 새 출제 방식의 정확한 내용 정책, 족보 경향의 집계 기준, Concept Tree의 깊이, 학습 경로의 해금·재방문·숙련도 정책, 최초 시범 강의. 사용자가 상세 방향을 제시할 때 별도 명세로 확정한다.

이 문서는 현재 문제의 내용을 수정하거나 재출제하는 승인이 아니다. 이번 대화의 요청에 따라 분석·설계·구현 계획을 작성했으며, 구현·실제 보관 이동·운영 배포는 실행하지 않았다.

## 2026-10-26 승인 및 범위 명확화

사용자는 “좋아. 지금 행동은 진행해줘”라고 P0~P2를 승인했고, Process Flow loop는 이번
리팩토링만이 아니라 “이 사이트에 대해” 지속 적용할 것임을 명확히 했다.
따라서 공통 개발 안내·새 작업 생성·승인/검증/리뷰 gate·공개 웹/API 관측과 기존 매시간
피드백 자동화 연결을 구현한다. 운영 배포·DB 변경·강의 재출제·과거 데이터 이동은 하지 않는다.
계획의 P3 이후 기능/자료 이전은 계속 별도 실행 범위다.
