# Main-Quiz 생성→선지 시간 단축 1차(선지 묶음) — 설계

## 요구사항과 수용 기준
R1. 선지 작성 묶음은 12문항이다(`quizbank/root_mcq.py` `BATCH`). 재생에서 15문항의 답이 6.6천·7.1천 토큰, 166·178초였고
    묶음마다 1.75배쯤 흔들려(40문항 때 1.3만~2.2만 토큰) 300초에 여유를 두려고 12로 잡는다(보통 2~2.5분).
R2. 함께 도는 묶음은 8이다(`WORKERS`). 실제 동시 수는 기계 전체 Codex 자리(`studyez_llm.execution` 8)가 정한다.
    다른 강의가 같이 돌면 자리를 나눠 쓴다.
R3. 작성 출력 스키마의 `jokbo`는 객체 또는 null이다. 지시문은 「source가 jokbo가 아니면 null」 한 줄만 바뀐다.
    source가 jokbo인 오답의 연도·번호 검사(`row_errors`)와 asset에 싣는 모양(`entry_v2`)은 그대로다.
R4. 러너는 게시·근거 뒤 선지와 순서 맞추기 판정을 나란히 부른다. 둘 다 실패해도 게시는 그대로다(지금과 같다).
R5. 회차(2)·시도(2)·의학 검토·표기 검사·오답 수 기준은 바꾸지 않는다.

수용 기준
- `tests/quizbank/test_root_mcq.py`, `tests/runner`의 선지·게시 검사가 통과한다.
- 실제 묶음 재생(저장된 판의 문항 30개, 15문항 두 묶음, 올리지 않음): 두 묶음이 각각 300초 안에 끝나고, `jokbo: null` 출력이 스키마를 통과한다.

## 책임·입출력 계약·오류 상태
- 입력(`input.json`)·출력(`proposals`) 칸 이름, `root-mcq/2` asset, 서버 붙이기는 그대로다.
- 묶음마다 `jokbo`·`block_pool`(45KB쯤)이 다시 들어가 강의 하나의 입력이 0.3MB쯤 는다(출제 전체 입력의 2% 아래).
- 묶음 호출 실패·검토 실패의 처리(그 묶음만 빠지고 둘째 회차로)는 그대로다.
- 이미 만든 선지는 다시 만들지 않는다. 묶음 구성과 지시문이 달라 저장된 `output.json`은 재사용되지 않는다(다시 돌릴 때만 해당).

## 호환성과 데이터 보존
- 게시된 판·문항 ID·학습 기록·올라간 선지 asset을 건드리지 않는다. 새로 출제하는 편부터 적용된다.
- 러너 `.runtime` 재설치가 있어야 실제 출제에 들어간다(병합 뒤, 사용자 확인).
