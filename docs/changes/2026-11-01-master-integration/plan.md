# Implementation Plan

1. 최신 origin/master와 현재 브랜치 및 기존 실패를 확인한다.
2. --no-commit 병합 후 충돌 파일을 대조해 양쪽 의도를 통합한다. 원문/개인 자료는 보존한다.
3. 웹 테스트 mock과 현재 표시·권한 기대를 교정하고 동시 기록의 Windows 접근 문제를 재현·수정한다. 인코딩 및 검사 환경 문제를 해결한다.
4. 최종 통합 소스에서 root/server/web/integration 검사를 실행하고 회귀를 고친다. 검사와 리뷰를 기록하고 병합·수정 커밋을 만든다.
5. origin/master가 통합본의 조상인지 확인하고 일반 push한다. 원격이 추가로 바뀌었으면 새 변경을 보존해 통합 후 검증한다. force push와 별도 클라우드 배포는 하지 않는다.

현재 사용자 요청은 실패 수정·통합·master 일반 push를 명시적으로 포함한다. 동일 범위 승인을 반복 요청하지 않는다.
