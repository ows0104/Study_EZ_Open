## 코드 리뷰·검증 결과
구현(설계와 다른 점):
- 링크 계산 `carry_links`는 계약(`studyez_contracts/roots/generation_v4.py`)에 둔다. 결과 검사(`_judgments4`)가 문서를 다시
  조립해 대조하므로, 재배치 결과(`manifest.unplacedOnly`)이고 packet에 `carrySources`가 있으면 같은 함수로 링크를 다시 계산해 대조한다.
- 생성기는 `carrySources`가 없으면 모델 호출 전에 멈추고, 이전 판 과제 중 새 판에 남은 것이 하나라도 이어지지 않으면 게시 전에 멈춘다.
- 「내 중요도」 이벤트에는 문항 지문이 없다. 그래서 서버가 가벼운 문서를 만들 때 링크된 이전 판의 사본 칸(`light`)으로
  (이전 판, 문항 ID) → 새 문항 ID 표(`carried_questions`)를 만들고, `personal_tiers`·`excluded_ids`·`tiers_for`가 이 표로만 잇는다.
  표에 없는 (내용이 바뀐) 문항의 선택은 잇지 않는다. 같은 문항에서 새 판의 선택이 더 늦으면 그것이 이긴다.
