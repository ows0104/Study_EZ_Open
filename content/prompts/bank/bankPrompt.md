## 2. 최상위 출제 철학: 중요한 연결을 스스로 복원하게 한다

지식을 개념과 개념의 연결로 다룬다. 세부 사실과 함께 그 사실에 접근하고 활용하는 데 필요한 기초 연결도 시험한다. 개념→분류·역할, 구조→기능, 원인→결과, 현상→설명, 상황→사용할 개념·방법, 주장→근거, 조건→성립·예외를 구분하며 모든 지식을 직선적인 단계로 만들지 않는다.

A→B→C에서 A→B를 발문에 주고 B→C만 답하게 했다면 A→B의 회상을 시험한 것으로 세지 않는다. 발문·보기에 제공된 관계, 정답으로 회상·판별하는 관계, 해설에만 등장한 관계를 구분한다. 필요한 각 방향의 연결 전체를 실제 문항으로 회상하게 한다.

기초 연결의 필요성은 후속 학습의 토대인지, 실제 판단·오류 예방에 필요한지, 다른 지식만으로 추론하기 어려운지, 기출의 혼동 지점인지로 판단한다. 가장 앞선 연결이나 추상적 분류가 항상 우선이라고 가정하지 않는다.

개념을 계산·설명할 수 있는 것과 어떤 상황에서 그 개념을 사용할지 떠올리는 것은 구분하여 시험한다. 관계가 성립하는 조건·예외뿐 아니라 연결을 결론 내려서는 안 되는 한계도 의미 있는 판단 목표다.

- 한 문항은 하나의 의미 있는 회상·판단 목표를 중심으로 만든다. 독립 요구를 한 서술형으로 합치지 않는다.
- 같은 축의 목록·비교나 함께 기억할 가치가 있는 기전·과정은 하나의 목표가 될 수 있다. 작은 사실마다 자동 분할하거나 모든 세부 문항 앞에 기초 문항을 붙이지 않는다.
- 기초와 세부 연결을 각각 회상할 가치가 있으면 구분하되, 한 문항이 필요한 연결을 실제로 함께 회상시키면 충족을 인정한다.
- 형식·문장·보기 조합만 바꾼 중복은 통합한다. 필요한 다른 방향·구별·적용은 보존한다.
- 누락은 기존 문항 수정으로 보완할 수 있는지 먼저 검토한다. 기존 핵심 목표를 보존하기 어려운 독립 목표만 새 문항으로 만든다.
- 필수 목표의 누락과 선택적인 확장 세부사항을 구분한다. 추가로 물을 수 있다는 이유만으로 필수 누락으로 판단하지 않는다.
- 문항 수·형식·tier의 고정 개수나 비율을 맞추지 않는다. 각 문항은 단독으로 이해·채점할 수 있어야 한다.

### 2.1 핵심 설계 예시

아래 예시는 설계 기준이다. 예시 주제를 실제 출제 범위에 추가하지 말고 첨부 자료의 용어·정답·범위를 따른다.

**기초 연결을 직접 회상시키기**
- “Metyrosine은 tyrosine hydroxylase를 억제한다. 저해 유형은?”은 약물→표적을 발문에 제공하므로 그 연결의 회상을 시험하지 않는다.
- “Metyrosine이 억제하는 효소는?” → tyrosine hydroxylase. 약물→표적을 직접 회상시킨다. 작용 방식까지 별도로 회상할 가치가 있을 때만 후속 문항을 둔다.

**함께 묶을 목표와 별도 목표 구분하기**
- “생태계의 생물을 영양적 역할에 따라 나누는 세 범주는?” → 생산자, 소비자, 분해자. 같은 분류 축이므로 하나의 list로 묶을 수 있다.
- “죽은 생물의 유기물을 분해하는 역할에 해당하는 범주는?” → 분해자. 분류 목록 회상과 역할→범주 대응은 다르다. 둘 다 필요할 때 구분하되, 같은 목록을 항목마다 자동 분할하지 않는다.

**질문 축은 남기고 정답 단서는 없애기**
가상 지역의 겨울 강수량이 가장 많다는 자료가 있을 때:
- 부적절: “이 지역은 여름과 겨울 중 {겨울}이 여름보다 강수량이 많다.” 남은 문장만으로 답을 알 수 있다.
- 적절: “이 지역에서 강수량이 가장 많은 계절은 {겨울}이다.” 질문 축은 계절이며, 답하려면 자료의 지식이 필요하다.

## 3. 구체적인 출제 기준

### 3.1 범위와 충돌

발문·선지·정답·채점 단위는 첨부 자료의 범위와 표현 수준에 근거한다. 자료에 없는 균명·세부 분류·임상 조건·권고를 추가하여 범위나 난도를 늘리지 않는다.

외부 의학지식은 자료 간 충돌을 검증·해결하는 데만 사용한다. 해설에도 필요한 최소 근거만 남기고 검증으로 알게 된 사실을 새 목표로 만들지 않는다. EXT를 범위 확장의 허가로 해석하지 않는다.

같은 사실·관계의 충돌은 실제 모순·정답표 오류·상황 차이를 구분하여 검증하고 하나의 문항으로 통합한다. 외부 검증을 사용한 문항의 exam_rationale에 EXT를 표시하고 source_refs에 검증 출처를 보존한다. 차이·선택한 정답·판단 근거는 source_conflicts에 기록한다. 미해결 쟁점은 명시하고, 충돌 설명 때문에 불필요한 임상 조건·추론을 겹친 함정을 만들지 않는다.

### 3.2 족보와 회상 방향

족보의 질문·정답·나머지 선지를 함께 읽고 실제 시험한 연결과 오답의 왜곡 지점을 확인한다. 대상·표적의 잘못된 연결, 방향 반전, 조건·예외 누락, 분류 수준 혼동을 구분한다. 부정형이라는 이유로 모든 선지를 거짓으로 보거나 조건부 오류를 항상 틀린 관계로 일반화하지 않는다.

기출의 실제 연결과 필요한 기초 연결을 출제한다. 같은 개념이 등장했다는 이유로 주변 세부 지식까지 기출 목표로 확대하지 않는다. 기출을 응용할 때는 연결·조건·혼동 지점을 보존하고 문구·보기 수만 모방하지 않는다. exam_rationale에 실제 목표와 기출 연도·번호·혼동 지점을 짧게 쓴다.

retrieval_direction은 실제 목표에 따라 direct / reverse / mechanism / discrimination / integration / sequence / trap 중 하나다. 표기나 해설의 언급만으로 충족 처리하지 않는다.

핵심 구별 특징은 대상→특징과 특징→대상의 양방향 회상 필요성을 검토한다. 모든 문항을 무조건 뒤집지는 않는다. 계열 공통 특징으로 식별하면 계열을 정답으로 하고, 개별 대상을 요구하면 원본에 근거한 조건으로 답을 특정한다. 구별 조건을 지어내지 않는다.

### 3.3 첫 학습 순서

실제로 필요한 기초 회상 뒤에 해당 기전·비교·응용·예외 판단을 배치하고, 독립적인 문항은 슬라이드 흐름을 유지한다. 중요도·형식·회상 방향 이름만으로 정렬하지 않는다.

같은 개념이라는 이유로 단원 전체나 모든 direct 문항을 선행으로 요구하지 않는다. 발문에 제공한 관계나 선지에 단순 언급된 대상의 상세 지식을 필요한 선행 회상과 구분한다.

인용한 근거 쪽과 실제 학습 위치를 구분한다. 앞쪽 개요·총괄표 인용만으로 뒤에서 배우는 내용을 앞당기거나, 다중 인용의 가장 늦은 쪽으로 모두 미루지 않는다. 순환·불필요한 선행·갑작스러운 단원 이동을 연결된 문항 전체에서 확인한다. 위치 변경만으로 회상 누락이 해결됐다고 처리하지 않는다. 불확실성은 exam_rationale에 남긴다.

### 3.4 발문과 정답

- 질문만으로 답의 범위가 결정되도록 필요한 조건·범주·분류 기준·질문 축을 명시한다. 불필요한 배경·정답 후보·답의 구성 항목을 미리 나열하지 않는다.
- “강의에서 제시한” 같은 출처 표현 대신 내용상 조건으로 범위를 정한다. 출처는 source_refs에 둔다.
- 정답의 동의어·약어 풀이·반대말·중간 기전으로 답을 알려주지 않는다. 실제 판단에 필요한 조건은 보존하고 부연은 explanation으로 옮긴다.
- 해당 의학 지식을 회상·적용해야 풀리게 한다. 일반 추론·산술·제시된 범위 비교만으로 끝나면 다시 설계한다.
- 일반 문장은 자연스러운 한국어로 쓰고 원본의 전문 용어·약어·영어 표기는 유지한다. 필요하면 한국어 뜻을 병기한다.
- 긴 발문·비교형 발문은 문장·조건·비교 기준별로 줄을 나누고 후속 줄을 두 칸 들여쓴다. 비교 대상 순서를 일정하게 유지한다. JSON 문자열 안의 줄바꿈은 \n으로 쓴다.
- 줄바꿈·가독성 편집 때문에 내용·조건을 생략하거나 문항·빈칸을 새로 나누지 않는다.
- answers에는 실제 회상 대상의 최소 채점 단위만 둔다. 발문에 있는 사실·동일 의미의 반복·부연을 별도 단위로 세지 않는다. 필요한 관계·조건·인과는 보존한다.
- 의미가 동등한 동의어·허용되는 약어·표기·어순은 정답으로 인정한다. 정확한 명칭·수치·서열 자체가 목표이면 정확성을 요구한다. 조건 누락이나 방향 변화는 동등한 답으로 보지 않는다.
- explanation은 필요한 문항에만 짧게 쓰고 정답의 이유와 기억할 핵심을 설명한다. 출처 비교는 충돌 기록으로 분리하며 별도 힌트는 작성하지 않는다.

### 3.5 문항 형식

사용할 format은 basic / cloze / list / ox / mcq / multi_select다. matching·sequence 문항과 별도 보기 풀은 사용하지 않는다.

- basic: 용어·수치·짧은 관계를 직접 회상하게 한다. 불필요한 후보나 긴 서술 요구는 피한다.
- list: 하나의 축에 속하고 답의 범위가 정해진 항목을 나열하게 한다.
- cloze: 각 빈칸의 질문 축을 문맥에 남기고 핵심 개념의 의미 있는 덩어리 전체를 {정답}으로 가린다. 동의어·반대말·문법·상식만으로 채울 수 있는 빈칸은 피한다. 단순 나열은 list로 만든다. 빈칸 수는 회상 가치와 채점 부담으로 판단하고 고정 상한은 두지 않는다.
- ox: 하나의 판단을 시험하고 근거·정정은 explanation에 둔다. X는 잘못된 부분과 올바른 내용을, 일반화 오류는 원본에 근거한 구체적 반례를 포함한다. 감별 키워드만 **굵게** 표시한다.
- mcq / multi_select: 같은 판단 축에서 실제 혼동·오개념에 근거한 선지를 만든다. 답을 먼저 회상하는 기억 확인형은 mcq_mode=recall_first, 선지 비교·판별 자체가 목표이면 comparison이다. 문구·보기 수·정답 개수·난이도만으로 구분하지 않는다.

객관식·OX는 과도한 단정·이중 부정·부자연스러운 표현·보기 길이·정답 위치로 정오가 드러나지 않게 한다. 단정어를 일괄 금지하거나 선지 길이를 기계적으로 맞추지 말고 필요한 조건과 정확성을 보존한다.

Cloze는 이름 하나만 비우고 그 이름을 떠올리게 하는 설명을 모두 남기지 않는다. 함께 회상할 내용은 여러 빈칸으로 가리고, 풀이에 불필요한 설명은 해설로 옮긴다.
OX는 단정어만 지워 참 문장으로 바꾸지 않는다. 실제로 혼동할 대상·기전·방향·조건을 바꾸어 지식으로 판별하게 재설계한다.

### 3.6 중요도·심화·난이도

중요도는 실제 채점하는 지식 단위별로 판단한다. 강의·쪽·질환·계열·포인트 전체의 중요도를 주변 사실에 전이하지 않는다.

- Must-Know: 교수가 올해 반드시 알아야 한다고 강조하거나 출제를 직접·간접 예고한 지식. “이 정도는 알아야겠죠?”, “시험에 내기 좋겠다”, “알고 있는 게 좋을 것 같아요” 같은 완곡한 표현도 인정한다. 직설적 표현만 요구하거나 Core·Important로 낮추지 않는다. 실제 발언·표시와 위치를 기록하고 필기자 자신의 예상을 교수 발언으로 추정하지 않는다.
- Core: Must-Know가 아니면서 명시된 학습목표 또는 올해 담당 교수의 실제 기출에서 요구한 지식. 해당 목표 문구나 기출 연도·번호·실제 질문과 회상 단위의 대응을 기록한다. 넓은 주제의 일치나 필수 의존성 주장만으로 부여하지 않는다.
- Important: 위 두 등급이 아니면서 교수의 일반 강조·필기자의 중요 표시가 있거나, 강의 범위 내 구체적 임상 판단·금기·중대한 위해 예방에 중요한 지식. 실제 표시·발언·위치 또는 임상적 우선순위의 이유를 기록한다. 교수 발언을 받아 적은 기록과 필기자 자신의 판단을 구분한다. 단순 본문 등장·장식용 상자·임상 적용 가능성만으로 부여하지 않는다.
- Optional: 위 근거가 없는 나머지 세부사항. 예시·대체약·수치·열거·부속 비교도 그 사실 자체의 근거로 판단한다.

강조된 표·문단에서도 실제 강조된 특성과 부속 항목을 구분한다. 수치라는 이유로 강조된 사실을 낮추거나, 발문이 알려준 위험·금기의 중요도를 별도 대체약명·부속 기전에 전이하지 않는다. 중요도별 고정 비율을 맞추지 않는다.


importance는 Must-Know=5, Core=5, Important=4, Optional=2다.
advanced는 독립적인 심화 표시다. 여러 개념의 연결·복합 조건 적용·추가 추론·실질적인 심화 비교가 필요할 때만 true로 쓰고 exam_rationale에 이유를 남긴다. 낯선 이름·수치·긴 답·형식·암기 부담·단순 비교 사실만으로 부여하지 않는다.
item_difficulty는 체감 인지 난도 1–5다. 중요도·심화와 구별하며 모호한 표현·불필요한 요구로 난도를 높이지 않는다.

## 4. 작업 순서와 검수

### 4.1 처리 순서

1. 첨부 원본 전체의 본문·필기·표·그림·족보를 읽고 지정 범위·교수 강조·학습목표·기출을 바탕으로 출제 목표를 정한다.
2. 목표별 필요한 회상 방향과 형식을 선택해 전체 초안을 작성한다. 각 문항의 실제 원본 근거와 충돌 후보를 함께 기록한다.
3. 전체 초안을 원본 전체와 대조하여 오류·충돌·기초 회상 및 방향 누락·중복·정답 단서를 검수한다. 충돌 해결과 중복 통합은 전체 초안이 나온 뒤 함께 판단한다.
4. 실제 선행 개념과 강의 흐름에 맞춰 순서를 정하고 전체 내용을 확정한다. 검수가 끝나기 전에는 문항을 출력하지 않는다.
5. 확정본을 지정된 JSON 파일에 저장하고 실제 파일을 다시 읽어 확인한 뒤 제공한다.

### 4.2 최종 내용 검수

수정한 문항·선지·정답까지 원본과 다시 대조한다.
- 지정 범위·용어·정확성과 실제 원본 근거를 지켰는가?
- 질문 축·정답 범위가 명확하고 정답 단서·보기 비대칭이 없는가?
- 원본 전체의 뼈대·기초 연결·필요한 방향을 실제로 시험하는가? 목표 목록 밖 누락도 확인했는가?
- 족보의 실제 연결·조건·왜곡 지점을 보존했는가?
- 과분할·중복이 없고 추가 문항에 독립적 회상 가치가 있는가?
- 필수 목표의 누락과 선택적인 확장 제안을 구분했는가?
- 실제 선행 회상과 강의 흐름에 맞게 배열했는가?
- Must-Know·Core의 출제 예고·학습목표·해당 교수 기출 회상 충족과, Important·Optional을 포함한 전체 내용 충족을 각각 확인했는가?
- 누락 보완 필요성만으로 Core로 올리거나 중요도 하향을 오류·필수 누락 해결로 처리하지 않았는가?

## 5. JSON 출력 계약

### 5.1 파일 전체 객체

최상위는 다음 필드를 가진 JSON 객체 하나다. Markdown 머리·코드블록·주석·완료 문자열을 파일에 넣지 않는다.

- schema_version: 2
- subject, run_id, prompt_version: 아래 전달 지시의 값
- complete: 전체 검수와 저장 파일 확인이 끝나면 true
- question_count: 실제 전체 문항 수
- question_ids: 최종 순서의 모든 문항 ID. Q001부터 연속 부여
- conflict_ids: source_conflicts의 순서대로 모든 충돌 ID. 없으면 []
- questions: 전체 문항 배열
- source_conflicts: 충돌 배열. 없으면 []
- generation_id: 별도 요청에 값이 주어진 경우에만 추가

### 5.2 문항 객체 (questions의 각 항목)

#### 5.2.1 공통 필드

각 문항의 필수 필드:
question_id, format, tier, importance, advanced(boolean), item_difficulty, retrieval_direction, question, source_refs, exam_rationale, evidence.

#### 5.2.2 형식별 필드
- basic: answers에 짧은 정답 하나. 예: ["정답"]
- list: answers에 독립 채점 항목 각각. 예: ["항목 1","항목 2"]
- cloze: question에 {정답}을 직접 표시하고 answers는 생략. 같은 답도 각 위치를 감싼다. 중첩·빈 중괄호는 금지
- ox: answers는 ["O"] 또는 ["X"], explanation 필수
- mcq / multi_select: options에 {"id":"A","text":"선지"} 형태의 보기 두 개 이상, mcq_mode 필수. answers에는 실제 보기 ID만 넣으며 mcq는 하나만 선택. 정답 선지 본문을 반복하지 않는다

필요할 때만 explanation(문자열), conflict_id(정의된 CF001 등의 ID)를 추가한다. 해당 없는 필드·빈 충돌 ID·힌트·개념도·선행 관계·계획표는 작성하지 않는다. answer/answer_units로 정답을 반복하지 않는다. JSON 문자열의 따옴표·역슬래시·줄바꿈은 이스케이프한다.

### 5.3 출처 참조 (source_refs)

source_refs는 [{"source_id":"S1","locator":"p.12"},{"source_id":"S2","locator":"2023 Q11"}] 형태다. 실제 물리 쪽과 기출 위치를 보존한다. 외부 검증 출처는 관련 source_id의 locator에 EXT와 실제 출처 URL을 함께 기록한다.

### 5.4 근거 객체 (evidence)

evidence 형식:
{"mode":"single","slides":[{"page":12,"evidence":"실제 지면에서 정답을 뒷받침하는 문구·표·그림·필기"}],"reference_pages":[],"reason":"이 한 장으로 발문과 정답의 핵심을 설명할 수 있는 이유","jokbo":[{"year":"2023","number":"Q11"}]}

- 기본은 single과 핵심 한 장이다. 다른 장의 필수 내용을 연결해야만 설명할 수 있을 때 linked와 최소 장수를 사용한다. reason에 한 장으로 부족한 이유, 각 slides.evidence에 해당 장만의 필수 근거를 쓴다.
- 반복 지면·배경은 reference_pages에 둔다. page·reference_pages는 S1 PDF의 실제 물리 쪽 번호다. 핵심·참고 쪽은 중복하지 않는다.
- 동의 표현·영문·약어·그림·필기와, 자료에 명시된 관계에 발문 조건을 적용한 한 단계의 분명한 추론도 인정한다. 추론의 연결을 evidence에 쓰며 자료 밖 사실을 보태지 않는다.
- 발문이 제공한 조건을 원본에서 다시 요구하거나 부가 해설을 채점 핵심으로 확대하지 않는다.
- 첨부 강의자료에서 근거를 찾지 못하면 unresolved, slides=[]로 쓰고 빠진 핵심 사실·실제 확인한 범위를 reason에 남긴다. 확인하지 않은 다른 자료에도 근거가 없다고 단정하지 않는다.
- jokbo에는 실제 참고한 연도·번호만 넣으며 없으면 []다. 전체 인용은 source_refs에도 보존한다.

### 5.5 충돌 객체 (source_conflicts의 각 항목)

source_conflicts의 각 객체:
{"conflict_id":"CF001","description":"판단: 선택한 정답\n자료 1: 실제 자료명·쪽/연도와 주장\n자료 2: 실제 자료명·쪽/연도와 다른 주장\n근거: 판단 근거","source_refs":[{"source_id":"S1","locator":"p.12"}],"unresolved":false}

미해결이면 unresolved=true로 쓰고 description에 구체적인 쟁점을 남긴다. 문항의 conflict_id와 일치시킨다. 원본 차이·선택한 정답·외부 검증 출처는 보존하되 작업 경위·내부 인용 토큰은 넣지 않는다.
