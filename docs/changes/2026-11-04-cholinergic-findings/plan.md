# 콜린성 예시의 20개 검수 기록과 3개 미준비 방향 원인 교정 — 구현 계획

## 변경 범위·대상 파일·순서
1. studyez_contracts/roots/source_assessment.py 및 source/extract 프롬프트의 방향 미정 계약·지도 완전성 기준을 교정한다.
2. 이 change 폴더의 once-only 실행 도구로 원본/이전 예시/예산을 고정하고 1차 참고자료를 별도 재고로 수집한다. 지도 단계는 BANK/문항 검수에서 분리한다.
3. 모델에 지도→BANK교정→전체 원본 대조→blind medical을 맡긴다. 실제 남은 오류/누락만 예산 내 교정한다. 시작/원문/usage/hash를 보존한다.
4. 별도 최종 확인으로 원래20개+3방향의 처리 근거/상태를 받는다. 결정적 재컴파일·변경 내역·예산/원본 보존을 확인하고 읽기 전용 실제 preview를 새 파일로 제공한다.
5. 원본에서 필수로 확인된 구조 그림은 visual_support.py의 모델 작성 crop/결정적 렌더로 예시에 표시한다. blind medical에는 질문 자극만 --image로 첨부하며 기존 tools-off/ephemeral 판정 검사를 유지한다. 전환 전 도구/증거를 보존하고 한 번의 계획된 BANK 교정 안에서 작성한다. 이 보강은 사용자가 승인한20개 교정 중 시각 지적의 직접 구현이다.
6. source1의 실제 기초 명칭 관계 누락과 복합 관계의 과대 집계 진단에 한하여 map_patch.py가 원본 전용 표적 보완1회를 추가한다(지도 총2회). 문항/검수 내용은 지도 단계에 제공하지 않는다. 이전 도구·proof·전체 소비 이력을 보존한 전환을 기록하고 나머지 BANK/source/medical 상한은 그대로 유지한다. 후속 round_patch.py는 수정된 문항만 모델에 작성시키고 변경하지 않은 문항을 결정적으로 보존하며, 원본 대조에서 복합 관계의 모든 필요한 사실을 실제 회상하는지를 명시적으로 검사한다. 현재 사용자20개 원인 교정의 같은 범위이며 운영 변경은 없다.
7. map-2의 프로세스/세션 조사 끝에 완성된 JSON·task_complete·usage를 확인했다(CLI는2400초 시간초과). recover_map.py의 방어 검사가 재호출을 막았으며 이 도구로 새 모델은 실행되지 않았다. recover_completed_map.py는 정확한 원문을 추출·검증하고 assembly-map2로 결정적 복구한다(추가모델0). 모델이 작성한 동일 부모/자식의 중복 classification 역방향만 기존 계층에 맞춰 정규화하며 사실 문구·근거·ID는 보존한다. prerequisite kind/끝점 계약이 맞지 않는 제안4개는 원문에 남기고 채택하지 않는다. 실패 stage는 completed로 바꾸지 않는다. 최종 검사는 세션 완료와 원문·usage·정규화·미채택 제안 이력을 모두 대조한다. 지도 실제 호출은2회이며 다른상한·운영권한도 늘리지 않는다.
8. source2의 실제 필수 공백을 final_patch.py의 마지막3차 내용 수정에 전달한다. 이 단계에서 D24의 명시된 참조 오류만 모델 작성 subset으로 교정할 수 있다. 다른 필수 방향에 사실이 보존되는지 코드로 검사하며 문구·범위·조건·다른 방향은 바꾸지 않는다. 원문·수정 전 brief·모델 작성 이유·전체 전후 hash를 남기고 source3/medical3 및 최종20개 처리 확인으로 검증한다. 현재 사용자의20개 원인 교정과 미준비 방향 해결의 동일 범위이며 원본 전용 새 추출이나 운영 변경은 없다.
