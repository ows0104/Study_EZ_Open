# quizgen 작업 안내

강의 PDF → 예습·복습 카드 → Anki 덱을 만든다.
실행은 [quizgen 안내](../docs/quizgen.md), 프롬프트 파일은
[조립 구조](../docs/prompt-architecture.md), 검사는 `python -m pytest tests/quizgen`이다.

## 수정 위치

| 책임 | 파일 |
|---|---|
| 복습·예습 단계 | `run.py`, `prequiz/run.py` |
| 공통 실행·재개 | `runbase.py`, `session.py` |
| 지침 조립·입력 준비 | `prompting.py`, `assemble.py`, `pack.py` |
| 구조·규칙 검사 | `validate.py`, `prequiz/validate.py` |
| 질문만 보고 다시 풀기 | `reproduce.py` |
| 카드·덱 생성 | `build.py`, `anki_models.py` |
| 원본 판 변경 | `slidediff.py`, `revise.py` |

## 학습 목적과 규칙

복습은 **시험에 나올 수 있는 것**, 예습은 **모르면 수업을 따라가기 어려운 것**을 고른다.
암기와 이해는 동등하며, 시험 점수와 이해 모두 목적이다. 족보는 중요한 길잡이다.
올해 강의 교수가 출제한 해를 우선하고 다른 출제자의 문항은 참고로 사용할 수 있다.

예습의 목적은 수업 이해, 중요한 지점 예고, 흥미, 예습 대화 이해 확인, 공부 효능감이다.
목적을 추상 문구로 복사하기보다 `must_know.signals`·`why_tags`·`challenge` 등
이미 합의한 장치로 구현한다. 이유 글(`why_asked`)은 답을 본 뒤에, 배지는 앞면에 나온다.
2026-10-06 사용자 결정으로 10문항을 기준으로 내용에 따라 총 8~12문항을 만들고, 그 안에 선택 도전 1~2문항을 포함한다.

`quizgen.prequiz.run --simple --note <설명본>`은 한 편씩 시험하는 간소화 경로다.
설명본으로 목표·문항을 함께 생성하고, 기계 검증 뒤 새 세션에서 전체를 검수한다.
문제가 있을 때만 수선한다. 답을 보는 검수이므로 재현 풀이 통과로 표시하지 않는다.
`batch_review.json`에 문항별 판정과 검수한 카드의 지문을 남긴다.
핵심은 쉬운 시작·읽기 확인·중요한 구분·작은 적용·핵심 정리 순서다.
`learning_support`로 힌트·학습 범위·수업 질문을 전달하고, 예습 원문 발췌는 검토용으로 남긴다.
웹 도전은 핵심 학습 뒤에 선택하며 평가·진행률·복습 일정에서 제외한다.

관리자 인터뷰의 분량·시간 목표는 방향을 보는 값이며 탈락 기준이 아니다.
목적이나 목표값을 바꿀 때는 [인터뷰](../docs/archive/interview.md)와
[변경 전 규칙](../docs/archive/2026-10-06-originals/quizgen/CLAUDE.md)을 먼저 확인한다.
사용자의 관찰·허용을 새로운 의무로 바꾸지 않는다.

## 유지할 계약

- 프롬프트 변경 시 대응하는 검증 코드도 확인한다. soft flag와 hard error를 구별한다.
- `--force`·재개에서 옛 산출물을 이번 입력의 결과로 사용하지 않는다.
- `run.py`는 수선 뒤 결함을 표시한 채 빌드할 수 있다. `.apkg` 존재를 품질 보증으로 해석하지 않는다.
- 질문 길이·문자 유사도 검사는 카드 형식별 차이를 고려한다.
- 예습 커버리지는 승인된 must-know 항목과 `must_id`로 잰다.
- 전체 슬라이드 커버리지나 표시 개수만으로 새 배포 차단 기준을 만들지 않는다.
- 관리자가 확인할 새 신호는 실제 카드·검토 화면까지 전달한다.
- Anki GUID의 씨앗과 모델 식별자를 바꾸면 사용자의 복습 기록이 끊길 수 있다.

## 프롬프트 검증

새 생성 한 편의 수치만 비교하면 생성·채점 변동이 섞인다.
문구 비교는 같은 표본을 가린 `python -m quizgen.judge` 평가를 사용한다.
재현 일치율만으로 자명한 카드나 나쁜 cloze를 선별할 수 없다.

실제 카드 예시가 포함된 강의·같은 주제를 평가 표본으로 쓰지 않는다.
예시 출처는 `prompting.py`의 `DOMAINS` 위 주석에 있다.

실패 사례와 아직 검증하지 못한 가설은 [quizgen 사례](../docs/archive/quizgen-cases.md)에 있다.
과거 표본 수를 현재 상태로 복사하지 말고 필요한 산출물에서 다시 확인한다.
