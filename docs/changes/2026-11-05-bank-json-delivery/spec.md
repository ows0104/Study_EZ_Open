# 웹 문제은행 순수 JSON 전달과 프롬프트 간소화 — 설계

## 요구사항과 수용 기준
후속 보완: 구체적인 회상/목표 분할/Cloze 설계 예시를 짧게 남긴다. 출제 철학에 운영·범위 기준을 종속시키지 않고, JSON은 최상위→문항→형식별 필드→출처/근거/충돌 객체로 설명한다. 품질 추출은 자료·작업 절차·출력 형식을 제외하고 철학/예시/출제 기준만 포함한다.
프롬프트 1.80부터 authored JSON schema_version=2를 사용한다. 최상위에는 과목·강의·프롬프트 판·선택적 generation_id, complete=true, 전체 문항 수/순서/충돌 ID, questions, source_conflicts가 있다. 문항의 최소 작성 필드와 형식별 answers/options, 원본 근거를 구조화한다. JSON 중복 키·비유한 수·잘못된 형식/참조/순서/빈칸/필수 해설·근거를 거절한다. 파일의 실제 UTF-8 바이트 해시와 길이, 요청 판과 generation ID를 검증한다. 구조 통과는 의학 검수 완료가 아니다.

수집 확장·수동 웹 입력·일반 API·뿌리 생성 API·러너는 새 JSON과 보존된 MD를 함께 읽는다. 새 요청 판은 새 JSON만 허용하며, MD를 JSON으로 이름만 바꾸거나 완료 문자를 덧붙이는 우회는 거절한다. 같은 원문 재전달은 기존 멱등성과 기록 보존을 유지한다.

JSON은 공용 순수 모듈에서 기존 BANK 3.2로 결정적으로 변환한다. 질문/선지/정답/출처/충돌/문항 순서와 authored-evidence를 보존하고, 기계적 기본값만 채운다. CLI 원본·독립 정답 검수/학습 구조 및 뿌리 생성의 원본 지도·검수·최대 3회 수정 예산은 유지한다. 기존 Markdown 변환 경로는 그대로 둔다.

웹에 보내는 정본은 합의된 출제 원칙을 축약하고 출력 설명을 JSON에 맞춰 바꾼다. 실제 교수 메타데이터가 있을 때만 이름을 전달하고, 파일명의 필기자 이름을 교수로 추측하지 않는다. 지정 강의 범위는 유지한다.

## 책임·입출력 계약·오류 상태
검증/변환 정본은 studyez_contracts/bank, 브라우저의 동일 판정은 bridge/bank-file.js다. API는 파일 신원과 해시를 검사하고 원문을 보존한다. invalid JSON은 검수 모델 호출 전에 거절한다.

## 호환성과 데이터 보존
기존 판 MD는 기존 파서로 처리한다. JSON은 새 판 요청에만 사용한다. 운영 DB·기존 파일·학습 상태·진행 중 실행 ledger는 변경하지 않는다.
