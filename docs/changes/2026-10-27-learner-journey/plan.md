# 학습자 여정과 핵심 화면 구성 — 구현 계획

2026-11-02 추가: 블록 시작의 교수 변경 안내·교수별 기출 스타일은
[별도 Implementation Plan](../2026-11-02-block-professor-briefing/plan.md)에 파일 후보·순서·검사·복원을 작성했다.
요구는 [Spec/S11](spec.md#s11-블록-시작-교수-변경과-출제-스타일), 세부 결정 대기는 [P10](open-design.md#p10-블록-시작-교수-변경과-출제-스타일)을 따른다.
해당 초안은 전체 학습자 여정의 미작성 계획을 대신하거나 제품 구현 승인을 뜻하지 않는다.

## 변경 범위·대상 파일·순서
2026-11-02 첫 제품의 구현 단위를 [강의별 뿌리 학습 계획](../2026-11-02-root-learning-product/plan.md)으로 구체화했다.
콘텐츠 계약 → 별도 목표/방향 기록·추천 → API/재전송 → 현황/지도/풀이/종료 → 검사/복원의 순서다.
대상 코드와 실제 구조 조사 근거는 해당 계획에 있다. 전체 세부 트리·이미지 crop·bridge 확장·교수 안내는 별도 범위다.
전체 여정 Spec의 합의를 유지하며 첫 제품의 세부 추천안은 [제품 Spec 제안](../2026-11-02-root-learning-product/spec.md)에 분리했다.

## 검사 명령과 성공 조건
제품 계획의 계약·상태·API·보존·추천·UI·웹·이용현황 검사표를 따른다. 이 상위 변경의 design-review는
제안과 기존 합의의 대응, 사용자 주요 선택, 실제 콘텐츠 범위를 검토한 근거다. 코드 테스트·콘텐츠 의학 검토·운영 확인은 서로 대신하지 않는다.

## 위험·복원·승인할 범위
첫 제품은 기존 은행/학습 기록을 보존하는 추가형 계약과 기능 플래그, 불변 콘텐츠 판·학습 사건의 보존을 권고한다.
복원 순서·후보·미확인 요청 처리와 승인 경계는 제품 계획에 있다. Spec의 주요 선택·콘텐츠 범위 확정 후
revision에 결부된 로컬 Build 승인을 받고, 운영 변경은 검사/리뷰 후 별도 중요 승인을 받는다. 현재 Build는 미승인이다.
