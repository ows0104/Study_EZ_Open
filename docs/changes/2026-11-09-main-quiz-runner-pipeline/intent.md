# Main-Quiz 생성 러너 일반화 — 의도

## 문제와 사용자 효과

Main-Quiz 생성은 두 강의에서 끝까지 갔다. 감염병리1(261104_02)과 사슬알균(261105_01)이고, 둘 다 학생에게 공개됐다.
두 번 모두 강의별 시범 스크립트를 사람이 지켜보며 돌렸다.

- 앞 단계(개념 지도 → 포인트 → 대조 → 보완 → packet)는 강의마다 `run.py`를 복사해서 돌렸다. 원본 경로·해시·범위 문구를 손으로 적었다.
  - 감염병리1: `docs/changes/2026-11-08-importance-basis/run.py`
  - 사슬알균: `docs/changes/2026-11-09-main-quiz-second-lecture/run.py`
- 생성 중간에 사람이 멈추고 이어 갔다. `--resume`, `--rerun source-2`, 「통과시키기」 결정이 그 예다.
- 반입과 공개도 강의별 스크립트였다(`publication.py`, `open_to_students.py`).

그래서 강의 하나를 내는 데 사람의 하루가 든다. 관리자가 강의를 고르면 러너가 끝까지 처리해 학생에게 여는 길을 만든다.
사용자: 2026-11-09 「이제 진짜 파이프라인 가동이 가능한가?」 → 「설계 결정부터」 → 「스펙 작성 시작」.

## 사용자가 정한 설계 결정 (2026-11-09, 선택지 응답 원문)

1. 보완 예산 — 「따로 세기」
   - 초기 지도 교정은 보완 3회와 따로 센다.
   - 출제 단계가 초기 지도 오류를 고치는 것은 보완 회차로 치지 않는다. 보완 3회는 언제나 보완에 쓴다.
2. 검토 포기 — 「새 세션 1회 자동」
   - 원본 대조·맥락 검사가 포기했을 때는 그 단계만 새 세션으로 한 번 자동으로 다시 돌린다. 같은 세션에 되돌려도 안 된 경우다.
   - 보완 횟수는 늘지 않는다. 그래도 포기하면 멈추고 알린다.
3. 승인 단위 — 「관리자 화면 요청」
   - 관리자가 웹에서 그 강의의 Main-Quiz 생성을 요청하는 것을 그 강의 하나의 승인으로 본다.
   - 이 승인이 강의 원본을 Codex CLI로 보내는 것을 덮는다. 호출 범위는 화면에 표시한다.
4. 공개 범위 — 「학생 공개까지 자동」
   - `result.json`이 계약 검증을 통과하면 운영에 반입하고 바로 학생에게 연다.

## 범위

- 이번 단계는 문서만 만든다: intent, spec, Implementation Plan.
- 구현은 계획 승인 뒤에 한다. 대상은 다음과 같다.
  - 러너 명령 하나: 과목과 run_id만 받는다.
  - 엔진·계약: 결정 1·2.
  - 서버·웹 관리자 요청 경로: 결정 3.
  - 자동 반입·공개: 결정 4.

## 범위 밖

- 이미 공개된 두 강의의 판·학습 기록. 다시 생성하거나 바꾸지 않는다.
- Quiz Bank(웹 출제) 경로와 Pre-Quiz.
- 출제 지시문의 내용 정책(문항 형식·중요도 규칙). 구조를 옮기면서 바꾸지 않는다.
- 블럭 단위 자동 시작. 결정 3에 따라 강의마다 관리자가 요청한다.
