# 이용현황에 새 행동 추가하기

사이트 기능에 새 사용자 행동을 추가할 때 기록과 이용현황 표시를 함께 구현한다.

1. 서버가 확인 가능한 사실을 정한다. 시작 시도, 링크 주소 저장, 클릭, 웹 평가, 파일 요청을 성공·열람 완료로 추정하지 않는다. 서버 확인 이벤트가 있으면 그 시각에 기록하고, 외부 이동은 화면에서 명시적으로 알린다. 사용자·강의별 기존 저장소를 재사용하거나 승인된 추가 저장소를 설계한다. 접속 기록표는 만들지 않는다.
2. `server/app/usage_actions.py`의 `ACTIONS`에 코드·한국어 이름·그룹·요약/상세 단위·수집 경로를 등록한다. 새 그룹이면 `ACTION_GROUPS`에도 추가한다. `usage.py`가 반환하는 원본 수집 필드에 연결한다. 기존 기록을 바꾸거나 과거 목적을 추정하지 않는다.
3. 파일 목적은 `FilePurpose`와 카탈로그를, 링크 행동은 `PREVIEW_ACTION_KINDS`와 카탈로그를 함께 수정한다. 호출자에 기록을 연결한다. `usage_actions` 검사가 등록 누락을 탐지한다. 만드는 시도는 create, 기존 링크 열기는 share/mine이며 대화 저장과 다르다.
4. API가 카탈로그/행동별 값을 반환하므로 이용현황 UI에는 별도 행동 이름 목록을 추가하지 않는다. 요약·상세 모두 같은 정의를 순회한다. 새 행동이 없는 사용자도 0 또는 기록 없음으로 처리한다.
5. `server/.venv/Scripts/python.exe -m tests usage_actions`, 관련 기록 경로 검사와 `usage`, 웹 typecheck/build를 실행한다. 신규 행동의 사용자/강의/기간/실패·취소 의미와 개인정보 비노출을 확인한다. API를 먼저 배포하고 웹을 배포한다.

`개인 링크 만들기 시도`는 버튼에서 새 대화를 시작한 요청이다. `개인 예습 링크 저장`은 현재 계정에 주소가 남아 있다는 뜻이다. 외부 AI 생성 완료나 실제 학습 완료를 증명하지 않는다. 도입 전 시도 기록은 소급해서 만들지 않는다.
