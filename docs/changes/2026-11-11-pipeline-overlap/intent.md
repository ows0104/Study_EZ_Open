# Main-Quiz 호출 시간 단축: 입력 인라인·의존 관계대로 겹치기

## 문제와 사용자 효과
사용자 요청(2026-11-11, 채팅): 「좀 더 진단해줄래? 근본적으로 시간을 더 단축할 수 있는방법이 없을까?」 → 진단 보고 뒤 「겹치기까지 같이」
(1번 입력을 첫 메시지에 넣기 + 2번 의존 관계대로 더 겹치기).

진단: 정상 실행 두 건(6e5c581a, fa71412a)의 생성 단계 Codex 세션 기록 101개(`~/.codex/sessions/2026/11/11/rollout-*.jsonl`)를
타임스탬프로 분해했다. 합계 211분.

| 쓰인 곳 | 시간 | 비중 |
|---|---|---|
| 가장 긴 생각 한 번(실제 출제·검토) | 85분 | 40% |
| 둘째로 긴 생각 | 20분 | 9% |
| 셸 명령 실행 대기 | 50분 | 24% |
| 그 사이 짧은 모델 응답 | 55분 | 26% |

- 명령 왕복 한 번이 약 12초(명령 실행 중앙값 4.2초 + 다음 명령까지 모델 응답 7.9초).
- 검토 호출은 평균 141초 중 가장 긴 생각이 57초. 왕복 6.6번 중 4.2번이 `task.md`·스키마·`input.json` 읽기.
- 첫 읽기가 출력 한도에 잘려 다시 읽는다(표본 11개 세션에서 26번).
- 앞 단계 호출은 왕복 12번 안팎, 그중 5번이 입력 읽기.

의존 관계(코드 확인):
- `normalize`의 입력은 제목·범위·지도·최종 포인트·원본뿐이다. 문제은행·재대조와 무관한데 앞 단계가 끝난 뒤에 시작했다(4~8분).
- 문항 검토 첫 호출(`v4-review-<b>-0`)의 입력은 그 묶음 문항·인용 충돌·지도 관계다. 추가 출제는 문항을 뒤에 붙이기만 하므로,
  40문항으로 찬 묶음의 입력은 그 뒤 회차가 끝나기 전에 이미 정해져 있다.
  실제 실행 4건: 접수 74~128문항 + 추가 54~114문항(거의 전부 1회차). 추가 1회차 직후 마지막 묶음을 뺀 전부가 찬다.
- 임상 정리(`v4-context-0`)는 합친 뒤의 문제은행·충돌만 읽고 커버 재확인(`coverage-merge-0`) 결과는 읽지 않는다.

사용자 효과(추정, 실측 전):
- 인라인: 호출마다 30~50초(읽기 왕복이 실제로 없어질 때). 한 강의 12~17분.
- normalize 겹치기: 재대조·문제은행이 끝날 때까지의 4~5분.
- 검토 첫 호출 겹치기: 마지막 덜 찬 묶음의 사슬이 다른 묶음보다 그만큼 짧을 때에 한해 최대 검토 한 번(3~4분). 보장되지 않는다.
- 임상 정리 겹치기: 커버 재확인이 필요한 강의에서 2~3분.
- 합쳐서 PR #115 뒤 65~70분으로 예상한 6묶음 강의가 45~50분대.

## 범위와 성공 기준
- 생성 단계: 지시문·스키마·입력을 첫 메시지에 싣는다(파일은 그대로 두고, 결과 파일·검사 방식 불변).
- 앞 단계: 지시문 뒤에 그 단계 입력 파일 내용을 붙인다(`task.md` 불변).
- early-call/1: 입력이 이미 정해진 단계를 차례 전에 부르고, 차례가 왔을 때 입력 지문이 같으면 그 답을 쓴다.
  - 앞 단계가 포인트 확정 직후 생성기의 `normalize`를 부른다(map-tree/3).
  - 40문항으로 찬 묶음의 검토 첫 호출을 추가 회차와 나란히(추가 전과 각 회차 직후).
  - 임상 정리를 커버 재확인과 나란히.
- 바꾸지 않는 것: 지시문 파일, 단계 이름·입력·ledger 단계 기록·결과 형식, 서버·DB, 검수·수정 상한, 판정 규칙.
- 성공 기준: 새 합성 검사 통과, 기존 회귀가 이 변경 전과 같은 결과. 실제 단축은 러너 재설치 뒤 첫 강의로 확인한다.

## 근거·미정 사항
- 승인: 위 사용자 발언. 운영 DB·공개 범위·자료 전송 경로는 그대로다(같은 호출을 같은 경로로, 순서만 앞당김).
- 미정: 인라인이 실제로 읽기 왕복을 얼마나 없애는지는 모델 행동에 달려 있어 실측이 필요하다.
  고치기 회차까지 추가 회차와 겹치는 것은 커버리지 행을 양쪽이 고쳐 이번에 하지 않았다.
- 이 브랜치는 PR #115(`claude/pipeline-resilience`) 위에 쌓았다.
