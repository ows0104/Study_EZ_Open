검사: tests/development 29 passed (22.11s), tests/contracts 6 passed (2.82s).
실제 PowerShell 배포 래퍼는 격리된 가짜 gcloud로 성공/실패를 검사했다. 웹 게시도 가짜 명령으로 검사했다.
설계 재승인 후 이전 검사 재사용, 검사 중 설계 변경, 누락 입력(Spotter/시간표/잠금 파일),
오래된 기록, 후보·환경·소스 변경, 잘못된 대상, 배포 실패, 사후 검사 실패 및 사건 종료 차단을 확인했다.

리뷰: 검사/리뷰는 영역별 소스와 설계에 연결된다. 기존 기록을 성공 기록으로 자동 승격하지 않는다.
배포 후보는 검사한 파일과 대조한 별도 사본이며 승인도 그 후보에 묶인다.
서버/웹 게시 진입점은 실제 결과를 기록하고 health와 승인된 핵심 동작 검사 후에만 성공한다.
사건의 관측 복구와 배포된 수정으로 종료를 구분한다. 최신 배포 또는 최신 사후 검사 실패는 종료를 막는다.
기존 coverage 사건은 기존 해결 근거를 보존한 completed_local 상태로 정리한다.

배포 전 남은 일: 실제 배포 작업에 server/web와 contracts 등 필요한 검사를 지정하고,
읽기 전용 인증·핵심 학습 smoke 명령, 목적지, 실제 버전 조회, 복원 절차를 작성·검토한다.
현재 작업에는 운영 후보와 배포 승인이 없으므로 deploy gate는 실패해야 한다.
외부 저장소/Pages의 직접 push 차단 설정과 운영 환경변수·원격 secret 버전은 별도 운영 검토 대상이다.
로컬 파일 검사는 원격 계정 권한이나 사람이 직접 실행하는 명령까지 강제하지 않는다.

자동화 복구 결과는 별도 automation-verification.json에 기록한다. 기존 시간표·스레드·활성 상태를 유지한다.
