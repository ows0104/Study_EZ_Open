# C005 마지막1회 구조보완과 검수·이미지·업로드 — 구현 계획

## 변경 범위·대상 파일·순서
1. 최신master 별도 worktree에서 PR12를 보존 통합하고 대시보드에 현재 승인을 등록한다.
2. studyez_contracts/roots/plan_repair.py와 runner/root_plan_repair.py에 한행 schema/불변성/3of3 소비/실제CLI 영수증/기존22검수+새 전역대조 연결을 추가한다. chunked.validate_continuation은 3차 proof가 있으면 원래2차 bank/view를 복원해 기존 증명을 먼저 검증한다. 표준 generation_v2의 전체 검증/단계/상한은 유지한다.
3. 이전 후속 runs를 별도 출력에 복사하고 이전 디렉터리는 읽기 전용/전체hash 검증한다. root 모델은 내용을 직접 작성하지 않고 실제CLI 결과 한행만 결정적으로 조립한다. 동일 임상·개별검수 입력은 원래 제공자 영수증으로 재사용하며 새 전역CLI는 전체원본/모든 문항/실제그림/완료partial들을 대조한다.
4. 기존 등록/로컬UI 스크립트의 경로와 최종 proof 연결을 갱신한다. 전체 검증·앱/이미지/원본PDF 확인, 검토/CI, 같은SHA API/웹 배포 후 관리자 시범 업로드/읽기 확인을 이어간다. 구체적 업로드 승인은 이미 현재 세션에 있다.

## 검사 명령과 성공 조건
plan-regression: 승인한 한행 외 변경·예산초기화·누락/중복/다른내용·중단 재호출·변조 proof 거부, 기존319+서버4 및 새3차 합성 E2E. preserved-origin: 기존 pilot/22검수 파일 hash/판정/원본이미지 보존. live-evidence: 실제한행CLI 영수증·새 전역대조·완전한 최종 계약·원본19PNG와15문항·격리UI/원본링크. 실패/미실행은 통과로 표시하지 않는다.

## 위험·복원·승인할 범위
현재사용자의 남은1회 승인과 앞선 지정PDF 전송/CLI/업로드 승인을 적용한다. 임상내용·그림 변경 없이 학습계획 한행만 CLI가 작성한다. 모델 제한/중단은 반복하지 않고 실패/3회상한을 보존한다. 자동 코드 배포는 기존 협업 정책을 따르며 원본/판정 링크를 위한 동일SHA 검증을 먼저 한다. 복원은 새 판 비활성화와 이전 코드 복원만 가능하며 기존 원본/영수증/학생기록은 삭제하지 않는다.
