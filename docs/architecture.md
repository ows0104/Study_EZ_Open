# Study_EZ 설계

의대생 공부를 돕는 사이트. 이 문서는 **정해진 것**과 **왜 그렇게 정했는지**를
담는다. 절차는 `README.md`, 출제 규칙은 `.claude/skills/*/references/`에 있다.

## 한 줄 요지

**서버는 아무것도 만들지 않는다. 만드는 건 전부 로컬, 서버는 배급만 한다.**

만드는 사람이 관리자 한 명이고 결과물이 모두에게 똑같다. 그래서 작업 큐도,
사용자별 생성도, 과금도 없다. 참고한 meddeck-local-app은 사용자마다 서버에서
카드를 생성하느라 그 전부가 필요했고, 서버 파이썬 267KB 중 165KB(62%)가 그것
때문이었다.

```
 SynologyDrive/{과목}/필기/{2025,2026}/     {과목}/족보/{연도}/     시간표 JSON
        │                                        │                     │
        └────────────────────┬───────────────────┴─────────────────────┘
                             ▼
                  로컬 러너 (이 저장소)
                  · 강의 인덱싱 · 족보 분할 · 연도 매칭
                  · /quiz · /prequiz 스킬 실행
                  · 산출물 업로드
                             │  HTTPS + 관리자 토큰
                             ▼
                  Study_EZ 서버 (얇게)
                  메타 DB + 파일 저장 + 읽기 API
                             │
                             ▼
                  웹 — 흰 배경, 캘린더가 홈
```

## 스택

```
Supabase (Auth + Postgres)   로그인. 서버 코드 3KB, 비번·재설정 메일을 안 만든다
Cloudflare R2                PDF·apkg. 짧은 수명 서명 URL
FastAPI 1개 (Cloud Run)      읽기 API + 관리자 업로드. 워커 없음
정적 프론트 (Vite + React)    화면 3개. Next.js RSC까지 갈 이유가 없다
```

운영 지점 **3개**다. meddeck은 여기에 Cloud Tasks, Cloud Scheduler, Secret
Manager, PortOne, Cloudflare Workers가 더 있었다.

인증을 자체 구현하지 않는 이유는 그게 더 무겁기 때문이다. 비번 해시·재설정
메일·세션 회전을 직접 짜면 `auth.py` 3KB가 수십 KB가 된다. 무거웠던 건 인증이
아니라 작업 큐와 과금이었고, 그건 통째로 없어졌다.

## 화면

| 경로 | 화면 |
|---|---|
| `/` | 캘린더 (월/주). 강의 칩에 자료·퀴즈 유무 점 |
| `/lectures/{run_id}` | 강의 상세 — 새 창. 작년 강의록 · 예습 열기 · Pre-Quiz · 올해 강의록 · Main-Quiz |
| `/admin` | 매칭 확인, 업로드 현황, 예습 링크 입력 |

흰 배경 · 무채색 · 강조색 하나.

## 계정

관리자냐 아니냐, **불리언 하나**다. 콘텐츠가 모두에게 동일하므로 meddeck의
cohort 승인·소유권 검사가 필요 없다.

| | 관리자 | 일반 |
|---|---|---|
| 캘린더·PDF | 업로드 | 보기 |
| 예습 링크 | `/c/` 대화 + `/share/` 저장 | `/share/`만 |
| 퀴즈 | 업로드 | 다운로드 / 웹 풀이 |

**`/c/` 대화 URL은 만든 계정에서만 열린다.** 일반 사용자에게 내려보내면 안 되는
값이라 API 응답 자체에서 빼야 한다.

## Pre-Quiz는 웹 풀이 + apkg 둘 다

파이프라인이 `pre_items.final.json`을 만들고 그 다음에 `.apkg`를 만든다. 둘 다
올리면 되고 추가 생성 비용은 0이다.

웹 풀이의 값어치는 **채점 결과가 남는 데** 있다. 스킬의 설계 의도가 "틀린 문항이
그 강의의 청취 목표"이므로, 강의 상세 화면이 **"오늘 놓친 것 3개"**를 보여줄 수
있어야 의미가 산다. 그러려면 사용자별 응답 테이블이 하나 필요하고, 이것이 이
사이트에서 **유일하게 사용자별로 쓰이는 데이터**다. 나머지는 전부 읽기 전용이다.

Main-Quiz는 apkg만이다. SRS가 핵심이고 이미지 오클루전도 Anki 기능이다.

## 저작권은 전제다

작년 필기와 족보는 제3자 저작물이다. **로그인 필수, 짧은 수명의 서명 URL,
검색엔진 색인 차단.** 옵션이 아니다.

## 파이프라인 4개

| | 언제 | 하는 일 |
|---|---|---|
| 캘린더 | 학기 초 1회 | 시간표 JSON → 과목·강의 생성 |
| 족보 분할 | 학기 초 1회 | 과목 족보 PDF → 강의별 조각 + 필기 연결 |
| Main-Quiz | 매일 21:30 | 새 필기 감지 → `/quiz` → 업로드 |
| 예습 → Pre-Quiz | 강의 며칠 전 | 예습 대화 → `/prequiz` → 업로드 |

## 아직 구현되지 않은 것

**예습 링크 → Pre-Quiz 연결.** 지금 `/prequiz`는 PDF 하나만 먹는다.

1. 관리자 화면의 붙여넣기 칸에 `/share/` 링크를 저장 → `prequiz_pending`
2. 로컬 러너가 공개 share 페이지를 fetch → 대화 본문을 `preview.md`로
3. `/prequiz`가 그걸 세 번째 채널로 읽는다

`preview-rules.md`에 절이 하나 추가돼야 한다. **예습 대화 내용 자체가 출제
대상이고**, 그 대화를 이해했는지 확인하는 것이 1차 목적, 대화가 건너뛴 곳을
찌르는 것이 2차다. 의학적으로 중요하거나 암기가 필요한 것은 대화에 없어도 몇
문제 더 낸다.

share 페이지 구조가 바뀌면 파서가 깨질 수 있으므로 **실패 시 조용히 넘어가지
않고 멈춘다.**

## 설계가 바뀐 곳 (실물을 보고 뒤집힌 것)

### 족보의 출처 — 작년이 아니라 올해, 그보다 원본

처음엔 "작년 필기에만 족보가 붙어 있으니 작년 매칭이 Main-Quiz의 전제"라고
봤다. 틀렸다. **올해 필기에도 족보가 붙어 있고 그게 작년 것을 포함한다** —
필기자가 작년 족보를 그대로 옮겨 오기 때문이다(`260812_01` 실측: 작년 18문항이
올해 족보에 100% 포함).

그리고 그보다 나은 것이 따로 있다. `{과목}/족보/{연도}/`의 교실 공개 원본이다.

```
병리학 2026 족보   122쪽 · 텍스트 레이어 살아 있음(평균 1,646자/쪽) · OCR 불필요
                  p4~  "1  병리학 소개 – 과거, 현재, 미래" 로 강의별 분류
                  p78~ 실습 시험 블록
```

`studyez jokbo <과목>`이 이걸 강의별로 자른다. 그러면 족보 채널이 필기 속
캡처 이미지가 아니라 원본 PDF가 되고, 경계 판정이 필요 없어진다.

**다만 옵션이다.** 원본 족보가 없는 과목·연도가 있어서 필기 캡처본 경로를
남겨 뒀다. `prep.py --jokbo-pdf`를 주면 원본, 안 주면 캡처본이다.

작년 자료가 필요한 곳은 이제 **Pre-Quiz뿐**이다. 강의 전에 푸는 퀴즈라 올해
필기가 아직 없다.

### 강의 식별자 — `key`가 아니라 `uid`

처음엔 `날짜_교시`(`260813_03`)가 시스템 전체를 꿰는 키라고 봤다. 유일하지
않았다.

```
[260303_02] 역사 속의 감염병(김옥주, 이규원)
[260303_02] 질병사 관점에서 신종-재출현 감염병 (송진수)
[260303_02] 건강과 질병(박영수)
```

선택형 과목은 한 교시에 여러 강의가 동시에 열린다. 자세한 것은
[artifact-contract.md](artifact-contract.md)를 보라.

## 자료의 함정 (전부 실물에서 나왔다)

- **괄호는 두 가지다.** 숫자면 순번, 한글이면 교수. 같이 지우면
  `조직 재생 및 수복(1)`과 `(2)`가 한 강의로 뭉개진다
- **Synology 파일명 일부가 NFD**(자모 분해)다. 화면에는 똑같이 보이지만
  `[가-힣]` 정규식이 통째로 실패한다
- 같은 강의의 v1·v3이 공존하고, Synology 충돌 사본과 연도가 어긋난 파일이 섞인다
- **붙여넣은 이미지도 `Stamp`다.** 출제 이력 도장과 갈라야 한다 —
  `260813_03`에서 Stamp 69개 중 35개가 클립보드였다
- **색은 읽지 않는다.** 15편에서만 31종이 나왔고 필기자마다 규약이 다르다.
  뜻은 색이 아니라 `notes`의 글에 있다

## 배포는 자동이 아니다

`/quiz`는 Opus 5를 네 번 부르고 편당 45분이 걸린다. 족보 경계가 틀리면 뒤가
전부 어긋나고 `run.meta.json`에 `review_flagged`·`slides_unused`가 남는다.

**생성까지 자동, 배포는 사람이 본 뒤다.** 무인으로 두면 틀린 덱이 조용히
배포된다. 워처는 업로드하지 않는다.
