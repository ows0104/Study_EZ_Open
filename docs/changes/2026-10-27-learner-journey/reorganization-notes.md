# Intent/spec 분리 기록

2026-11-01 사용자 요청: “합의한 내용은 유지하면서 intent와 spec을 구분해서 다시 정리해줘. 미확정 제안은 따로 표시하고, 아스트라가 이어받을 인계 문서도 갱신해줘.”

## 현재 문서의 책임

| 문서 | 담을 내용 | 담지 않을 내용 |
|---|---|---|
| 사이트 intent | 문제·사용자 효과·목적·원칙·범위·성공 기준 | 구체 화면 구성·버튼·계산식·저장 계약 |
| learner-journey/spec | 합의한 여정·화면·동작·단위·상태 판정과 수용 시나리오 | 미확정 수치를 확정한 구현 기본값처럼 표시하기 |
| open-design | 제안·미정 계약·채택하지 않은 안, 각 항목에서 유지할 기존 합의 | 결정되지 않은 안을 구현하도록 지시하기 |
| plan | 변경 파일·순서·검사·복원·승인 범위 | intent 합의를 구현 승인으로 대체하기 |
| next-session-handoff | 현재 단계·읽기 순서·다음 작업·미실행·주의점 | 제품 요구사항을 별도 정본으로 중복 확정하기 |

사이트 intent 폴더의 spec은 현행 설계 정본으로 안내하는 문서다. learner-journey/intent는 작업 목적·사용자 발언 이력을 보존한다.
이 분리는 문서 편집이며 새 기능 결정·제품 구현·운영 변경·출시 승인이 아니다. state.json의 승인/검사 기록을 임의로 만들지 않았다.

## 미확정 사항의 이동

화면 색/배치·피드백 시간 → P01. 목표 분할·필수 방향·평가 버튼/척도·도움 판정 → P02.
U/D·H·보완량·유입 예측·FSRS → P03. 출처 대조표·충족 판정·교수 유형 처리 → P04.
자료 준비 조건·보정 시점 → P05. 하루 경계·비교 → P06. API/DB·저장/복원·기록 승계 → P07.
웹/CLI 실행 세부와 bridge 확장·자동 회수 미검증 → P08.
