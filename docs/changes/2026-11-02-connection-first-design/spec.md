# 연결 중심 학습과 구조·시험·임상 중요도 구분 — 설계

## 요구사항과 수용 기준
1. 개념도는 개념과 관계의 의미·근거·학습 위치를 담고, 문제는 그 관계 중 무엇을 직접 회상·판단하게 하는지 연결한다. 분류선·비교·인과·선행관계를 혼동하지 않는다.
2. 뼈대/가지/세부는 구조적 역할이다. 중요도의 근거는 강의 이해에 필요한 이유, 시험에서 묻는 연결과 깊이, 임상 판단·행동에 중요한 이유로 구분한다. 서로 배타적인 등급이나 고정 점수로 만들지 않는다. 중요한 세부와 기출 없는 뼈대 모두 가능하다.
3. 자료를 바탕으로 구조·문제를 만들고 중요도를 평가·보정한다. 중요도 평가를 위해 원본을 나중에만 읽거나 기존 문제 목록으로 전체 범위를 제한하지 않는다. 독립 포인트는 문제를 역으로 요약하지 않고 원본에서 추출한다.
4. 족보는 실제로 판단한 연결·회상 방향·조건·깊이와 오답이 바꾼 연결/조건을 근거 문항과 함께 분석한다. 관찰한 출제와 올해 예측을 구별한다. 모든 오답을 존재하지 않는 관계로만 해석하지 않는다.
5. 대조 시 발문에서 제공한 관계, 실제 시험한 관계, 해설에만 있는 관계, 누락된 관계를 구별한다. 제공/해설만으로 회상 충족을 인정하지 않는다. 원본과 대조해 트리·포인트 자체의 누락과 과분할도 확인한다.
6. 첫 학습은 필요한 뼈대를 먼저 만나고 세부로 확장한다. 모든 뼈대의 완벽한 숙련을 다음 진입 조건으로 삼거나 분류 나열을 일률적으로 강제하지 않는다. 중요도는 순서·반복을 조절하며 범위 안 세부의 첫 학습을 없애지 않는다.
7. 연결을 알려주는 안내와 도움 없는 회상 평가를 구별한다. 설계상 취약할 것으로 예상한 연결과 실제 응답으로 확인된 취약성을 구별한다. 한 연결의 정답으로 경로 전체를 숙련 처리하지 않는다.

| 수용 상황 | 기대 결과 |
|---|---|
| 강의 이해에 필요하지만 기출 근거가 없는 관계 | 필요한 뼈대 질문으로 포함하고 구조적 필요의 이유를 기록함 |
| 세부 관계가 기출에서 반복되거나 구체적 임상 판단에 중요함 | 세부라는 이유로 낮게 취급하지 않고 해당 중요성 근거를 표시함 |
| 발문이 A→B를 주고 B→C만 질문함 | A→B 회상은 미확인, B→C만 실제 시험 범위로 인정함 |
| 중요도가 낮은 범위 안 세부가 남음 | 첫 학습 경로와 잔여 범위에 남고 뼈대 완료로 전체 완료를 선언하지 않음 |
| 족보/임상 근거가 부족함 | 자료 부족을 표시하며 중요도 0이나 출제 가능성 0으로 단정하지 않음 |

## 책임·입출력 계약·오류 상태
제품 원칙의 정본은 site-intent/intent.md, 합의 동작은 learner-journey/spec.md, 수치·저장·판정의 미확정 계약은 open-design.md P02/P03/P04다. 실제 시범 채택·구현 계획은 root-learning-product의 C1/C3에서 구체화한다. 이 작업은 위 문서 사이의 의미를 연결하며 새 데이터 스키마나 자동 생성 실행을 정의하지 않는다.

## 호환성과 데이터 보존
기존 문항·ID·원본·개인 수정·제외·학습·검수 이력을 보존한다. 구조적 중요성을 이유로 기존 Must-Know/Core/Important/Optional을 자동 재분류하지 않는다. 첫 제품은 강의별 뿌리이며 장기적으로 세부까지 접한다는 요구를 첫 버전 전체 구현으로 확대하지 않는다. 뿌리 범위와 강의 전체 범위의 완료는 구별한다.

## Plan을 위한 로컬 검토 묶음 계약안

2026-11-02 Plan 요청에 따른 **구현 제안**이다. 위 합의된 목적과 구별하며 현재 데이터 형식이나 사용자에게 이미 제공되는 기능으로 설명하지 않는다. 기존 BANK/PLAN/REPORT를 교체하지 않고 별도 `learning-links` v1 묶음을 사용한다.

| 항목 | 첫 계약에 담을 내용 |
|---|---|
| 범위·판 | schema_version, lecture_id, scope_label, 명시적 포함/제외, 원본/은행/검토 입력의 지문, 실제 검토 범위·한계 |
| 출처 | source_id, 종류, 원본 지문, 물리 쪽 또는 문항 위치, 교수/연도(미상이면 미상). 같은 자료의 쪽 체계 구분 |
| 개념과 관계 | 안정적인 concept_id/relation_id, 관계 양끝·유형·성립 조건·근거. 구조적 역할과 실제 선행관계 구분 |
| 목표·방향 | target_id/direction_id, 회상할 관계·답 범위, 주어진 단서, 필수/선택/미정, 구조적 역할 뼈대/가지/세부와 선정 이유 |
| 문항 대응 | question_id와 정확한 문항 지문, target/direction 참조, 실제로 시험한 관계·발문이 제공한 관계·해설에만 있는 관계·검토 이유 |

| 포인트 대조 | 원본 독립 포인트 ID, 목표/방향 참조, covered/partial/gap/unknown/excluded와 이유, 누락·충돌·범위 밖 근거 |

실제 JSON 필드의 세부 분리는 위 의미를 보존해 구현하되 계약 버전을 고정하고 strict validation을 적용한다. 별도 점수·새 학습 등급·개인별 상태는 A에 넣지 않는다. 의미 판단이 담긴 구조화 입력은 허용된 작성/검토 경로가 만든 결과이며 로컬 도구가 원문에서 의미를 추론하지 않는다.

### 검증과 오류 처리

- 목표·방향·관계·포인트·문항 참조와 지문을 대조한다. 누락/중복 ID, 존재하지 않는 문항·원본, 검토 판과 다른 입력은 invalid다. 알 수 없는 관계를 자동 생성하거나 ID만 같다고 새 판으로 승계하지 않는다.
- covered에는 해당 필수 방향에서 직접 시험하는 문항 대응이 있어야 한다. provided/explanation만 있거나 필수 방향이 미정이면 충족으로 받지 않는다. partial은 확인한 부분과 미확인/누락 부분을 함께 남긴다. 코드 검증은 이런 모순을 찾으며 '직접 시험함'의 의학적 의미 자체를 인증하지 않는다.
- gap은 필요한 과제가 없음이 검토된 상태, unknown은 검토나 자료가 부족한 상태다. 빈 질문 목록만으로 둘을 혼동하지 않는다. excluded는 명시적 범위/제외 이유가 있어야 하며 중요도가 낮다는 이유만으로 세부를 제외하지 않는다.
- 모든 관계/포인트가 대조 결과에 등장하게 하되 목록 밖 누락 확인 범위를 별도로 기록한다. 기존 수신본의 독립성이 확인되지 않으면 그대로 표시하고 독립 추출 완료로 바꾸지 않는다.
- 계층 소속·선행은 유형별로 검증한다. 명시적 선수 관계의 순환은 오류로 보고하고 비교/상호작용의 순환을 무조건 잘못된 것으로 처리하지 않는다. 관계선 전부를 강제 학습 순서로 변환하지 않는다.
- 문항 지문은 표시/평가에 필요한 문항 내용 전체를 정규화해 계산하고 정책 버전을 남긴다. 최소한 발문·정답·선지/짝·해설·출처·기존 검수 상태 변경을 검출한다. 개인 수정본은 다른 판으로 취급하며 원본의 대응을 조용히 재사용하지 않는다.
- 중요성 근거의 부족은 invalid와 다르다. 세 범주를 모두 채우려고 외부 주장을 만들지 않는다. 교수 미상·다른 교수 자료·실제 출제 관찰·올해 예측은 구별한다. 족보 이미지 미확인은 남겨 둔다.
- 출력은 새 폴더에만 만들고 입력 불변을 확인한다. 구조 검증 성공과 의미 검토 완료는 별도 표시한다. 검토 입력이 reviewed라고 주장해도 도구가 새 검토 권한이나 공개 승인을 만들지 않는다. 학습자의 첫 학습·회상 상태는 생성하지 않는다.

### 첫 구현의 산출물

정규화한 `learning-links.json`, 입력과 도구/계약 판을 담은 `manifest.json`, 구조 검사 결과 `validation.json`, 사람이 읽을 `review.md`, 마지막 완료 표시를 만든다. 보고서는 강의/뿌리 등 실제 범위, 개념 위치와 연결된 문제, 세 종류 중요성 근거, 실제 시험/제공/해설, 부족한 질문·방향, 남은 세부·미검토를 보여준다. 이 완료 표시는 로컬 묶음 작성 완료이며 공개·의학 검수·학습 완료가 아니다.
