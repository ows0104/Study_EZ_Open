# 공개 강의 존재 목표 보강을 빠르게

## 사용자 지시 (2026-11-16)

- 「시간을 더 단축할 수는 없나?」에 이어 「이미 만들어진 게 있는데 그래도 오래걸리나?」라고 물었다.
- 내가 동시 상한·단계 줄이기·그대로의 세 가지 선택지를 드렸고, 사용자가 「상한 4편 + 보강 단계 줄이기」를 골랐다.

## 배경

- 공개된 Main-Quiz 30편 중 27편이 presuppose-only/1 보강 대상이다(운영 DB 읽기 전용 확인, 11-16).
- 2차 로컬 시범(`docs/changes/2026-11-16-existence-question-shape/release.md`)에서 한 편 보강에 약 28분 걸렸다.
  시간은 모델 호출이 앞 결과를 기다리며 줄지어 도는 데 들었고, 단계별로는 다음과 같다.

| 단계 | 시간 |
|---|---|
| 전제 판정(6묶음 동시) | 6분 |
| 정규화 → 범위 확인 → 지도 점검 | 6.5분 |
| add 2회와 각 범위 확인 | 6분 |
| 검토 → 수정 → 재검토 → 범위 재확인 | 6.5분 |
| 의학 검토·조립 | 1분 |

- 서버 `MAX_RUNNING = 2`(관리자 지시 2026-09-01)가 동시에 도는 편을 막는다. 27편 생성에 약 7시간이 걸린다(추정).

## 바꾸는 것

1. 동시 상한을 2편에서 4편으로 올린다. 서버 `server/app/jobs/queue.py` `MAX_RUNNING`과 러너 `runner/agent.py` `WORKERS`를 같이 바꾼다.
   편당 비용은 그대로이고 벽시계만 줄어든다. 대신 Codex 세션이 최대 16개까지 겹친다.
2. 보강 경로(`quizbank/connection_presuppose.py`):
   - add를 1라운드로 줄인다. 존재 목표마다 문항이 하나이고(`pre.written_for`), 2차 시범의 둘째 라운드는 엉뚱한 문항 4개를 썼다. 그중 2개는 과제가 되지 못했다.
   - 범위 확인과 지도 점검을 동시에 돌린다. 둘 다 늘어난 지도만 읽는다.

## 바꾸지 않는 것

- 검토 → 수정 → 재검토. 재검토는 수정이 문항을 더 나쁘게 만들었을 때 되돌리는 근거다.
  2차 시범에서 수정은 이미 한 라운드만 돌았다.
- 새 출제(root-generation/4) 경로의 단계.
