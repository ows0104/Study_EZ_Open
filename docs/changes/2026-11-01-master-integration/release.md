# 남은 검사 수정 및 master 통합 — 배포 준비

## 코드 리뷰·검증 결과

원격 master `0fcdce3d`와 세션 작업 `cf03cbc08`를 병합한다. 양쪽 이력을 보존하고 force push는 하지 않는다.
원격 최신 MD 자동 회수, 학습 이력 보관·동일 문항 복원, 관리자 이용 기록 집계는 현재 코드와 대조했다.
모듈로 분리된 bank API/runner 함수와 원격 단일 파일의 함수 AST를 비교해 원격 기능 누락이 없음을 확인했다.

과거 원격 병합으로 제거되던 검수 재사용·출처 연결 복구·실행 버전 기록·예습 출처 이미지·
시간표 범위 제한·서버 링크 보존·개인 매칭·학습 기록 보호와 해당 회귀 검사를 유지한다.
원격의 새 4칸 cloze 서버 검사도 함께 보존한다. `test_route_contract`의 중복 목록만 제거한다.

변경은 다음과 같다.

- 개발 검사 기록의 읽기/원자 교체에 일시적인 Windows PermissionError가 생기면 최대 5초만 재시도한다.
  영구 거절·깨진 JSON·실제 설계 변경은 계속 실패한다. 동시 검사의 기록 누락도 검사한다.
- 화면의 실제 문장 배치·명시적 들여쓰기·관리자 전용 대화 링크 정책을 웹 테스트에 반영한다.
- 실제 문제 메뉴를 열고 개인 문항 추가를 검사하며, 공용 편집 검사는 초기 학습 요청의 완료 순서와
  무관하게 관리자 API 경계를 검사한다. 모든 정답·실패 재시도·학습 평가 검증은 유지한다.
- 패키지 계약 테스트는 파일을 명시적으로 UTF-8로 읽는다. 빠져 있던 requests는 로컬 검사 환경에 설치했다.

검사 로그와 최종 결과는 state.json의 현재 source_hash/plan_hash에 연결했다.
Python 1,500개, 서버 전체 86개 파일, 웹·확장 185개, Chrome 동작 32개 및 웹 타입 검사·빌드가
모두 통과했다. 최종 네 검사의 source_hash는
`13e273acceea86bb29e5131ee786a2e852ef008bd52268f9fbce1cec2c2dc7af`로 일치한다.
초기 실패와 소스 변경 도중 완료되어 stale 처리된 검사도 지우지 않는다.
공유 bank-prompt.json을 쓰는 웹 빌드와 Python 패키지 검사는 순서대로 실행한다.

## 배포 대상 버전·순서·데이터 변경

사용자의 현재 요청에 따라 병합 커밋을 GitHub origin/master에 일반 push한다.
감염과 면역 원본 PDF, 관리용 JSON·이미지 및 개인 자료는 기존 Git 제외 정책대로 로컬에 보존한다.
이 작업은 운영 DB 변경이나 별도 Cloud Run 배포를 실행하지 않는다.
원격 최신 버전을 다시 fetch해 통합본의 조상인지 확인하고, 새 변경이 생기면 보존해 통합한다.

통합 커밋 `a6f7aaa1`을 master와 작업 브랜치에 일반 push한 뒤 원격 일치를 확인했다.
master 체크아웃은 저장소의 기존 `.gitattributes`에 따라 혼재하던 CRLF를 LF로 정규화했다.
코드·계획 내용은 같지만 바이트 지문이 달라, 이 체크아웃에서 네 검사와 리뷰 근거를 다시 기록한다.
`web/public/bank-prompt.json`도 LF 정본의 실제 해시와 원문으로 다시 생성했으며 별도 내용 변경은 없다.
검증 기록과 이 생성 파일을 후속 커밋으로 반영하고 최종 원격 일치를 재확인한다.

## 배포 후 확인·롤백·필요한 사람 승인

현재 사용자 발언은 실패 수정·원격 master 통합·commit/push를 명시적으로 승인했다.
푸시 후 원격 master와 로컬 HEAD의 일치, 양쪽 부모의 조상 관계, 미해결 충돌 및 작업 폴더 상태를 확인한다.
되돌림이 필요하면 게시된 이력을 삭제하지 않고 후속 revert 커밋을 검토한다.
현재 병합본은 위험한 일괄 복원 대신 검토한 기능 묶음별로 보존했으며, 중간 병합본과 양쪽 차이는
`tmp/master-merge-checkpoint`에 해시 검증된 로컬 사본으로 보관했다.
