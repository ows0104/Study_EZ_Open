# Main-Quiz 새 출제 구조 root-generation/3

## 문제와 사용자 효과

지금 생성기 `root-generation/2`의 검토·보완 루프는 고치는 만큼 새로 망가뜨린다. 사슬알균 26110901 generation-4에서 이렇게 나타났다(`docs/changes/2026-11-09-main-quiz-second-lecture/release.md`).

- **보완이 기존 문항을 망가뜨린다.** 빈 목표를 메우려고 문제은행 전체를 다시 쓰면서 멀쩡하던 문항을 바꿨다(Q097·Q089). 검토②·③의 wrong 9문항 중 4개가 직전 보완이 바꾸거나 새로 만든 문항이다.
- **같은 글을 다시 판정하면 결과가 흔들린다.** 매 라운드 검토자가 전 문항을 처음부터 새로 판정했다. 글자가 같아도 판정이 바뀌었다(Q013·Q037·Q042·Q066·Q091).
- **보완 상한에 막혀 끝난다.** 보완 3회를 다 쓰고도 고치지 못한 지적 67개(빈 목표 26)와 정답 오류 3문항이 남은 채 끝났다.

관리자가 원하는 효과는 다음과 같다.
- 출제가 빈 곳만 메우며 앞으로만 나아간다.
- 이미 통과한 것은 다시 흔들리지 않는다.
- 모델에는 그 단계에 필요한 것만 준다. 2026-11-10 사용자: "LLM에게 괜히 부하를 줄 필요는 없을 거 같아서".

## 범위와 성공 기준

**사용자 결정 (2026-11-09~10, 이 세션)**
- 구조(사용자 제안): 0 준비 → 1 지도·포인트&중요도·문제 독립 병렬 추출 → 2 지도 관계 문제 + 문항이 포인트를 커버하는지 확인 → 3 커버 안 된 포인트만 출제 → 4 검토·보완 → 5 의학 검토
- 의학 검토는 이미 `medical-final/1`로 master에 들어갔다(`docs/changes/2026-11-10-medical-final/`).
  - 원본끼리 충돌(강의↔족보, 본문↔손글씨)은 판정한다.
  - 그 밖은 "현재 의학:" 해설만 붙인다.
  - 맨 끝에 한 번 하고, 과제에서 문항을 빼지 않는다.
- 3단계 반복 횟수, 포인트 점검 지적 처리, 1c 독립 출제는 아래 「근거·미정 사항」의 기본안을 쓴다. 사용자는 2026-11-10 「spec 써줘」로 기본안을 받았다.

**범위**
- 새 생성 판 `root-generation/3`을 `root-generation/2` 옆에 따로 만든다.
- /2와 그 실행 기록·재개·결과 검증은 바꾸지 않는다.

**성공 기준** — 사슬알균 시범에서 아래가 모두 맞으면 성공이다.
1. 기존 문항이 지적 없이 바뀐 횟수: 0. 코드가 거절한다.
2. 같은 글의 문항을 다시 판정한 횟수: 0. 판정을 기록하고 재사용한다.
3. 단계마다 모델 입력에서 쓰지 않는 칸: 0. spec의 입력 표대로만 넘긴다.
4. 준비된 목표가 generation-4(79/119 ready)보다 많거나, 적으면 왜 적은지 단계별 기록으로 설명할 수 있다.

## 근거·미정 사항

**시험 근거**: 추가 전용 시험(`docs/changes/2026-11-10-add-only-trial/release.md`, PR #67)

| 확인한 것 | 결과 |
|---|---|
| 추가 전용 출제 | 기존 102문항 변경 0 |
| 지도 변경 | 프롬프트로 막지 못했다. 모델이 목표 8개에 recall_units를 붙였다 |
| 149문항 전체 재확인 | 커버 판정을 포기했다(119개 전부 unknown) |
| 좁힌 재확인(목표 63 + 문항 47) | 5.6분 만에 판정했다. confirmed 21 · missing 19 · unknown 23 |
| 같은 47문항의 판정 | 전체 재확인 wrong 1, 좁힌 재확인 wrong 6 |

**좁힌 재확인의 unknown 23개 진단** (2026-11-10, 기록만 읽음)
- 15개: 그 목표를 커버하는 문항이 doubt를 받아 목표까지 unknown이 됐다(`generation_v2._compile_assessment`의 unknown 규칙). 커버 판정과 문항 품질이 묶여 있다.
- 5개: 관계 판정이 unknown이었다.
- 4개: 위 규칙에 걸리지 않는 기타다. recall_units 묶음 판정으로 보이며, 아직 확인하지 않았다.

**입력 실측** (`.native/<stage>/work/input.json`)

| 단계 | 크기 | 비고 |
|---|---|---|
| 커버 확인 | 76만 자 | |
| 추가 출제 | 160만 자 | 원본 대조 전체 59만 자, 이전 판 중복 31만 자, 원본 포인트 24만 자, 원본 지도 10만 자 |
| 검토 | — | 원본 46쪽 그림이 매번 전부 붙는다 |

**기본안** (사용자에게 보인 그대로, 시범 결과로 다시 본다)
- 3단계(추가 출제 + 좁힌 재확인)는 2번까지 돈다. 남은 목표는 「준비 안 됨」으로 표시한다.
- 포인트 점검 뒤에도 지적이 남으면 멈추지 않는다. 그 포인트의 목표에 표시를 남긴다.
- 1c 문제은행은 포인트를 보지 않는다. 기본인 웹 출제도 이 방식이다.

**미정**
- 4단계 묶음 크기: 47문항은 성공했고 149문항은 실패했다. 30~50문항에서 시작해 실측으로 정한다.
- 근거 쪽만 주면 다른 쪽의 관련 내용을 놓칠 수 있다. 시범에서 확인한다.
