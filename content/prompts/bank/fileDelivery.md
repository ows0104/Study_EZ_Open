- 이번 강의의 결과는 실제 UTF-8 Markdown 파일 `study-ez-{{run_id}}-bank.md` 하나로 제공한다. 파일 작성 도구를 사용해 전체 확정본을 저장한다. 채팅 본문이나 코드블록을 파일이라고 부르거나, 만들지 않은 파일의 링크를 지어내지 않는다. 파일 작성 도구가 없으면 파일 생성이 불가능하다고 알리고 완료로 처리하지 않는다.
- 도구 호출 한 번에 전부 쓸 필요는 없다. 같은 확정본을 여러 차례 나누어 파일에 기록할 수 있으나, 최종 파일 하나에는 모든 문항·선지·정답·해설·근거·출처 충돌이 들어가야 한다. 파일 크기를 줄이려고 문항이나 필요한 회상 방향을 생략하지 않는다.
- 파일의 첫 줄은 `<!-- STUDYEZ_BANK_FILE {JSON} -->`이다. JSON에는 `schema_version: 1`, `subject: "{{subject}}"`, `run_id: "{{run_id}}"`, `prompt_version: "{{prompt_version}}"`, `question_count: 실제 전체 문항 수`, `question_ids: 확정본의 모든 문항 ID를 순서대로 담은 문자열 배열`, `conflict_ids: 실제 출처 충돌 ID의 순서대로 된 문자열 배열`을 넣는다. 충돌이 없으면 conflict_ids는 []다. 설명용 자리표시를 그대로 쓰지 말고 유효한 한 줄 JSON을 완성한다.
- 그 아래에 6.1–6.3 형식의 문항 블록과 필요한 출처 충돌 기록을 전부 쓴다. 문항 ID는 Q001부터 순서대로 이어진다. 파일 마지막 줄에만 STUDYEZ_BANK_COMPLETE를 쓴다. 채팅 본문에 이 완료 표식을 대신 쓰지 않는다.
- 작성 뒤 반드시 실제 저장 파일을 도구로 다시 읽고 확정본과 대조한다. 헤더의 과목·강의 ID·버전, question_count와 question_ids의 순서·누락·중복, 문항별 필수 필드와 정답 JSON, 실제 선지 ID와 정답 참조, 모든 매칭의 왼쪽 항목과 정답 짝, 순서 항목의 완전한 순열, cloze 빈칸, 충돌 ID 정의·참조, 마지막 완료 표식을 확인한다. 문항 내용·정답·해당 강의의 지정 범위·기초 연결 회상도 전체 원본과 대조해 검수한 확정본이어야 한다. 파일이 존재한다는 사실만으로 검증 완료라고 하지 않는다.
- 오류나 누락이 있으면 파일을 고친 뒤 다시 읽어 확인한다. 전체가 완성되고 대조가 끝난 뒤에만 응답 본문에는 전체 문항 수와 실제 `.md` 다운로드 링크를 짧게 제공한다. 전체 문제은행을 채팅 본문에 다시 출력하지 않는다. 외부 수집기는 파일을 실제로 읽고 별도의 구조 검사·원본·정답 검수를 수행한다.
