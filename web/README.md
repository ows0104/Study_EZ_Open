# Spotter — 땡시 연습

과목 다섯이 한 사이트다. **전부 로그인해야 열린다.**

| | 문항 | 사진 | 화면 |
|---|---|---|---|
| `parasitology` 기생충학 | 6,425 | 555 | 이 저장소의 `web/` |
| `exam1` Extremities | 1,142 | 147 | 배포 저장소에만 |
| `trunk` Trunk | 452 | 433 | 〃 |
| `head-neck` Head & Neck | 722 | 722 | 〃 |
| `neuro` Neuroanatomy | 325 | 53 | 〃 |

**문항 DB도 사진도 저장소에 없다.** 전부 R2 비공개 버킷(`spotter/<과목>/`)에
있고, 로그인한 사람에게만 서명 URL로 나간다. 배포 저장소에는 화면만 남는다.

```
web/                이 저장소가 들고 있는 것
  index.html        기생충학 화면
  app.js            문항 조립·풀이·채점·신고
  gate.js           로그인 문 — 다섯 과목이 같이 쓴다
  auth.js           Supabase GoTrue REST
  session.js        세션 저장소 (Study_EZ와 나눠 쓰는 사본)
  config.js         배포마다 다른 값 다섯

build/              배포되지 않는다. R2로 올릴 원본이다
  quiz_db.json · images/
```

## 문제 화면은 두 단이다

**왼쪽 사진, 오른쪽 보기.** 세로로 쌓으면 사진과 보기를 같이 볼 수 없어 눈이
오르내리는데, 시간을 재는 화면에서 그건 그대로 손해다. 보기는 사진 옆 **가운데**에
선다 — 위로 붙이면 사진 절반 높이만큼 빈자리가 남는다.

문제를 푸는 동안만 `.wrap`이 1240px로 넓어진다(`body:has(#quiz:not(.hidden))`).
980px에서 두 단을 세우면 사진이 원본보다 작게 줄어드는데, **알아보라고 내는 사진을
줄이는 것은 문제를 바꾸는 일이다.** 시작·결과 화면은 글이라 980px가 읽기 좋다.

760px 아래에서는 다시 한 줄로 쌓는다. 그 폭에서 나란히 세워봐야 둘 다 좁아질 뿐이다.
해설은 두 단 아래 전체 폭에 깔린다 — 보기 칸에 넣으면 줄이 좁아 읽기 나쁘다.

신고 버튼은 카드 아래에 **빨간색**으로 홀로 선다. 신고는 눌러 주는 사람이 있어야
쌓이는데 조용한 회색이면 있는 줄도 모른다. 이미 신고한 문항은 초록으로 바뀐다 —
빨강이 "누르세요"라면 초록은 "받았습니다"이고, 둘이 같은 색이면 구별이 안 된다.

## 사진 출처를 화면에 띄운다

사진 밑에 `출처: 실제실습본 p.56  practical/056_4.png`가 붙는다. 확대 화면과
결과 다시보기에도 나오고, 신고에도 함께 실려 간다. 흐리거나 잘못 잘린 사진을
만났을 때 원본을 짚을 자리가 없으면 신고가 "3번 사진이 이상함"에서 멈추기 때문이다.

출처는 문항마다가 아니라 **`meta.images`에 사진마다 한 번** 들어 있다. 같은 문장이
문항 수만큼 되풀이되지 않게 하려는 것이다. 선명도가 12 미만이면 "흐린 사진"도 같이
적는다 — 안 보이는 것이 내 눈 탓인지 사진 탓인지 가르라고.

## 시계는 문항이 바뀔 때만 되감는다

`render()`는 답을 고를 때도 불린다. 거기서 무조건 `startTimer()`를 부르면 **답을
누르는 것이 곧 시간 연장**이 된다. `S.timedFor`가 지금 시계가 어느 문항의 것인지
들고 있고, 그게 바뀔 때만 되감는다.

## 문

**한 번 로그인하면 다섯 과목을 자유롭게 오간다.** 세션이
`Domain=.studyez.kr` 쿠키에 있어서 같은 도메인 아래 형제가 다 읽고, Study_EZ
까지 같이 열린다. 어느 과목으로 처음 들어오든 거기서 로그인하면 된다.

`gate.js` 하나가 그 일을 한다 — 로그인 화면, 토큰 갱신, API 호출, 사진 서명.
쓰는 쪽은 한 줄이다.

```js
GATE.start('exam1', async (db) => { /* 화면을 세운다 */ });
```

콜백은 로그인이 끝난 뒤에만 불린다. 그 전에는 문항 DB를 아예 안 받아 온다.
과목을 안 주면(`null`) 로그인만 확인한다 — 과목 고르는 허브가 그렇게 쓴다.

승인은 필요 없다. 서버의 `APP_POLICY`에서 땡시가 `auto`이기 때문이고,
Study_EZ가 `manual`인 것과 갈리는 지점이다
(`Study_EZ_Open/docs/sibling-apps.md`).

## 서버

Study_EZ와 같은 서버·같은 계정을 쓴다. 경로는 `/api/spotter/` 아래다.

| | |
|---|---|
| `GET /subjects/{과목}/db` | 문항 DB. 서버가 gzip하고 ETag를 붙인다 |
| `POST /subjects/{과목}/images/sign` | 그 판이 쓸 사진의 서명 URL |
| `GET /state` · `POST /finish` | 기록과 오답노트 (기생충학만 쓴다) |
| `POST /reports` | 문항 신고 (기생충학만 쓴다) |
| `GET /admin/reports` | 신고함 (관리자) |

과목 없는 옛 주소(`/db`, `/images/sign`)는 기생충학을 가리키는 별칭으로
남아 있다. 과목이 하나뿐이던 시절에 열어 둔 탭을 위한 것이고, 한 학기쯤
지나면 떼면 된다.

## 설정

`config.js` 다섯을 채운다. **배포 저장소의 것이 사실이다** —
`deploy_pages.py`는 이 파일만은 안 덮는다.

```js
apiBase          https://studyez-api-xxxxxxxx.asia-northeast3.run.app
supabaseUrl      https://xxxxxxxx.supabase.co
supabaseAnonKey  (공개되어도 되는 값이다)
sessionDomain    studyez.kr  ← Study_EZ의 VITE_SESSION_DOMAIN과 같아야 한다
localTestToken   (배포에서는 반드시 비운다)
```

## 고치고 올리기

```bash
# ① 기생충학 문항을 다시 굽는다
uv run --python 3.13 --with pillow python scripts/build_web.py

# ② 과목 하나를 R2로 올린다 (기생충학은 build/, 나머지는 배포 저장소의 과목 폴더)
uv run --python 3.13 --with requests python scripts/upload_subject.py build --subject parasitology
uv run --python 3.13 --with requests python scripts/upload_subject.py ../Spotter_Quiz_pages/exam1

# ③ 화면을 배포 저장소에 맞춘다 (해부학 넷에 로그인 문을 달아 준다)
uv run --python 3.13 python scripts/deploy_pages.py ../Spotter_Quiz_pages
```

그리고 배포 저장소에서 커밋·push 하면 Cloudflare Pages가 빌드한다.

올리는 쪽은 R2 키를 안 든다. 서버가 서명한 PUT 주소를 받아서 바이트만 붓고,
인증은 `RUNNER_TOKEN`(없으면 관리자 로그인)으로 한다. 안 바뀐 사진은 ETag를
견줘서 건너뛴다.

**해부학 넷의 index.html은 이 저장소에 원본이 없다.** 각자 완성된 한 파일짜리
앱이고 배포 저장소에만 있어서, `gate_subject.py`가 문이 되는 자리만 갈아
끼운다. 과목 앱을 새로 구우면 그 표시가 사라지므로 ③을 다시 돌려야 한다.

## 로컬에서 보기

개발 서버는 저장소 루트를 연다.

```bash
uv run --python 3.13 python -m http.server 8811
```

<http://localhost:8811/web/> 로 들어간다. `config.js`의 `apiBase`가 비어 있으면
로그인 없이 `build/`를 바로 읽는 갈래로 떨어진다 — **localhost에서만이다.**

서버까지 붙여 보려면 Supabase 없이도 된다. 서버를 `ENVIRONMENT=local-test`로
띄우고 `config.js`에 `apiBase`와 `localTestToken: 'local-test-token'`을 넣는다.

## 기능

| | 땡시 모드 | 공부 모드 |
|---|---|---|
| 제한 시간 | 있음 (기본 30초, 다 되면 자동으로 다음 문항) | 없음 |
| 정답 공개 | 채점할 때 한 번에 | 고르는 즉시 |
| 해설 | 채점 후 다시보기에서 | 고르는 즉시 |

- **문항 조립은 브라우저에서** 한다. 서버가 넘기는 것은 완성된 후보 6,461개고,
  거기서 족보 출제빈도(`weight`)로 가중 표집해 세트를 만든다.
  같은 표본이 두 번 나오지 않고, 한 종은 최대 두 문항까지만 나온다.
  사진이 다르면 별개 문항이라 같은 표본도 매번 다른 사진·다른 보기로 나온다.
- **보기 순서는 풀 때마다 새로 섞인다.** 위치를 외우는 걸 막는다.
- **문항 순서** — '시험처럼'은 충란을 앞쪽에 몰고 나머지를 섞는다.
  족보 8개년을 보면 충란은 예외 없이 앞에 몰리지만 분류군 순으로 정렬되지는 않는다.
  '완전 랜덤'을 고르면 충란도 흩어진다.
- **시드 번호**를 넣으면 같은 세트가 다시 나온다. 친구와 같은 문제로 풀 때 쓴다.
- **범위 고르기 — 내용이 먼저다.** 시작 화면 맨 위가 **분류군**(선충·흡충·조충·
  원충·말라리아·의용곤충)과 **표본**(충란·충체·조직·혈액도말·육안)이다. 그날
  배운 데까지만 풀 때 실제로 쓰는 것이 이 둘이라서 위에 뒀다.
  묻는 방식(감염경로·치료·지시 구조물 …)은 아래에 접어 둔다 — 열두 개가 이름표
  없이 깔려 있으면 무엇을 고르는 칸인지부터 안 읽힌다.
  좁히면 **비율을 그 범위 안에서 다시 잡는다.** 흡충만 골랐는데 선충 몫 29%를
  그대로 두면 그 자리가 빈 채 남아 40문항을 시켜도 서른 몇 개만 나온다.
  범위 아래에 **지금 몇 문항인지**를 적어 둔다. 같은 표본이 한 판에 두 번 안
  나오므로 천장은 문항 수가 아니라 **표본 수**이고, 40문항이 안 나오는 조합은
  시작을 누르기 전에 그 사실을 알린다.
- **오답노트** — 틀린 문항이 계정에 쌓이고 "오답만 다시 풀기"로 복습한다.
  다음에 맞히면 목록에서 빠진다. 기기가 바뀌어도 따라온다.
- **문항 신고** — 문항이 자동 생성이라 오류가 남는다. 푸는 중에도, 다시보기에서도
  그 자리에서 신고할 수 있고 **신고하는 동안은 시계가 멈춘다.**
  한 사람이 한 문항에 한 줄이며, 다시 신고하면 그 줄을 고쳐 쓴다.
- **신고함** — 관리자에게만 보인다. 시각순이 아니라 **문항으로 묶어서** 낸다.
  한 사람이 잘못 읽은 것과 열 명이 같은 자리에서 멈춘 것은 다른 일이다.
- 사진은 클릭하면 확대된다. 키보드 `1`~`4`로 답을 고르고 `Enter`로 넘어간다.
- 다크 모드는 시스템 설정을 따라간다.

## 저장되는 것

기생충학은 계정에 남는다(Supabase Postgres). **해부학 넷은 아직 아니다** —
기록·오답노트·신고는 기생충학 화면에만 있고, 해부학은 로그인 문만 지난다.

| 표 | 내용 |
|---|---|
| `spotter_record` | 최근 기록 30개 (시각·모드·점수) |
| `spotter_wrong` | 아직 못 맞힌 문항 id |
| `spotter_report` | 문항 신고 (신고 당시의 문면을 함께 뜬다) |

세션은 `Domain=.studyez.kr` 쿠키에 있다(형제 앱과 공유). 쿠키가 거부되는
자리에서는 `session.js`가 그것을 알아채고 `localStorage`로 떨어진다 — 공유는
잃지만 로그인은 된다.

그 밖의 `localStorage`는 **로그인 전과 서버에 못 닿을 때만** 쓴다. 로그인
없이 쓰다가 계정을 만들면 그동안의 오답이 한 번 계정으로 합쳐진다(더하기만
한다 — 빼기까지 하면 한 기기의 오래된 목록이 다른 기기에서 맞힌 것을 되살린다).
