# Study_EZ 설계

의대생 공부를 돕는 사이트. 이 문서는 **정해진 것**과 **왜 그렇게 정했는지**를
담는다. 절차는 `README.md`, 출제 규칙은 `quizgen/prompts/`와
`quizgen/prequiz/prompts/`에 있다. 그 규칙이 어디서 왔는지는 [interview.md](interview.md)다.

## 한 줄 요지

**서버는 아무것도 만들지 않는다. 만드는 건 전부 로컬, 서버는 배급만 한다.**

만드는 사람이 관리자 한 명이고 결과물이 모두에게 똑같다. 그래서 작업 큐도,
사용자별 생성도, 과금도 없다. 참고한 meddeck-local-app은 사용자마다 서버에서
카드를 생성하느라 그 전부가 필요했고, 서버 파이썬 267KB 중 165KB(62%)가 그것
때문이었다.

전체가 지금 어떻게 도는지는 [README 「한 장 그림」](../README.md#한-장-그림)에 있다.
이 문서는 그 모양을 **왜** 골랐는지를 적는다.

## 스택

```
Supabase (Auth + Postgres)   로그인. 서버 코드 3KB, 비번·재설정 메일을 안 만든다
Cloudflare R2                PDF·apkg. 로그인한 사람에게만 서명 URL로
FastAPI 1개 (Cloud Run)      읽기 API + 관리자 업로드. 워커 없음
정적 프론트 (Vite + React)    화면 3개. Next.js RSC까지 갈 이유가 없다
```

운영 지점 **3개**다. meddeck은 여기에 Cloud Tasks, Cloud Scheduler, Secret
Manager, PortOne, Cloudflare Workers가 더 있었다.

인증을 자체 구현하지 않는 이유는 그게 더 무겁기 때문이다. 비번 해시·재설정
메일·세션 회전을 직접 짜면 `auth.py` 3KB가 수십 KB가 된다. 무거웠던 건 인증이
아니라 작업 큐와 과금이었고, 그건 통째로 없어졌다.

**이 스택은 잠긴 것이 아니다.** 더 단순하거나 싸거나 운영 지점이 적은 대안이
있으면 제시하라. 지키려는 것은 특정 제품이 아니라 **운영 지점을 적게, 서버는
얇게**라는 두 가지다.

## 화면

| 경로 | 화면 |
|---|---|
| `/` | 캘린더 (월/주). 강의 칩에 자료·퀴즈 유무 점 |
| `/lectures/{run_id}` | 강의 상세 — 새 창. 작년 강의록 · 예습 열기 · Pre-Quiz · 올해 강의록 · Main-Quiz |
| `/prequiz/{run_id}` | Pre-Quiz 웹 풀이 — 전용 창. 덱은 여기서 받는 것이 아니라 위 화면과 캘린더에서 받는다 |

흰 배경 · 무채색 · 강조색 하나.

## 계정

관리자냐 아니냐, **불리언 하나**다. 콘텐츠가 모두에게 동일하므로 meddeck의
cohort 승인·소유권 검사가 필요 없다.

| | 관리자 | 일반 |
|---|---|---|
| 캘린더·PDF | 업로드 | 보기 |
| 예습 링크 | `/c/` 대화 + `/share/` 저장 | `/share/` (당분간) |
| 퀴즈 | 업로드 | 다운로드 |

### 예습 링크는 `/share/`가 기본이고 `/c/`가 목표다

**퀴즈를 만드는 기본 링크는 `/share/`다.** 공유본이라 안정적이고, 로컬 러너가
그걸 받아 `preview.md`를 만든다.

`/c/` 대화 링크를 지금 일반 사용자에게 안 내보내는 것은 **원칙이 아니라 그 링크가
아직 불안정하기 때문**이다. **최종적으로는 학생에게도 `/c/`를 준다** — 대화를
직접 열어 이어서 질문할 수 있는 게 예습의 값어치이기 때문이다. 안정화되면 열면
되고, 그때 API 응답과 화면을 함께 바꾼다.

## Main-Quiz는 apkg로 준다. Pre-Quiz는 웹이 먼저다

Main-Quiz는 `.apkg` 다운로드뿐이다. SRS와 이미지 오클루전이 Anki 기능이고, 학생이
이미 쓰는 도구다.

**Pre-Quiz는 2026-08-23에 뒤집었다(관리자 지시).** 누르면 웹 풀이(`/prequiz/…`)가
전용 창으로 열리고, 덱은 그 옆의 내려받기 버튼으로 내려갔다. 강의 직전 한 번
훑는 것이 예습 덱의 쓰임이라 여는 데 Anki가 끼는 것이 걸림돌이고, 반복해서 돌릴
사람은 그 버튼에서 받는다.

예습 덱은 그래서 `pre_items.final.json`도 함께 낸다(추가 비용 0). **채점은 서버가
아니라 본인이 한다** — 답을 펴 보고 「알고 있었다 / 몰랐다」를 찍는다. Anki가 하는
방식이고, 이 덱이 실제로 쓰이는 방식이다.

한동안 이 자리가 5지선다에 서버 채점이었다. 파이프라인이 pdf2anki(지금의 `quizgen/`)로 갈리면서 카드가
**자유회상**이 되었고, 답이 여러 줄 산문일 때가 많아 문자열로 재면 전원이 틀린다.
별칭 목록을 파싱해도 「거의 맞았다」를 가르지 못한다. 그래서 판정하는 자리를 사람에게
넘겼다 — `quiz_attempt.correct`는 이제 **서버의 판정이 아니라 본인의 판정**이고,
화면이 그것을 서버 판정처럼 그리면 안 된다.

**그래도 답은 문항과 함께 안 내려보낸다.** 편 사람만 `reveal`로 받아 가고, 그래야
그 기록이 무언가를 뜻한다.

**그림 카드는 웹에 안 실린다.** 앞면이 이미지라 텍스트만으로는 물음이 성립하지
않는다(`이 조직은 어느 장기이며…`). apkg에는 그대로 있고, 몇 장이 빠졌는지는
`pre_run.meta.json`의 `web_excluded`가 든다.

## 저작권

작년 필기와 족보는 제3자 저작물이다. **로그인 필수.** 아무나 열 수 있는 자리에
두지 않는다.

## 파이프라인 4개

| | 언제 | 하는 일 |
|---|---|---|
| 캘린더 | 학기 초 1회 | 시간표 JSON → 과목·강의 생성 |
| 족보 분할 | 학기 초 1회 | 과목 족보 PDF → 강의별 조각 + 필기 연결 |
| Main-Quiz | 올해 필기가 처음 올라올 때 | 새 필기 감지 → 서버 일감 → `quizgen.run` → 업로드 |
| 예습 → Pre-Quiz | 예습 링크가 바뀔 때 | 예습 대화 → 서버 일감 → `quizgen.prequiz.run` → 업로드 |

뒤의 둘은 종일 떠 있는 러너(`python -m runner agent`)가 서버의 일감을 집어 가서
만든다. 시각에 맞춰 도는 크론은 2026-08-23 에 걷어냈다 — 왜인지는 README 「재료가
도착하면 만들기 시작한다」.

## 예습 링크 → Pre-Quiz

| | 무엇 | 상태 |
|---|---|---|
| 1 | 관리자 화면의 `/share/` 링크 입력 칸 | 됨 |
| 2 | 공유 페이지 → `preview.md` (`runner preview`) | 실물 링크로 검증됨 |
| 3 | `quizgen/prequiz/prompts/must.md` — 무엇을 물을지 | 됨 |
| 4 | `quizgen.prequiz.run --note preview.md` 가 세 번째 채널로 읽기 | 됨 |

**예습 대화가 정리해 준 것을 그대로 물어도 된다.** Pre-Quiz는 수업 전에 알고
들어가야 하는 것을 실제로 들고 있는지 보는 퀴즈다. 대화가 표로 묶어 준 지점일수록
좋은 문항 자리다 — 학생이 그걸 들고 강의에 들어가야 하기 때문이다.

대화가 건너뛴 곳을 찌르는 것은 2차이고, 의학적으로 중요하거나 암기가 필요한 것은
대화에 없어도 몇 문항 더 낸다.

`source_type`을 새로 만들지 않는다. 예습 대화는 채널이 아니라 **렌즈**다 — 무엇을
물을지 고르는 데 쓰고 근거는 여전히 강의록 슬라이드다.

share 페이지는 남의 서비스라 구조가 언제든 바뀐다. **실패 시 조용히 넘어가지 않고
멈춘다** — 글이 400자 미만이거나 사람·AI 발화가 둘 다 없으면 예외로 세운다.
빈 `preview.md`를 쓰고 넘어가면 예습 없이 만든 퀴즈가 겉으로는 멀쩡해 보인다.

## 설계가 바뀐 곳 (실물을 보고 뒤집힌 것)

### 족보의 출처 — 작년이 아니라 올해, 그보다 원본

처음엔 "작년 필기에만 족보가 붙어 있으니 작년 매칭이 Main-Quiz의 전제"라고
봤다. 틀렸다. **올해 필기에도 족보가 붙어 있고 그게 작년 것을 포함한다** —
필기자가 작년 족보를 그대로 옮겨 오기 때문이다(`260812_01` 실측: 작년 18문항이
올해 족보에 100% 포함).

그리고 그보다 나은 것이 따로 있다. `{과목}/족보/{연도}/`의 교실 공개 원본이다.

```
병리학 2026 족보   122쪽 · 텍스트 레이어 살아 있음(평균 1,646자/쪽) · OCR 불필요
                  p4~  "1  병리학 소개 – 과거, 현재, 미래" 로 강의별 분류
                  p78~ 실습 시험 블록
```

`runner jokbo <과목>`이 `quizgen.jokbo`를 불러 이걸 강의별 조각으로 자른다.
그러면 족보 채널이 필기 속 캡처 이미지가 아니라 원본 PDF가 되고, 경계 판정이
필요 없어진다.

**어느 조각을 어느 강의에 물릴지는 로컬 러너가 정하지 않는다.** quizgen가 카드를
만들 때 목차 제목으로 대조한다 — 두 곳에서 각각 짝지으면 카드가 본 조각과 뒷면에
붙는 조각이 갈릴 수 있다. 한동안 `runner/jokbo.py`가 `links.json`으로 따로 짝지어
넘겨줬는데, 그 자리를 없앴다.

작년 자료가 필요한 곳은 이제 **Pre-Quiz뿐**이다. 강의 전에 푸는 퀴즈라 올해
필기가 아직 없다.

### 강의 식별자 — `key`가 아니라 `uid`

처음엔 `날짜_교시`(`260813_03`)가 시스템 전체를 꿰는 키라고 봤다. 유일하지
않았다.

```
[260303_02] 역사 속의 감염병(김옥주, 이규원)
[260303_02] 질병사 관점에서 신종-재출현 감염병 (송진수)
[260303_02] 건강과 질병(박영수)
```

선택형 과목은 한 교시에 여러 강의가 동시에 열린다. 자세한 것은
[artifact-contract.md](artifact-contract.md)를 보라.

## 자료의 함정 (전부 실물에서 나왔다)

- **괄호는 두 가지다.** 숫자면 순번, 한글이면 교수. 같이 지우면
  `조직 재생 및 수복(1)`과 `(2)`가 한 강의로 뭉개진다
- **Synology 파일명 일부가 NFD**(자모 분해)다. 화면에는 똑같이 보이지만
  `[가-힣]` 정규식이 통째로 실패한다
- 같은 강의의 v1·v3이 공존하고, Synology 충돌 사본과 연도가 어긋난 파일이 섞인다
- **붙여넣은 이미지도 `Stamp`다.** 출제 이력 도장과 갈라야 한다 —
  `260813_03`에서 Stamp 69개 중 35개가 클립보드였다
- **색은 읽지 않는다.** 15편에서만 31종이 나왔고 필기자마다 규약이 다르다.
  뜻은 색이 아니라 `notes`의 글에 있다

## 배포는 검문을 통과한 것만 자동으로 나간다

`publish`가 편마다 `runner.gate`에 물어보고, 막힌 편은 강의록만 내보내고 덱은
미룬다. 무엇을 막고 무엇을 적기만 하는지는 [runner/gate.py](../runner/gate.py)
첫머리에 있다.

**파이프라인이 이미 막는 것은 검문에서 다시 막지 않는다.** quizgen는 재현 검사를
통과하지 못한 카드가 남으면 덱을 만들지 않는다. `.apkg`가 있다는 것 자체가 그
검사를 지났다는 뜻이라, 검문은 **산출물이 스스로 주장하는 것과 다른 경우**로 좁혀
있다.

**아직 문턱이 안 선 것이 하나 있다** — "무엇이 이상한 것인가". 후보(개수 계수기)는
CLAUDE.md에서 이미 넷이 탈락했고, 새 파이프라인에서 무엇이 그 자리를 대신할지는
편이 몇 개 쌓여야 안다. 그 전까지 개수로 막지 않는다.
