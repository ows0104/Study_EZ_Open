# 리팩토링 전체 현황 — 2026-10-26 최종 점검

구조 정리의 핵심 구현과 확인된 자료 보관은 로컬에서 완료했다.
전체 개발 루프는 동작하지만 마감해야 할 연결부가 있으며, 운영 배포와 새 출제/학습 기능은 아직 진행하지 않았다.

| 단계 | 현재 판정 | 남은 작업 |
|---|---|---|
| P0 기준점 | 로컬·API·실행 경로 확인 | 웹 운영 revision과 최종 배포 후보 포함 범위 확정 |
| P1 읽기 범위/절차 | 완료 | 실제 작업에서 필요하면 지도 유지보수 |
| P2 계약·프롬프트 | 로컬 구현/검증 완료 | 최종 배포 후보에 포함 후 배포 확인 |
| P3a 은행 API | 로컬 구현/검증 완료 | 당시 서버 85개 테스트 파일 통과, 현재 릴리스 후보 검사와는 구분 |
| P3b 러너 | 로컬 구현/검증 완료 | 러너 477개 + 공용/개발 14개 통과. 운영 재시작 없음 |
| P4 독립 영역/보관 | 확인된 범위 완료 | 12개 배포 사본+125개 테스트 폴더 보관. 불확실 자료 보존, 추가 정리는 선택 과제 |
| P5 새 출제 시범 | 요구사항 대기 | 26필기/족보 → 개념·경향·포인트 독립 추출, 누락 검증, 시범 강의의 수용 기준 |
| P6 Concept Tree 학습 | 요구사항 대기 | 뿌리부터 탐색하는 학습 정책, 진행도·복습·기존 기록 이전/복원 |
| P7 Maintain | 기본 관측/제보 루프 동작 | 지시문 복구, 사건 종료·배포 결과 연결, 기능/DB/큐/러너 관측 범위 확정 |

P5/P6는 기존 구조 정리의 누락 구현이 아니라 새로운 제품 기능이다. 사용자의 상세 설명과 별도 설계/승인이 필요하다.
Spotter 물리적 저장소 분리, 기존 덱 코드 완전 독립, 보존한 자료의 추가 이동은 필수 마감 작업으로 강제하지 않는다.

## 우선순위

1. **개발 루프 마감:** 자동화 한글/오래된 상태 정리, 검증 범위와 설계 지문 연결,
   배포 후보·사후 검사·사건 종료 기록. [구체 계획](changes/2026-10-26-workflow-hardening/plan.md).
2. **릴리스 준비:** 다른 미커밋 작업과 이번 변경을 구분하고 웹/API/러너 후보·검사·복원 범위를 고정한다.
   운영 배포는 해당 후보에 대한 사람 승인 뒤 수행한다. 과거 gate를 억지로 갱신하지 않는다.
3. **새 출제/학습 설계:** 사용자 아이디어를 intent/spec/plan으로 구체화한 뒤 기존 은행을 덮어쓰지 않는 시범부터 진행한다.

보강 계획의 로컬 구현·검사·리뷰 완료. [검증 결과](changes/2026-10-26-workflow-hardening/test-results.md)와 [사용 절차](development/release-and-incidents.md)를 참조한다. 운영 배포는 미실행이며 별도 후보·중요 승인이 필요하다. 기존 최종 감사의 발견 사항은 당시 기록으로 보존한다.
