# 91문항 고정 분할 원본검수 및 이미지 확인·업로드 — 구현 계획

## 변경 범위·대상 파일·순서
1. 최신master 전용 worktree에 PR11 후보를 보존 통합하고 대시보드에 이어받은 범위를 등록한다.
2. quizbank/connection_chunked.py 및 studyez_contracts/roots/chunked.py에 분할 계약·ID/쌍 완전성·완료영수증·전역대조를 구현한다. runner/root_chunked_review.py로 기존 repair-2와 source-2.input을 검증해 별도 후속 runs에 새 검수만 실행한다. 기존 ledger와 모든 완료/실패 자료는 읽기 전용으로 연결·해시 검증하며 manifest에 원래 실패와 고정은행/수정소비 증명을 추가한다. c.validate_result와 Native 검증에 새 증명 경로를 명시한다.
3. 회귀/원본보존 검사를 통과한 코드로 실제 CLI 분할 검수와 blind 의학 검수를 수행한다. 원본 전체·최종 실제 이미지·문항·지도/포인트를 검수하고 결정적으로 집계한다. 변경된 후보를 새로 출제하지 않는다.
4. 최종 계약·이미지 바이트/위치·실제 표시를 확인한 뒤 기존 업로드 계약으로 지정 강의에 등록하고 읽기 전용 확인을 남긴다. 기존 학생기록/은행은 보존 정책에 따라 다룬다.
실제 배치 I/O는 runner/root_chunked_tasks.py에 두어 quizbank→runner import 금지를 지킨다. 업로드에 필요한 명시적 검수완료 반입은 server/app/root_learning/reviewed_import.py 및 기존 revealed_answer의 읽기 호환으로 처리한다. 원래 packet/result와 새 원본 snapshot 매핑은 분리해 입력 지문을 보존하며 기존 웹 dispatch로 가장하지 않는다. 완료된 실제 검수만 반입하고 job은 처음부터 done인 명시적 반입 기록, 관리자 전용 시범으로 등록한다. 기존 판/은행/학습은 변경하지 않으며 제로기존 상태를 사전 확인했다. 운영 스크립트와 서버 로컬 회귀로 검증한다.

## 검사 명령과 성공 조건
chunked-regression: 빠진/중복/다른 ID, 빈 검수, 입력/자료/영수증 변조, 중단 자동반복, 전역누락, 예산/은행변경 거부 및 기존288+40관련 회귀. preserved-origin: 원본 source-2 실패·모든 기존파일의 해시 일치. live-evidence: 실제 모델 완료 영수증·전체 검수/이미지·게시 응답·읽기 확인. 미완료를 통과로 기록하지 않는다.

## 위험·복원·승인할 범위
사용자의 현재 명시 승인이 구현·지정91문항 후속검수·이미지확인·업로드를 포함한다. 전송 승인을 반복 요청하지 않는다. 일반 코드 운영 배포가 반드시 필요하면 revision별 검증 절차를 따른다. 새 source 검수 분할은 콘텐츠 거절의 우회가 아니라 model_timeout 대응이며 원래 거절 분류를 확인한다. 실패하면 새 요청/ID로 반복하지 않고 원본/실패/소비를 보존한다. 복원은 새 후속 게시만 기존 보존 정책으로 비활성화하며 원래 runs/사람기록은 삭제하지 않는다.
