# 조사 결과 — 후속 P3a에서 해결

실행 기록과 승인 범위: [2026-10-26-bank-api-boundaries](../2026-10-26-bank-api-boundaries/plan.md).

원인은 테스트 기대값 불일치다. 같은 build에 보강 문항을 추가하면 현행 보존 로직은
원본 상태를 보관하고 원래 평가를 재생하면서 origin_event_id·question_fingerprint 등
출처 메타데이터를 추가한다. 과거 검사는 전체 JSON이 같을 것을 요구해 이 추가만으로 실패했다.
재현에서 평가 시각·등급·문항·숙련도·안정도·예약 상태는 동일했다. 보관 상태 2개와 은행 버전
2개를 확인했다. 실제 운영 데이터 조사가 아니라 격리 fixture 재현 결과다.

검사는 원래 history의 모든 필드와 개수, 다른 기존 state 필드 전체, 문항 fingerprint,
추가 문항에 과거 평가가 없음, 원본 상태 보관, 전후 은행 보관을 각각 확인한다.
세션 시작 후에도 보강 완료 직후 history가 그대로 유지되는지 확인한다.
bank_retention/study_retention 및 운영 학습 정책은 변경하지 않았다.

최종 검사 근거는 후속 작업의 state.json과 test-results.md를 따른다. 이 작업은 후속 작업에서
통합 해결했으므로 별도 배포 승인이 아니다. 이전 실패 로그는 역사적 증거로 보존한다.
