# 시간표

캘린더가 이것만으로 그려진다. 파이프라인 산출물이 하나도 없어도 화면은 완성된
모습이고, 자료가 올라오면 칸에 점이 붙는다.

```bash
cd server
.venv/Scripts/python.exe -m app.cli seed-timetable      # 여기 있는 최신 학기 파일
.venv/Scripts/python.exe -m app.cli seed-timetable <경로>  # 다른 것을 먹일 때
```

## 어디서 오나

**만드는 코드는 없다.** 학사 요람의 주별 시간표(이미지 PDF)를 사람이 옮겨 적는다.
`sourcePage`가 그 요람의 몇 쪽인지다.

2026-08-31까지 이 파일은 `Study_EZ_Claude/TimeTable/`에 혼자 살고 있었다. 정본은
이 저장소인데 학기마다 쓰는 입력이 옛 파이프라인 저장소에 있어서, 그쪽을 지우고
여기로 옮겼다.

## 무엇이 흔들리나

칸마다 **`details`의 어디까지가 제목이고 어디부터가 담당인지**가 흔들린다. 같은 꼴의
칸인데 8/31은 소제목을 담당에 넣었고 9/7은 안 넣었다.

    details    "(MDL)⏎연충란⏎최민호, 신은희, 여선주,⏎송현범, 김주현"
    professor  "연충란 최민호, 신은희, 여선주, 송현범, 김주현"   ← 소제목이 넘어왔다

2026 시간표 369칸 중 14칸이 그랬다. 화면은 담당에 든 줄을 제목에서 빼므로(교수 이름이
제목에 붙는 것을 막는 정상 동작이다) **그 칸은 제목이 통째로 사라진다.**

14칸은 요람 원본과 대조해 고쳤고(2026-08-31), `seed-timetable`도 넣기 전에 같은 것을
되돌린다(`server/app/naming.py`의 `strip_lead_topic`). 지금은 둘이 맞아서 「소제목을
뗀 칸」 줄이 안 뜬다 — **새 학기 파일에서 그 줄이 뜨면 옮겨 적기가 또 흔들린 것이고,
찍힌 줄을 요람과 대조한 뒤 이 파일을 고쳐라.** 되돌리기는 이름을 배울 데가 없는
칸(그 칸에만 나오는 교수)을 일부러 건드리지 않으니, 찍힌 수가 눈에 띄게 적으면
그쪽을 의심하라.

**`details`는 칸의 원문이고 `professor`는 거기서 뽑아낸 것이다.** 둘이 다투면
`details`가 이긴다.

## 2026-11-05 감염과 면역 수정 공지

11월 2~27일 학생 공지 4쪽을 대조해 16칸을 갱신했다. 원본·변경표·승인·검사 기록은
`docs/changes/2026-11-05-immunity-timetable/`에 있다.

시간이 바뀐 12강의는 **주제를 따라 기존 event ID와 run ID를 유지**한다.
`identities/2026-2.json`은 event ID→기존 run ID, `identities/2026-2-notes.json`은
올해 필기의 기존/수정 교시와 정확한 주제→기존 run ID의 검토된 별칭이다.
이 파일들은 시간표 배열이 아니므로 별도 하위 폴더에 둔다. `seed-timetable`의 최신 학기 선택에는 포함되지 않는다.

러너는 수정된 날짜·교시와 보존된 ID를 함께 사용한다. 기존 `_pairs`·runs 경로·자료·링크·학습 기록의 키를
새 교시로 일괄 변경하지 않는다. 수정 시간표가 처음 등록되는 DB에는 기존 seed를 쓰고, 이미 운영 중인
DB의 이번 갱신은 검토된 조건부 데이터 변경 도구 `scripts/immunity_timetable_update.py`를 쓴다.

## 2026-11-11 번호를 현재 시간표로 되돌림

사용자 2026-11-11 「현재 시간표대로 맞춰야해」「12강 다 맞춰줘」로 위 결정을 되돌렸다.
12강의의 run ID는 이제 칸의 날짜·교시 번호와 같다. `identities/`의 두 파일은 빈 `{}`이고, 러너는 날짜 키만 쓴다.
11-05의 별칭 원본은 `docs/changes/2026-11-05-immunity-timetable/identities/`에 남겼다.

운영 DB·R2·runs의 이전은 `scripts/immunity_renumber.py`가 한다. 기록은 `docs/changes/2026-11-11-immunity-renumber/`에 있다.
- 되돌린 이유: 철자가 조금 다른 올해 필기(「미코플라즈마」)가 별칭을 비껴 새 번호 행에 붙었다. 미코플라스마·무산소 두 행이 섞였다.

다음에 시간표가 바뀌면 칸의 번호를 그대로 run ID로 쓴다. 옛 번호를 지키는 별칭은 다시 만들지 않는다.
