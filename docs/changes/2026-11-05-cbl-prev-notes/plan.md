# 미정 CBL 3개 작년 필기 확인과 연결 — 구현 계획

## 변경 범위·대상 파일·순서
1. 사용자 승인 범위와 세 ID를 기록하고 운영 현재값·_pairs 원상·보존 대상 테이블을 읽기 전용 스냅샷한다.
2. 2025년 해당 주제 PDF를 직접 읽고 표지/관련 페이지를 시각 확인해 대조 결과와 SHA-256을 기록한다. 관련 없는 일반 자료를 대체하지 않는다.
3. 원본을 수정하지 않는 고유 ID의 예습 참고 사본과 기존 packet_sources 계약의 provenance manifest를 runs/_materials/감염과 면역/prequiz-inputs에 만든다. 실제 운영 runs/_pairs/감염과 면역.json에 세 키만 추가한다. 먼저 격리된 runs에서 계획과 필기 선택을 검증한다.
4. 현재 서버의 버전/보존 계약을 사용해 세 강의의 preview_source와 notes_prev만 연결한다. 기존 일반 강의 연결과 식별 필드는 그대로 둔다. 공통 제품 코드를 바꾸지 않는 자료 연결 작업이며 API/웹 재배포는 필요하지 않다.
5. 실제 PDF 해시, 읽기 전용 운영 화면, 보호 테이블/기존 매핑 보존, 재계획에서도 선택 유지 여부를 확인하고 러너 상태를 원상 복원한다.

## 검사 명령과 성공 조건
source-review: 세 실제 PDF의 제목·담당·관련 페이지·해시·원본 보존을 직접 확인한 기록과 기계 검증. selection: 격리된 runs에서 publish/readiness 모두 3개 사본을 2025년으로 선택하고 나머지 매핑이 유지되는지 검증. preservation: 세 운영 첨부의 실제 바이트와 공개 메타데이터, 기존 강의 필드/예습·학습·은행 기록 보존을 확인. 최종 운영 영수증은 자료 해시와 대상 ID에 묶어 기록한다.

## 위험·복원·승인할 범위
현재 사용자 발언을 세 CBL의 자료 대조·수동 매핑·예습 첨부 운영 반영 및 필요한 로컬 스크립트/검증의 승인으로 적용하며 같은 승인을 다시 요청하지 않는다. 원본 해시·실제 대상·스냅샷을 고정한 뒤 적용한다. 실패하면 일시정지 상태에서 기존 매핑·메타데이터·첨부 연결을 보존 스냅샷으로 복원하며 새 원본/기록을 삭제하지 않는다. 문항·은행 내용·권한·비밀값·다른 강의 변경은 범위 밖이다.
