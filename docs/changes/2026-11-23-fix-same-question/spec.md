# Main-Quiz /4 고치기는 같은 물음 안에서만 — 설계

## 요구사항과 수용 기준

R1 (`content/prompts/learning-links/v4/fix.md` 첫 목록):
- 고친 문항은 원래 문항이 묻던 것을 묻는다. 이유는 ID에 학습 기록이 이어지기 때문이다.
- 묻는 대상·범주를 바꾸지 않는다. 판단·이유·기전 문항을 목록·수치·분포 문항으로 바꾸지 않는다.
- 같은 물음 안에서 형식(basic·ox·cloze·객관식)·발문·정답·채점 단위를 고친다.
- 같은 물음으로 치는 셋:
  - 틀리거나 원본이 정하지 않은 정답을 원본 정답으로 바꾸는 것(후보를 함께 들면 모두)
  - 같은 범주 목록의 빠진 원소를 채우는 것(발문에 주던 같은 목록 원소를 답으로, input.existence components 포함)
  - 줄이거나 나누어 한 층으로 맞추는 것
- 다른 물음을 요구하는 지적은 이 ID에 적용하지 않는다. 이유를 exam_rationale에 한 줄 남기고, 따로 물을 내용은 싣지 않는다.

R2 (`v4/item-review.md` fix 칸 아래):
- fix는 그 문항이 묻는 것 안에서 고칠 방향이다. 다른 대상·범주로, 「존재 문항으로」 바꾸라고 쓰지 않는다.
- R1의 셋은 같은 물음 안이다.
- 「지식 없이 풀린다」는 지적도 같은 물음을 지식이 필요한 형식·발문으로 바꾸는 방향으로 쓴다.
- 따로 물을 것은 note에 「별도 문항: …」으로 적는다. 그 이유만으로 design을 doubt·wrong으로 하지 않는다.

수용 기준:
- `tests/quizbank/test_fix_same_question.py` 5개가 통과한다. master 지시문으로 바꿔 돌리면 5개 모두 실패한다.
- `pytest tests studyez_contracts` 전체가 이 변경으로 새로 실패하지 않는다.

## 책임·입출력 계약·오류 상태

- 지시문만 바꾼다. 코드·스키마·검사 규칙(`v3.check_fixed`)·조립·서버·DB는 그대로다.
- 모델이 규칙을 어겨도 지금처럼 조립된다. 막는 코드는 없다.
- 어겼는지는 실행 뒤 처음 문항과 고친 문항을 비교해 센다(release.md).

## 호환성과 데이터 보존

- 공개 판·문항 ID·학습 기록·검수 이력은 그대로다. 운영 재출제는 하지 않는다.
