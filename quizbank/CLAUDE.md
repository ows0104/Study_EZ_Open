# quizbank 작업 안내

관리자가 만든 ChatGPT 답을 서버에서 쓸 문제은행으로 정리한다.
최초 문항 생성 프롬프트는 `../content/prompts/bank/bankPrompt.md`다.
2026-10-16 저녁 사용자 지시로 러너는 `--web-postprocess`를 사용한다. 아래 기존 전체 생성 경로와
구분하며, 웹 문항·해설을 보존하고 최초 원본·정답 검수 후 지적을 기록·게시한다. 별도 보기 풀·해설
작성과 자동 내용 수정 반복은 하지 않는다. 독립 포인트는 이미 완료된 동일 원본의 캐시만 재사용한다.
캐시가 없으면 웹 문항 색인을 쓰되 원본 전체 대조에서 목록 밖 누락을 확인한다. 색인을 독립 추출로
표시하지 않는다. 학습 구조는 기존 문항을 바꾸지 않고 앱에 필요한 연결만 수행한다.
웹 후처리에서는 정답 단위가 하나이고 answer와 정확히 일치하는 list만 basic으로 정규화한다.
문제·정답·출처·원본 파일은 보존하며 `format-normalization.json`에 형식 변경을 기록한다.
다른 형식 오류나 내용 지적을 이 규칙으로 통과시키지 않는다.
그 안의 「문항 품질 원칙」은 `generate.item_quality_guidance()`로 CLI 원본 검토·수정·
보강에 함께 전달한다. 공통 출제 원칙은 이 절에서 수정하며 CLI 지침에 별도 사본을 만들지 않는다.
CLI 프롬프트는 단계별 할 일·자료·판단 순서·검토·출력 계약을 먼저 전달한 뒤 이 공통 원칙을 붙인다.
정리기는 내용 보존·변환만, 독립 의학 검토는 정답의 정확성만 맡으므로 출제 원칙을 별도로 주입하지 않는다.

프롬프트 1.42 이상은 문항 우선 구조다. 웹은 원본 전체로 문항·선지·정답·출처 충돌만 작성한다.
CLI는 새 원본 전용 작업 폴더에서 독립 포인트를 추출한 뒤 실제 문항·원본·필요 회상 방향을
대조·보완한다. 목록 밖 누락과 목록 자체의 과분할·범위 오류도 검토한다. 내용 검수가 끝난 뒤
`question_first.py`가 별도 CLI에 개념도·회상 계획·선행 연결을 맡긴다. 연결은 문항 내용을
바꿀 수 없으며 모든 ID·최종 은행을 검증한다. 내용 지적이 남아도 최종 검수 뒤 학습 구조를 연결하고, 지적을 보존해 게시한다.
학습 가능한 구조 검증과 내용 검수 판정은 별도이며, 구조가 깨진 기술 실패는 게시할 수 없다.
사용자 후속 지시(2026-10-18): 신규 출제·검수는 정본 1.77의 첫 학습 순서 기준을 적용한다.
실제 선행 회상과 슬라이드 흐름으로 배열하며 개요 인용의 최솟값·회상 방향 이름으로 대신하지 않는다.
원본 검수는 기초 회상 누락과 순서 문제를 구분해 기록하고, 사후 학습 구조는 모든 문항의
learning_page와 실제 prerequisites를 작성한 뒤 연결된 후속 경로까지 재검토한다.
기존 한 번의 구조 작성 안에서 summary에 판단 근거·불확실성을 남기며 추가 모델 검수 단계를 만들지 않는다.
사후 회상 방향 목록은 연결된 최종 문항의 `retrieval_direction` 고유값으로 계산한다.
CLI 원문은 `learning-structure.raw.json`, 집계 차이와 적용 구조는 `learning-structure.resolution.json`에 보존한다.
문항 검수 단계의 빈 학습 구조는 내부 계약이며 서버의 기본 전체 검증은 계속 이를 거절한다.
1.41 이하의 기존 계획표·완성 은행 입력은 기존 경로로 읽는다. 1.42 재개 포인트는 동일 원본의
`independent-origin.json` 이력이 필요하며 웹 계획표를 독립 추출 결과로 대신 쓰지 않는다.
1.43 이상은 웹의 보기 풀 표도 받지 않는다. 새 초안 정리 뒤 `option_pools.py`가 실제 변형 가치가
있는 객관식에만 선택적으로 풀 후보를 작성한다. 고정 발문·정답·선지는 보존한다. 이후 모든 후보를
기존 해설·원본·정답 검수와 최대 3차례 수정에 함께 포함한다. 재개 시 풀을 다시 작성하지 않는다.
보기 풀 검수는 실제 후보 목록의 ID·내용 hash와 후보별 참·거짓·선택 기준 판정을 대조한다.
사이트의 웹 출제 버튼은 `points` 일감도 요청한다. `quizbank.independent`가 원본만으로 포인트를
미리 저장하며, 이후 `quizbank.run --points-cache-root`가 같은 PDF·족보·강의 범위의 완료 결과를
재사용한다. 출처 지문이 다르거나 비어 있거나 깨진 목록은 재사용하지 않는다.
독립 포인트의 상위 목표·대상 근거 쪽 연결만 어긋나면 원본 전용 CLI로 한 차례 복구한다.
목표·포인트의 내용·ID·순서·제외 기록은 보존하고, 다시 실패하면 멈춘다. 원문과 복구본·사용량을
별도 파일로 남기며, 이 근거 메타데이터 복구로 문항 수정·검수 잔여 횟수를 초기화하지 않는다.
누락·중복·없는 ID·변경된 내용의 기록은 완료로 세지 않는다. 후보별 기록이 없는 과거 풀 검토는
고정 선지를 사용한다. OX 해설 작성은 기존 채점 근거를 보존하며, 근거 없이 O/X만 있을 때 한 번 채운다.

수정 후 검수는 `incremental.py`가 같은 실행 안에서 문항별 판정을 재사용한다. 최초·재개 첫 검수는
전체를 수행하고, 이후 동일 문항·근거·검수 기준의 해설·정답·개별 설계 판정만 보존한다.
문항 전체·보기 풀·선행 참조·출처 충돌·PDF·족보·모델·프롬프트 변경은 관련 재사용을 무효화한다.
출제포인트 변경은 연결된 문항과 근거 쪽이 겹치는 문항의 원본 검수를 다시 수행한다.
작업 요약·과거 경고는 전역 대조에서 읽으며 정답·해설 검수의 재작성 근거로 쓰지 않는다.
원본 전체·모든 포인트·목록 밖 누락·문항 간 중복·충돌·Core 범위는 매번 다시 대조한다.
`tier_checks`는 매번 전체 문항의 실제 인출 단위와 학습목표·기출·강조·임상 중요성 근거 및 독립 심화 여부를 남긴다.
주변 세부사항에 중요도를 전이하지 않으며, Tier 불일치는 수정 대상으로 전달한다. 이 전역 판단은
개별 검수 캐시에 넣지 않는다. 등급 교정은 기존 오류·doubt·미시험 기록 보존과 독립적이다.
wrong·doubt와 후보별 검수 hash는 그대로 보존하고, 누락·깨진 판정은 재사용하지 않는다.
`review-reuse.jsonl`에 입력 hash·실제 재검수/재사용 ID·최초 판정 시각을 남긴다.
재사용은 수정 최대 3회 제한이나 최종 구조·전체 스키마 검증을 바꾸지 않는다.

검사: `python -m pytest tests/quizbank`.
운영 실행·업로드는 `runner/bank.py`가 맡는다.
실제 실행 사본과 공통 프롬프트의 버전·hash는 각 CLI 출력 폴더의 `runtime.json`에 기록한다.
호출한 채팅의 작업 폴더나 Git 커밋만으로 실행 중인 배포 사본이 갱신됐다고 판단하지 않는다.

프롬프트 1.61부터 출제 시 `근거:` JSON으로 핵심·추가 참고·족보를 구분한다. 정리기는 이를
`authored-evidence.json`에 보존하고 문항 스키마·정답·해설에 섞지 않는다. 최종 문항의 발문·정답·출처가
유지되면 그 선택을 사용하며, 기존 문항·내용 수정분·새 보기 풀 후보만 CLI가 추가 대조한다.
인용 순서·키워드로 핵심을 대신하지 않는다.
1.62부터 그림·필기·동의 표현과 발문 조건으로 가능한 짧은 추론을 인정한다. 첨부 원본에서 충분한
근거를 못 찾으면 `evidence_sources.py`가 같은 과목·연도의 필기 폴더에서 찾은 다른 강의까지 CLI가
검색한다. 출제 때의 unresolved는 재사용하지 않는다. 전체 검색 뒤 미선정 원인과 검색 범위를 기록한다.
다른 강의 지면은 원본 run·파일명·SHA256·물리쪽을 가진 `slideFocus` v3로 저장하고, 선택된 이미지들만
해당 문제은행의 `bank_media`에 복사한다. 자기 강의의 쪽 번호 목록에 다른 강의 쪽을 섞지 않는다.
`exam_focus.py`는 강의 근거가 없고 족보로 확인된 문항의 실제 족보 이미지를 대조해 최소 핵심을
선택한다. 강의 PDF에 첨부된 기출도 출처를 구분해 연결한다. `validation.evidenceResolution`은
문항 hash와 족보 핵심/근거 일부 부족/자료 충돌/근거 미확인/판정 어려움을 저장하며 학생 화면에 표시한다.
`validation.slideFocus`는 문항 내용 hash와 지면별 선택 근거를 보존하며, 한 장으로 충분하지 않은
연계 문항만 여러 장을 선택한다. 실제 근거를 못 찾으면 unresolved로 남긴다. `validation.jokboPages`는
첨부한 족보 조각의 연도·문항 번호와 절단기 원본 PDF 쪽을 매칭한다. 문항·정답·검수 등급은 바꾸지 않는다.

출제포인트 수와 문항 수는 일대일로 맞추지 않는다. 원본 대조는 목표의 등장과 방향별 실제 시험을
분리해 기록하고 필수 누락·확장 제안을 구분한다. 수정은 기존 문항 보완을 우선하며, 추가 문항에는
독립 목표·기존 문항 수정으로 해결하기 어려운 이유·필수/확장 판단을 남긴다. 수정 summary에 문항 수
증감과 근거를 적고 실제 추가·수정·삭제 ID는 `changes.json`으로 대조한다. 문항 감소 자체가 통과 기준은 아니다.

스키마·검증의 정본은 `studyez_contracts/bank/`의 의존성 없는 모듈이다.
`schema.py`·`validate.py`는 이를 재공개한다. 관리자 수정과 생성 결과에 같은 검증을 적용한다.

## 유지할 계약

- `validate_dropping`은 문항 ID에 귀속되는 오류만 해당 문항 제거로 처리한다.
- 제거된 문항의 선행 관계를 정리하고 다시 검사한다. 전역 구조 오류는 전체를 막는다.
- 제거 원문·이유는 `validation.dropped`, 제거 전 은행은 `bank.raw.json`에 남긴다.
- 외부지식 검토는 정답을 몰래 바꾸지 않고 표시로 전달한다.
- 프롬프트 1.29 이상은 최초 검수 후 수정·보완과 재검수를 최대 3차례 수행한다(검수 최대 4회).
  wrong·검토 누락·구조 오류·실제 지식 누락은 수정 대상이며, doubt만 남으면 주석으로 완료한다.
  원본·해설 검수의 문항별 doubt도 정답 열람 시 보이는 검토 주석에 함께 보존한다.
  원본 대조나 정답 검토를 생략하면 검수 완료로 처리하지 않는다.
  `bank.before-repair.json`, `repairs.json`, `repair/<차례>/`에 수정 전후와 근거를 남긴다.
  확실한 오류·실제 누락이 남으면 CLI 기록·문항 검토 표시를 보존하고 게시한다.
  validation.pass나 원본·정답 검수 판정을 통과로 바꾸지 않고 publication으로 학습 가능 여부를 구분한다. 웹 대화로 수정 요청을 보내지 않는다.
  상한을 우회하는 반복 재실행이나 의심 0건을 얻기 위한 추가 검수는 하지 않는다.
  JSON 스키마를 읽을 수 있으면 의미 검증 오류가 있어도 원본·정답 검수를 함께 수행해
  한 번의 수정에 전체 지적을 전달한다. 스키마 오류가 있는 입력은 먼저 CLI가 복구한다.
  `--max-repair-rounds`는 복구 시 남은 횟수를 0~3회로 제한한다. 재개 기록에 남은 횟수를 보존한다.
  이 대화의 에이전트가 문항 내용이나 검수 등급을 직접 수정하는 우회 복구는 사용하지 않는다.
- 출처 충돌은 합친 문항과 충돌 기록으로 보존한다.
- 웹 이어쓰기에서 같은 ID의 문항 블록이 정확히 반복되면 한 번만 정리하고 반복 ID·경고를
  남긴다. 완료 표시·Markdown 외곽 표시는 비교에서 제외하되, 문항·정답·근거가 다른 반복은 중단한다.
- 자료 밖 내용은 `EXT`·`external_knowledge`로 표시한다.
- 과거 형식도 읽을 수 있어야 한다. 프롬프트 변경만으로 옛 은행을 무효화하지 않는다.
- 러너·quizgen을 import하지 않는다. 러너가 하위 프로세스로 실행한다.

결정 배경은 [변경 전 기록](../docs/archive/2026-10-06-originals/quizbank/CLAUDE.md)에 있다.

프롬프트 1.63 / JSON 3.2는 중요도 Core·Important·Optional과 문항 advanced boolean을 분리한다.
Core는 실제 학습목표·해당 교수 기출·올해 출제 예고(명시·암시), Important는 교수 일반 강조·필기자 중요 표시·구체적인 임상 중요성, 그 외는 Optional이다.
importance는 tier의 수치 표현(5/4/2)이며 심화만으로 중요도·목표 숙련도를 높이지 않는다.
새 생성·원본 대조·수정은 공유 문항 품질 원칙을 사용한다. 옛 Advanced 등급은 읽기 호환에서
중간 우선순위로만 표시하고 심화로 추정하지 않으며, 원본 재분류가 이를 최종 교정한다.
현재 정본은 1.77이다. 최상위 사용자 표기는 Must-Know이며 기존 저장 값 Essential과 호환한다. 교수의 직접·간접적인 필수 지식 강조·올해 출제 예고를 모두 Must-Know로 인정한다. “이 정도는 알아야겠죠?”, “시험에 내기 좋겠다”, “알고 있는 게 좋을 것 같아요”를 Core·Important로 구분해 낮추지 않는다. CLI basis의 exam_hint·must_know_implied는 Must-Know, note_emphasis는 Important 근거다. 필기자 표시를 교수의 출제 예고로 추정하지 않는다. 임상 적용 가능성만으로 Important를 부여하거나 누락 보완 필요성만으로
Core로 올리지 않는다. Core의 학습목표·기출·출제 예고 회상 충족과 Important·Optional을 포함한 전체
은행의 내용 충족은 구분해 검토한다. 단계별 지침은 이 공통 기준을 완화하지 않는다.
1.72의 공통 원칙은 중요한 기초 연결과 세부 연결의 실제 회상을 구분한다. 원본 추출·전체/증분
검수는 제공된 관계와 시험한 관계, 족보의 연결·왜곡 지점을 기존 target·note에 기록한다.
사후 학습 구조는 실제 기초 문항만 선행 연결하며 내용 보존·수정 상한·기존 은행 호환 계약을 유지한다.
1.73의 2.4는 이를 과목 공통의 출제 철학으로 설명한다. 좋은 문항·정답·필요한 이유·후속 연결의
예시는 설계 기준이며 해당 과목·주제를 실제 출제 범위에 추가하는 지시가 아니다.
1.74는 철학과 네 예시를 「문항 품질 원칙」 맨 앞의 독립 최상위 절로 옮겼다. 목표 선정·설계·
누락 판단·검수가 여기서 출발하며, CLI도 기존 공통 원칙 추출 경로로 같은 절을 전달받는다.
1.75는 `lectureScopes.json`의 제목·올해 원본 접두어가 일치하는 중추신경계 두 강의에서만
원래 회색 본문을 시험 범위에서 제외한다. 필기자의 회색 주석과 구별하며, 제외 내용을
누락 보완·기초 문항으로 되넣지 않는다. 웹과 CLI가 같은 강의별 범위를 사용한다.
