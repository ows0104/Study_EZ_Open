# 공통 뿌리 파이프라인 시간 초과 원인 분리 및 같은 수신 결과 재사용 — 설계

## 요구사항과 수용 기준
기본 짧은 JSON과 실제 AUTHOR 스키마의 짧은 합성 입력을 제한 시간 내 비교한다. 모델/권한을 유지하며 실패 시 부분 JSONL/stderr·세션·완료 이벤트·미상 사용량을 로컬 증거로 남기고 본문/인증값을 화면에 노출하지 않는다. 무제한 재호출이나 단순 시간 제한 증가는 하지 않는다.
진단 결과 서비스/스키마 자체의 영구 실패는 배제됐고 큰 AUTHOR 완성 단계의 병목이 남았다. workspace 저작/원본 검수는 원래 전체 JSON 수용 계약을 파일에 작성하고, native 최종 응답은 작은 경로/SHA 영수증으로 받는다. 큰 초기 지도/BANK를 모델 최종 메시지로 재출력하지 않고 변하지 않은 부분은 로컬 코드로 그대로 복사하도록 한다. 모델 완료+동일 workspace의 실제 파일+SHA+크기/경로/링크/중복키 검사 후 원래 schema/의미/출처/지도/문항ID 검증을 전부 수행한다. 파일 존재만으로 성공 처리하지 않는다. 독립 의학 검수의 blind 도구 격리와 입력 화이트리스트는 바꾸지 않는다. 공급자 내부 지연의 단일 원인을 이 진단만으로 확정하지 않는다.

## 책임·입출력 계약·오류 상태
runner 실행 어댑터가 transport/진단만 맡고 quizbank의 원본 계약·생성/검수/최대3회/판정/그림 렌더링을 그대로 호출한다. 기존 생산자 identity는 생산자 파일 지문으로 유지하고 새 실행 어댑터 버전·소스SHA·계약/입력/모델/native 완료/실제 파일SHA/원문SHA를 별도 실행 영수증으로 usageHash에 묶고 게시 전에 대조한다. 부모는 모델 JSON을 읽고 검증할 뿐 문항/지도/의학 판정을 작성하지 않는다. 후속 단계의 실패도 보존하고 자동 반복하지 않는다.

## 호환성과 데이터 보존
같은 packet/inputHash/webResponseHash/76개 원래 ID와 원본2개/normalize 및 기존 두 실패/세션/부분 사용량 미상을 보존한다. 현재 사용자의 수정 후 같은 강의 재사용 요청에 따라 수정된 실행 방식으로 초기 generate를 명시적으로1회 수용하며 새로운 journal/proof를 먼저 기록한다. 이전 failed ledger와 저널은 불변 사본으로 남고 repairRounds=1을 유지한다. 성공한 단계만 캐시를 채우고 기존 같은입력 재개 버튼은 이후 아직 시작하지 않은 단계만 진행한다. /1은 기존 실행기를 유지한다. DB/공개 범위/API/웹을 바꾸지 않으며 기존69문항과 학습 기록을 보존한다.

실제 보완 단계에서 공급자의 명시적 생물학 콘텐츠 제한 거절이 확인됐다. 이는 시간 초과와 구별해 model_content_restricted로 기록한다. 기존 실패 원문을 보존한 별도 입력/원장/진단 지문에 묶고, 같은 입력의 재호출과 해당 미완료 작업의 게시를 차단한다. 자료를 변형하거나 다른 모델/경로를 사용해 제한을 우회하지 않는다. 학습 화면까지의 실제 성공은 이 외부 제한으로 미완료임을 명시한다.
