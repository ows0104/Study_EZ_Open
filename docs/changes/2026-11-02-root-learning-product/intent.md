# 강의별 뿌리 학습 첫 제품

## 문제와 사용자 효과
강의별 큰 구조에서 필요한 관계를 회상하고, 첫 학습과 현재 회상을 구별하며 다음 학습으로 이어지는 실제 제품 흐름을 만든다. 2026-11-02 사용자는 작은 수신 기록·차이 확인보다 크고 중요한 작업을 진행하라고 요청했다. 이에 콘텐츠 검토와 제품 설계를 연결하는 첫 구현 범위를 제안한다.

## 범위와 성공 기준
전체 Intent와 learner-journey Spec의 합의를 계승한다. 첫 콘텐츠 시범은 콜린성 약리학(1), 제품 구조는 강의별 독립 뿌리다. 현황 → 추천 → 회상/확인/평가 → 지도 변화 → 종료/재개의 흐름을 끝까지 포함한다. 기존 문항·개인 수정·제외·학습·검수 이력을 보존한다. 이미지 문제·자동 bridge·교수 안내·강의 간 통합·전체 세부 트리 구현은 이 첫 Build에 자동 포함하지 않는다.

## 근거·미정 사항
근거는 ../2026-10-27-site-intent/intent.md, ../2026-10-27-learner-journey/spec.md 및 open-design.md, 수신한 시범 트리·포인트다. 이 문서의 작성은 새 Build 승인이 아니다. spec.md는 미합의 계약의 추천안을 포함한 검토용 문서이며, 기존 정본의 합의와 구별한다. 2026-11-02 사용자의 구체적인 전송 승인 후 한 차례 읽기 전용 [콘텐츠 대조](content-comparison-review.md)를 완료했다. 뿌리 목표 후보 15개와 첫 8문항 경로를 제안했으며, 목표 분할·필수 방향의 최종 채택, 미준비 과제 처리와 추천 정책 선택은 남아 있다.

## 2026-11-03 Build 진행
사용자는 “슬슬 구현과 빌드 단계를 진행하자.”에 이어 범위를 “뿌리 학습 전체 계획까지 확장(목표 집계·오늘 추천 포함)”으로 명시했다. 이를 전체 로컬 제품 구현 진행 승인으로 적용한다. 운영 배포·콘텐츠 공개·미검토 의학 목표의 자동 채택은 포함하지 않는다.

## 2026-11-03 초기 정책 선택 완료
사용자: “복습 간격은 학습 결과와 시험일까지 남은 기간에 따라 유동적으로 조정하고, 하루 경계는 새벽 4시로 하자.” 기존 고정 간격/09시 제안을 채택하지 않고 결과·실제 경과 시간·시험일을 반영하는 초기 제품 정책과 KST 04시를 구현한다. 기존 전체 제품 로컬 Build 승인과 현재 정책 선택을 적용하며 같은 범위의 승인을 다시 요청하지 않는다.
