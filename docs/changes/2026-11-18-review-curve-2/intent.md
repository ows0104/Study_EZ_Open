# Main-Quiz 복습 간격 2차: 평가는 버티는 힘만, 중요도·난이도·늦게 맞힌 보너스

1차(`docs/changes/2026-11-18-review-curve`, PR #217, 배포됨) 뒤 이어지는 작업.

## 문제와 사용자 효과

1차 뒤에도 Again·Hard는 중요도와 상관없이 늘 다음 날이었다. 복습일이 숙련도 M과 목표치의 비교(9S(M/T−1))라
M이 목표치보다 낮은 Again·Hard는 항상 0일 이하 → 1일이었다. Hard만 계속 누르면 Optional도 매일 나왔다.

## 사용자 결정 (2026-11-18)

- 「Hard 반복은 매일보다 덜 자주?」에 「어 조금 더 빨리 빠져도 될 것 같고, Again, Hard도 중요도가 반영되면 좋겠어.
  나는 한번 봤다는 것도 기억에 어느 정도는 영향을 준다고 생각해. 그리고 시험 전에 안 중요한데 어려운것보다 차라리 중요한 걸 더 보고 싶어.」
- 제안(복습 직후 기억은 꽉 찬 것으로 보고 평가는 버티는 힘만, 시험 압축은 Core 이상, 복습은 중요도 순)과 Anki FSRS 비교 뒤:
  「늦게 맞힌 보너스랑 난이도도 넣어서 만들어줘」

## 범위

1. 복습일 = 복습 직후 꽉 찬 기억이 1/(1+t/9S)로 목표치까지 떨어지는 날. 평가는 버티는 힘 S만 바꾼다. Again·Hard도 중요도를 탄다.
2. Hard 성장 1.1 → 1.35(난이도 반영 뒤 약 1.3). Again은 S를 1일 이하로 묶되 약한 문항은 볼 때마다 1.2배(본 효과).
3. 늦게 맞힌 보너스: 계획보다 늦게 맞히면 S가 더 는다(최대 2배).
4. 문항 난이도 D: 처음 평가로 시작, Again은 올리고 Easy는 내리고 Good은 가운데로. 성장에 (1.5−D)를 곱한다.
5. 시험 직전 압축은 Essential·Core만.
6. 지난 네 단계 평가(11-09 이후, targetParameters 있음)도 이 규칙으로 다시 읽는다(1차 R3와 같은 방침).

범위에서 뺀 것: 「오늘 복습은 중요도 순」. 구현해 보니 목록 순서는 선행 연결·목표 묶음·문항 선행(order_plan) 순서가 먼저라
복습 정렬만 바꿔서는 Essential이 앞에 온다고 보장할 수 없었다(검사용 문서에서 Essential 복습이 맨 뒤로 감). 사용자에게 알리고 뺐다.
학습률(M)은 그대로.
