# 협업 대시보드와 작업 시작 대원칙

## 문제와 사용자 효과
2026-11-05 사용자 요청. 두 사람이 각자 여러 세션으로 작은 프로젝트를 동시에 작업하면서 작업 범위가 자주 겹친다.
작업 전에 누가 무엇을 하는지 확인하고 선점하는 절차가 없어 충돌·덮어쓰기·의도하지 않은 자동 배포 위험이 있다.

사용자 원문 요지: 대시보드 md를 별도로 두고, 새 기능마다 (1) 새 브랜치 생성 (2) git pull
(3) 대시보드에서 다른 세션과 겹칠 여지 확인·조정 (4) 대시보드에 내 작업 작성 후 시작하는 것을
반드시 지켜야 하는 대원칙으로 작성한다. 대시보드에는 진행 중 작업/작업자/우선순위, 약속된 예정 작업/
예정 작업자/우선순위, 논의가 필요한 제안 아이디어를 적는다.

## 범위와 성공 기준
- `dashboard` 브랜치(master와 기록을 공유하지 않는 orphan)에 `DASHBOARD.md`를 만든다.
- CLAUDE.md·AGENTS.md 최상단과 docs/development/collaboration.md에 네 단계 대원칙과 명령을 적는다.
- 코드·DB·배포 설정은 바꾸지 않는다.

## 설계 결정
- 대시보드를 기능 브랜치에 두면 merge 전까지 상대에게 보이지 않는다.
- master에 두면 대시보드 수정마다 `deploy.yml`(master push 트리거, 경로 필터 없음)과 Cloudflare Pages
  운영 배포가 실행된다. 그래서 배포 트리거가 없는 별도 `dashboard` 브랜치에 두고 직접 push한다.
- 사용자 순서 "브랜치 생성 → pull"은 `origin/master`를 fetch한 뒤 그 위에 브랜치를 만들고,
  pull은 대시보드에 적용하는 것으로 구체화했다. 새 로컬 브랜치에서 pull하면 최신 master를 받지 못한다.
- push 거절을 "그사이 누가 선점했다"는 신호로 보고 겹침 확인부터 다시 하게 했다.

## 승인
사용자의 이번 요청이 문서 변경의 구현 승인이다. `dashboard` 브랜치 push와 PR·merge는 별도로 확인받는다.
