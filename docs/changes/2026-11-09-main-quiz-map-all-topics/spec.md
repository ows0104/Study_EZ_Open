# Main-Quiz 개념 지도 빠진 주제 복원 — 설계

## 요구사항과 수용 기준
`web/src/bank/rootMapTree.ts`의 `buildTree`(입력 `RootMapData`):

1. **답 노드 판정.** 개념 X는 아래를 모두 만족하면 답 노드다.
   - 정확히 한 문항의 `concept_ids`에만 있다.
   - 어떤 개념의 `parent_ids`에도 없다.
   - 연결(relations)이 하나 이상 있다.
   - 연결 상대가 모두, X의 부모가 있으면 그 부모 안에 있고, 없으면 그 문항의 다른 개념 안에 있다.
2. **문항의 주제.**
   - 문항에 부모가 있는 답 노드가 있으면, 그 부모(답 노드가 아닌 첫 부모)에 단다.
   - 아니면 답 노드가 아닌 개념 중 가장 많이 쓰인 것에 단다(기존 규칙).
   - 그것도 없으면 「기타」에 단다.
3. **주제 노드.** 문항을 단 주제와 그 조상(기존)에 더해, 다음을 모두 만족하는 개념도 주제 노드가 된다.
   - 답 노드가 아니다.
   - 부모가 있거나, 다른 개념의 부모이거나, 연결이 있다.
   - 고립 개념(부모·자식·문항·연결 모두 없음)은 노드가 아니다.
4. 형제 사이 같은 이름은 합치고(기존), 순서는 첫 쪽 순이며 쪽이 없으면 뒤로 간다(기존).

수용 기준:
- 감염병리1 map-tree-26110803 판으로 만든 트리:
  - 주제 노드 75개, 답 노드 노드화 0, 문항 82개
  - T025는 「항산염색 AFB」 아래
  - 결핵↔항산염색 AFB 연결이 양 끝 노드를 가진다
- 기존 단위 검사(옛 공개판 모양: 같은 이름 합침, 정답 노드 숨김, 순서·상태)가 통과한다.
- root-ui 브라우저 검사의 「고립 개념 126개는 노드가 아니다」가 통과한다.

## 책임·입출력 계약·오류 상태
- 입력 계약(`RootMapData`)은 바꾸지 않는다. `lanes`·`questionsOf`와 `RootMap` 그리기는 그대로다.
- 문항이 없는 주제는 「문항 0개」로 보이고 상태 점이 없다.
- 순환 parent_ids는 기존 경로 가드(path·깊이 12)를 그대로 쓴다.

## 호환성과 데이터 보존
- 서버, API, DB, 판, 학습 기록을 바꾸지 않는다. 학습 상태 계산(`targetStatus`)도 그대로다.
- 바뀌는 것은 화면의 트리 모양뿐이다.
  - 문항이 걸리는 주제가 더 정확해진다(예: T025는 결핵 → AFB).
  - 숨던 주제가 보인다.
