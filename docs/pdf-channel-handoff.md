## 확인 완료 (2026-08-17, 재시작 후) — 각인은 남는다

재시작으로 PATH가 잡혔고 `pages` 호출이 된다. **쪽 번호는 안 붙는다.**
돌아오는 것은 헤더 한 줄이 전부다.

```
PDF pages extracted: 2 page(s) from ...\model_input.pdf (2.3MB)
```

`page="N"`도 없고, 요청한 범위(`8-9`)를 되돌려주지도 않는다. 1-6과 8-9를 각각
읽었는데 헤더 모양이 같았다. 이미지가 순서대로 올 뿐이라 **어느 쪽인지는 세어야
안다.** 그러니 `pages` 경로에서 슬라이드 번호를 아는 근거는 각인뿐이다.

→ **각인은 남기고 PNG 두 세트만 없앤다.**

`pages` 경로는 **이미지만** 준다(텍스트 레이어 없음). 그래서 이 경로를 쓰는
단계에서는 각인이 제목을 덮는 문제가 텍스트로 보완되지 않는다.

### 딸려 나온 것 — `render.py` 수정이 아직 실물에 안 걸렸다

읽은 8장 전부 각인이 **좌상단**이다. `choose_stamp_corners`는 이 편에서 우상단을
고르므로(좌상 52% / 우상 0%), 지금 `runs/260812_02/model_input.pdf`는 **수정 전
판본**이다. 그리고 좌상단 각인이 실제로 먹고 있다 — s2·s4·s5·s6·s9는 제목 앞이
잘리고 **s8은 `Cell death`가 통째로 사라진다.**

각인이 남기로 정해졌으니 이 수정은 덜 중요해진 게 아니라 더 중요해졌다.
검증하려면 `prep.py`를 다시 돌려 재렌더해야 한다.

## 여기까지 실측한 것

**Read 툴은 경로가 둘이다.**

| | `pages` 없이 | `pages` 지정 |
|---|---|---|
| 방식 | PDF 네이티브 첨부 | pdftoppm 래스터화 |
| poppler | 불필요 | **필요** |
| 상한 | 33쪽 확인됨 | 20쪽 |
| 쪽 번호 | `page="N"` 명시 | **미확인** |
| 받는 것 | 텍스트 + 이미지 | 이미지만 |

- 33쪽 통째 읽기가 된다. `page="1"`~`page="33"` 연속.
- **텍스트 레이어에 제목이 온전하다.** 각인이 이미지에서 s8·s12의 제목
  (`Cell death`)을 100% 덮는데 텍스트에는 남아 있다.
- 다만 **각인이 텍스트 레이어도 오염시킨다.** 위치가 일정하지 않아 본문을 끊는다 —
  s2가 `2026 Slide 2 년1학년 2학기`로 나온다.
- poppler는 winget으로 깔았다(`oschwartz10612.Poppler` 25.07.0). 레지스트리 사용자
  PATH에는 들어갔고 직접 호출하면 동작한다. 150 DPI 렌더가 현 PNG(1152x864)보다
  또렷하고 한글도 온전하다.

## 걸림돌 — 2단계가 조각별로 돈다

조각 에이전트는 자기 구간만 읽는다. 통째로 읽히면 6명이 각자 전체를 받는다.

```
지금 (조각별 PNG)    25 + 14x2 = 53장
통째 PDF x 6조각     132 + 78  = 210장     ->  4배
```

그러니 통째 읽기가 `pages`를 대체하는 게 아니다. **전부 볼 때만 쓴다.**

| 단계 | 읽는 것 | 맞는 경로 |
|---|---|---|
| 0.5 구조 판별 | 뒤쪽 전부 | 통째 |
| 1 청사진 | 강의록+족보 전부 | 통째 |
| 2 카드 작성 x6 | 자기 조각만 | `pages` |
| 4 감사 | 지목된 몇 장 | `pages` |

## 하지 말 것

- **캔버스를 늘려 각인 자리를 만들지 마라.** `labels.json`은 원본 PDF에서,
  오클루전 렌더는 `model_input.pdf`에서 좌표를 잡는데 둘의 기하가 같아야 맞물린다.
  한쪽만 늘리면 정규화 분모가 갈려 `y=0.5` 상자가 12.6pt 위에 앉는다.
  아래로 늘리면 절대 좌표는 안 움직이지만 분모는 그대로 갈린다.
- **각인을 고정 코너로 옮기지 마라.** 어느 코너가 비는지는 필기자 템플릿마다
  뒤집힌다(`260812_02` 좌상 52%/우상 0%, `250820_01` 4%/41%).
