# Implementation Plan

1. 현재 운영 Pages ID와 성공 후보를 읽기 전용으로 확인하고, 보존된 이용현황 검증 사본을 별도 새 폴더로 복사한다. node_modules·runs·출력/환경/캐시는 소스에서 제외하고 필요한 빌드 환경과 설치 의존성만 별도로 준비한다.
2. 교수 규칙 반영 전 baseline 빌드가 운영 후보 manifest와 정확히 같은지 검사한다. 검증된 네 파일을 반영하고 변경 allowlist/해시를 기록한다.
3. 교수/예습/최신 프롬프트 회귀, 공용 계약, 운영 기반 보존 및 production build를 scripts/development.py로 검증한다. release.md와 코드 리뷰에 실제 결과와 이전 Pages 복원 ID를 기록한다.
4. 고정 후보를 준비하고 현재 사용자 발언을 해당 후보 배포 승인 근거로 기록한다. check --phase deploy 후 release_evidence.py publish-web으로 실제 게시한다. 긴 Windows 경로는 같은 파일/디렉터리임을 확인한 짧은 경로로 전달한다.
5. 실제 운영 주소·Pages 주소·고유 배포 주소의 정적 파일을 후보와 대조하고 health·인증 경계·자료 조회를 읽기 전용 확인한다. 결과를 본 작업 기록에 보존하고 관련 보류/정책 기록을 최신 상태로 갱신한다. 실패 시 실제 영수증을 보존하며 무조건 재배포하지 않는다.

현재 사용자 명시적 웹 배포 지시는 위 동일 기능의 안전한 결합·검증·운영 게시를 포함한다. 추가 확인을 반복하지 않는다. 복원 대상은 배포 전 실제 현재 Pages a0edf1f4-981e-4568-8b5a-7c2ad1e54617이다.
