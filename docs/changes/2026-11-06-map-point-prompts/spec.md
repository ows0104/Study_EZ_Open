# Map와 독립 출제포인트 추출 지침 정리 — 설계

## 요구사항과 수용 기준
Map 요청문은 원본의 중심 질문·개념·의미 있는 관계·교차 연결·큰 흐름만 다룬다. 문제/문항/누락 판정/회상 평가/문항 학습 순서는 지시하지 않는다. 포인트는 원본 전체에서 회상·판단 목표, 단서→답 범위, 조건/예외/필요 방향과 중요도 근거를 추출한다. 문항 수에 맞추거나 모든 사실을 자동 분할하지 않는다.

## 책임·입출력 계약·오류 상태
같은 원본만 각각 제공하여 독립 추출한다. 출력 구체화 승인에 따라 Map은 개념·관계 목록의 JSON, 포인트는 목표·방향 목록의 JSON으로 작성한다. 버전·원본·범위·근거·불확실성을 보존한다. 문항 대응·누락 판단은 이후 별도 대조이며 원본 추출만으로 실제 누락 문항을 확정하지 않는다. 현행 자동 생성기 연결과 호출 분리는 이번 범위가 아니다.

최종 간소 형식 /2: Map은 overview, concepts(concept_id/title/core_facts/source_refs), relations(from_id/to_id/relation/source_refs), notes만 수집한다. 관계의 의미·중요한 방향/조건은 relation 문장으로 표현한다. 포인트는 points(point_id/point/source_refs), notes만 수집하며 point에 실제 인출·구별·적용 대상과 필요한 조건·방향을 구체적으로 적는다. 공통 헤더는 schema_version/title이다. 메타데이터 재작성·관계별 분류/판정 장부·목표별 중요도 점수/숙련도/반복량을 요구하지 않는다. 의미 있는 불확실성·범위 한계는 notes에 남긴다. 두 결과는 서로의 ID를 추출 입력으로 요구하지 않는다.

## 호환성과 데이터 보존
원본·범위·교수/연도·그림·불확실성 및 기존 문항/기록/검수 상한을 보존한다. 현행 learning-brief/2 및 PLAN JSON을 교체하지 않는다. 구조적 위치·시험·임상 중요성과 심화를 구별한다.

후속 예시 실행은 위 승인 범위의 원본 전용 Map·포인트 두 호출만 허용한다. 서로의 결과·기존 문제은행을 입력에 넣지 않는다. 각 최초 호출 이후 실패/중단은 자동 반복하지 않는다. 형식 통과와 의학적 정확성/독립 내용 검수 완료를 구별한다. 기존 운영 요청/원장/문항/학습 상태는 변경하지 않는다.

후속 포인트 개선은 새로운 사용자 요청으로 한 번 재추출한다. 하나의 의미 있는 단서→답 범위와 독립적 회상 가치를 기준으로 단위를 정하고, 목록/비교/과정 전체가 하나의 목표이면 유지한다. 같은 원본으로 기존 결과를 보지 않는 최초 추출1회와 결과/원본 대조1회를 수행한다. 대조가 실제 과도한 묶음·누락을 확인하면 이유를 보존하고 최대1회 보완과 재대조만 허용한다. 수를 늘리기 위한 분할/목표개수 설정은 하지 않는다. 이 횟수는 기존 문제은행 수정 상한을 변경하지 않는다.
