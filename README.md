# Study_EZ

의대생 공부를 돕는 사이트와 그 자료를 만드는 로컬 러너.

**서버는 아무것도 만들지 않는다. 만드는 건 전부 로컬, 서버는 배급만 한다.**
관리자 한 명이 만들고 결과물은 모두에게 똑같다. 그래서 작업 큐도 과금도 사용자별
생성도 없다.

```
 SynologyDrive/{과목}/필기/{2025,2026}/     시간표 JSON
        │                                      │
        └──────────────┬───────────────────────┘
                       ▼
            로컬 러너 (이 저장소)
            · 강의 인덱싱 · 작년 짝 붙이기
            · pdf2anki 실행 (덱을 만드는 자리)
            · 산출물 업로드
                       │
                       ▼
            Study_EZ 서버 → 웹 (캘린더가 홈)
```

## 이 저장소만으로 돌아간다

```
studyez/     로컬 러너 — 파일명 파싱, 연도 매칭, 워처, 업로드
studyez/deck.py   그 러너와 파이프라인의 유일한 접점
pdf2anki/    덱을 만드는 파이프라인. 명령 하나가 PDF에서 .apkg까지 간다
runs/        산출물. 원본 PDF에서 언제든 재생성된다 (저장소에 안 들어감)
server/      읽기 API + 관리자 업로드 (FastAPI, Cloud Run)
web/         정적 프론트 (Vite + React)
```

바깥 의존은 `PyMuPDF`·`genanki`·`jsonschema` 셋과, 이미 로그인된 `claude` CLI다.

## 만드는 자리에 사람이 안 들어간다

한동안 파이프라인의 가운데가 뚫려 있었다. 코드가 prep까지 하고 `runs/queue.json`을
남기면, **사람이 연 Claude Code 세션**이 `/quiz` 스킬을 돌려 문항을 만들고, 다시
코드가 빌드했다. 편당 53~72분이었고 그 시간이 세션의 컨텍스트를 통째로 먹었다.

`pdf2anki`는 모델이 필요한 자리마다 `claude -p`로 **빈 세션을 스스로 띄운다**
([pdf2anki/session.py](pdf2anki/session.py)). 이력도 설정도 도구도 없는 세션이라
이 저장소의 `CLAUDE.md`도 메모리도 딸려가지 않는다. 그래서 명령 하나로 끝난다.

```bash
python -m pdf2anki.run "<올해 필기 PDF>"
```

로컬 러너가 그 명령을 강의 단위로 부르고, 나온 것을 서버 계약의 모양으로 옮긴다
([studyez/deck.py](studyez/deck.py)). 파이프라인 자체의 사용법은
[pdf2anki/README.md](pdf2anki/README.md), 설계와 실패 기록은
[docs/pdf2anki.md](docs/pdf2anki.md)에 있다.

## 쓰는 법

```bash
python -m studyez jokbo 병리학         # 과목 족보를 강의별로 자른다 (학기당 1회)
python -m studyez match 병리학         # 올해 강의를 작년 강의에 붙인다
python -m studyez match --all

python -m studyez watch                # 새 필기를 훑고 무엇을 만들지 보여준다
python -m studyez watch --build        # 이대로 복습 덱까지 만든다
python -m studyez watch --all-dates    # 블럭으로 안 좁힌다 (밀린 것을 몰아 만들 때)

python -m studyez agent                # 러너. /admin의 「Pre-Quiz 만들기」를 기다린다
python -m studyez agent --once         # 한 바퀴만 — 붙는지 볼 때

python -m studyez prequeue             # 관리자가 저장한 예습 링크 → 자리 세우기
python -m studyez prequeue --build     # 이대로 예습 덱까지 만든다
python -m studyez preview <run_id> --url <공유 링크>   # 예습 대화 하나만 손으로

python -m studyez import --from ../PDF2ANKI/out   # 다른 곳에서 만든 덱을 옮긴다
python -m studyez release <run_id>     # 옮겨 온 덱의 보류를 푼다
python -m studyez rebuild              # 이미 만든 카드로 덱만 다시 굽는다
python -m studyez rebuild --reflag     # 검사 규칙이 늘었으면 표시도 다시 센다

python -m studyez done <run_id>        # 빌드를 확인한 뒤. 표시하고 그 편을 올린다
python -m studyez publish --all        # 아직 안 올라간 것을 전부 훑는다
```

Python은 PATH에 없다. Anaconda를 직접 부르고 한글 출력이 깨지므로
`PYTHONIOENCODING=utf-8`을 붙인다.

```bash
PYTHONIOENCODING=utf-8 "$USERPROFILE/anaconda3/python.exe" -m studyez watch
```

### 두 덱은 방향이 반대다

복습 덱(Main-Quiz)은 **필기가 올라오는 것**에서 시작한다. 예습 덱(Pre-Quiz)은
**사람이 예습하는 것**에서 시작한다 — 관리자가 작년 강의록으로 AI와 예습하고 그
대화를 `/admin`에 저장하면, 거기서부터 자동이다.

```
관리자가 /admin에 예습 링크 저장
  → studyez prequeue           작년 짝 고르기 · preview.md
  → studyez prequeue --build   pdf2anki.prequiz가 덱을 만든다
  → studyez publish            덱·문항·링크가 함께 올라간다
```

**`publish`는 올리기 전에 링크를 서버에서 먼저 당겨 온다.** 이 저장소에서 방향이
반대인 것은 예습 링크 하나뿐이라(사람이 `/admin`에 저장하므로 서버가 원본이다),
당겨 오지 않으면 `preview.md`에 적힌 **옛 주소를 서버에 덮어쓴다** — 관리자가 방금
바꾼 링크가 조용히 되돌아간다. `--no-prequeue`로 끄고, `--dry-run`이면 안 한다.

맞춘 뒤에도 덱은 옛 대화로 만든 것일 수 있다. 그런 편은 **링크만 내보내고 Pre-Quiz는
미룬다**(`publish.hold_pre`). 반대로 하면 학생이 읽고 온 대화와 문항이 어긋난다.
미룬 편은 다음 `prequeue --build`가 다시 만든다.

`prequeue`는 멱등이다. `preview.md`에 적힌 출처가 서버의 링크와 같으면 그대로 두고,
`pre_items.final.json`까지 있으면 `done`으로 적어 건너뛴다. 링크가 바뀌었는데 덱이
이미 있으면 `stale`로 적는다 — 그 덱은 다른 대화로 만든 것이라 다시 만들어야 한다.

**예습 덱의 이름은 올해 강의로 선다.** 작년 필기로 만들지만 학생은 올해 캘린더를
보고 예습을 하기 때문이다. 아직 필기가 없어 시간표에만 있는 강의도 거기서 온다.
그래서 예습과 복습이 Anki에서 한 노드 아래 모인다.

```
병리학
└ [260824_01] 종양의 병태 생리(2) 종양의 분자생물학(1)(전윤경)
   ├ 예습     ← 작년 필기 + 예습 대화
   ├ 강의록   ← 올해 필기
   └ 기출     ← 족보
```

**덱 이름과 파일 이름은 같은 꼴이다**(`studyez.deck.deck_node`). 둘이 다르면
Anki에서 본 것과 받아 둔 파일을 맞춰 보는 일이 사람 몫이 된다.

### 만드는 것은 버튼이 시작한다

> **2026-08-23에 야간 크론을 걷어냈다.** `21:30 · 04:00 · 06:00`으로 돌던 작업 셋을
> 지웠고, 그 자리에 **관리자가 누르는 버튼과 종일 떠 있는 러너**를 놓았다. 지워진
> 스케줄 배선은 `scripts/install-scheduled-task.ps1`에 그대로 있다 — 등록만 안 되어 있다.

```
관리자가 /admin에서 예습 링크 저장 → [Pre-Quiz 만들기]
  → POST …/prequiz-job              일감 한 줄 (서버)
  → 러너가 15초마다 집어 간다        POST …/prequiz-jobs/claim (노트북)
  → prequeue --build → publish
  → PUT …/prequiz-jobs/<id>         queued → running → done|failed
  → /admin이 단계를 그대로 보여 준다
```

| 언제 | 무엇이 | 무엇을 |
|---|---|---|
| 사람이 누를 때 | `/admin`의 「Pre-Quiz 만들기」 | 그 한 편을 만들고 올린다 |
| 편이 끝날 때 | `studyez done <run_id>` | 그 한 편 |
| 10분마다 | 러너가 스스로 | 놓친 것을 쓸어 올린다 (`publish`) |

**왜 크론을 걷어냈나.** 빌드가 아니라 **실패를 알리는 일**을 못 했다. 06:00 쓸기는
2026-08-18부터 나흘 연속 「강의 0편 · 올릴 것이 없다」로 끝나면서 종료 코드 0을 냈고,
아무도 몰랐다. 같은 날 예습 빌드는 `0xC000013A`(강제 종료)로 죽었는데 로그에는
머리글만 남았다 — 그 스크립트가 **자식이 끝난 뒤에야** 로그를 쓰기 때문이다.

넷 다 04:00·06:00이 아니라 **깨어난 직후 따라잡기 회차**(09:15 · 06:48 · 07:15 · 06:56)
였다. 노트북이 그 시각에 자고 있었고, 깨어나면 밀린 둘이 같은 초에 동시에 쐈다 —
"만드는 것이 먼저"라는 순서가 깨어나는 날마다 깨졌다.

**사람이 누른 일감은 다르다.** 화면에 줄이 남고, 끝나지 않으면 끝나지 않은 채로
보인다. 러너가 안 떠 있으면 `/admin`이 그렇게 말한다.

```bash
powershell -ExecutionPolicy Bypass -File scripts\install-agent-task.ps1
powershell -ExecutionPolicy Bypass -File scripts\install-agent-task.ps1 -Subject 병리학
powershell -ExecutionPolicy Bypass -File scripts\install-agent-task.ps1 -Remove
```

로그온 5분 뒤에 뜬다. **깨어난 직후를 피하는 것이 뜻이 있다** — 실패한 넷이 전부
그 시각이었고, 한 회차에서는 2초 사이에 자료 폴더가 보였다 안 보였다 했다. 러너는
계속 떠 있으므로 5분 늦는 것으로 잃는 것이 없다. 로그는 `runs/agent.log`이고
흘려 쓴다. 로그온해 있어야 돈다.

**복습 덱은 아직 버튼이 없다.** 편당 Opus 호출이 여러 번이라 비용을 먼저 재기로
했다(`runs/<run_id>/run.report.json`의 `cumulative.cost_usd`). 그때까지는
`studyez watch --build`를 손으로 부른다.

### 러너가 스스로 지키는 것

- **한 번에 한 편.** 한 편이 이미 빈 세션 넷을 띄운다. 서버도 `running`이 있으면
  새 일감을 안 준다
- **성공을 종료 코드로 안 본다.** `prequeue`는 만들 자리가 없어도 0으로 끝난다 —
  배선 시험에서 아무것도 안 만들고 「덱을 만들었다」가 찍혔다. 지금은
  `pre_items.final.json`이 **이번 실행에서** 나왔는지로 가른다
- **검문에 걸린 것은 성공으로 적되 이유를 남긴다.** 강의록만 나가는데 화면이
  「올라갔다」고만 말하면 학생에게는 아무것도 안 간 것을 모른다
- **멈추면 끊는다.** `--timeout`(기본 3시간)을 넘기면 그 편을 버리고 실패로 적는다
- **못 적어도 하던 일은 계속한다.** 서버가 잠깐 안 뜬 것 때문에 다 만든 덱을
  버릴 이유가 없다

### 왜 블럭으로 좁히나

`필기/<올해>` 폴더는 학기가 바뀌어도 그대로 남는다. 좁히지 않으면 스캔이 그 폴더를
전부 훑고 **날짜 오름차순으로** 자르기 때문에 지난 학기 필기가 먼저 걸린다 —
2026-08-17 밤 자동 실행이 조직학 3월 6편을 prep까지 끌고 갔고, 그날 올라온 병리학은
한 편도 안 잡혔다.

그래서 `studyez/blocks.py`가 **오늘 날짜로 시간표에 물어** 이번 블럭의 구간을 정하고,
그 안에 든 강의만 큐에 세운다. 시간표를 못 읽거나 오늘이 어느 블럭에도 안
들어가면 **큐를 세우지 않고 2로 끝난다.** 열어 두는 쪽이 훨씬 비싸다.
사람이 `--since`/`--until`로 구간을 주거나 `--all-dates`로 푼다.

## 다루지 않는 과목

**선택교과와 인간사회의료는 파이프라인에서 뺀다.** 시험을 보지 않고, 학생마다 듣는
과목이 달라 캘린더가 뒤섞인다. 강의록 연결도, 예습도, 복습 덱도 만들지 않는다.

인간사회의료는 **한 교시에 강의가 셋씩 열린다.**

```
[260303_02] 역사 속의 감염병(김옥주, 이규원)
[260303_02] 질병사 관점에서 신종-재출현 감염병 (송진수)
[260303_02] 건강과 질병(박영수)
```

`studyez/filenames.py`의 `EXCLUDED_SUBJECTS`(정확한 이름)와 `EXCLUDED_PREFIXES`
(`인간사회의료 1`·`2`처럼 번호가 붙어 늘어나는 것)에 있고, 이름을 직접 대도 막힌다.
`# 교과서`, `# 족보 오류토의`처럼 `#`·`_`로 시작하는 폴더도 과목이 아니므로 뺀다.

## 자료의 모양

파일명이 곧 계약이다.

```
[260813_03]조직 재생 및 수복(2)(김혜령)_최나예v1.pdf
 └──┬──┘└┬┘└──────┬──────┘└─┬──┘ └─┬─┘└┬┘
   날짜  교시      제목       교수   필기자 판
```

교시는 09:00부터 세고 04가 점심이라 시각은 `교시 + 8`시다.

실물에서 확인한, 규칙을 배신하는 것들:

- **`날짜_교시`는 유일하지 않다.** 선택형 과목은 한 교시에 여러 강의가 동시에
  열린다. 실제 식별자는 `날짜_교시 + 제목어간 + 교수`(`uid`)다
- **괄호는 두 가지다.** 숫자면 순번, 한글이면 교수. 같이 지우면
  `조직 재생 및 수복(1)`과 `(2)`가 한 강의로 뭉개진다
- **파일명 일부가 NFD로 저장돼 있다.** 화면에는 똑같이 보이지만 `[가-힣]`
  정규식이 통째로 실패한다
- 같은 강의의 v1·v3이 공존하고, Synology 충돌 사본과 연도가 어긋난 파일이 섞인다

이 전부를 `studyez/filenames.py`가 처리하고, 읽지 못한 파일은 **반드시 이유와
함께 보고한다.**

## 족보

`{과목}/족보/{연도}/`에 교실이 공개한 원본 족보 PDF가 있다. 필기에 붙은 캡처본과
비교가 안 된다.

```
병리학 2026 족보  122쪽 · 텍스트 레이어 살아 있음(평균 1,646자/쪽) · OCR 불필요
                 p4~  "1  병리학 소개 – 과거, 현재, 미래" 로 강의별 분류
                 p78~ 실습 시험 블록 (같은 강의 번호를 다시 훑는다)
```

`studyez jokbo <과목>`이 `pdf2anki.jokbo`를 불러 이걸 강의별 조각으로 자르고
`runs/_jokbo/<과목>/`에 둔다. 문항·정답·이의제기를 짝지어 붙이고 연도별 반복률과
교수 교체 여부까지 계산해 두므로, 그 판정이 복습 덱의 전략(필기 중심이냐 족보
중심이냐)을 가른다.

**어느 조각을 어느 강의에 물릴지는 로컬 러너가 정하지 않는다.** pdf2anki가 카드를
만들 때 목차 제목으로 대조한다. 두 곳에서 각각 짝지으면 카드가 본 조각과 뒷면에
붙는 조각이 갈릴 수 있다.

**올해 필기에도 족보가 붙어 있고, 그게 작년 필기의 족보를 포함한다**(`260812_01`
실측: 작년 18문항이 올해 족보에 100% 포함). 그래서 복습 덱은 올해 필기만 쓴다.
작년 자료를 끌어올 일은 예습 덱뿐이다.

## 색

**색은 아예 읽지 않는다.** 병리학 2026 15편에서만 서로 다른 색이 31종 나왔고,
필기자마다 도구도 규약도 달라 같은 색이 정반대를 뜻한다. 회색이 사담일 때도 있고
"이 부분은 시험에 안 낸다고 하셨습니다" 같은 결정적인 말일 때도 있다.

**뜻은 색이 아니라 글에 있다.** 그래서 필기 본문은 그대로 싣고 색은 버린다.
남겨 두면 쓰이고, 쓰이면 근거로 둔갑한다.

## 배포는 검문을 통과한 것만 자동으로 나간다

`publish`가 편마다 [studyez/gate.py](studyez/gate.py)에 물어보고, 막힌 편은
**강의록만 내보내고 덱·run-meta·예습은 미룬다.** 통째로 멈추지 않는 이유는
강의록이 그 검토와 무관한 자료이고, 먼저 나가야 캘린더 칸이 열리기 때문이다.

**파이프라인이 이미 막는 것은 여기서 다시 막지 않는다.** pdf2anki는 질문만 보고
다시 푼 답이 원래 답과 갈리고 그 사유가 문항 결함이면 그 카드를 다시 쓰게 하고,
그래도 안 되면 빌드를 거부한다. `.apkg`가 있다는 것 자체가 그 검사를 지났다는 뜻이다.

그래서 검문은 **산출물이 스스로 주장하는 것과 다른 경우**로 좁혀 있다 — apkg를
다시 열어 센 노트 수가 `item_count`와 다를 때, 카드가 부르는 이미지가 패키지에
없을 때, `run.meta.json`이 없을 때, 그리고 사람이 `HOLD`를 놓아 두었을 때.

`slides_unused`·`untouched_slides`·검토 표시 총계로는 **막지 않는다.**
CLAUDE.md "계수기는 아직 사람을 부를 줄 모른다"가 그 후보들을 이미 떨어뜨렸다.
적어서 보고에 올릴 뿐이다.

## 저장소에 없는 것

강의 PDF와 `runs/`는 들어가지 않는다. 제3자 저작물이고, 산출물은 원본에서 언제든
재생성된다.
