# Main-Quiz 새로 출제

## 문제와 사용자 효과
실패·중지된 Main-Quiz 판이 있으면 관리자 화면에 「이어서 만들기」만 있다. 서버는 같은 입력(같은 S1·S2·pipeline·공개 범위)의
새 요청을 받지 않고 그 실패 판을 돌려준다. 이어 하기는 그 판의 문항별 수정 상한(2회)·빈 목표 추가(2회) 안에서만 움직인다.

계기: 아데노·폭스바이러스(감염과 면역 261110_02) 판 `6e5c581a…`는 목표 중요도 근거 중복으로 보류됐다(#103으로 수정).
이 판은 이미 추가 2회를 썼고 수정 받은 123문항 가운데 51문항이 상한 2회를 다 썼다. 그 사이 /4 생성기가 여러 번 바뀌어
(#94·#92·#103·#106 등) 관리자는 최신 파이프라인으로 처음부터 다시 만들고 싶다.

사용자 2026-11-11: 「파이프라인이 완전 바뀌어서 처음부터 만들어야할 거 같은데?」 → 「어 새로 출제 버튼을 만들어줘」.

## 범위와 성공 기준
- 실패·중지된(공개 전) 판이 화면에 보일 때 「이어서 만들기」 옆에 「새로 출제」 버튼이 있다.
- 누르면 같은 강의·최신 파이프라인(map-tree/3)으로 **새 생성 작업**이 등록된다. 새 생성 ID·새 러너 폴더라 수정·추가 횟수를 처음부터 받는다.
- 옛 판의 DB 행·러너 산출물·실패 기록·이어 하기 이유는 그대로 남는다. 새 판은 어느 판을 대신하는지(`restartOf`)와 이유를 기록한다.
- 이미 공개된 판이 있으면 지금처럼 거절한다(판 교체는 별도 승인). 진행 중인 작업이 있으면 거절한다.

## 근거·미정 사항
- CLAUDE.md 「기존 출제·검수 상한은 재실행으로 초기화하지 않는다」의 명시적 예외다. 예외는 관리자가 이유를 적고
  버튼을 누른 그 강의 한 번에만 적용된다(이어 하기 이유와 같은 방식). 자동 경로·재시도는 상한을 새로 받지 않는다.
- 버튼은 승인 문구에 적힌 대로 S1·S2를 OpenAI Codex CLI로 다시 보낸다. 이 버튼이 그 강의 전송의 승인이다(2026-11-09 결정과 같은 방식).
