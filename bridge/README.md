# Study EZ 예습 브리지

작년 필기와 예습 프롬프트를 **ChatGPT·Gemini·Claude 새 대화에 직접 채우고**, 만들어진 개인·공유
링크를 강의에 되돌려 주는 크롬 확장입니다.

웹페이지는 남의 사이트에 파일을 첨부할 수 없습니다. 그래서 이것이 없으면 학생이
직접 PDF를 내려받아 첨부하고 프롬프트를 붙여넣어야 하고, 만든 대화의 링크도
손으로 옮겨 적어야 합니다. 이 확장은 그 셋을 없앱니다.

캘린더에서 AI를 고르면 같은 자료와 프롬프트가 해당 서비스로 갑니다. 개인 대화는
사용자별로, 공개 공유 링크는 강의별 기본 링크로 저장됩니다.

## 설치

1.3.9는 재첨부로 파일명에 `(1)` 같은 번호가 붙어도 업로드 완료를 확인합니다.
32MB 이상의 첨부는 최대 10분 기다리며, 업로드 완료와 전송 준비가 확인된 경우에만 한 번 전송합니다.

1.3.8은 이미 동의한 경우 작은 박스에 동의 상태 문구를 표시하지 않습니다.
기억된 동의의 반복 설명과 체크박스는 접고, 자료·개인정보 처리와 동의 해제는
‘자세히’에서 확인합니다. 처음 동의할 때는 체크박스와 설명을 표시합니다.

직접 전송하는 예습·복습·문제은행은 웹스토어 공개판 1.2.0으로 사용할 수 있습니다.
예습과 복습의 자료·프롬프트 및 저장 위치는 사이트가 구분합니다. 복습 구분을
모르는 구버전에도 사이트가 개인 대화 요청을 보내고 결과를 복습에 연결합니다.
자동전송은 1.3.3 이상이 필요합니다. 버튼·프롬프트를 바꾸는 것만으로 확장
업데이트가 필요하지 않습니다.

1. Chrome에서 `chrome://extensions`를 엽니다.
2. 오른쪽 위 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 누릅니다.
4. 이 `bridge` 폴더를 고릅니다.
5. Study_EZ 탭을 새로고침합니다.

소스를 고친 뒤에는 `chrome://extensions`의 카드에서 새로고침을 누르고 Study_EZ
탭도 새로고침해야 합니다.

1.3.4는 확장 업데이트 뒤 남은 페이지에서 연결이 끊겨도 오류를 처리하고
새로고침을 안내합니다. 이때는 **Study EZ와 열려 있는 AI 대화 탭을 모두
새로고침**하세요. 공유 주소는 공유 대화상자의 입력·링크·텍스트에서 읽으며,
복사 버튼만 있는 화면에서는 해당 대화의 공유 기록을 확인합니다. 링크 생성·공개
확인에 실패하면 30초부터 최대 2분 간격으로 재시도합니다.

Chrome Web Store 등록용 ZIP은 개발용 ZIP과 분리합니다. 로컬 주소를 제거하고
manifest가 ZIP 루트에 있는지 검증하는 `build-store-package.ps1`을 실행하세요.

```powershell
.\bridge\build-store-package.ps1
```

## 어떻게 도는가

```
Study_EZ 패널에서 "예습 시작하기"
  └ 웹앱이 서명 URL을 받아 STUDYEZ_OPEN_PREVIEW를 postMessage
      └ studyez-bridge.js → background.js
          ├ 자료 주소를 허용 목록으로 검사 (R2 또는 로컬 산출물 경로만)
          └ 선택한 AI 새 탭을 열고 자료를 세션 저장소에 넣음
              └ chatgpt-bridge.js(공통 입력 브리지)가 확인 카드를 띄움
                  ├ 첫 실행이면 자동 첨부·전송 및 결과 저장에 동의
                  │   (AI 서비스·모드별로 기억. 다음부터 3초 후 자동 시작. "자세히"에서 해제)
                  ├ 배경이 PDF를 받아 조각으로 넘김
                  ├ input[type=file]에 DataTransfer로 첨부
                  └ 프롬프트 삽입 → 모든 첨부 파일명·업로드 상태·전송 버튼 확인 → 자동 전송
                      └ 제공자별 링크 감시가 답이 끝나기를 기다림
                          ├ 개인 대화 주소를 냄
                          └ shared면 공개 공유를 만들고 비로그인 접근을 확인한 뒤 냄
                              └ 웹앱이 저장 → 확장에 확인 → 대기 목록에서 삭제
```

**저장 확인이 오기 전에는 링크를 지우지 않습니다.** 탭이 닫혔거나 잠들어 전달이
실패해도 다음 기회에 다시 보냅니다.

1.3.3부터 예습·복습 모두 **수동입력**과 **자동입력** 버튼을 따로 제공합니다.
수동입력은 확장 카드에서 자료·프롬프트를 넣고 사용자가 직접 전송합니다. 자동입력은 첨부와 전송까지 진행합니다.
두 방식의 동의는 별도로 저장합니다. 예습에는 작년 필기와 올해 강의에 연결된 족보 조각을 함께 첨부합니다.
올해 필기가 아직 없는 강의도 시간표의 제목·교수로 족보를 찾아 업로드합니다. 족보가 없으면 화면에 표시합니다.

1.3.0부터 Study EZ에서 시작한 요청을 자동 첨부·전송합니다. 이전 수동 전송 동의는
자동 전송 동의로 사용하지 않으므로 업데이트 후 서비스·모드별로 한 번 다시 동의합니다.
전송 전 카드의 ×나 동의 해제를 누르면 이후 자동 진행을 중지합니다. 이미 첨부한
파일은 입력창에 남을 수 있고, 전송된 메시지는 취소되지 않습니다.

1.3.1은 ChatGPT의 문단 간격을 프롬프트 수정으로 오인하던 문제를 고쳤습니다.
입력창이 다시 만들어져도 현재 입력창의 내용을 확인하며, 실제 내용 변경 시에는 계속 중지합니다.

1.3.2부터 기억된 동의도 체크된 체크박스로 계속 표시합니다. 자동 시작은 유지하며,
동의를 취소하려면 **자세히 → 동의 해제**를 누릅니다.

첨부 준비가 1.5초 동안 유지될 때만 전송합니다. 2분 안에 준비를 확인하지 못하거나
입력 내용/대화 화면이 바뀌면 멈춥니다. 전송 클릭 뒤 접수 여부가 불명확해도 재전송하지
않습니다. 오류 카드가 남으면 AI 화면을 확인해 직접 처리하거나 Study EZ에서 새 대화로
시작합니다. 로그인 만료, 서비스 화면 변경, 잘린 답의 이어 생성은 무인 복구하지 않습니다.

검사: `node --test tests/bridge/test_autosend.cjs` 및 `python -m pytest tests/bridge`.
`tests/bridge/autosend-browser.html`은 모의 AI 입력창에서 동의·첨부·전송을 검사하는
브라우저용 테스트입니다. 저장소 루트를 로컬 HTTP로 제공한 뒤 열며 외부 AI에는 전송하지 않습니다.

## 두 가지 링크

`preview`와 `user_preview`의 링크 칸에 들어갑니다.

| 종류 | 저장되는 칸 | 누가 열 수 있나 |
|---|---|---|
| `chatgpt`·`gemini`·`claude` | `user_preview.conversation_url` | 만든 계정만 |
| `*_share` | `preview.share_url` | 링크를 가진 누구나. **Pre-Quiz의 재료** |

대화 주소만으로는 반 친구에게 죽은 링크입니다. 공유 링크를 따로 만드는 이유가
그것이고, `runner preview`가 읽는 것도 이쪽입니다.

**둘 다 확인한 뒤에만 냅니다.** 주소가 생긴 것은 성공이 아닙니다 — 공유는 아직
비공개 초안일 수 있고, 대화는 주소창에 `/c/…`가 떠 있어도 실제로는 안 만들어져
있을 수 있습니다. 확인을 못 지나면 저장하지 않고 콘솔에 어디서 걸렸는지 남깁니다.

공개 기본 링크 저장은 관리자만 성공합니다. 개인 대화 링크는 승인된 사용자라면
누구나 자기 `user_preview`에 저장할 수 있습니다.

Claude와 Gemini의 공개 공유는 각 서비스가 화면에 공유 기능을 제공할 때만 됩니다.
특히 Gemini는 계정 정책이나 첨부 자료 종류에 따라 공유 버튼을 숨길 수 있습니다.
그 경우에도 개인 대화 주소 저장은 정상 동작합니다.

## 기본 링크가 404로 보일 때

**대개 링크가 아니라 여는 계정 문제입니다.**

`/share/` 주소는 로그인 없이 열립니다. 그런데 ChatGPT Enterprise/Edu 워크스페이스
계정으로 로그인한 채 열면 요청이 그 워크스페이스 범위로 들어가 404가 납니다.
실제로 그렇게 한 번 헤맸습니다 — 개인 계정이 만든 공유를 학교 계정에서 열어
404를 보고 공유가 안 만들어진 줄 알았는데, 시크릿 창에서는 멀쩡히 열렸습니다.

가르는 법은 하나입니다. **시크릿 창으로 그 링크를 열어 보세요.**

| 시크릿에서 | 무엇 |
|---|---|
| 열린다 | 공유는 정상. 여는 쪽 워크스페이스 정책이다 |
| 404 | 공유가 공개로 안 바뀐 것. 아래를 보라 |

두 번째는 이제 잘 안 나옵니다. `chatgpt-share.js`가 주소를 얻은 뒤 **쿠키 없이
한 번 받아 보고 200일 때만** 웹앱에 넘기기 때문입니다. `/share/create`는 비공개
초안만 만들고 공개로 바꾸는 것은 그다음 PATCH인데, 그게 안 먹어도 주소는 멀쩡히
생깁니다 — 만든 사람은 자기 초안이라 열리고 남은 404를 봅니다. 확인을 못 지나면
저장하지 않고 콘솔에 어느 단계에서 걸렸는지 남깁니다.

## 개인 링크를 눌렀는데 빈 ChatGPT 창이 뜰 때

**주소는 저장돼 있는데 그 대화가 없는 경우입니다.**

0.1.0까지는 주소창에 `/c/<id>`가 뜨는 순간 그것을 저장했습니다. 그런데 그 주소는
대화가 있다는 뜻이 아닙니다 — 보내기 전에도 뜨고, 못 보내면 그 id로는 아무것도
안 남습니다. 그렇게 저장된 주소를 나중에 열면 대화가 아니라 빈 창이 뜹니다.
공유 쪽에서 이미 한 번 겪은 것과 같은 실수입니다(`d68cefa`).

0.2.0부터는 `chatgpt-share.js`가 답이 하나 끝나기를 기다렸다가 **그 대화를 이
계정으로 한 번 받아 본 뒤에** 냅니다. 못 받으면 저장하지 않고 다시 시도합니다.

이미 저장된 옛 주소는 그대로 남아 있습니다. 패널의 **"새 대화로 다시 시작"** 을
누르면 새 대화로 갈아탑니다.

새 주소인데도 빈 창이면 여는 계정 문제입니다. `/c/`는 만든 계정에서만 열리므로
ChatGPT 계정이나 워크스페이스를 갈아탔으면 자기 대화도 안 보입니다.

## 보안 범위

- Study_EZ 주소에서 온 요청만 받습니다 (`background.js`의 `WEBAPP_ORIGINS`).
- 자료는 서명된 R2 주소나 로컬 테스트 서버의 `/api/local-storage/lectures/` 아래에서만
  내려받습니다. 웹앱이 시키는 주소로 fetch하므로 이 허용 목록이 유일한 관문입니다.
- 공유 링크는 감시 기록에 적힌 강의에만 붙습니다. 페이지가 아무 강의에나 링크를
  달 수 없습니다.
- 검색 노출(`is_discoverable`)은 끕니다. 링크 밖으로 새지 않습니다.
- **자동 전송에 동의한 서비스·모드에서만 준비 상태를 확인한 뒤 한 번 전송합니다.**
- ChatGPT 액세스 토큰은 ChatGPT 대화·공유 요청에 메모리에서만 쓰고 저장하거나 Study EZ로
  보내지 않습니다.

배경이 요청을 안 받거나, 그 반대가 됩니다.

- `background.js`의 `WEBAPP_ORIGINS`
