# 콜린성 약리학(1) 뿌리 시범 검토 — 구현 계획

## 변경 범위·대상 파일·순서

상태: 로컬 시범 자료 분석과 검토 초안 작성 계획에 사용자가 동의한 뒤 웹/CLI 비교를 먼저 요청했다.
현재는 [실행 경로 검토](execution-strategy.md)를 우선하고 시범 실행은 시작하지 않았다.
역할 배치에 따른 실질 변경과 기존 동의 범위를 구분한다. 앱 구현과 운영 반영 승인은 별도다.

사용자의 웹 이용 조건 확인과 2026-10-31 “오케이. 그러면 진행해볼까? 한번 파이프라인을 보여줘봐.”에 따라
원본 기반 작성은 웹, 후처리·필수 대조·연결은 코드/CLI에 배치한 [pipeline.md](pipeline.md)를 제시한다.
아래 순서를 해당 역할로 수정했다. 2026-10-31 후속 진행 요청에 따라 두 웹 요청 문서와 검토용 파일 계약을 작성했다.
첫 뿌리 파일을 사용자가 직접 내려받아 로컬 검토 자료로 전달하는 절차는 [next-step.md](next-step.md)를 따른다.
보조 파일 구현·웹 전송·새 추출은 미실행이다. 현행 bridge의 자동 수신이나 운영 bank-response를 사용하지 않는다.
실행 전에는 웹 출력 계약·실제 검토 입력과 범위·실행 근거를 구체화한다. 이전 동의를 앱 구현·운영 승인으로 확대하지 않는다.

### 실행 범위

콜린성 약리학(1) 한 강의의 필기 전체와 연결 족보에서 뿌리 후보·관련 포인트를 각각 추출하고,
기존 69문항을 읽기 전용으로 대조해 사용자가 검토할 설계 초안을 만든다. 새 전체 은행을 생성하지 않는다.

### 대상 파일

- 입력: [sources.md](sources.md)의 올해 필기·교수별 합본 족보 조각·지면 확인용 원본 PDF 및 고정한 로컬 은행.
- 새 로컬 전용 보조 파일: `work/concept-tree-cholinergic-20261029/run_review.py`, `check_review.py`.
- 새 입력/결과: 같은 작업 폴더의 `inputs/`, `raw/`, `roots-draft.json`, `points-draft.json`, `coverage-draft.json`, `review.md`, `checks.json`.
- 사용자의 검토 결과와 실행 범위만 이 변경 기록에 갱신한다. 기존 문제은행·생성기·서버·웹·공용 프롬프트를 고치지 않는다.

### 순서

1. 원본의 현재 지문·지면 수와 합본 족보의 출처를 확인하고 전용 입력 목록을 고정한다. 필기/족보 그림·표를 지면과 함께 읽을 자료를 준비한다.
2. 사용자가 수동 전송하는 원본 전용 웹 대화에서 뿌리와 큰 구조를 제안받는다. 기존 은행·옛 포인트·옛 트리는 입력에서 제외한다.
3. 별도의 원본 전용 웹 대화로 뿌리 관련 출제 포인트·족보 근거를 추출한다. 이전 뿌리 결과나 기존 문제에서 목록을 역으로 만들지 않는다. 완성 원문·출력 구간을 회수하고 일반 코드의 구조 검사 후 CLI 대조로 넘긴다.
4. 위 두 결과와 기존 은행을 처음으로 대조한다. 포인트별 실제 시험 방향과 해당 문제 ID, 부분/미충족, 합본 범위의 불확실성을 기록한다. 기존 문항 내용·등급·검수 판정은 바꾸지 않는다.
5. 뿌리에서 큰 가지로 이어지는 순서 초안과 첫 학습 흐름을 작성한다. 없는 뿌리 질문은 검토용 후보만 작성하고 은행에 넣지 않는다. 세부 Tree 전체·강의 간 연결·전 강의 출제는 하지 않는다.
6. 기계적 출처·참조·보존 점검 후 `review.md`로 원본 근거·뿌리·문제 대조·사용자 판단이 필요한 지점을 제시한다.

원본 전용 추출 두 건과 대조·순서 작성은 역할이 다른 검토 초안 작성이다. 기존 은행의 추가 수정·검수
차수로 실행하지 않는다. 각 저작 역할은 1회씩 수행하고 원문·오류를 보존한다. 불완전 결과는 재실행으로
기존 횟수를 초기화하지 않으며 범위 재검토 없이 추가 의학 검수 루프를 만들지 않는다.

모델 호출은 기존 `studyez_llm.codex` 어댑터와 기본 모델 설정을 사용한다. 이번에 구현할 보조 파일은
작업 폴더에만 두고 원본 입력·CLI 출력·참조 검사 연결만 맡는다. 의학 내용과 검수 판정을 수동 수정하지 않는다.

## 검사 명령과 성공 조건

아래는 승인 후 보조 파일과 결과를 만든 뒤 실행할 계획이다. 현재 해당 파일과 결과는 없다.

`python`은 저장소 루트의 `.venv/Scripts/python.exe`를 사용한다.

| 체크 | 계획한 명령 | 성공 조건 |
|---|---|---|
| source-identity | `python work/concept-tree-cholinergic-20261029/check_review.py source-identity` | 실제 입력 지문·지면 수·합본 범위·독립 입력 목록을 기록하고 기존 기준과 비교. 새 추출과 기존 색인의 출처를 구분 |
| independent-roots | `python work/concept-tree-cholinergic-20261029/check_review.py independent-roots` | 원본 전용 추출에 기존 은행·색인이 입력되지 않았고 뿌리·포인트별 근거와 불확실성이 있음 |
| coverage-mapping | `python work/concept-tree-cholinergic-20261029/check_review.py coverage-mapping` | 참조 ID가 실제 존재하고 각 포인트의 대조 상태가 있음. 미배정·부분 충족·근거 부족을 성공으로 숨기지 않음 |
| preservation | `python work/concept-tree-cholinergic-20261029/check_review.py preservation` | 원본·기존 은행·재개/검수 기록의 전후 지문이 유지되고 변경 파일이 작업 전용 범위 안에 있음 |

이 검사는 참조·보존·실행 계약의 검사이며 의학 내용의 정답성이나 뿌리 선정의 교육적 적절성을 자동
증명하지 않는다. 원본과 작성 결과의 근거·불확실성은 별도 CLI 결과에 남기고 사용자가 검토한다.
앱 기능·운영 로그인·채점·저장 검사는 이 로컬 검토 계획의 성공 조건에 포함하지 않는다.

## 위험·복원·승인할 범위

- 실행 범위: 위 한 강의의 원본을 웹에서 독립 작성하고, 회수 결과를 CLI로 대조하며 로컬 전용 보조 파일·설계 검토 초안을 작성하는 작업. 웹 전송은 사용자 수동이다. 실제 실행 전에 출력 계약과 기존 동의 적용 범위를 기록한다. 기존 내용의 교체나 앱 구현·배포는 포함하지 않는다.
- 위험: 합본 족보 범위 오인, 문항 색인을 독립 포인트로 오인, 원본의 그림/필기 누락, 초안을 검수 완료로 오인. 원본 근거와 출처·미해결 표시로 구분한다.
- 지문이 예상과 다르거나 입력이 불명확하면 실제 차이를 기록하고 해당 부분을 보류한다. 자료를 자동 교체하거나 개인 기록을 연결하지 않는다.
- 복원: 기존 자료를 수정하지 않는다. 새 파일은 전용 경로에 남기고 앱은 종전 상태를 유지한다. 결과를 쓰지 않기로 해도 원문·실행 이력을 삭제하지 않는다.
- 현재는 파일 탐색·일부 지문 확인·문서와 실행 경로 분석만 수행했다. 모델 저작·새 추출·보조 파일 구현·제품 변경은 미실행이다. 실제 실행 전 현재 계획의 지문과 사용자 동의의 적용 범위를 개발 절차에 맞춰 기록한다.
