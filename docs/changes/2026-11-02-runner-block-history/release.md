# 러너 현재 블럭 화면과 이전 기록 분리 — 배포 준비

## Review와 Test

현재 블럭의 과목·강의 복합 키로 기본 화면의 서버 상태·진행 카드·일괄 작업·완료/오류 집계를 제한한다.
서버 작업은 현재 갈래의 최신 상태로 집계한다. 지난 실패 시도가 현재 성공 뒤에도 오류로 남지 않는다.
등록된 로컬 작업은 알려진 과목 정보도 유지하여 같은 ID의 다른 과목을 구분한다.

이전 기록 조회는 기존 러너 인증과 읽기 전용 DB 트랜잭션을 사용한다. 최근 50개 제한 없이 조회하며
작업 ID·원문 상태/메시지·생성/시작/완료 시각·제목을 보존한다. 계정 식별자는 조회본에 중복 복사하지 않는다.
보관은 runs/_history/runner/history-<내용해시>.json에 추가 저장한다. 같은 내용은 재사용하고 변경본은 별도 보존한다.
원본 runs/work/DB/HOLD/CHOSEN과 생성 작업은 이동·삭제·상태 변경하지 않는다.

- runner: 전체 514개 통과(500 + 프로그램 GUI 12 + 기존 상태 GUI 2).
- desktop-db: 60개 과거 작업과 동일 ID의 다른 과목을 포함하는 격리 조회·비변경 검사 통과.
- 실제 조회본: 서버 502건(약리학333·기초신경과학4·미생물학74·기생충학74·병리학17),
  등록된 로컬 일괄 작업 31건을 합한 533건 저장. 원본은 유지했다.
- 첫 화면에서 해당 과거 일괄 작업은 0개로 분리되는 것을 실제 snapshot과 GUI 회귀로 확인했다.

## 로컬 반영 범위

정본 revision-bound 코드/설계 지문과 로그는 state.json에 있다. 다른 대화 변경은 커밋·배포하지 않는다.
사용자의 현재 요청을 해당 로컬 UI 수정·추가 보관·화면 갱신 승인으로 적용한다.
서버/웹 배포·DB 스키마·기록 상태·프로세스 실행 정책 변경 없음.
기존 프로그램 창만 새 코드로 갱신한다. --no-auto-start로 창을 열어 기존 사용자의 자동 시작 선택을 다시 켜지 않는다.
러너·생성기·업로드 프로세스는 유지한다.

## Maintain와 복원

프로그램의 “이전 블럭 기록” 버튼은 별도 읽기 전용 창과 새 조회본 저장을 제공한다.
첫 화면에서 숨긴 것은 기록 삭제나 작업 취소가 아니다. 상세 원본 위치는 조회본의 originals에 남긴다.
복원은 UI 코드 원복이며 원본·추가 보관본은 삭제하지 않는다. 실제 화면 반영 결과는 local-verification.md에 기록한다.
