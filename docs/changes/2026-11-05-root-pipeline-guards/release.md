## 배포 대상 버전·순서·데이터 변경
운영 미배포. DB 스키마 변경·운영 DB 접속·기존 문항/학습 기록 변경이 없다. 신규 요청은 source-assessment/2 및 root-generation/2를 사용하고, 기존 요청은 고정된 /1 계약·입력·검수 상한을 유지한다. 프로토콜 변경만으로 새 작업이나 새 예산을 만들지 않는다. 이미 게시된 과제를 자동 승격하거나 재검수한 것으로 표시하지 않는다.

향후 배포는 이 작업 변경만 분리한 고정 후보에서 다시 검사·리뷰 후 진행한다. 순서는 그림 표시·확인값 전송을 지원하는 웹 → 새/구 계약을 함께 받는 서버 → 러너다. 진행 중 호출을 자동 재실행하지 않으며 완료 결과는 원본 증거를 검증한 경우만 재사용한다.

## 배포 후 확인·롤백·필요한 사람 승인
이번 승인 범위는 공통 구현과 로컬 검증이다. 운영 변경 승인을 이 기록으로 만들지 않는다. 배포 단계에서는 고정 후보와 실제 대상·복원 절차를 검토하고 필요한 운영 승인을 적용한다.

배포 후에는 신규 요청 버전·기존 작업 재개·수정 횟수·그림 동일성·보류 사유·준비 과제 및 선행 순서·계정별 공개 범위를 확인한다. 구 서버/러너는 새 요청을 처리할 수 없으므로 신규 큐를 멈추고 작업 원장·자료를 보존한 상태에서 이전 후보를 복원한다. 신규 /2 결과를 /1로 바꿔 재게시하거나 예산을 초기화하지 않는다. 현 상태에서는 미배포 코드를 유지하므로 운영 복원 작업이 필요하지 않다.
