# 선지 보기·객관식 모드 선지 합치기 — 설계

## 요구사항과 수용 기준

### 한 장 요약
```
게시(러너) ──▶ 과목 족보 선지 풀(족보 PDF당 1회, sha로 캐시)
           └─▶ 오답 작성(출처 넷) → 코드 검사(계약·문체) → 독립 의학 검토 → 모자라면 둘째 회차
                 └─▶ asset root_mcq/<revision>.json (root-mcq/2: 문항마다 오답 풀)
풀이(서버) ──▶ 이번 풀이에 보일 오답 일부를 골라 앞면 mcq_choices
           └─▶ 답면 mcqCorrectIds + 보인 오답의 「왜 틀렸나」·출처
화면 ──▶ 객관식 모드: 처음부터 선지 / 주관식: V로 같은 선지를 편다(「선지 봄」)
```

### 오답
- 출처(`source`) 넷 중 하나:
  - `lecture`: 같은 강의의 다른 문항·내용
  - `block`: 같은 과목의 다른 강의(`block-pool/1`)
  - `jokbo`: 족보의 실제 선지·보기. 그 강의 족보와 같은 과목 다른 강의의 족보(결정 4). 연도·번호·교수·강의를 남긴다
  - `made`: 모델이 직접 만든 것. 사소한 부분 변경(Fe2+→Fe3+, 순서 바꾸기)과 강의 밖 일반 의학 지식을 포함한다
- 매력적이어야 한다. 오답마다 `why_tempting`(학생이 왜 고를 만한가)과 `why_wrong`(왜 이 질문의 답이 아닌가)을 쓴다.
- 매력의 근거 `why_tempting` 필수는 유지한다(결정 2, 2026-11-12 결정 그대로).
- 족보 우선순위: 문항에 직접 연결된 족보 쪽(`jokboPages`)의 선지 → 같은 강의 족보의 다른 문항 선지(올해 같은 교수 기출 먼저, `docs/policies/jokbo-attachments.md`)
  → 같은 과목 다른 강의 족보의 선지 → 나머지 출처.
- 「선을 넘는 오답」은 작성 지시문에 규칙을 늘어놓지 않고 마지막 독립 의학 검토가 뺀다.
  검토는 작성 쪽 이유를 보지 않고, 정답으로 볼 수 있거나 정답의 동의어·상하위 개념이거나 실제로 목록에 속하거나 지어낸 용어이거나 확신할 수 없는 오답을 뺀다.
  내용이 틀렸다는 이유만으로는 빼지 않는다.

### 문체 맞춤(코드 검사)
- 선지마다 표기 갈래를 정한다: 한글만 `ko`, 라틴 문자만 `en`, 둘 다 `mixed`(예: 「폐렴사슬알균(S. pneumoniae)」).
- 오답의 갈래는 그 문항 정답 선지들의 갈래 중 하나여야 한다. 아니면 그 오답을 빼고 둘째 회차에 「표기 언어가 정답과 다름」으로 다시 쓰게 한다.
- 작성 지시문도 정답의 표기 방식(언어, 「한글(영문)」 꼴, 명사형/문장형)을 따르라고 쓴다.
- 정답이 티 나는 다른 단서도 코드로 거른다(결정 1):
  - 길이: 정답만 눈에 띄게 길거나 짧다. 구체 기준(예: 오답 글 길이가 정답 길이의 절반 미만·두 배 초과)은 시범 분포를 보고 정한다.
  - 단정 표현: 오답에만 「항상·절대·~에만·모두·전혀」가 있다.
  - 걸린 오답은 빼고 둘째 회차에 이유와 함께 다시 쓰게 한다.

### 오답 수와 회전(결정 5)
- 오답 수를 맞추지 않는다. 괜찮은 오답이 나오는 만큼 쓰고, 의학 검토·코드 검사를 통과한 것만 남긴다.
- 한 번에 보이는 오답은 4~5개. 남은 오답이 그보다 적으면 남은 것을 다 보인다.
- 남은 오답이 보이는 수보다 많을 때만 회전이 생긴다.
- list는 정답 단위 전부 + 오답, 합쳐 16개 이하.
- 통과한 오답이 하나도 없는 문항은 둘째 회차 한 번 뒤에도 없으면 선지 없이 둔다.
  하나라도 있으면 붙인다 — 「나오는 만큼」을 이렇게 읽었다. 최소 수가 필요하면 고친다.

- 서버가 풀이마다 보일 오답을 고른다. 같은 사용자·같은 문항·같은 풀이 차례면 늘 같은 오답(새로고침·되돌리기 뒤에도), 다음 풀이 차례면 다른 조합.
  고르는 함수는 계약(`studyez_contracts`)에 두어 서버와 검사가 같이 쓴다. 선지 순서도 같은 씨앗으로 섞는다.
- 정답 선지는 늘 전부 보인다(list는 정답 단위 전부).

### 두 모드가 같은 자료를 쓴다
- 객관식 모드: 지금처럼 `mcq_choices`로 처음부터 선지. 기록은 일반 풀이.
- 주관식: `V`·「선지 보기」가 같은 `mcq_choices`를 편다. 기록은 지금처럼 「선지 봄」(`helped`).
  지금은 basic·list만 펴지는데, 새 자료가 있는 cloze·sequence도 편다(결정 3).
- 새 자료(`root-mcq/2`)가 없는 판은 지금과 같다: `root-mcq/1` → 주관식은 `root_choices`.

### 답면 「왜 틀렸나」
- 답면 응답에 이번에 보인 오답마다 `why_wrong`과 출처 표시(`jokbo`면 「2022 족보 45번」, 다른 강의 족보면 강의명도)를 싣고 화면에 보인다(결정 6).
  앞면에는 싣지 않는다(출처만 봐도 오답임이 드러난다).
- 화면은 고른 오답 아래에 한 줄로 보인다. 고르지 않은 오답은 접어 둔다.

### 빈칸 문항
- 게시된 cloze는 빈칸이 `{답}` 꼴이다. 사이트가 빈칸을 그리는 규칙과 같은 규칙으로 빈칸 수를 세어 `answer_units`와 맞으면 대상이다.

### 수용 기준
1. 같은 판·문항에 대해 앞면 두 번(같은 풀이 차례)은 같은 선지, 다음 풀이 차례는 다른 오답 조합이다(오답 풀이 보이는 수보다 클 때).
2. 앞면에 정답 ID·`why_wrong`·출처가 없다. 답면에는 보인 오답의 것만 있다.
3. 표기 갈래가 정답과 다르거나, 길이·단정 표현 단서에 걸린 오답은 asset에 없다.
4. 의학 검토를 받지 못한 오답은 asset에 없다. 통과한 오답이 하나도 없는 문항만 선지 없이 둔다.
   한 번에 보이는 오답은 4~5개(남은 게 적으면 전부)다.
5. `root-mcq/1`·`root_choices`만 있는 판은 화면·응답이 지금과 같다.
6. 게시 직후 러너가 이 생성기를 한 번 부른다. 실패해도 게시 결과는 그대로다. `root_choices` 생성은 더 부르지 않는다.
7. cloze 문항이 대상에 들어간다(27강의 재생성에서 cloze 작성 문항 > 0).

## 책임·입출력 계약·오류 상태

### asset `root_mcq` — `root-mcq/2`
파일명은 지금처럼 `<revision>.json`. 서버는 `schema`로 1과 2를 가른다.
```json
{
  "schema": "root-mcq/2",
  "revision": "auto-…",
  "counts": {"eligible": 0, "written": 0, "skipped": 0, "failedBatches": 0, "removedByReview": 0, "removedByStyle": 0},
  "jokbo": {"sources": [{"sha256": "…", "filename": "2026-S23-족보-김현제.pdf", "items": 0}]},
  "medicalReview": {"policy": "…", "questions": {}},
  "questions": {
    "Q012": {
      "question_hash": "…",
      "wrong": [
        {"id": "w1", "text": "…", "parts": [], "source": "jokbo", "basis": "…",
         "jokbo": {"run_id": "261113_01", "year": "2022", "number": "45", "professor": "김현제"},
         "why_tempting": "…", "why_wrong": "…"}
      ]
    }
  },
  "skipped": {"Q013": "…"}
}
```
- 정답 선지는 asset에 넣지 않고 서버가 문항의 정답에서 만든다(지금 v1과 같은 원칙).
- 오답 `id`는 문항 안에서 고정이다. 풀이 기록에 남는 선지 ID는 서버가 보인 순서로 붙인 `A`~`P`가 아니라 이 `id`와 정답 표시로 되돌릴 수 있게 한다(구현 시 확인).

### 족보 선지 풀 — `jokbo-pool/1`
- 입력: 실행 packet의 `sources` 중 `kind: jokbo` PDF(로컬 `localPath`). 같은 과목의 게시된 강의마다(블록 재료처럼).
- 족보 PDF마다 모델 호출 1회(쪽 이미지를 읽음): 문항마다 연도·번호·교수·발문·보기·(표시돼 있으면) 정답.
- 결과는 `runs/_root-generation/jokbo-pool/<sha12>.json`. 같은 sha면 다시 부르지 않는다. 여러 강의가 같은 족보 PDF를 쓰면 한 번만 읽는다.
- 생성기에는 그 강의 족보 전부와, 다른 강의 족보 중 문항 정답과 겹치는 말이 있는 항목만 넘긴다(입력 크기 제한).
- 족보가 없거나 읽기에 실패하면 족보 출처 없이 계속한다.

### 생성기 `quizbank/root_mcq.py`
- 입력: 판 문서, `block-pool/1`, 족보 풀, 문항별 `jokboPages`(근거 asset에 있으면).
- 40문항 묶음: 작성 → 계약·문체 검사 → 독립 의학 검토 → 둘째 회차(뺀 오답·이유 전달) 한 번.
- 지시문: `content/prompts/learning-links/mcq/write.md`·`review.md` 개정, 새 `jokbo.md`.
- 모델 호출은 지금처럼 `studyez_llm.codex`(Codex CLI). API를 직접 부르지 않는다.

### 러너
- `runner/connection_generation.py`: 게시 직후 `root_choices.publish` 대신 `root_mcq.publish`.
- `runner/root_mcq.py`: 수동 명령 유지(`--all-published`·`--missing`·`--no-upload`·`--upload-only`). packet의 족보 PDF를 넘긴다.
- `runner/root_choices.py`: 남겨 두되 기본 경로에서 부르지 않는다.

### 서버
- `server/app/root_learning/mcq.py`: v2 읽기, 풀이 차례로 오답 고르기, 앞면 `mcq_choices`, 답면 `mcqCorrectIds`·`mcqWrongNotes`.
- 풀이 차례: 그 사용자·문항의 지난 평가 수(기존 학습 기록에서 읽음). 앞면과 답면이 같은 값을 써야 한다.
- 오류 상태: asset이 없거나 깨졌거나 판·지문이 다르면 선지 없이 응답한다. 풀이를 막지 않는다.

### 화면
- `web/src/bank/quizMode.ts`: 주관식 `V`도 `mcq_choices`를 먼저 쓴다.
- `RootSolve.tsx`·`BankQuestion.tsx`: 답면 「왜 틀렸나」 한 줄과 출처.

## 호환성과 데이터 보존
- 문항·판·학습 기록·DB 스키마를 바꾸지 않는다. bank_retention 대상이 아니다.
- 지금 올라간 `root-mcq/1`(27강의)·`root_choices`는 지우지 않는다. 재생성 전까지 그대로 쓰인다.
  재생성으로 같은 이름 `<revision>.json`을 올리기 전에 로컬 v1 파일을 `mcq/v1-<revision>.json`으로 남겨 되올릴 수 있게 한다.
- 옛 화면은 `mcqWrongNotes`를 모르므로 무시한다.
- 과거 풀이 이벤트는 건드리지 않는다.

## 사용자 결정(2026-11-14 「1 적용, 2 유지, 3 열어, 4 써, 5 4-5개 정도 좋아. 개수를 꼭 맞출 필요는 없어. 그냥 괜찮은 오답이 나오는 만큼, 6 보여줘」)
1. 길이·단정 표현 단서도 코드로 거른다 — 적용.
2. `why_tempting` 필수 — 유지.
3. 주관식 `V`를 cloze·sequence에도 — 연다.
4. 다른 강의 족보 선지도 출처로 — 쓴다.
5. 한 번에 4~5개, 오답 수는 맞추지 않고 괜찮은 만큼.
6. 답면 족보 출처 — 보인다.
