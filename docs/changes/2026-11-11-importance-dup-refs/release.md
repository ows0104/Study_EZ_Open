# 목표 중요도 근거의 같은 쪽 중복 제거 — 배포 준비

## 코드 리뷰·검증 결과
- 바뀐 것: `importance.target_axes`가 근거 한 줄의 같은 참조를 한 번만 남긴다(`_unique`).
- 새 검사 1개는 수정 전 코드에서 `[[23,35],[35],[35]]`를 낸다.
- 재생
  - 실패한 아데노 실행(`runs/_root-generation/6e5c581a…/generation`)을 짧은 경로 사본에서 모델 호출을 막고 이어 했다.
  - 조립 예행을 통과했다: 목표 140개 중 전부 출제됨 114개, 과제 196개, 중복으로 합침 6개, 목표 없음 1개.
  - 그다음 의학 검토 단계(모델 필요)에서 멈췄다.

## 배포 대상 버전·순서·데이터 변경
- 계약 코드만 바뀐다. DB·웹은 바뀌지 않는다.
- 순서: 병합(API 배포) → 러너 재설치 → 실패한 실행 이어 하기(사용자 선택)

## 배포 후 확인·롤백·필요한 사람 승인
- 확인: `/api/health` revision, 이어 한 실행의 결과 검증 통과
- 롤백: git revert와 이전 Cloud Run revision으로 되돌린다
- 실제 실행·공개는 관리자 화면의 강의별 요청이 승인이다
