# 전체 검수 완료 후 등록 구조 보류

실제22개 검수(문항7·관계4·목표3·의학7·전역1)는 전부 완료했다. 최종 등록 계약은 원래91문항 은행의 `C005: 회상 계획 누락`을 거절했다. C005에는 Q081(direct)이 있으나 retrieval_plan 행이 없다. 최초 생성 및1차 수정에도 재사용할 C005 계획은 없어 기존 값의 결정적 복원으로 해결할 수 없다.

문항91개·brief·그림 명세19개(15문항)·수정2/3과 원래 source-2 실패는 보존했다. 검수 판정을 바꾸거나 C005를 지우거나 임의 학습 예산/목표를 만들어 검사를 통과시키지 않는다. result.json을 수동 생성하거나 등록 검증을 약화하지 않는다. 모델 재호출 및 운영 업로드/배포는 하지 않았다.

## 구체적인 후속 선택
현재 승인의 “수정 횟수2/3 그대로” 조건을 유지하면 게시 보류다. 완료된22개 검수·실제 원본 그림·모델 영수증을 모두 보존한다.

사용자가 남은1회 사용을 승인한다면 CLI가 C005의 누락된 retrieval_plan 한 행만 작성하게 한다. 수정3/3을 명시적으로 소비하며 원래91문항/답/선지/출처/그림·기존계획·개념·brief는 byte-equivalent JSON 값으로 보존한다. direction은 실제 Q081의 authored retrieval_direction과 일치해야 하고 repetition_budget/target_mastery는 CLI가 기존 정책으로 판단한다. 다른 임상/문항 보완은 하지 않는다. 원래 구조 실패와22개 검수는 새 승인에 연결하고 삭제/성공 승격하지 않는다.

수정 후 필요한 원본/의학 재검수 및 전체 커버리지·이미지 확인을 기존 총3회 수정/최대4차례 검수 안에서 수행한다. 다시 구조 오류가 나면 자동 재수정/새ID/예산초기화 없이 보존·중단한다. 최종 수용 및 격리 UI/원본링크 검사를 완료한 뒤 같은 검증 후보의 배포·지정 강의 관리자 시범 업로드를 이어간다. 추가 승인은 이 예산 변경/구조 보완 범위에 한정하며 이미 승인한 전송/업로드를 반복 요청하지 않는다.
