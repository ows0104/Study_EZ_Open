# 사람이 뺀 문항 (operator-exclusions/1)

## Intent
사용자 「탄저 문항 빼고 마무리해줘. 굳이 수정이나 검수 안해도 될듯.」(2026-11-15).
261109_02(레지오넬라·리스테리아·바실루스) Claude 판(job 620, generation 2bcdcf1f…)의 `v4-fix-1-1`이 두 번 모두
Claude 안전 분류기에 끊겼다(세션 기록 `stop_reason: refusal`, 고칠 문항 Q044 탄저 백신·Q051 탄저 관리·치료·Q073).
처음 지시 「필요하다면 탄저균 파트는 빼고 돌려도 돼」의 범위 안에서, 그 두 문항을 고치거나 다시 검수하지 않고 판에서 뺀다.

## Spec
- 파일 `<generation id>/operator-exclusions.json`(generation 폴더 옆, operator-resumes.json과 같은 자리):
  `{"version": 1, "questions": [...], "reason": "...", "approval": "<사용자 원문>", "at": "<시각>"}`. 형식이 틀리면 실행이 멈춘다.
- 목록의 문항은 아직 끝나지 않은 수정 회차의 대상에서 빠진다. 이미 끝난 수정 회차는 기록된 대상 그대로 다시 읽힌다(재개 재생 보존).
  빠진 뒤 대상이 비고 그 회차가 실패 기록으로 남아 있으면 resume 보관소로 옮긴다(다른 대체된 단계와 같다).
- 문항 검수가 끝난 뒤(맥락 판정·조립·의학 검토 전) 목록의 문항을 bank에서 뺀다: 선행 문항 연결, 그림, 중요도 근거, 검수 결과,
  목표별 근거·중복 묶음에서 지우고 목표 상태는 남은 근거로 다시 정한다(covered/missing).
- manifest: 뺀 문항은 `offGoalQuestions`에 `operator-exclusion: <reason>`으로, 파일 원문은 `operatorExclusions`로 남는다.
  기존 검증(처음 문항이 사라지면 안 됨, 과제가 되면 안 됨)은 그대로 통과한다.
- 파일이 없으면 동작은 이전과 같다. 프롬프트·스키마·검수 기준·수정 상한은 그대로.

## 검사
`tests/quizbank/test_root_generation_v4.py`: 뺀 문항은 수정 없이 bank·과제·근거에서 빠짐 / 형식 오류는 멈춤 /
수정 단계가 실패한 뒤 resume하면 그 문항을 빼고 끝남 / 이미 끝난 수정 회차는 같은 대상으로 재생.
