# Implementation Plan

1. RootGeneration 요청/재사용/응답 JSON에 inputMode(source/provided)를 연결한다. source 기본에 빈 지도/포인트를 허용하고 실제 원본과 과목 시험일로 고정한다. provided와 구형 작업 재개는 호환한다.
2. 순수 brief 검증은 원본 전용 추출에서만 독립 추출 provenance를 허용한다. 생성기 normalize 입력을 mode에 따라 분리하고 source 프롬프트는 실제 원본만 읽게 한다. 웹 원문 보존 정리·전체 ID 검사·검수/수정 상한은 유지한다.
3. RootGenerationPanel은 source 기본의 단일 자동전송 버튼과 접힌 고급 설정으로 바꾸고 BankPanel에서 직접 보이게 한다. 정본 웹 프롬프트와 등록 자료는 기존 브리지 자동전송을 사용한다. 원본 모드는 빈 지도/포인트를 보내고, 수동 모드는 두 값을 모두 전달한다.
4. 계약·생성기·러너·격리 API·실제 브라우저의 무입력 버튼→파일 회수→게시 흐름과 수동 입력 호환을 검증한다. 독립 추출에 웹 답이 섞이지 않음, 과목 시험일/미정, 중복·취소·기존 기록 보존을 검사한다. TS/생산 빌드 및 기존 root 회귀도 실행한다.
5. 원래 작업 폴더의 별개 변경은 유지하고 이번 파일만 기존 배포 사본에 반영한다. 7개 required_checks를 같은 지문에서 기록하고 review/release/고정 후보/현행 사용자 배포 승인 근거를 적용해 API→웹을 배포한다. 실제 사후 검사와 승인된 개인 시범 1건을 확인한다. 에이전트는 ChatGPT에 직접 접속하지 않는다.

복원은 이전 API/웹 revision 및 새 root 판 비활성화다. DB 표/기존 은행/사용자 사건/원본/실패·검수·전송 기록은 삭제하지 않는다.
