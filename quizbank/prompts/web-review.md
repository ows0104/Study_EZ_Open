원본 강의자료·족보와 웹에서 생성한 문제은행을 검수해라.

1. 원본 텍스트와 모든 쪽의 이미지를 확인하고, 출제 포인트 계획에 중요한 사실·조건·예외가 빠졌는지 검토해라. 교수 강조·학습목표·족보와 현재 강의 범위를 함께 판단해라.
2. 각 포인트를 실제로 시험하는 문항을 연결하고 covered / partial / gap / uncertain으로 판정해라. 같은 지식을 다른 표현으로 묻거나 하나의 문항이 여러 포인트를 시험하는 경우도 인정해라. 답을 발문에서 제공하거나 해설에만 언급한 내용은 직접 인출과 구분해라.
3. 문항·정답·모든 선지·해설·보기 풀의 정확성, 원본 근거, EXT·출처 충돌 표시를 확인해라. 의료 지식에 관한 판단은 ok / doubt / wrong으로 기록하고 불확실한 내용을 확정하지 마라.
4. 발문의 명확성, 정답 노출, 채점 단위, prerequisites, 형식·tier·객관식 유형을 확인해라. 같은 인출·판단의 중복은 찾되, 회상과 별도 비교·적용은 구분해라.

함께 전달된 「문항 품질 원칙」으로 정답의 정확성과 문항 설계의 적절성을 각각 검토한다.
서술형 basic, 독립 요구의 과도한 묶음, 불필요한 채점 항목, 부적절한 List·Cloze,
의미상 정답 노출, 의학 지식 없이 풀리는 문항, 표현만으로 정오가 드러나는 보기를 확인한다.
확인된 원칙 위반은 question_issues의 error로 기록하고 해당 문항·문제·수정 근거를 명시한다.
가벼운 불확실성은 doubt, 단순한 취향이나 가능한 다른 표현은 suggestion으로 구분한다.
기존 문항을 형식만 바꾸어 재출제하거나 가능한 변형을 늘리도록 요구하지 않는다.
정상적인 같은 축의 묶음·다단계 기전과 내용상 필요한 한정어는 허용한다.

현재 bank.json의 모든 최종 문항에 공통 원칙의 「최종 문항별 검수」를 적용한다.
출처로 범위 한정, 평가 지식의 발문 노출, 정답 선지에만 조건·설명이 집중된 비대칭을
각각 확인한다. 작성자의 자기검수 선언으로 점검을 생략하지 않는다. 확인된 위반은
error로 기록하고 해당 문항·문제 표현·수정 근거를 명시한다. 단어 검색이나 선지 길이
차이만으로 오류를 확정하지 말고 학습 목표·내용상 조건·판단 축을 함께 확인한다.
목표별 형식 적합성도 검토한다. Cloze가 0문항이면 사용하지 않은 근거를 summary에
짧게 기록한다. 이유가 원문에 없으면 없다고 밝히고 자료·현재 문항에서 적합한 목표가
있는지 판단한다. 0문항 자체나 이유 기록 누락만으로 error·지식 gap을 만들거나
Cloze 추가를 강제하지 않는다. 형식만 다른 중복 문항을 요구하지 않는다.

실제 풀이 화면의 계약을 적용해라. cloze는 같은 {{c1}}의 각 등장 위치를 answer_units의 순서대로 독립 연결하므로 서로 다른 답에 같은 토큰을 쓰는 것은 형식 오류가 아니다. OX 화면은 'O 인가 X 인가, 그리고 왜인가'를 명시하고 answer_units를 판단 근거·정정 설명 목록으로 보여준다. CLI가 OX 해설을 그 목록에 추가하는 저장 구조도 정상이다. 반복 토큰이나 설명이 그 목록에 있다는 사실만으로 수정 대상으로 삼지 마라. 빈칸의 위치별 답이 틀리거나 OX의 판단·근거가 틀린 경우에는 구체적인 오류를 지적해라.

문제를 몰래 수정하거나 추가 출제하지 말고 다음을 보고해라.
- 전체 판정과 실제 검토 범위·읽지 못한 자료
- 포인트 대조: point_id | question_ids | status | reason
- 계획 자체의 누락·오류: 원본 위치와 판단 근거
- 문항 문제: question_id | issue | reason | suggested_action
- 삭제·수정이 필요한 불필요한 중복 문항 묶음과 객관식 유형 수정 제안. 서로 다른 회상·비교·적용 목표라 유지할 문항은 duplicates에 넣지 마라.
- 웹에 전달할 수정 요청

수정 요청은 확인된 누락·오류·중복에 근거해라. 단순히 다른 변형도 가능하다는 이유로 문제를 늘리지 마라.
검수 결과는 확인한 자료에 대한 판단이며, 확인하지 않은 근거를 확인했다고 쓰지 마라.
