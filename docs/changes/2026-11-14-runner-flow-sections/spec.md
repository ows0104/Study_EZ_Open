# 러너 창 흐름 순서 — 설계

## 요구사항과 수용 기준
`DesktopWindow` 화면 순서(위→아래): 머리줄 · 도구줄(자동 시작 문구, 일시정지, 이전 블럭 기록, 자동 시작 취소) ·
① 시작할 수 있는 강의 · ② 대기열 · ③ 실행 중 · ④ 완료·실패 · 접힌 목록/상세 기록 · 업데이트 시각.

서버 `tasks` 행의 상태(사용자 선택 `choice`·`cancelRequested` 반영 뒤)로 구역을 나눈다.

| 구역 | 들어가는 행 | 버튼 |
|---|---|---|
| ① 시작할 수 있는 강의 (기본 접힘) | ready · held · unavailable(자료 대기, 이유 표시) · 중지됨 | 시작 / 재개, 취소 |
| ② 대기열 | queued (서버 `waiting` 순서, 없으면 날짜순) | 중지, 취소 |
| ③ 실행 중 | 기존 카드(로컬·서버·다른 세션 작업) | 고른 강의 기준 중지, 취소 |
| ④ 완료 · 실패 | failed · canceled · done, 실패 → 취소 → 완료 순, 같은 묶음은 날짜 최근 먼저 | 다시 시작(실패·취소만) |

- 각 구역 머리 = `이름 N` (①은 ▸/▾로 접고 펼침). 비면 「없음」 한 줄.
- ③의 카드 아래 작은 표로 실행 중 desktop 행(강의·구분·단계)을 두어 고르면 중지·취소를 쓸 수 있다.
- ④에서 행을 고르면 아래 로그 칸에 `runs/agent.<runId>.log` 마지막 40줄을 보인다. 파일이 없으면 서버 `message`·`reason`.
- 버튼 활성 조건은 기존 규칙(신선한 서버 조회, 일시정지, busy, done 금지 등)을 그대로 쓴다. 구역이 버튼 종류를 줄일 뿐 판정은 바꾸지 않는다.
- 한 번에 한 행만 선택된다(다른 구역에서 고르면 이전 선택 해제).

## 책임·입출력 계약·오류 상태
- 입력은 기존과 같다: `JobClient.read()`의 `tasks`·`waiting`, `collect()` 스냅숏. 새 서버 호출·새 파일 쓰기 없음.
- 로그 읽기는 기존 `status.tail()`(크기 제한 읽기) 사용, 고를 때 한 번. 읽기 실패는 「로그 없음」.
- 조회 실패 때는 마지막 결과를 유지하고 버튼을 끄는 기존 동작 유지.

## 호환성과 데이터 보존
표시만 바뀐다. 시작·중지·취소·자동 시작·일시정지 호출(`JobClient.call`)과 `runs/desktop-control.json` 형식은 그대로.
`StatusWindow`에는 카드 위에 구역을 끼울 수 있는 빈 훅 하나만 추가하고 읽기 전용 상태 창 모양은 바뀌지 않는다.
