# 생성기 시작 단계의 반복 값 자동 정리

## 문제와 사용자 효과
감염과 면역 261102_02를 root-generation/4로 로컬 시범 생성하던 중(2026-11-11) 생성기 시작 단계에서 실행이 멈췄다. 앞 단계(개념 지도, 포인트 84개, 독립 문제은행 79문항)는 모두 끝난 뒤였다.
- 원인: 독립 문제은행의 개념 C06 회상 계획 방향에 `reverse`가 두 번 적혀 있었다(`["direct","reverse","mechanism","sequence","reverse"]`).
- 은행 검사(`validate_bank`)는 이것을 특정 문항에 속하지 않는 형식 오류로 보고 결과를 만들지 않는다. /3도 같다.
- 같은 종류의 반복이 문항 안에 있으면(선행 문항 ID, 정답 선택지 ID) 그 문항 전체가 접수 단계에서 빠진다.

사용자 결정(2026-11-11): 다른 세션이 생성 시간 단축(병렬 처리)을 하는 동안, 이런 형식 오류로 멈추는 일을 줄인다. 「자동 정리만 진행」 — 정보 손실 없는 자동 정리만 하고, 모델에게 다시 고치게 하는 단계는 만들지 않는다.

## 범위와 성공 기준
- 순서·개수에 의미가 없는 목록에서 같은 값이 반복된 것만 첫 번째를 남기고 정리한다. 정리한 내역은 결과의 intakeProjection에 기록한다.
- 의미 판단이 필요한 오류(빠진 회상 계획, 선택지 ID 중복, 선행 순환, 빠진 필드 등)는 지금처럼 둔다.
- 성공: C06 같은 경우가 멈추지 않고, 반복 하나 때문에 문항이 빠지지 않는다. 반복이 없는 은행의 정리 결과는 지금과 같다.
