# 추가 전용 시험 — 계획

## Intent

사슬알균(26110901) 기록으로 새 출제 구조의 핵심 한 가지를 싸게 확인한다.
- 지금 구조: 빈 목표를 "전체를 다시 쓰는 보완"으로 메운다.
- 새 구조 2·3단계: 빈 목표만 새 문항으로 더한다.

이번에 볼 것은 두 가지다.
- 빈 목표가 얼마나 줄어드는가.
- 기존 문항 회귀가 0인가.

## 승인

2026-11-09 사용자 「승인, 돌려줘」. 필기 S1·족보 S2와 그 파생 자료를 OpenAI Codex CLI(gpt-6.1-sol)로 다시 보내는 것을 포함한다.

## 고정 입력

- generation-4 `packet.json`: S1·S2 sha256
- generation-4 `generate.json`: 목표 119개, 첫 출제 102문항

## 모델 호출 3번

`trial.py`가 실행한다. 자동 재시도는 없다.

1. **`coverage`** — 지금 원본 대조 단계(`source-v2.md`, 원본 그림 첨부, 연결 목표 규칙)로 102문항을 검토해 목표 커버를 판정한다.
   - 입력은 생산자 코드로 만들고, generation-4 source-0 입력과 차이가 없는지 확인했다(drift 0).
2. **`add`** — 커버 안 된 목표(missing·unknown·partial)의 required_gap만 넘긴다.
   - 저작 단계(`author-v2.md`) 끝에 추가 전용 지시를 붙인다(이 시험에서만 쓴다).
   - 코드가 확인하는 것: 기존 문항이 바이트 단위로 같은지, 지도가 그대로인지, 기존 충돌·그림 항목이 남아 있는지.
   - 이 확인을 통과하지 못하면 3번으로 가지 않는다.
3. **`recheck`** — 합친 문제은행 전체를 같은 원본 대조로 다시 검토한다.
   - 처음 계획은 "새 문항만 재확인"이었다. 그러려면 검토 프롬프트와 스키마를 범위만 좁혀 새로 써야 해서, 지금 단계를 그대로 쓰기로 바꿨다.
   - 대신 기존 102문항의 판정이 같은 글에서 얼마나 바뀌는지(검토 흔들림)를 함께 잰다.
   - 호출 수와 보내는 자료는 같다.

## 비교

`compare` 단계가 비교한다.

| 측정 | 내용 |
|---|---|
| 커버 변화 | 1번 → 3번 |
| 빈 목표 | 다시 채워진 목표와 남은 목표 |
| 새 문항 | 판정 결과 |
| 기존 문항 | 판정이 바뀐 문항 |
| 기준선 | generation-4 최종(source-2): 커버 확인 89/119, 문항 133 |

## 하지 않는 것

이번 시험에서 하지 않는 것은 다음과 같다.
- 의학 검토
- 4단계 문항 보완
- 결과 조립·반입
- 생성기·프롬프트·계약 변경

generation-4 기록은 읽기만 한다. 결과는 `runs/_e2e/26110901/add-only-trial/`(git 밖)에 둔다.
