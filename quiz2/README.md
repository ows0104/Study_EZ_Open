# quiz2 — 단발 호출 파이프라인 (작업 중)

`quiz/`(v1)를 대체하려고 짓는 중이다. **2026-08-20에 빈 자리가 없어졌다** —
0.5단계부터 빌드까지 모든 단계에 코드가 섰다.

**다만 한 편을 처음부터 끝까지 돌려 본 적은 없다.** 1회차(`260819_01`)는 0.5단계를
사람이 손으로 쓰고 오클루전 없이 돈 것이다. 새로 선 셋 중 **빌드만 실물로 확인했고**
(그 편을 다시 빌드했다), 0.5단계 스폰 문구와 오클루전 패스는 아직 에이전트를 안
태웠다. 다음 편이 그 시험이다.

v1은 `pre-rewrite-agentic` 태그로 보존돼 있다. 같은 강의록으로 나란히 돌려 견주려고
남긴 것이니 **`quiz/`를 고치지 마라.**

## 왜 다시 짓나

v1 조각 하나를 뜯어보니 도구 호출 47회 중 **26회가 입력을 스스로 찾는 데** 쓰였고,
매 호출이 문맥 12만 토큰을 다시 읽었다. 한 편이 캐시읽기 1억 7,700만 토큰 ·
52.9~72.2분이었다. 예전 `meddeck-local-app/pdf_to_anki`는 같은 일을 한 편 9.6분에
했는데, 거기서는 **코드가 프롬프트를 조립하고 모델을 한 번 불렀다.**

원인은 모델도 규칙도 아니고 **프롬프트 조립을 코드에서 모델로 옮긴 것**이었다.

## 파일

    prompt.py      출제 철학. **이 파일이 규칙 문서다.** 코드가 조립해 한 번에 보낸다
    chunks.py      조각별 PDF 자르기 (clean + 필기본 + 필기 메모)
    assemble.py    조각에게 줄 스폰 프롬프트 조립
    merge.py       조각 결과를 v1 뒷단이 읽을 꼴로 합침
    validate.py    기계 검증. 판정하지 않고 세어서 표시한다
    structure.py   0.5단계. 경계와 주제 덩어리를 정할 스폰 문구를 조립한다
    occlusion.py   오클루전 패스. 후보 추림 + 렌더 + 누출 검사 (㉙~㉟)
    timings.py     단계 계측. **모델 단계는 오케스트레이터가 찍어야 한다**
    reproduce.py   재현 검사. q만 주고 a가 다시 나오는지 본다 (⓹)
    build.py       .apkg. 뒷면 빨간 박스에 신호 셋을 각자 머리글로 세운다 (③⃝)

    INTERVIEW.md   **무엇을 정했나, 왜, 무엇을 일부러 안 넣었나**
    RUNS.md        돌려 보니 어땠나, 무엇이 깨졌나

**규칙을 고치거나 지우기 전에 `INTERVIEW.md`를 먼저 읽어라.** 빈 프롬프트에서
시작해 관리자에게 50항목을 하나씩 물어 "넣어라"고 한 것만 넣었다. **안 넣은 것이
왜 안 들어갔는지도 적혀 있다** — 그걸 "빠졌네" 하고 되넣는 것이 문서가 부푸는
방식이다.

## 한 편 돌리는 법

    # 0. 준비 (v1 코드 그대로)
    python quiz/prep.py "<강의록.pdf>" --jokbo-pdf "runs/_jokbo/<과목>/<연도>/L__.pdf"

    # 0.5 경계와 주제 덩어리 → runs/<id>/structure.json
    python -m quiz2.structure runs/<id>         # → spawn/structure.md
    python -m quiz2.timings runs/<id> start 0.5-write     # ← 띄우기 직전
    #    서브에이전트 하나에게 그 파일을 읽고 그대로 따르라고만 시킨다
    python -m quiz2.timings runs/<id> end   0.5-write     # ← 받은 직후
    python quiz/structure.py runs/<id>          # 쓴 뒤 검증 (v1 코드 그대로)

    # 1. 조각 자르기 + 스폰 문구 조립
    python -m quiz2.assemble runs/<id>

    # 2. runs/<id>/spawn/*.md 마다 서브에이전트를 하나씩, 동시에
    #    각 에이전트에게는 "그 파일을 읽고 그대로 따르라"만 시킨다
    #    **조각마다 라벨을 붙여 찍어라. 안 찍으면 편 시간이 사라진다**
    python -m quiz2.timings runs/<id> start 2-write --label c01
    python -m quiz2.timings runs/<id> end   2-write --label c01

    # 3.5 오클루전 패스 — 렌더-확인-수정을 도는 유일한 자리 (㉙~㉟)
    python -m quiz2.occlusion plan runs/<id>    # → spawn/occl.bNN.md
    #    배치마다 서브에이전트 하나. 각자 render를 돌려 가며 고친다
    #      python -m quiz2.occlusion render runs/<id> --items items.raw.occl_b01.json
    #    여기도 --label b01 로 찍는다 (3.5-occlusion)

    # 4. 합치기 + 검증
    python -m quiz2.merge runs/<id>
    python -m quiz2.validate runs/<id>          # v1의 quiz/validate.py를 쓰지 마라

    # 4.5 재현 검사 — 에이전트가 두 바퀴 돈다 (푸는 쪽 · 채점 쪽)
    python -m quiz2.reproduce split runs/<id>   # → verify/spawn/answer.*.md
    #    푸는 쪽 에이전트에게는 그 파일만 읽히고 **다른 것을 열지 말라**고 못박는다
    python -m quiz2.reproduce grade runs/<id>   # → verify/spawn/grade.*.md
    python -m quiz2.reproduce score runs/<id> --apply items.reproduced.json

    # 5. 빌드 — **v1 build를 쓰지 마라** (cloze·근거 줄이 조용히 사라진다)
    python -m quiz2.build runs/<id> --items items.reproduced.json --project <과목>
    #    v1 덱과 한 Anki에서 견주려면 --project를 갈라라 (예: 병리학-v2)

취소선 친 항목을 지우지 않고 둔다. **무엇을 왜 안 했는지가 다음 사람이 되넣지

편이 있어야 움직인다.

### ~~1. 코드 필터~~ — 2026-08-20에 닫았다. 이식하지 않는다

`quality_filter.py`(1,485줄)가 무엇을 잡는지 **v1 10편 + v2 1편 = 1,368장**에
대 보고 접었다.

| 검사 | 걸린 카드 |
|---|---|
| `a`에 cloze 마크업 (q↔a 뒤바뀜) | **0** |
| cloze 마크업 깨짐 / format 불일치 | **0** |
| c1 정규화 필요 | 1 (build가 이미 한다) |
| 방향어 단독 답 · `설명하시오` | **0** |
| `아마·추정·가능성·불명확` | 10 |

**0이 눈이 감긴 게 아니다.** 같은 파일들에 cloze 카드가 37장 있고 37장 전부 `q`에
마크업이 있다 — 볼 대상은 있었다. 유일하게 울린 `가능성` 4건은 열어 보니 넷 다
정상이었다(*"근친혼의 **가능성**이 높아진다"*). 병리에서 `가능성`은 헤지가 아니라
내용이다.

**남을 것이 없는 이유는 셋이다.** 검출은 `quiz2/validate.py`가 이미 한다. 모델
호출 부분(rewrite·semantic dedup·final review·coverage)은 API를 안 쓰기로 한
자리다. 남는 수리는 위 표가 할 일이 없다고 말한다. 1회차 `suspects.json`의
`removed: 0`도 같은 말이다 — 하드로 잘린 카드가 없으니 수리가 구할 카드도 없다.

README가 근거로 적었던 *"조각이 `Edit`을 일곱 번 걸며 고쳤다"*는 **에이전트가 자기
카드를 고치던 v1의 구조**였다. v2는 조각이 JSON을 한 번 쓰고 끝난다.

되살리려거든 먼저 세라. 안 세고 넣으면 지난 세션이 걷어낸 가짜 플래그 308건과
같은 종류가 다시 들어온다.

### ~~2. `structure.json`을 만드는 자리~~ — 2026-08-20에 지었다 (`structure.py`)

`python -m quiz2.structure runs/<id>`가 `spawn/structure.md`를 낸다. 판정에 쓸
근거를 전부 문구에 박아 넣는다 — `outline.json`의 슬라이드 제목표(주제 경계),
`page_features.json`의 수치표(족보 경계), 외부 족보 원문(`exam_focus`), 그리고
정규식 스캐너의 짐작을 **판정이 아니라 짐작으로** 붙인다.

**남는 읽기는 하나뿐이다.** 필기 꼬리에 붙은 족보는 캡처 이미지라 글자가 안 잡혀
(`260819_01`에서 s68~76이 21~52자였다) 그 구간만 `pages`로 본다.

검증기가 따지는 것을 문구에 그대로 옮겨 적었다 — 안 적으면 쓰고 나서 걸리고,
그때마다 한 바퀴가 더 돈다. **그 절과 `quiz/structure.py`의 `verify`가 어긋나면
코드가 주인이다.**

`260819_01` 스폰 문구는 37,117자(약 18.6k 토큰)이고 그중 3분의 2가 족보 원문이다.

**아직 안 돌려 봤다** — 이 문구로 서브에이전트가 쓴 `structure.json`이 검증을
한 번에 통과하는지는 다음 편에서 본다. 지금 있는 `structure.json`(손으로 쓴 것)은
검증을 통과한다.

### ~~3. 오클루전 패스~~ — 2026-08-20에 지었다 (`occlusion.py`)

1회차에 한 장도 안 나온 이유는 단순했다 — `prompt.py`에 `OCCLUSION` 규칙 문자열이
있는데 **`make_prompt`가 그걸 어디에도 안 넣었다.** 규칙만 있고 부르는 자리가 없었다.

`plan`이 후보를 추려 배치별 스폰 문구를 내고, `render`가 앞/뒤 PNG를 뽑는다.
**렌더-확인-수정을 도는 것이 이 패스의 정상 동작이다** — 다른 패스는 한 번에 쓰고
끝내라고 못박지만 여기만 반대다.

**후보 추림은 `or`다** — 1단계가 그림·표를 근거로 카드를 낸 슬라이드 **또는**
그림 비율이 높은 슬라이드(라벨 2개 이상). `or`인 근거가 실측에 있다:
`260819_01`은 `image_ratio`가 0인 슬라이드가 67장 중 45장인데 그중에도 `figure`
근거 카드가 있었다(s9의 Mutation 도식). **벡터로 그린 도식은 비율이 0으로 잡힌다.**
비율만 보면 그런 그림을 통째로 놓친다. 이 편에서 후보 17장 → 배치 4개가 나왔다.

#### 코드가 세 가지를 대신 센다

`CLAUDE.md`가 감사의 한계로 적어 둔 자리다 — *"상자가 라벨을 덜 덮은 것은 셋 중
하나만, 가린 답이 아래 행에 그대로 있던 것은 아무도 온전히 못 잡았다."*

    answer_text_elsewhere      가린 답이 안 가린 다른 라벨에 글자로 또 있다 (㉝)
    answer_text_in_annotation  가린 답이 그 슬라이드 필기에 글자로 또 있다 (㉞)
    rect_clips_label           직접 적은 좌표가 라벨을 걸치기만 하고 다 못 덮었다

**누출 비교는 낱말 배열로 잰다.** 뭉갠 문자열로 재면 오탐이 섞인다 — 이 편에서
실제로 `Male` ⊂ `Female`, `1 in 250` ⊂ `1 in 25,000`이 걸렸다. 낱말로 끊으면
27건이 20건으로 줄고, 둘 다 안 걸리며, v1에서 실제로 샌 것(캡션 `Disuse atrophy`가
바로 아래 URL `.../disuse-atrophy`에 그대로 있던 것)은 그대로 걸린다.

#### ㉞의 위험이 첫 렌더에서 바로 나왔다

인터뷰가 *"필기에 답이 적혀 있으면 가려도 그 필기가 답을 보여 준다"*고 적어 둔
그 자리다. 시험 삼아 s13을 렌더했더니 인쇄된 `(beta globin)`을 덮었는데 하단 필기가
`beta-globin allele 건드리는 혈액질환`이라고 적고 있었다.

그래서 `annotations.json`의 `notes`를 같은 잣대로 함께 센다. 후보 슬라이드의 라벨
267개 중 **7개**가 그 슬라이드 필기에 글자로 또 있었다 — 성기고 구체적이라 신호다.

**못 세는 것이 남는다.** 필기가 답을 바꿔 말하거나(s13의 *"같은 유전자의 mutation의
결과이다"*) 글자가 아니라 그림으로 그려져 있으면 이 검사가 못 본다.

**아직 이 문구로 안 돌려 봤다.** 렌더와 검사 셋은 손으로 만든 카드 3장으로 확인했다
(둘은 일부러 결함을 넣어 잡히는 것을, 하나는 안 걸리는 것을 봤다).

### ~~4. v2 build~~ — 2026-08-20에 지었다 (`build.py`)

빨간 박스에 신호 셋이 각자 머리글로 선다. **셋이 의심하는 대상이 다르다.**

    족보 검토: …  ㉓ 족보 문항의 정답을 의심한다   (+ `검토 근거:`)
    재현 주의: …  ⓹ 이 카드가 안 선다
    자료 주의: …  ⑳‴ 자료 자체가 이상하다

전에는 `reproduce score --to-card-back`이 셋째를 `review_note`에 문자열로 이어붙여
v1의 박스를 빌려 썼다. **그 필드는 이미 두 뜻을 겸하고 있었다** — ⑳‴ 자료 주의와,
㉓ 플래그가 붙었을 때 요구되는 검토 근거(`prompt.py`)다. 그래서 `--to-card-back`을
없앴고, build가 `--apply`가 박아 둔 `reproduce` 객체를 직접 읽는다.

1회차에 안 터진 것은 `review_flags`가 0/145였기 때문이다 — 족보 카드 26장에서 한
번도 안 나왔다. 설계가 막은 게 아니다.

## 안 풀린 것

- **`importance`가 `core` 92%.** 2티어(인터뷰 ⑰)가 필터 구실을 못 한다.
  v1의 80%보다 오히려 더 쏠렸다
- **어투 체언 종결 43%.** v1 69.7%에서 내려왔지만 절반이다. 인터뷰 ⑤⃝에서 규칙을
  **일부러 안 넣고** 결과를 보기로 했고, 이게 그 결과다. 넣을지는 관리자가 정할 일
- **`50 + 슬라이드 수`가 `슬라이드 × 2`보다 나은지.** 관리자가 대안으로 흘렸고
  물음표가 붙어 있었다. 얇은 강의록에서 크게 갈린다
- **`coverage_gaps`의 문턱이 안 섰다.** 회수 목표 152개 중 37개(24%)가 걸렸는데
  겹침 값이 0.4~0.5에 몰려 있다(문턱 0.55). 셋을 뽑아 대조했더니 셋 다 카드가
  있었다 — 다만 **셋으로 서른일곱을 말할 수는 없다.** 문턱을 만지려면 세어야 한다
- **길이 한도가 재현 실패를 거의 못 맞힌다.** 110/110/50은 v1에서 넘어온 근거 없는
  숫자인데(인터뷰는 *"길이는 코드가 센다"*(⑵)까지만 정했다), 1회차 실측에서
  `answer_too_long` 9/53 · `compound_question` 5/28로 **밑값 13%보다 겨우 몇 점
  높았다.** 거꾸로 플래그 71장 중 58장은 재현이 멀쩡했다. 한 편이니 숫자를 아직
  만지지 않았다 (`RUNS.md`)
- **재현 실패는 버릴 이유가 아니다** (2026-08-20 판정, INTERVIEW 4부). 깨진 자리가
  *"강의록이 고른 특정 예시·숫자·표 값"*에 몰렸지만 실패 19장 중 8장이 `exam_hit`이고
  실패율이 exam_hit 12% vs 아닌 것 14%로 거의 같다. 표·그림 카드를 거르지 않는다.
  **표시하고 남긴다**

## 조심할 것

- **`quiz/`를 고치지 마라.** 비교 기준선이다
- **`quiz/validate.py`를 v2 산출물에 대지 마라.** 없앤 필드를 찾아 가짜 플래그가
  308건 나온다. `quiz2/validate.py`를 써라
- **`quiz/build.py`도 v2 산출물에 대지 마라.** 이쪽은 더 나쁘다 — **에러가 아니라
  손실**이라 성공한 것처럼 끝난다. v1은 cloze를 `card_type`에서 찾는데 v2는
  `card_format`이라 빈칸 카드 6장이 통째로 basic이 되어 **답이 앞면에 그대로 나가고**,
  `source_anchor`가 없어 `근거:` 줄이 145장 전부에서 사라진다
- **v2 build는 `runs/INDEX.md`를 기본으로 안 쓴다.** `update_index`가 같은
  `lecture_id`의 줄을 덮어쓰기 때문이다. 견주려면 같은 강의를 두 번 빌드해야 하는데
  그때 v1 기준선 줄이 지워진다. 켜려면 `--index`. 덱 이름도 같은 이유로 겹치니
  `--project`를 갈라라
- **`prompt.py`에 사건을 적지 마라.** 규칙만. 사건은 `RUNS.md`
- **인터뷰에 없는 규칙을 넣지 마라.** 넣어야겠으면 관리자에게 먼저 물어라.
  이 저장소가 앓았던 병이 정확히 그거다 (`CLAUDE.md`의 「규칙 문서를 쓰는 법」)
- **API를 쓰지 않는다.** 관리자가 명시했다. 서브에이전트로 돈다
- **재현 검사에 손대면 푸는 쪽으로 답이 새는지 먼저 세어라.** 첫 구현이 cloze를
  안 가리고 내보내 2장이 답을 들고 나갔다. 그대로 뒀으면 cloze 6장이 전부 `same`으로
  통과하면서 **아무 신호도 안 냈을 것이다.** 확인은 한 줄이다 — `asked.b*.json`
  원문에 원본 `a`가 들어 있는지 세면 된다
