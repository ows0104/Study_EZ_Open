# 감염병리1 Main-Quiz 새로 생성 — 설계

## 요구사항과 수용 기준
1. **품질 측정 → 보완 사유.** `roots/generation_v2.repair_reasons`가 `validation['warnings']` 중 품질 측정
   (회상 부담·basic 복수 단위·예/아니오 쏠림·단정어 겹침·형식 쏠림·일부 노출)을 `question_fix`로 넣는다.
   문항 ID가 있는 경고는 `question_ids`를 채운다. 보완 상한 3회는 그대로이며 경고만으로 상한을 늘리지 않는다.
   수용: 합성 은행에서 경고 1개가 보완 사유 1개가 되고, 경고 0이면 사유가 늘지 않는다.
2. **basic 채점 단위 측정.** `bank/quality.py`에 「basic인데 채점 단위 2개 이상」 경고를 추가한다(warning, 문항을
   떨어뜨리지 않음). 메시지는 list·cloze 표·문항 분할 중 고르라고 안내한다. 기존 Quiz Bank 35편에서 새 경고 수를 세어 보고한다.
3. **저작 지시(author-v2.md).** 세 줄을 보강한다: basic은 정답 하나; 여러 항목·대응은 list·cloze 표·객관식;
   「한계·주의」를 발문 끝에 덧붙이지 않고 별도 문항이나 해설로; 해설 정책은 사용자 결정(아래).
4. **중요도 단계.** `runner.root_importance_review`의 자격을 「수정 3/3 소진」에서 「모든 단계 완료·결과 없음」으로 넓힌다.
   갈래별 호출·즉시 저장·최종 원본 대조 5400초는 그대로다. 계약 `importance_review`/`generation_v2`가 이미 일반 n을
   받는지 검사로 확인하고, 필요하면 같은 범위로 고친다. 새 실행에서는 생성 루프가 끝난 뒤 이 도구를 정해진 단계로 실행한다.
5. **실행.** 새 폴더 `runs/_e2e/26110802`에서 Map /3 → 포인트 → 포인트 정제 → packet → root-generation/2 →
   중요도 보완 → 조립. 실행 스크립트는 `2026-11-08-infection-path1-map/run.py`의 사본에서 폴더 id만 바꾼다.

## 책임·입출력 계약·오류 상태
- 결정적 검사(품질 측정·보완 사유·계약)는 모델 없이 돈다. 모델 호출은 Codex CLI 하위 프로세스(gpt-6.1-sol)뿐이다.
- 실패한 호출은 자동 재시도하지 않고 원문·ledger를 보존한다. 상한 도달은 보류로 보고한다.
- 노트북이 자면 단계 시한이 깨지므로 실행 동안 깨어 있기를 요청한다.

## 호환성과 데이터 보존
- 품질 경고 → 보완 사유는 새 실행부터 적용된다. 기존 결과의 검증(`validate_result`)은 repair-decision 기록을
  다시 계산하므로, 기존 ledger가 계속 통과하는지 검사한다(통과하지 않으면 정책 버전으로 구분한다).
- 기존 실행 폴더·공개 판·Quiz Bank·학습 기록 불변. 계약 변경은 master 병합으로 API에 자동 배포된다(추가만, 하위 호환).
