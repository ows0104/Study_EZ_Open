# Main-Quiz 관리자 출제를 버튼 하나로 — 설계

## 요구사항과 수용 기준
- 새 요청 화면에 버튼은 「Main Quiz 만들기」 하나, 입력은 체크박스 하나뿐이다. textarea·라디오·날짜·「설정·기존 지도 사용」이 없다.
- 체크하지 않고 누르면 본문이 정확히
  `{conceptMap:'',points:'',scope:'',examDate:null,inputMode:'source',authoring:'cli',parallelAuthoring:false,pipeline:'map-tree/3',privatePilot:false,resume:false,requestId:<새 UUID>}`다.
- 체크하고 누르면 `privatePilot: true`만 다르다. 안내도 「내 계정에만 공개」로 바뀐다.
- 이전 판이 비공개·기존 지도·병렬이었어도 새 요청은 위 기본값이다(이전 판의 범위·지도·공개 범위를 끌어오지 않는다).
- 승인 안내(`role="note"`)는 새 요청을 보낼 수 있을 때만 버튼 바로 아래에 보인다: 승인 문장, S1·S2 → OpenAI Codex CLI,
  새 구조 2, 공개 범위, 러너 안내, 호출 상한, 기존 기록 보존, 공개된 판이 있으면 거절.
- 버튼 이름 「Main Quiz 만들기」는 그대로다(사이트 전체 표기·안내 페이지·브라우저 검사와 같게).

## 책임·입출력 계약·오류 상태
- 이어 하기: 실패·중지된 판이 있으면 버튼은 「Main Quiz 이어서 만들기」이고 원래 요청(requestId·입력·authoring·pipeline·privatePilot)을
  그대로 보낸다. 체크박스는 숨기고 「같은 공개 범위(학생 공개/비공개)」를 적는다. map-tree 요청은 이유 입력이 있어야 누를 수 있다.
- 진행 중(queued·running·웹 응답 대기)에는 버튼이 막힌다. 게시되면 상태 줄에 학생 공개/비공개를 함께 적는다.
- 첫 조회 실패 시 「기존 작업 다시 확인」으로 다시 조회만 한다. 옛 웹 출제 판의 「응답 전달 복구」와 「생성·검수 결과」는 유지한다.
- 서버 API·요청 검증은 그대로다.

## 호환성과 데이터 보존
- DB·운영 데이터·이미 만든 판·학습 기록은 건드리지 않는다. 화면이 보내는 값만 고정된다.
- 옛 구조 판의 이어 하기는 계속 된다. 옛 구조로 새로 요청하는 길은 화면에서 없어진다(서버 API는 그대로 받으므로 되돌리기 쉽다).
