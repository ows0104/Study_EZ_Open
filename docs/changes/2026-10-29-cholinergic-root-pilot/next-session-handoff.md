## 합의한 핵심

- 전체 올해 시험 범위를 최소 한 번 만난다. 중요도는 순서와 반복량에 반영하되 지엽적인 내용을 생략하는 근거로 쓰지 않는다.
- 회상 시도 후 정답을 확인하면 틀렸어도 한 번 공부한 것으로 본다. 첫 접촉과 현재 회상/이해 상태는 구분한다.
- 기본 입력은 머릿속 회상 → 정답 확인 → 자기평가다. 매번 답·이유를 입력하게 하지 않는다.
- 강의의 뼈대에서 큰 가지·세부로 확장하고 여러 번 방문하며 깊이를 늘린다. 완벽한 숙련/정답을 다음 진입 조건으로 삼지 않는다.
- 관계도 회상한다. 하향·상향·비교 등 필요한 방향별 상태를 구분하되 모든 관계에 역방향을 의무화하지 않는다.
- 동일 목표를 여러 방향/문제로 공부해도 전체 범위는 한 번만 센다. 방향 상태와 목표 단위의 합산 기준은 learner-journey spec을 따른다.
- 강의별 독립 지도로 구성한다. 블록 전체를 하나의 지도로 만들거나 강의 간 목표를 지금 합치지 않는다.
- 첫 화면은 강의별 하나의 누적 막대로 회상 가능/공부했으나 보완 필요/미학습을 구분한다. 중요한 미학습을 눈에 띄게 보여준다.
- 지도는 뼈대·큰 가지부터 펼치며 접힌 가지에도 미학습·중요 미학습을 표시한다. 풀이 중 현재 지도 위치를 보여준다.
- 자기평가 후 다음 질문으로 바로 이동하며 위치와 직전 상태의 변화를 짧게 보여준다.
- 오늘 완료 화면은 새로 본 범위·회상 변화·중요 미학습을 보여준다. 기본 행동은 “오늘은 여기까지”다.
- 시간 설정 없이 시험 일정·범위·기록으로 매일 새 진도와 필요한 복습을 추천한다. 고정 비율·고정 10개 보완은 채택하지 않았다.
- 시험 2일 전까지 전체 범위의 첫 학습을 목표로 한다. 마지막 이틀에도 늦은 필기·중요 미학습의 새 학습은 허용한다.
- 필요한 새 진도와 급한 복습이 최근 학습량보다 많으면 사용자는 “분량을 늘려”를 선택했다. 최근 기록을 강제 상한으로 삼지 않는다.
- 평일 강의 유입은 3~6개, 평균 약 4개다. 필기 도착과 같다는 뜻은 아니다. 새 지도 학습은 필기가 들어온 뒤 시작하고 예습은 기존 퀴즈를 쓴다.
- 현재 상태의 시각적 파악, 지도 채움과 약점 회복에서 얻는 보람이 핵심이다.

- 실제 과거 파일 수신 기록 10건/6강의를 읽어 raw.md와 크기·SHA256·문항 수·구조가 맞는 것을 확인했다.
  중복 시도도 있으므로 10번의 독립 자동 전송 성공이라고 해석하지 않는다. 자동/수동의 구별도 이 기록만으로 확정하지 않는다.
- 기존 Node bridge 검사 62개, pytest 35개(autosend 1개 제외), 웹 수신 검사 5개, 격리 서버 저장 검사가 통과했다.
- 격리 HTTP 검사는 시작 후 반환하지 않아 중단했다. 실제 Chrome 파일 선택 검사는 로컬 접속 거절로 미완료다.
  두 검사를 운영 왕복 통과로 쓰지 않는다. 처음의 임시 폴더/SQLite/인코딩 오류와 재실행 결과도 report.md에 기록했다.
- 조사 당시 소스는 1.3.20, 로컬 `web/public/studyez-extension.zip`은 1.3.19였다.
  ZIP에는 최신 파일 카드 다운로드 회수 경로가 없었다. 실제 설치·운영 버전은 미확인이다.
- 현행 pending 결과 키는 웹앱 탭과 강의 단위다. 문제/포인트/트리를 작업별로 영속 저장·확인·재개하는 계약은 없다.
- 진단 중 제품 소스·패키지를 고치거나 운영에 전달하지 않았다. 재패키징·재설치·세 종류 수신 지원은 미실행이다.

## 남은 설계와 다음 순서

추가 요구(2026-11-01): 사용자는 현재 감염과 면역 블록과 다른 블록에서 이미지 문제가 중요하다고 설명했다.
open-design/P09에 해설 근거 이미지와 문제 이미지의 구별, 시각 목표 추출·원본 자산 보존/전달·질문/해설 표시·방향별 상태의 설계 후보를 남겼다.
후속으로 필기·족보의 필요한 원본 이미지 영역을 crop해 출제하는 방향은 합의해 spec/S8에 반영했다.
영역 선정·출처/좌표·정답 단서·문제용/해설용 표시·전달·검수·상태 기준은 아직 미정이다.
실제 사례 1~2개로 텍스트 문항만으로 빠지는 학습 목표와 최소 흐름을 검토한다. 실제 crop이나 이미지 기능 구현은 실행하지 않았다.
MD에 이미지 링크가 있다는 이유만으로 실제 자산 수신·화면 표시·시각적 회상 목표가 충족됐다고 보지 않는다.
이 요구로 기존 콜린성 시범·강의별 뿌리의 첫 구현 범위를 자동 확대하지 않는다.

1. **먼저 실제 트리 결과를 검토한다.** 사용자가 이미 실행했다면 결과부터 받아 보고, 아직이면 최신 짧은 요청문을 쓴다.
   큰 흐름·뿌리의 대표성·묶음·관계·빠진 범위와 원본 근거를 함께 살펴본다. 요청문을 다시 길게 만드는 일부터 시작하지 않는다.
2. **별도 원본 전용 포인트 결과를 받는다.** 트리 결과를 포인트 대화의 정답 기준으로 넣지 않는다.
3. **두 결과와 기존 69문항의 대조를 구체화한다.** 기존 충분한 문제와 부족한 목표/방향을 구별하고 첫 학습 흐름을 만든다.
   별도 CLI의 실행/출력 계약과 보조 프로그램은 기존 계획·현재 동의 범위를 맞춰 준비한다. 새 전체 은행을 생성하지 않는다.
4. **첫 제품 구현 spec/plan을 마무리한다.** 실제 목표 분할·필수 방향, 자기평가 문구와 도움 받은 회상,
   급한 복습·초기 기록 부족·유입 예측·재계획, 저장/API·실패·중복·복원·기록 보존을 정한다.
5. **구체 계획 승인 후 구현한다.** 현재 첫 적용 범위는 강의별 뿌리다. 세부 트리가 결과에 포함되어도 구현 범위를 자동 확대하지 않는다.
   bridge를 통한 확장은 별도의 작업 구분·보관·저장 확인·재개 계획과 실제 검증이 필요하다.

`learner-journey/plan.md`는 TODO 틀이다. 시범 `plan.md`에는 로컬 보조 파일과 검사안이 있지만 해당 파일은 이 세션에서 구현하지 않았다.
이 두 작업의 state.json은 planning이며 approvals/checks가 비어 있다. UI 설계 동의·시범 진행 동의와
제품 구현/운영 승인을 구분한다. 이전에 받은 같은 범위의 동의를 무시하고 처음부터 재승인 인터뷰를 반복하지 않는다.
전체 재인터뷰보다 실제 한 강의 결과를 검토하고 그 근거로 다음 설계를 구체화하는 것이 다음 단계다.

## 보존·작업 환경

- 기존 문항·ID·개인 수정·제외·학습 기록·자료·검수 이력을 보존한다. ID가 같다는 이유만으로 새 목표에 기록을 자동 승계하지 않는다.
- 저장소에는 이번 작업 전부터 미커밋 변경이 많다. 현재 설계 문서 폴더들도 untracked다. 정리/초기화/일괄 커밋/배포하지 않는다.
- `server/.env`는 운영 DB를 가리킬 수 있으므로 열거나 테스트 설정에 사용하지 않는다.
- ChatGPT 웹 자동 접속/전송을 실행하지 않는다. 사용자 수동 전송 정책과 관련 보존 정책을 따른다.
- 의학 내용·문항/정답·출제 포인트 JSON·검수 통과 판정을 이 에이전트가 직접 고치지 않는다. 해당 작업은 허용된 별도 CLI 경로와 기존 상한을 따른다.
- 실제 파일·원문·메타데이터가 필요한 지정 경로만 읽는다. work/tmp/runs 전체를 무작정 로드하지 않는다.
- 구현 변경은 intent → spec → plan → 승인 → 검사 → 리뷰·승인된 출시 절차를 따른다. 이번 인계는 새 구현 승인이 아니다.
