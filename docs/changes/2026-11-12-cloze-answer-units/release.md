# Main-Quiz cloze 정답 단위를 발문 빈칸에 맞춤 — 배포 준비

## 코드 리뷰·검증 결과
- 실제 두 문항(261104_03 Q186, 261105_01 Q023)의 저장 모양으로 서버 검사: 단위 수 = 보이는 빈칸 수, 정답 글 유지,
  정답을 고친 개인 수정본은 단위 없음.
- 계약 검사: 접수·추가·수정 병합에서 단위가 빈칸 순서로 바뀌고, 인라인 빈칸이 없는 cloze는 그대로, 두 번 불러도 같음.
- 서버 `-m tests main_quiz` 8개 통과, `root` 41개 중 39개 통과. 실패 2개(`test_root_map_tree`, `_v3`)는 로컬 venv에
  PyMuPDF가 없어서이고 master에서도 같다(CI에는 있다).
- 운영 읽기 전용 집계(편마다 최신 판 23편): 고치기 전 cloze 696문항 중 92문항이 어긋남. R1 뒤에는 모든 cloze의 단위 수가
  보이는 빈칸 수와 같다(`normalize_cloze`가 빈칸 하나에 단위 하나를 낸다).

## 배포 대상 버전·순서·데이터 변경
- master 병합 → API·웹 자동 배포. 서버만 바뀌면 이미 게시된 판에도 즉시 적용된다(DB 변경 없음).
- 러너 재설치는 도는 실행이 없을 때. 새 러너로 옛 실행을 이어 하면 접수 은행에 어긋난 cloze가 있던 실행은
  뒤 단계 입력 지문이 달라져 멈출 수 있다(`--resume` 필요).
