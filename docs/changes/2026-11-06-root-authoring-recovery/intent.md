# 완료 작성 초안의 구조 실패를 기존 보완 예산으로 복구

## 문제와 사용자 효과
E2E 실험에서 심내막염47문항 작성 호출은 완료됐으나 중요도 근거축 오류로 generate 수용 검사에 실패했다. 이미 완료한 원문을 다시 출제하지 않고 기존 잔여 보완 예산으로 구조 오류만 고쳐 원본·독립 정답 검수와 실제 풀이까지 이어간다.

## 범위와 성공 기준
완료 입력/원문/사용량/NativeJson 영수증·원본 지문을 검증하는 명시적 운영자 복구만 제공한다. 이전 실패와 소비 횟수는 보존하고 남은3회 중1회를 다음 구조 보완 호출 전에 소비한다. 수정본 전체 계약과 실제 원본/독립정답검수는 그대로 요구한다. 중단·모델거절·불명확 호출은 재실행하지 않는다.

## 근거·미정 사항
사용자가 구체 복구안 질문(기존47문항·실패 기록 재사용, 같은 최대3회 상한 내 실행기 수정)에 “복구 경로까지 수정해 이어가기”를 선택했다. 원본/Map/포인트/문항/검수결과의 OpenAI 전송·최대3회 보완 승인은 현재 채팅에서 별도로 받았다. CNS가 실행 중인 작업 공간의 코드는 변경하지 않고 별도 worktree에서 구현한다. 운영548·기존은행·학습기록·운영배포는 범위 밖이다.
