# 연결 중심 학습과 구조·시험·임상 중요도 구분 — 구현 계획

상태: **Implementation Plan v1 — 검토용, Build 전.** 2026-11-02 사용자의 Plan 진행 요청에 따라 구체화했다. 아래 신규 경로·명령·산출물은 구현 예정이며 현재 동작한다는 뜻이 아니다. 앞선 원칙 문서 반영은 완료했고 확인 기록은 [review-notes](review-notes.md)에 보존했다.

후속 상태: 사용자가 A를 “계획대로 구현해줘”라고 승인했다. 아래 범위를 로컬 Build하고 실제 결과는 release.md에 기록한다. 공용 패키지의 기존 명시적 패키지 목록(`studyez_contracts/pyproject.toml`)에 신규 모듈을 등록하는 일은 A의 계약 배포 가능성을 위한 필수 연결이다. 과거 개념도·포인트를 정본으로 고정하거나 새 결과에 자동 병합하지 않는다.

## 1. 결과와 작업 경계

첫 구현의 결과는 **한 강의의 개념도·연결된 문제·중요성의 근거·부족한 질문을 함께 확인하는 로컬 검토 묶음**이다. 단순 철학 문구 추가로 끝내지 않고, 실제로 시험한 관계와 발문이 제공한 관계를 구분해 후속 제품이 읽을 수 있게 만든다.

콘텐츠 준비는 이 change, 실제 자료의 의미 검토는 기존 콜린성 시범, 학습 저장·화면·추천은 기존 root-learning-product가 맡는다. 공용 계약은 하나만 만들고 제품 쪽에서 import한다. 같은 기능을 두 change에서 중복 구현하지 않는다.

| 단계 | 구체 결과 | 담당·진입 조건 |
|---|---|---|
| A. 연결 검토 묶음 | 출처 판·관계·목표/방향·문항 연결·중요성 근거·누락을 담은 JSON과 읽을 수 있는 보고서 | 이 change의 첫 로컬 Build 제안 |
| B. 실제 한 강의 적용 | 기존 15개 후보/69문항 대조 근거를 재사용한 채택 후보, 미확인 목록, 부족한 질문 목록 | 콜린성 시범의 허용된 자료·실행 범위. 기존 한 차례 대조 승인을 반복 호출 승인으로 사용하지 않음 |
| C. 지도 속 학습 | 목표별 질문→확인→평가→다음, 현재 위치, 저장/재개, 첫 학습과 회상 분리 | root-learning-product B1~B3. 검토된 콘텐츠와 해당 Build 승인 |
| D. 중요도와 범위에 따른 추천 | 필요한 뼈대 선행, 중요한 연결 반복, 새 세부 첫 학습을 확보하는 유한 경로 | root-learning-product C3/B4. 추천 정책의 구체 사례를 확인한 후 |
| E. 일반 출제에 적용 | 정본 프롬프트와 기존 검수 경로의 보강, 여러 강의 적용 | 한 강의 결과를 검토한 후 별도 확정 범위. 전체 재출제·자동 웹 전송은 포함하지 않음 |

첫 Build는 A까지만이다. A는 합성 자료로 입출력·보존·오류 처리를 검증하며 실제 의학 내용을 작성하거나 판정하지 않는다. A의 완료가 B~E나 사용자 학습 완료를 뜻하지 않는다. 단계 A 계약은 세부 역할도 표현할 수 있게 하되 첫 제품의 실제 콘텐츠 범위는 강의별 뿌리로 유지한다.

## 2. 현재 구조에서 확인한 점

- `content/prompts/bank/bankPrompt.md` 1.77의 최상위 철학에는 제공한 관계/시험한 관계, 기초 연결, 족보 왜곡 분석이 이미 있다. 같은 철학을 여러 프롬프트에 복제하는 것이 첫 작업은 아니다.
- `quizbank/points.py`의 PLAN은 목표·target·쪽이며 중요성/방향 근거가 주로 문자열 안에 들어간다. `question_first.py`는 이를 포인트 목록으로 바꾸고 최종 문항에 학습 구조를 연결한다.
- `quizbank/web_audit.py` REPORT는 포인트별 covered/partial/gap/uncertain/excluded와 note를 보존하지만 관계별 제공/시험/해설 및 세 종류 중요성 근거를 별도 계약으로 갖지 않는다.
- 시범 `roots-request.md`와 `points-request.md`는 간단한 자연어 요청이다. 이미 받은 원문을 새 구조에 맞춘다고 덮어쓰거나 독립성을 새로 인증하지 않는다.
- 기존 대조에는 실제 근거가 있는 목표 후보 15개와 경로 8문항이 있으나, 합본 족보 원본 이미지 미확인·복합 문제 평가·부족한 과제가 남는다. 이 수를 확정 목표 수나 전체 완료 기준으로 쓰지 않는다.

## 3. A의 변경 파일과 구현 순서

경로는 저장소 루트 기준이다. 신규 파일은 아직 없다.

1. **공용 계약과 검증:** 신규 `studyez_contracts/learning_links/__init__.py`, `schema.py`, `validate.py`. 표준 라이브러리와 순수 공용 모듈만 사용한다. [Spec 계약안](spec.md#plan을-위한-로컬-검토-묶음-계약안)의 참조·판·자료 부족·관계별 판정을 검증한다. 기존 BANK/PLAN/REPORT 형식을 수정하지 않는다.
2. **로컬 검토 입력 안내:** 신규 `content/prompts/learning-links/README.md`, `mapping-review.md`. 구조화된 검토 결과의 작성 계약을 제시한다. 원본 기반 포인트의 독립 추출과 문항을 본 뒤의 연결 검토를 구분한다. 이 파일은 실행 중인 공통 출제 프롬프트에 자동 삽입하지 않는다.
3. **읽기 전용 입력·새 결과 출력:** 신규 `quizbank/connection_plan.py`. 명시적으로 전달한 구조화된 검토 JSON과 은행·출처 목록만 읽고 새 출력 폴더에 정규화본·검증 결과·사람이 볼 보고서를 쓴다. PDF 내용이나 자연어를 키워드로 해석해 의학 관계를 만들지 않고, 모델·네트워크·runner·서버를 호출하지 않는다. 파일 지문은 코드가 직접 계산한다.
4. **보고서:** 신규 `quizbank/connection_report.py`. 탐색 구조별로 목표/질문, 제공된 관계, 실제 시험 관계, 중요성 근거, 부분/누락/미검토, 세부 잔여와 원본 근거를 표시한다. 범위 이름과 검토 범위를 앞에 표시하고 학습 숙련도를 생성하지 않는다.
5. **검사와 경계 안내:** 신규 `tests/contracts/test_learning_links.py`, `tests/quizbank/test_connection_plan.py`, `tests/quizbank/test_connection_report.py`; `studyez_contracts/CLAUDE.md`, `quizbank/CLAUDE.md`, `docs/map.md`에 새 책임과 검사 위치를 짧게 연결한다.

계획한 로컬 명령은 `python -m quizbank.connection_plan --review <검토.json> --bank <기존은행.json> --sources <출처목록.json> --out <새폴더>`이다. 인자 누락·잘못된 참조·입력 판 불일치는 실패로 반환한다. 유효한 묶음에 gap/unknown이 남은 것은 입력 오류와 구별해 보고한다. 기존 출력 폴더 덮어쓰기와 입력 파일 수정은 거절한다. 오류 보고가 있어도 완료 묶음으로 오인되지 않게 완료 표시는 모든 구조 검사와 출력이 끝난 뒤 마지막에 쓴다.

## 4. B~E로 연결하는 방법

### B. 콜린성 한 강의의 검토

먼저 기존 수신본과 [대조 결과](../2026-11-02-root-learning-product/content-comparison-review.md)를 입력 근거로 재사용한다. 해당 기록이 확인하지 않은 중요성·관계·족보 이미지에 대해서는 unknown과 확인 필요 이유를 남긴다. 포맷을 맞추려고 현재 에이전트가 의학적 의미를 새로 판정하지 않는다. 추가 CLI 의미 검토가 필요하면 입력·목적·잔여 횟수·실행 범위를 기존 시범 계획에서 확정한다.

검토 결과는 (1) 충분한 기존 문제 재사용, (2) 제공/해설뿐인 관계, (3) 부족한 질문, (4) 자료 충돌/미확인으로 나눈다. 빠진 질문은 초안이 필요한 목록이지 자동 추가 지시가 아니다. 수정 잔여 0회를 초기화하거나 별도 검토 묶음으로 기존 검수 상한을 우회하지 않는다.

### C. 제품 연결

root-learning-product의 `studyez_contracts/roots/`는 learning_links의 판/목표/방향 참조를 사용하고 중복 콘텐츠 스키마를 만들지 않는다. `server/app/root_learning/content.py`는 검토·채택한 묶음을 draft로 가져오며 보류 목표도 삭제하지 않는다. 학습 가능 과제와 미준비 방향을 구별하고 검증 통과만으로 공개하지 않는다.

지도는 뼈대·가지·세부 위치를 보여주고 선택한 목표에 실제 연결된 질문을 제공한다. 첫 버전의 단일 평가는 그 과제가 실제로 시험하는 방향에만 적용한다. 복합 문제의 목표별 채점이 없다면 해당 문항을 여러 목표의 성공 근거로 연결하지 않는다. 구체 API/화면/저장·재개는 기존 제품 계획 B1~B3를 따른다.

### D. 추천 정책에 전달할 요구와 비교 사례

고정 중요도 합산 점수는 A에서 만들지 않는다. C3에서 다음 사례의 실제 추천 목록을 제시해 규칙을 확정한다.

- 기출 없는 뼈대가 후속 과제를 이해하는 데 필요하면 처음 만나는 후속 과제보다 앞에 배치하되, 오답이라고 후속 진입을 잠그지 않는다.
- 시험/임상 근거가 높은 세부도 우선 후보로 다룬다. 모든 뼈대를 끝낼 때까지 세부를 막지 않는다.
- 높은 중요도 복습이 많아도 전체 첫 학습 목표에 필요한 새 범위 분량을 별도로 확보한다. 낮은 중요도의 미학습 세부를 후보군에서 없애지 않는다.
- 아직 문항이 없는 목표는 준비 전으로 남긴다. 추천 가능한 과제 소진을 전체 범위 완료로 표시하지 않는다.
- 실제 학습 약점은 학습 사건에서 판단하고 콘텐츠의 '취약할 것으로 예상' 근거로 실패 기록을 만들지 않는다.

하루 계산·복습 간격·도움 평가·시간 경계는 기존 C2/C3 미확정 항목이다. A의 구현을 막지 않지만 실제 추천 제품 공개 전에는 확정해야 한다.

### E. 일반 출제 확장

실제 시범으로 부족한 부분이 확인되면 `bankPrompt.md`의 공통 품질 원칙을 한 곳에서 보강하고 버전을 갱신한다. `quizbank/prompts/points.md`, `web-review.md`, `learning-structure.md`와 `question_first.py`/`web_audit.py`의 필요한 생산·소비 경로를 함께 갱신한다. 기존 은행/캐시는 호환으로 읽고 새 근거가 없는 필드는 미확인으로 둔다. 이 확장은 첫 A Build의 일부가 아니며 자동 수신·게시 경로 변경은 별도다.

A 완료 조건은 위 검사와 코드 리뷰, 사람이 읽을 수 있는 합성 보고서 확인이다. B의 의학 의미 검토는 별도 증거다. C에서는 동일 공용 계약에 대해 서버 소비자·목표 집계·보존·API·UI 검사를 기존 제품 계획에 추가한다. 서버를 바꾸지 않는 A에서 운영 DB나 서버 환경을 불러오지 않는다.

## 6. 보존·복원·승인 범위

기존 은행·ID·Tier·정답·근거·개인 수정·제외·학습·검수·원문을 보존한다. A는 새 결과 폴더만 만들고 실행 시 사용자가 지정하지 않은 자료를 탐색하지 않는다. 패키지 검토 상태와 기존 검수 판정은 독립이다.

복원은 새 도구 사용을 중단하고 기존 제품 경로를 유지하는 것으로 가능하다. 생성한 초안과 실패 기록은 삭제하지 않는다. 다른 작업의 미커밋 변경은 커밋·복원에 섞지 않는다. 후속 제품의 공개/DB 복원은 root-learning-product 계획을 따른다.

구현 승인 시 범위는 **A의 공용 계약·로컬 입력 검증·보고서·입력 안내·검사·문서 연결**로 명시한다. 모델 호출·실제 문항 작성/수정·은행 재검수·웹 전송·서버/DB/UI 변경·배포는 포함하지 않는다. 이는 작은 완결 단위의 제안이며 목적 전체가 A로 끝난다는 뜻이 아니다.

사용자의 현재 발언은 Plan 진행 승인이다. Build 전에는 docs/development/README.md의 “승인받은 Implementation Plan의 범위만 구현한다”를 따라 해당 intent/spec/plan의 지문에 묶인 승인을 기록하고 check --phase build로 확인한다. Test/Review 후 배포 후보와 중요 승인은 후속 단계다.
