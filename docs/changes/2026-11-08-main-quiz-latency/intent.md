# Main-Quiz 풀이 지연 제거

## 문제와 사용자 효과
사용자 요청 원문(2026-11-08, 채팅): "메인 퀴즈를 풀때 여전히 저장중.. 이라고 뜨면서 다음 문제가 너무 느리게 나와.
공부할때 너무 신경이 쓰이는 최우선 해결과제야. 다른 걸 포기하더라도 이 시간은 줄이고 싶어. 저번에 미리 다음 문제
로딩해두기는 잘 작동되고 있는거야? space를 누르고 나서도 왜 이렇게 오래 걸리는지 도대체 이해가 안돼."
이어서: "아 답과 참고 슬라이드도 늦게 나와."

현재 `/bank/:subject/:runId`의 Main-Quiz는 공개된 뿌리 학습 판이 있으면 `RootLearning`(뿌리 학습)을 연다.
**지난번의 「다음 문제 미리 준비」는 Quiz Bank 풀이(`BankSolve`)에만 있고 이 화면에는 없었다.**

운영 로그(Cloud Logging, 2026-11-07 15:20Z~18:18Z, 감염과 면역/261104_02)에서 한 동작마다:

| 단계 | 지연 |
|---|---|
| `POST …/events` (저장) | 0.25–2.3 s |
| 이어서 `GET /sessions/{id}` (답이 있으면 생성 기록 `result` JSON까지 읽음) | 답 없음 0.2 s · **답 포함 0.8–8.9 s** |
| 이어서 `GET` 강의 개요 | 0.2–4.1 s |
| 참고 PDF 첫 `GET`(PDF.js가 전체 파일부터 요청) | 22.7 MB, 1.4–8.8 s |
| 이후 범위 요청 하나마다 | 약 0.7 s, 차례로 |

화면은 세 요청이 끝날 때까지 「저장 중…」을 띄우고 답·다음 문항을 그리지 않았다. 답이 뜬 뒤에야 PDF를 열기
시작했고, PDF 문서는 15초 동안 안 쓰면 닫혀 다음 답마다 다시 열렸다.

## 범위와 성공 기준
- Space 뒤 답, 평가 뒤 다음 문항이 저장 응답을 기다리지 않고 즉시 그려진다.
- 참고 슬라이드는 문제를 보는 동안 미리 그려 두고, PDF 전체 파일 GET을 하지 않는다.
- 저장은 지금처럼 이 브라우저에 먼저 보관되고 순서대로 확정된다. 실패·충돌은 지금처럼 드러나고 보존된다.
- 성공: 저장을 1.5 s로 늦춘 브라우저 검사에서 답·다음 문항이 1 s 안에 그려지고, PDF 요청이 모두 범위 요청이다.
  운영에서 같은 동작 사이에 `GET /sessions/{id}`가 사라진다.

## 근거·미정 사항
- 답을 미리 받는 것은 Quiz Bank의 `/prepare`(2026-10)와 같은 원칙이다: 미리 받기는 아무것도 기록하지 않고,
  열람·평가는 `/events`가 저장할 때만 사실이 된다.
- DB 스키마·학습 기록·은행은 바꾸지 않는다.
