# 자유 노트 플로팅·강의명·로컬 사진 — 설계

## 요구사항과 수용 기준
**1. 플로팅 노트**
- 셸(App.tsx `Shell`)에 `FloatingNotes` 하나. 승인된 사용자, `/notes`가 아닌 모든 경로(풀이 화면 포함)에 우측 하단 원형 버튼.
- 누르면 우측 하단에 노트 창(데스크톱 약 420×600, 휴대폰 폭에선 아래쪽 전체 폭 시트). 창 머리: 노트 고르기(최근 노트 목록 ▾)·새 노트·강의명·전체 화면(`/notes`로)·닫기.
- 본문은 기존 `NoteEditor` 그대로(블록·md·색·태그).
- 창이 열린 채 경로가 바뀌어도 창·편집 중인 노트 유지(셸 밖으로 안 나감).
- 창 안 키 입력은 퀴즈 단축키(숫자·V·Z·Space 등)로 새지 않는다: 창 루트에서 keydown 전파를 막는다(퀴즈의 window keydown 처리기들이 contentEditable을 거르지 않는 곳이 있음: RootSolve·BankSolve).
- 버튼이 풀이 화면 하단 고정 답 버튼을 가리지 않는 위치·크기(풀이 화면에선 작게, 겹치면 위로 올림)를 실제 화면에서 확인.
- 닫을 때·경로 이동·탭 숨김 때 남은 저장을 보낸다(지금 NotesPage와 같은 규칙).

**2. 강의명 버튼**
- 퀴즈 화면(Pre-Quiz `/prequiz`, Main-Quiz `/mainquiz`·`/bank/...`(roots 포함), 이전 Main-Quiz)이 지금 강의명을 셸에 알린다(`useNoteLecture(title)`).
- 강의명을 알고 있을 때만 창 머리에 「＋강의명」 버튼. 누르면 지금 노트 **본문의 커서 위치**에 강의명 글자를 넣는다(2026-11-13 사용자 결정: 태그 아님, 맨 앞 아님).
- 버튼은 mousedown 기본 동작을 막아 편집기 커서·선택을 잃지 않는다. 선택 영역이 있으면 그 자리를 강의명으로 바꾼다(일반 입력과 같음).
- 편집기에 커서가 한 번도 없었으면 마지막 글 블록 끝에 넣는다(마지막이 글 블록이 아니면 새 글 블록). 노트가 없으면 새 노트를 만들고 첫 블록에 넣는다.
- 같은 강의명을 여러 번 넣어도 막지 않는다(본문 글이므로).

**3. 사진**
- 새 블록 종류 `image`: `{id, type:'image', html:'', image:'<사진 id>'}`.
- 넣는 법: 블록에 이미지 붙여넣기, 편집기에 이미지 파일 끌어놓기, `/` 메뉴 「사진」(파일 고르기).
- 넣을 때 긴 변 1600px·WebP(지원 안 되면 JPEG) 0.85로 줄여 IndexedDB `studyez-note-images`에 `{id, userId, blob, w, h, createdAt}`로 저장.
- 그릴 때 IndexedDB에서 읽어 object URL로 표시. 이 기기에 없으면 회색 칸에 「이 기기에 없는 사진」.
- 사진 블록은 선택·삭제·끌어 옮기기 가능(다른 블록과 같은 손잡이).
- 노트 삭제 시 그 노트의 사진도 이 기기에서 지운다(최선 노력). 다른 기기 사진은 못 지움.

## 책임·입출력 계약·오류 상태
- 서버 `/api/me/notes`: BlockType에 `image` 추가, `image` 필드(`^[a-z0-9]{8,40}$`, image 블록일 때만 필수·저장). image 블록의 html은 항상 ""로 저장 → 서버에는 바이트·data URL이 들어갈 수 없다.
- 기존 html 정리(`sanitizeNoteHtml`)는 그대로 `<img>`를 허용하지 않는다(붙여넣은 data URL이 글 블록 html로 서버에 가지 않게).
- IndexedDB가 막힌 환경(시크릿·저장 거부): 사진 넣기 실패 문구 한 줄, 노트 글은 그대로 저장.
- 강의명 출처: Pre-Quiz·이전 Main-Quiz는 `QuizPage`의 `detail.title`, 새 Main-Quiz는 `RootLearning`의 `info.title`, Quiz Bank는 `BankStudy`가 받는 강의 정보(없으면 버튼 안 보임).

## 호환성과 데이터 보존
- DB 스키마 변경 없음(blocks는 JSON 열). migration 없음. 기존 노트·태그 그대로.
- 배포 순서: API 먼저(기존 자동 배포 순서). 이전 웹이 image 블록 노트를 받으면 알 수 없는 종류로 빈 칸 처리 — 새 웹이 같은 SHA로 곧 올라오므로 수용.
- 사진은 계정·노트가 아닌 이 브라우저에 남는다. 같은 브라우저에서 다른 계정으로 로그인하면 userId로 구분해 남의 사진을 그리지 않는다.
