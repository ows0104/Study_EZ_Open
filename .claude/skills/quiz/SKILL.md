# 강의 PDF → 시험 대비 Anki 덱

강의 한 편을 받아 **Opus 5 호출 3+N회**와 코드 4패스로 Anki 덱을 만든다.
0.5·1·4단계가 각 1회이고, 2단계는 조각 수만큼 동시에 돈다.

`timings.jsonl`로 잰 완전 분해가 둘 있다. 두 번째가 §16a 분할과 `plan_chunks.py`를
처음 쓴 편이다.

    260814_05 (115장·51슬라이드)  0.5단계 7.0 · 1단계 14.8 · 2단계 21.4(조각 8)
                                 · 4단계 17.9 · 코드 0.1 · 갭 10.9 = 72.2분
    260812_03 (118장·66슬라이드)  0.5단계 3.9 · 1단계 13.9 · 2단계 17.9(조각 12)
                                 · 4단계 14.6 · 코드 0.1 · 갭 2.1 = 52.9분

**혼자 도는 단계가 여전히 절반을 넘는다.** 조각화가 값을 하는 곳은 2단계뿐이고
거기서 작업합이 벽시계의 8.2배였다(147.4분 / 17.9분, 12개 동시).

두 편의 차 19.3분 중 **A(§16a 분할)와 B(배분)의 몫은 6.8분이다** — 4단계 −3.3,
2단계 −3.5(작업합이 32% 늘었는데도 줄었다). 나머지는 갭을 줄인 것과 편 차이다.
두 편이므로 아직 분포가 아니다.

모델은 카드와 **슬라이드 번호**까지만 책임진다. 이미지 첨부와 패키징은 코드가 한다.

목적과 출제 규칙은 [references/item-rules.md](references/item-rules.md)에 있다.
**이 파일은 절차만 다룬다. 무엇을 어떻게 출제할지는 전부 그쪽이다.**

## 역할 경계 (어기지 말 것)

| | 코드 (`quiz/`) | 모델 (이 스킬) |
|---|---|---|
| 하는 일 | PDF 자르기·각인·렌더, 족보 구간 분리, 스키마·범위·중복 검사, 덱 패키징 | 무엇을 물을지, 어떻게 물을지, 무엇을 지울지 |
| 안 하는 일 | 의미 판정 (세어서 표시만 한다) | 파일명·이미지·ID 조작 |

## 실행 절차

인자로 받은 강의 PDF 경로를 `<pdf>`라 한다. 인자가 없으면 아래에서 목록을 보여주고 묻는다.

    ~/SynologyDrive/{과목}/필기/{연도}/[YYMMDD_NN]제목(교수)_필기자vN.pdf

Main-Quiz는 **올해** 필기가 대상이다. 어느 강의의 작년 판인지는
`python -m studyez match {과목}`이 알려준다.

아래 `python`은 이 환경에서 PATH에 없다. 실제로는
`PYTHONIOENCODING=utf-8 "C:/Users/ows01/anaconda3/python.exe"` 로 부르고,
작업 디렉터리는 이 저장소 루트다.

### 단계마다 시각을 찍는다

**코드 단계는 스스로 찍는다.** 아무것도 안 해도 된다.

**모델 단계는 네가 찍는다.** 서브에이전트를 띄우기 **직전**과 결과를 받은 **직후**:

```bash
python quiz/timings.py runs/<lecture_id> start 1-blueprint
python quiz/timings.py runs/<lecture_id> end   1-blueprint
```

2단계처럼 여러 개가 동시에 도는 자리는 `--label`로 조각을 가른다. 그래야 **벽시계와
작업시간 합**이 갈린다 — 조각화가 줄이는 것은 합이 아니라 벽시계이므로, 하나만 보면
조각화의 값을 잘못 읽는다.

```bash
python quiz/timings.py runs/<lecture_id> start 2-write --label c1
python quiz/timings.py runs/<lecture_id> end   2-write --label c1
```

단계 이름은 아래로 고정한다. 바꾸면 편끼리 비교가 안 된다.

    0.5-model   1-blueprint(--label 조각)   2-write(--label 조각)   4-audit

**1·2단계는 조각별로 도니 라벨이 필수다.** 라벨이 없으면 벽시계와 작업시간 합이 안
갈리고, 그 둘의 차가 조각화의 값이다.

**왜 찍나.** 어디서 줄일지 정하려면 단계별 소요가 있어야 하는데, 예전엔 남는 시각이
`prepared_at`과 `built_at` 둘뿐이라 그 사이가 통짜였다. `260814_05`에서 처음으로
분해가 나왔고(위 머리말), 그게 아직 **유일한 완전 분해**다. 편이 하나면 분포가 아니다 —
쌓일 때까지 계속 찍어라.

`2-write`의 조각 라벨은 특히 중요하다. `plan_chunks.py`의 회귀 계수(4.9분 + 0.58분/카드)가
거기서 나왔고, 편이 쌓이면 다시 맞춰야 한다.

**한 번에 한 편만 돌려라.** 여러 편을 동시에 돌리면 에이전트끼리 밀려서 벽시계가
파이프라인의 비용이 아니라 그날 몇 개를 같이 돌렸는지를 재는 값이 된다 — 실측에서
여덟을 함께 돌렸더니 일곱은 10~16분인데 하나가 4시간을 넘겼다.

### 0단계 — 준비 (코드)

```bash
python quiz/prep.py "<pdf>"
```

`runs/<lecture_id>/`에 생기는 것:

- `model_input.pdf` — **사실 채널.** 필기 제거 + `Slide N` 각인. 슬라이드 N = **N쪽**
- `annotated.pdf` — **족보 채널.** 원본 그대로(문항이 annotation에만 있을 수 있음) + 각인. 슬라이드 N = **N쪽**
- `jokbo_input.pdf` — `--jokbo-pdf`를 줬을 때만. 원본 족보 + 각인.
  **여기만 offset이 붙는다** — 슬라이드 N = (N − `prep.json`의 `jokbo_slide_offset`)쪽
- `page_features.json` — 페이지별 글자수·annotation 수·답안 나열·족보 낱말·이미지 비율·**붙여넣은 이미지 수**. 0.5단계 입력
- `jokbo_text.md` — `--jokbo-pdf`를 줬을 때만. **원본 족보의 원문 텍스트.**
  선지를 한 글자도 흘리지 않고 옮길 수 있어 이쪽을 먼저 읽는다. 다만 정답표와
  사진 문항은 이미지에만 있으므로 `jokbo_input.pdf`를 함께 봐야 한다
- `outline.json` / `annotations.json` — 슬라이드별 본문 요약, 필기·형광펜·**도장(stamp)** 신호.
  `annotations.json`의 `marks`가 **표시가 무엇에 닿았는지**를 들고 있다
  (`covers`·`on`·`where`). `signals`는 개수뿐이다
- `labels.json` — 슬라이드별 라벨 후보와 정확한 bbox. 이미지 오클루전 카드가 여기서 좌표를 가져온다
- `media/` — Anki 카드 뒷면용 슬라이드 PNG. 모델 입력이 아니지만 **각인이 없다.**
  각인이 봐야 할 것을 덮었을 때 여는 곳이다 — `260814_05`에서 각인이 s48·s49의 족보
  정답표를 덮었고 조각 둘이 여기서 값을 회수했다. 족보 페이지는 처음부터 이쪽이 낫다
- `prep.json` — `slide_image_map`, `total_slides` 등 계약 파일. **경계는 여기 없다**
- `timings.jsonl` — 단계별 시작·종료. 코드 단계는 스스로 찍고 모델 단계는 네가 찍는다

`prep.json`의 **`poppler_available`이 `false`면 `pages` 읽기가 안 된다.** prep은 그래도
성공하므로(실측: 종료 코드 0) 조각 에이전트에 가서야 터진다. 0단계 출력의 경고를 보고,
뜨면 앱을 완전히 종료했다 켜라 — PATH는 프로세스가 시작할 때 한 번 잡힌다.

**두 채널이 겹쳐서 나온다.** 둘 다 전 페이지이고 쪽 번호도 같다. 경계가 어디로 정해지든
다시 만들지 않게 하려는 것이다.

#### PDF를 읽는 법

```
Read( runs/<lecture_id>/model_input.pdf , pages: "8-12" )
```

- **한 번에 20쪽까지.** 더 필요하면 나눠 부른다. `prep.json`의 `read_windows`가 창을
  미리 계산해 두고, **파일 경계에서 끊어 준다** — 외부 족보는 별도 파일이라 `21-39`를
  통째로 요청하면 33쪽짜리 `annotated.pdf`에 39쪽을 달라는 셈이 된다
- **돌아온 이미지에 쪽 번호가 없다.** 헤더는 `N page(s)`뿐이고 요청한 범위도 되돌려주지
  않는다. 그러니 **세지 말고 각인을 읽어라** — 각 쪽 코너의 노란 `Slide N`이 슬라이드 번호다
- `pages`를 **생략**하면 PDF가 통째로 첨부되고 텍스트 레이어까지 오는데, **쪽이 많으면
  거부된다.** `260814_05`(49쪽)에서 이렇게 막혔다:

  > `This PDF has 49 pages, which is too many to read at once. Use the pages parameter
  > to read specific page ranges (e.g., pages: "1-5"). Maximum 20 pages per request.`

  `260812_02`(33쪽)는 통째로 읽혔다. **문턱이 어디인지는 모른다.** 그러니 통째 읽기를
  기대하지 말고 `read_windows`로 나눠 읽는 것을 기본으로 삼아라 — 텍스트 레이어를
  잃지만 확실히 된다. 조각 단위에서 통째로 읽는 것은 애초에 금물이다(같은 강의록을
  여섯 번 받는다)

**0단계는 경계를 짐작하지 않는다.** 예전엔 힌트를 냈지만 네 강의 연속으로 모델이
뒤집었고(한 장 늦음·한 장 이름·세 장 이름) 방향이 일정하지 않았다. 게다가 힌트에 맞춰
라벨 추출 범위를 좁히는 바람에 오클루전 후보를 조용히 잃었다. 코드는 재기만 하고
(`page_features.json`) 판정은 0.5단계가 한다.

출력에서 stamp가 찍힌 슬라이드와 "라벨 많은 슬라이드"를 본다 — 뒤쪽은 그림 슬라이드
후보이고, 오클루전 카드를 낼 자리를 여기서 미리 본다.

**색은 나오지 않는다.** 필기자마다 도구도 규약도 달라 같은 색이 정반대를 뜻한다.
회색이 사담일 때도 있고 "이 부분은 시험에 안 낸다고 하셨습니다" 같은 결정적인 말일
때도 있다. 뜻은 색이 아니라 **글에 있다** — `annotations.json`의 `notes`를 읽어라.
거기에 필기자가 적어 둔 말이 그대로 있고, 그게 어떤 색보다 확실한 신호다.

**서브에이전트에게 채널을 명시하라.** 지정하지 않으면 에이전트가 필기가 살아 있는
`media/`로 우회하고, 강의록 구간의 사실/신호 분리가 조용히 무너진다. 강의록은
`model_input.pdf`, 족보는 `annotated.pdf`(또는 `jokbo_input.pdf`)라고 파일명으로 적어라.

### 0.5단계 — 구조 판별 (Opus 5 호출 ⓪)

`general-purpose` 서브에이전트. **문항도 카드도 만들지 않는다.** 경계와 주제만 정한다.

띄우기 직전에 `timings.py ... start 0.5-model`, 받은 직후에 `end 0.5-model`.

족보 경계는 문구 정규식으로 못 잡는다. 실물에서 이렇게 깨졌다 — 표지가 "정답"이면
낱말 목록에 없어서 놓치고, 문항 본문이 annotation 이미지뿐이면 "빈 페이지" 폴백도 안
걸린다. 필기자마다 쓰는 말이 다르고 앞으로도 다를 것이라, 규칙을 늘리는 대신 판단을 넘긴다.

필기자가 적어 둔 말은 좋은 단서지만, **문구를 경계로 착각하지 마라.**

> "여기서부터는 작년 선배님의 필기에서 가져왔습니다"

이건 **자료의 출처가 바뀌는 지점**이지 족보가 시작되는 지점이 아니다. 이 문구가
슬라이드 N에 있어도 **그 앞장이 이미 족보인 경우가 있다** — `260812_02`가 그랬다
(s27에 문구, s26이 2025 기출). N부터 잘랐다면 최신 연도 기출 한 장을 통째로
강의록으로 오인했을 것이다.

문구는 "이 근처에 경계가 있다"는 신호로만 쓰고, **어디서 갈리는지는 앞뒤 페이지를
직접 열어 문항 번호·5지선다·정답표가 어디서 시작하는지로 가려라.**

> `runs/<lecture_id>/page_features.json`과 `outline.json`을 읽어라. 그다음
> `annotated.pdf`를 **전 페이지** 읽어라 — 경계를 찾는 자리이므로 뒤쪽만 봐서는 안 된다.
> `prep.json`의 `read_windows`대로 `pages`를 나눠 부른다. 20쪽 이하인 편이면 `pages`를
> 생략해 통째로 읽어도 되고 그러면 텍스트 레이어까지 오지만, 넘으면 거부되므로
> 기대하지 마라. 강의록 뒷부분과 족보가 섞여 있고, 어디서 갈리는지를 네가 정한다.
>
> **외부 족보가 있으면 그것도 읽어라.** `prep.json`에 `external_jokbo_range`가 있으면
> `jokbo_input.pdf`(**offset 주의** — N쪽 = 슬라이드 N + `jokbo_slide_offset`)와
> 원문 텍스트 `jokbo_text.md`가 함께 나와 있다. `read_windows`의 마지막 창이 그
> 구간이고 **파일 경계에서 끊어져 있다** — `annotated.pdf`에 그 쪽을 달라고 하면 없다.
>
> **족보는 훑지 말고 문항 단위로 읽어라.** 경계만 찾을 거면 생김새만 봐도 되지만
> `exam_focus`를 여기서 내므로 선지와 정답까지 봐야 한다. `annotated.pdf`의 필기 꼬리
> 구간과 외부 족보는 **서로를 대체하지 못한다** — `260812_03`에서 2019 문항 6개와
> 2020 #9는 필기 꼬리에만 있고 2025 #66·#69·#100은 외부 족보에만 있었으며 **정답표는
> 필기 꼬리에만** 있었다. 둘 다 열어라.
>
> 판정을 `runs/<lecture_id>/structure.json`에 쓴다.
>
> - `lecture_range` `[1, N]` — 강의록 구간
> - `jokbo_range` `[N+1, 끝]` 또는 `null` — 기출 구간. 강의록과 겹치지 않고 사이가 비지 않게
> - `jokbo_evidence` — 왜 거기서 갈리는지. 슬라이드 번호를 대라. **족보가 두 곳에
>   나뉘어 있으면 어느 연도·문항이 어디에 있는지, 정답표가 어디 있는지까지 적어라** —
>   뒤 단계들이 이걸 읽고 판정한다
> - `chunks` — 강의록의 **주제 덩어리**. `{id, title, slides: [시작, 끝], summary}`.
>   `lecture_range`를 **빠짐없이·겹침없이** 덮어야 한다. 한 덩어리는 대략 5~15장이다
> - `exam_focus` — **족보에서 읽어낸 교수의 출제 성향.** 무엇을 어떤 꼴로 묻는지,
>   어떤 선지를 뒤집어 함정을 놓는지, 어느 지점이 해마다 반복되는지. 모양은 자유다
>
> **`exam_focus`가 왜 여기 있나.** 경계를 찾느라 족보 구간을 어차피 전부 읽는 자리다.
> 예전엔 그 읽기를 버리고 1단계가 같은 쪽을 다시 읽었다. 1단계가 조각별로 갈리면서
> 조각마다 족보를 다시 읽을 판이라 이쪽으로 옮겼다. **여기서 안 내면 조각 N개가
> 각자 족보를 읽는다.**
>
> 슬라이드 번호는 세지 말고 **각인된 노란 `Slide N` 라벨을 읽어서** 적어라.
> 헷갈리면 `jokbo_range`를 넓게 잡지 말고 좁게 잡아라 — 강의록을 족보로 오인하면
> clean 채널을 잃고 사실 근거가 통째로 사라진다.

```bash
python quiz/structure.py runs/<lecture_id>
```

경계가 자료의 모양과 맞는지 기계가 따진다. 답안표가 족보 구간에 있는지, 족보 구간에
강의록 수준의 본문이 섞였는지, chunk가 구간을 다 덮는지를 본다. **불평이 하나라도 나오면
그 단계를 다시 시킨다.** 손으로 JSON을 고쳐 넘기지 마라 — 여기서 잘못되면 뒤가 전부
어긋난다.

검증기는 뒤에서부터 세어 본 값과도 견준다. 네 판정과 3장 넘게 어긋나면 알린다 —
둘 중 하나는 틀렸다는 뜻이므로 원본으로 가려라.

#### 작년 자료는 끌어오지 않는다

**올해 필기에도 족보가 붙어 있고 그게 작년 것을 포함한다.** 필기자가 작년 족보를
그대로 옮겨 오기 때문이다(`260812_01` 실측: 작년 18문항이 올해 족보에 100% 포함).
작년이 필요한 곳은 Pre-Quiz뿐이고 그건 다른 흐름이다.

원본 족보를 쓰더라도 **필기 자신의 꼬리는 그대로 있다.** 둘은 가상 번호에서
맞닿으므로 `jokbo_range`는 `[필기 꼬리 시작, 원본 족보 끝]` 한 구간이 된다.

### 1단계 — 청사진 (Opus 5 호출 ①, **chunk별 동시 실행**)

**카드는 만들지 않는다.** 무엇을 물을지만 정한다.

**`structure.json`의 `chunks`마다 하나씩, 동시에** 돌린다. 족보 구간도 한 조각이다.

    c01   슬라이드 1-8     →  blueprint.c01.json
    c02   슬라이드 9-17    →  blueprint.c02.json
    ...
    jokbo 슬라이드 50-66   →  blueprint.jokbo.json

**왜 쪼개나.** 1단계가 두 편 모두 직렬 단계 중 가장 컸는데(`260814_05` 14.8분 ·
`260812_03` 13.9분), 나온 결과를 chunk 경계에 대고 세어 보니 **objective 78개 중
경계를 넘는 것이 하나도 없었다**(35 + 43). 66쪽을 통째로 읽고 만든 것이 실은 조각
단위로 완결돼 있었다. 전역이던 것 중 큰 것(`exam_focus`)은 0.5단계로 옮겼다.

**당분간 — 이 분할은 아직 한 편도 안 돌았다.** 위 0%는 *전체를 본 에이전트가 낸 결과*가
조각 안에 갇혀 있었다는 것이지, 조각별로 시켜도 같은 결과가 나온다는 뜻이 아니다.
조각들이 서로를 몰라 같은 걸 두 번 세우거나 사이를 흘릴 수 있다. 받을 자리는 있다 —
흘린 슬라이드는 `merge_blueprint.py`가 세고, 조각 사이 중복은 §16b가 본다. 첫 편에서
**흘린 슬라이드 수와 조각 겹침 수**를 확인하고, 많이 나오면 되돌려라.

**조각마다 따로 찍어라** — `start 1-blueprint --label c01` … `end 1-blueprint --label c01`.

```bash
python quiz/merge_blueprint.py runs/<lecture_id>
```

조각을 `blueprint.json` 하나로 합치고 `obj_N`을 다시 매긴다 — 조각들은 서로를 몰라
그대로 두면 `obj_1`이 여러 개 생긴다. `exam_focus`는 `structure.json`에서 가져온다.
**어느 조각도 안 덮고 `skip_slides`에도 없는 슬라이드가 있으면 알린다** — 조각이
서로를 못 봐서 흘린 것일 수도 있으니 직접 열어 보라.

각 조각에 주는 지시는 아래와 같다. `<조각>`과 슬라이드 범위만 갈아 끼운다.

> `runs/<lecture_id>/structure.json`을 먼저 읽어라. 네 chunk는 **`<조각>`(슬라이드
> A-B)**이고 그 범위만 맡는다. 다른 chunk는 다른 에이전트 몫이니 손대지 마라.
> `exam_focus`에 교수의 출제 성향이 이미 정리돼 있고 `jokbo_evidence`에 족보가 어디
> 있는지가 적혀 있다 — **둘 다 읽어라.**
>
> **강의록 조각이면 족보 원문을 열지 마라.** 0.5단계가 이미 읽어 `exam_focus`로
> 정리했고, 조각마다 다시 열면 그 자리를 옮긴 뜻이 없어진다. 어느 기출이 네 구간을
> 건드리는지는 `exam_focus`와 `jokbo_evidence`로 판단하고, 그것으로 안 풀리는 것은
> `objective`에 적어 넘겨라.
> **족보 조각(`jokbo`)이면 원문을 읽어야 한다** — 문항 자체가 회수 대상이라 선지와
> 정답표가 필요하다. `annotated.pdf`의 필기 꼬리와 `jokbo_input.pdf`·`jokbo_text.md`를
> 둘 다 열어라(offset 주의).
>
> 강의록은 `model_input.pdf`를 `pages`로 **네 구간만** 읽어라. `outline.json`과
> `annotations.json`(필기자의 말은 `notes`에 있다)도 네 구간만 본다. 슬라이드 번호는
> 세지 말고 **각인된 노란 `Slide N`을 읽어라.**
>
> `.claude/skills/quiz/references/item-rules.md`를 **전부** 읽어라. 특히 §1(무엇을
> 카드로 만드는가), §3(중요도와 출제 이력), §4(족보).
> 결과를 `runs/<lecture_id>/blueprint.<조각>.json`에 쓴다. 스키마는
> `references/blueprint.schema.json`이고 `objectives`·`skip_slides`·
> `estimated_item_count`·`summary`만 채운다(`exam_focus`는 0.5단계가 냈다).
>
> - **`objectives`의 각 항목에 `slides`를 반드시 붙여라.** 다음 단계의 조각 배분이 쓴다
> - 각 `retrieval_target`에 `importance`(`core` / `detail`)와 `exam_hit`(참/거짓)을 붙여라.
>   **둘은 독립이다** — 곱해서 우열을 매기지 마라
> - 제외는 §1의 여섯 사유 중 하나에 해당할 때만이고, 뺀 슬라이드는 `skip_slides`에 적어라.
>   **적지 않으면 합칠 때 "흘린 슬라이드"로 잡힌다**
> - `annotations.json`의 `stamp`는 기출 출제 이력이므로 `exam_hit`의 근거가 된다.
>   **도장이 0장인 편도 있다** — 필기자가 안 쓴 것이다. 그때는 `exam_focus`에서 읽어라
> - 족보가 그림으로 묻거나, 위치와 이름의 대응이 시험 대상인 슬라이드는 §15를 읽고
>   그 target에 **`occlusion_candidate: true`**를 붙여라. 산문으로만 적지 마라 —
>   다음 단계의 조각 배분이 이 값을 센다. 오클루전이 있는 조각은 픽셀을 재고 렌더해
>   확인하느라 예측보다 2~5분 길다(`260812_03` 실측)
> - 네 chunk 밖의 슬라이드가 근거로 필요하면 **열어 보되 objective를 세우지는 마라.**
>   그 자리는 그 chunk를 맡은 조각의 몫이다

합친 뒤 직접 `blueprint.json`을 열어 `core`와 `detail`이 둘 다 나타나는지, `exam_hit`이
붙은 target이 있는지, `merge_blueprint.py`가 알린 흘린 슬라이드가 정말 뺄 자리인지
확인한다.

### 2단계 — 카드 작성 (Opus 5 호출 ②, **조각별 동시 실행**)

**한 번에 다 쓰게 하지 마라.** 76장을 한 호출에 맡겼더니 `260812_02`에서 **68분을
돌다 API 오류로 죽었고 아무것도 남기지 못했다.** 기준 강의의 19분과 견주면 3.5배다.

배분은 코드가 계산한다. **정하지는 않는다 — 제안이다.**

```bash
python quiz/plan_chunks.py runs/<lecture_id> --slots 9
```

`structure.json`의 `chunks`와 청사진을 읽어 조각마다 예상 카드 수와 소요를 찍어 준다.
`chunk_plan.json`에도 남는다. **왜 코드가 세나** — `260814_05`에서 벽시계를 붙잡은 것이
슬롯이 아니라 조각 크기였다. 여덟 중 c6이 26장·jkA가 25장인데 나머지는 5~14장이라
둘만 두 배였고, 동시 실행을 6에서 8로 올려도 0.9분밖에 안 줬다. 다시 담으면 같은
자료로 18.3분이 13.2분이 된다.

출력의 **「쪼갠 주제」와 「합친 조각」을 직접 보고 말이 되는지 판단하라.** 경계 규칙은
코드가 지킨다 — 한 조각은 *온전한 chunk 하나 또는 여럿을 합친 것*이거나 *한 chunk를
자른 조각*이고, 쪼갠 조각을 옆 chunk에 붙이지 않는다. 족보는 쪼개기만 한다.

그 배분대로 **조각마다 서브에이전트를 하나씩, 동시에** 돌린다.

    c1     obj_1~3     슬라이드 1-6      →  items.raw.c1.json
    c2     obj_4~6     슬라이드 7-11     →  items.raw.c2.json
    ...
    jk1    obj_14~19   슬라이드 26-39    →  items.raw.jk1.json

**한 번에 다 띄워라.** 실측으로 여덟이 동시에 돌았다 — 완료 시각이 5분 안에 몰렸는데
개별 소요는 6.4~11.0분이었다. 직렬이었으면 66분이다. 웨이브로 나눠 돌리면 그만큼
벽시계가 는다.

**조각마다 따로 찍어라** — `start 2-write --label c1` … `end 2-write --label c1`.
라벨이 없으면 벽시계와 작업시간 합이 안 갈리고, 그 둘의 차이가 조각화의 값이다.

조각 하나는 5분 안팎이고 서로 독립이라 **하나가 죽어도 나머지는 남는다.**
objective를 조각에 배분할 때는 `slides`의 최솟값이 어느 chunk 범위에 드는지로
가린다.

각 조각에 **그 대목의 급소를 따로 일러줘라.** 청사진의 `exam_focus`와
`trap_patterns`에서 해당 슬라이드에 걸리는 것을 뽑아 넘기면 카드가 눈에 띄게
날카로워진다.

```bash
python quiz/merge_items.py runs/<lecture_id>
```

조각을 `items.raw.json` 하나로 합치고 `id`를 다시 매긴다 — 조각들은 서로를 몰라
그대로 두면 `q001`이 여러 개 생긴다. 조각이 같은 슬라이드를 나눠 가졌으면
중복 의심으로 알리고, 판단은 4단계에 맡긴다.

각 조각에 주는 지시는 아래와 같다. `<조각>`과 objective 목록만 갈아 끼운다.

> `blueprint.json`의 **`obj_N`~`obj_M`만** 만든다. 다른 objective는 다른
> 에이전트 몫이니 손대지 마라.
> 강의록은 `model_input.pdf`를 읽어라. **`pages`로 자기 조각 구간만** 읽는다 —
> 통째로 읽으면 여섯 조각이 같은 강의록을 여섯 번 받는다.
>
> **족보는 `structure.json`의 `jokbo_evidence`를 먼저 읽고 어디에 있는지 확인한 뒤에
> 열어라.** 필기 꼬리는 `annotated.pdf`, 외부 족보는 `jokbo_input.pdf`(**offset 주의**)와
> 원문 `jokbo_text.md`다. **한쪽만 보고 "그 문항은 없다"고 판정하지 마라** —
> `260814_05`에서 조각 셋이 `jokbo_text.md`만 보고 맞는 인용 20건을 지웠다. 그 편에
> 가짜 인용은 한 건도 없었다. 각인이 정답표를 덮었으면 `media/`의 PNG를 열어라.
> `references/item-rules.md`를 **전부** 읽고 그 규칙대로 카드를 만든다.
> 결과를 `runs/<lecture_id>/items.raw.<조각>.json`에.
> 스키마는 `references/item.schema.json`. `id`는 `<조각>_001`처럼 매긴다.
>
> - 모든 카드는 청사진의 `objective_id`와 `retrieval_target`에 묶인다
> - `slide_no`는 페이지를 세지 말고 **각인된 노란 `Slide N` 라벨을 읽어서** 적는다
> - 강의록 카드는 `source_type: "lecture"`, 족보 카드는 `"jokbo"`
> - 족보 카드는 선지에 의존하지 않게 자족적으로 압축한다 (§4.2)
> - 족보 정답이 검토 결과와 다르면 `review_flags`와 `review_note`를 남긴다 (§4.4)
> - 답은 핵심만, 부연은 `explanation`으로 (§11). 해설은 자료 밖 지식을 써도 된다 (§12)
> - 무엇과 헷갈리는지는 `trap_note`에 한 줄로. `trap` 유형은 필수다 (§12)
> - 그림 카드는 `labels.json`에서 `label_ids`를 골라 `occlusion`에 적는다. 좌표를 눈대중으로 찍지 마라 (§15)
> - 청사진의 target 중 카드를 만들지 않은 것은 `skipped`에 사유와 함께 남긴다
>
> **다 쓰고 나면 §16a로 자기 것을 다시 본다.** 쓰기와 같은 패스에서 하지 마라 —
> 다 쓴 결과물을 입력으로 삼아 처음부터 다시 읽어라. 먼저 기계 표시를 받아라:
> `python quiz/validate.py runs/<lecture_id> --items items.raw.<조각>.json`.
> 고친 것을 같은 파일에 반영해서 쓰고, 무엇을 확인했고 무엇을 유지했는지를
> `notes`에 산문으로 남겨라. **카드를 보태지는 않는다** — 빠져 보이는 자리는
> `skipped`에 사유와 함께 남기면 덱 감사가 받는다.

### 3단계 — 기계 검증 (코드)

```bash
python quiz/validate.py runs/<lecture_id>
```

`items.checked.json`(빌드 가능)과 `suspects.json`(감사 대상)이 나온다.
출력의 카드 수·난이도 분포·출처 분포를 사용자에게 한 줄로 보고한다.

### 4단계 — 덱 감사 (Opus 5 호출 ③)

새 `general-purpose` 서브에이전트로 돌린다. **§16b가 기준이다** — 카드 한 장 단위는
2단계의 §16a가 이미 끝냈다. 여기서 보는 것은 **조각 사이**다.

실측했다 ([docs/pipeline.md](../../../docs/pipeline.md) 4단계) — 값을 하는 것은
감사자가 다른 에이전트라는 게 아니라 **덱 전체를 한 번에 본다는 것**이다. 조각 경계
중복·회상 중복·과출제 집중은 거기서만 잡힌다. 카드 한 장 단위의 시각 확인은 오히려
2단계가 더 잘했다.

**조각들이 서로 어긋나게 판정한 것도 여기서 잡는다.** `260814_05`에서 조각 셋이 족보의
범위를 잘못 보고 맞는 인용 20건을 지웠는데 덱 감사가 전부 되돌렸다. 조각이 `notes`에
남긴 산문을 **먼저 읽어라** — 그게 없었으면 충돌이 보이지 않았을 것이다.

띄우기 직전에 `timings.py ... start 4-audit`, 받은 직후에 `end 4-audit`.

**최종 배열을 통째로 쓰게 하지 마라.** 74장을 다시 출력하면 2단계가 죽었던 그
자리에 또 걸린다. 감사가 실제로 손대는 것은 보통 2~3할이니 **바뀐 것만** 쓰게 한다.

조각을 나눠 돌렸으면 **조각 경계에서 중복이 났는지 반드시 확인시켜라.**
`merge_items.py`가 같은 슬라이드를 나눠 가진 곳을 짚어 준다. 기계는 회상 목적이
같은지까지는 못 본다.

> `suspects.json`과 `items.checked.json`을 읽어라. 조각들이 `items.raw.<조각>.json`에
> 남긴 `notes`도 전부 읽어라 — 무엇을 확인했고 무엇을 넘겼는지가 거기 있다.
> 원본 확인이 필요하면 강의록은 `model_input.pdf`, 족보는 `structure.json`의
> `jokbo_evidence`가 가리키는 쪽(필기 꼬리는 `annotated.pdf`, 외부는 `jokbo_input.pdf`와
> `jokbo_text.md`)에서 `pages`로 **지목된 슬라이드만** 읽어라.
> `references/item-rules.md`의 **§16b 덱 감사**를 따른다.
> **패치만** `runs/<lecture_id>/audit_patch.json`에, 판정 근거를 `audit.md`에 쓴다.
>
> ```json
> { "edit": [ { "id": "q012", "a": "고친 답" } ],
>   "drop": [ { "id": "q034", "reason": "q031과 회상 목적이 같다" } ],
>   "add":  [ { ...스키마를 갖춘 새 카드... } ] }
> ```
>
> `edit`은 **바꿀 필드만** 적는다. 언급하지 않은 카드는 자동으로 유지된다.
> `id`는 못 바꾼다 — 틀렸으면 `drop`하고 새로 `add`하라.
>
> - `near_duplicate_groups`와 `merge_items.py`가 짚은 조각 경계 겹침 — 회상 목적이
>   같은 것만 줄인다. 족보 카드와 강의록 카드가 같은 것을 물어도 목적이 달라 둘 다
>   남긴다. 답이 같아도 **회상 방향이 반대면 유지한다**
> - `coverage_gaps`와 조각들이 넘긴 `skipped` — **`add`는 여기서만 한다.** 판정하기
>   전에 그 target을 **이미 받고 있는 카드가 다른 조각에 있는지** 먼저 확인하라.
>   조각들은 서로를 못 봐서 넘긴 것이고, 실측에서 두 편 모두 대부분 이미 덮여 있었다
> - `hot_slides`·`untouched_slides` — **개수로 판정하지 마라.** 계수기가 문항이 아니라
>   슬라이드를 센다. 실측에서 네 번 울려 네 번 다 오탐이었다
> - 조각이 못 푼 기계 표시가 남아 있으면 여기서 푼다. 카드를 쪼개야 풀리는 것은
>   §16a가 `add` 금지라 넘길 수밖에 없다

### 5단계 — 빌드 (코드)

```bash
python quiz/apply_audit.py runs/<lecture_id>          # 패치 → items.final.json
python quiz/validate.py runs/<lecture_id> --items items.final.json   # 다시 통과하는지
python quiz/build.py runs/<lecture_id> --items items.final.json --project <과목>
```

감사 패치를 반영한 뒤 **검증을 한 번 더 돌린다.** 고친 것이 정말 고쳐졌는지는
기계가 세어야 안다 — 실측에서 soft 22건이 1건으로 떨어지는 것을 여기서 확인했다.

`slide_no`가 범위를 벗어나거나 이미지가 없으면 **빌드가 중단된다.** 임의로 번호를 바꾸지 말고
4단계로 되돌려 원본에서 확인시켜라. 오클루전 좌표가 풀리지 않을 때도 마찬가지다.

빌드는 마지막에 쓴 `.apkg`를 도로 열어 노트·카드·미디어 수를 실제로 센다.
여기서 실패하면 덱이 깨진 것이므로 **사용자에게 넘기지 마라.**
`runs/INDEX.md`(빌드한 덱 대장)도 이때 갱신된다.

### 6단계 — 표시하고 올린다 (코드)

```bash
python -m studyez done <lecture_id>
```

두 가지를 한다. `runs/<lecture_id>/source.json`에 무엇의 몇 판으로 만들었는지 적어
**다음 스캔에서 이 편이 빠지게** 하고, 이어서 그 편을 서버로 민다.

**빌드가 온전할 때만 불러라.** 표시가 찍히면 다음 스캔이 이 편을 다시 만들지 않는다.
5단계의 apkg 재검사가 실패했으면 부르지 마라.

올릴 것은 `studyez.gate`가 편마다 본다 — `answer_mismatch`가 있거나 apkg의 실제
내용물이 `item_count`와 다르면 **강의록만 나가고 덱은 미뤄진다.** 미룬 사유가 출력에
`✋`로 적히므로 사용자 보고에 그대로 옮긴다. 고친 뒤 다시 부르면 그때 올라간다.

`--dry-run`이면 표시도 업로드도 안 하고 무엇이 올라갈지만 적는다.

## 사용자 보고

- 덱 이름, 카드 수, 중요도(core/detail)·기출 여부(exam_hit)·출처(강의록/족보) 분포
- 이미지 오클루전 카드 수
- 족보 정오 검토 플래그가 붙은 카드 수
- 감사에서 삭제/수정/보충한 수
- **카드가 하나도 없는 슬라이드 번호** — 사용자가 직접 확인해야 할 항목
- `.apkg` 경로. Anki에서 수동 import한다 (자동 투입하지 않는다)
- **단계별 소요** — `python quiz/timings.py runs/<lecture_id> report`의 표를 그대로 붙인다
- **단계별 토큰** — `python quiz/tokens.py runs/<lecture_id>`의 표를 그대로 붙인다. 6단계의 `studyez done`이 `tokens.json`으로도 남긴다

## 실패 시

- 서브에이전트가 스키마를 어긴 JSON을 쓰면 그 단계만 다시 시킨다. 손으로 JSON을 고쳐 넘기지 않는다
- `validate.py`가 대량으로 hard 제거하면 2단계 지시가 잘못됐다는 신호다. 감사로 덮지 말고 2단계를 다시 돌린다
- 족보 구간을 잘못 잡으면 `prep.py --jokbo-start N`부터 다시
- 사용자가 카드 품질을 지적하면 `references/item-rules.md`의 해당 절을 직접 고친다. 다음 실행부터 세 에이전트가 그 규칙을 읽는다
