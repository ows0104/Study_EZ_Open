# 강의 목록 숫자 칸: 고른 블럭의 강의만 계산 — 설계

## 요구사항과 수용 기준
- R1 `GET /api/root-learning?lecture=<subject>/<runId>&lecture=…`
  - 열린(enabled·allowed) 강의 중 물은 강의만 계산해 준다.
  - 묻지 않은 강의의 `overview_data`는 돌지 않는다.
  - 열리지 않았거나 없는 키는 조용히 빠진다.
- R2 `lecture`가 없으면 지금과 같다(열린 강의 전부).
- R3 키는 마지막 `/`에서 나눈다. runId에는 `/`가 없다.
- R4 강의 목록은 지금 고른 블럭의 Main-Quiz 행의 키만 보낸다.
  - 숨긴 행도 넣는다. 숨김 관리 화면에서 숫자가 보이고, 숨기거나 풀 때 다시 묻지 않는다.
  - 그런 행이 없으면 요청하지 않는다.
  - 키 집합이 바뀌면(블럭 변경) 새로 묻는다.
- R5 60초 캐시와 창 focus 때 다시 읽기는 그대로다. 캐시는 키 집합마다 따로 둔다.
  - Optional 토글이 바뀌면 지금처럼 캐시를 버린다.
- R6 키 집합이 바뀌는 동안에는 숫자 칸을 「…」로 둔다. 앞 블럭의 숫자를 새 블럭 행에 쓰지 않는다.

### 새 카드·카드 기준(같은 세션에서 더함)
- R7 `state.question_progress`가 `newToday`를 더 준다.
  - 뜻: 오늘 계획(`reviewDue`와 같은 계획, 같은 중요도 칩)의 과제 중 단위가 아직 안 본 것(시도·평가 없음)의 수.
  - Optional 제외도 `reviewDue`와 같이 따른다.
  - 안 본 카드만 세므로 새 카드와 복습이 같은 카드를 두 번 세지 않는다.
- R8 강의 목록 요약 칸은 왼쪽부터 「오늘 새 카드 · 오늘 복습 · 학습률 평균 · 전체 카드」다.
  - 새 카드는 열린 강의의 `newToday` 합이다.
  - 좁은 화면에서는 2×2로 놓는다.
- R9 Main-Quiz 시작 화면은 숫자를 카드 기준으로 보인다.
  - 숫자 칸: 「전체 카드 · 본 카드 n/전체 · 회상 가능 n/전체」.
    - 본 카드 = 전체 − 미열람, 회상 가능 = 인출 + 저장(강의 목록 열과 같은 `questionProgress`).
  - 막대도 같은 값이다.
  - 오늘 추천 문구: 「새 카드 N장 · 복습 M장」. `newToday`가 없는 옛 API면 「오늘 카드 N장」(계획 과제 수)이다.
  - 접은 「학습 현황·자료 범위」는 목표 기준 그대로 두되, 「학습 목표 기준 ·」을 앞에 붙여 밝힌다.
  - 「첫 학습 목표일」은 날짜라 그대로 둔다.

## 책임·입출력 계약·오류 상태
- 응답 모양 `{lectures: [...], canManage}`는 그대로다. 강의 하나가 실패하면 그 강의만 빠지는 것도 그대로다.
- 시간표보다 먼저 쏘던 `prefetchRootCatalog`는 뺀다.
  - 시간표가 와야 블럭을 안다.
  - 전부를 미리 물으면 8 s짜리 계산을 서버에 한 번 더 시킨다.
  - 시간표는 0.3 s라, 그 뒤에 출발해도 빨라진다.

## 호환성과 데이터 보존
- DB·스키마·학습 기록 변경 없음. 읽기 전용 API 인자 하나를 더한다.
- 옛 웹 번들은 인자 없이 불러 R2로 전부를 받는다. 새 웹과 옛 API가 만나도 옛 API가 인자를 무시하고 전부를 준다.
  - 화면은 키로 찾아 쓰므로 어느 쪽이든 숫자가 맞다.
