# server 작업 안내

두 앱의 인증·DB·파일 배급·작업 상태를 담당하는 FastAPI 서버다.
`runner`·`quizgen`·`quizbank`를 import하지 않는다.

## 수정 위치

| 책임 | 파일 |
|---|---|
| API | `app/routes/` |
| Quiz Bank API 책임별 위치 | `app/routes/bank_api/CLAUDE.md` — 게시·편집·피드백·학습·표시 |
| DB 모델 | `app/models/` — 기존 `from app.models import ...` 유지 |
| 생성 작업 정책 | `app/jobs/`, `app/routes/prequiz_jobs.py` |
| 기존 퀴즈 복습 간격 | `app/srs.py` |
| Quiz Bank 다음 문항 | `app/study_engine/` |
| 설정·인증·저장소 | `app/config.py`, `auth.py`, `storage.py` |
| DB 초기화·호환 칼럼 추가 | `app/cli.py` |

## 검사와 로컬 환경

`server/`에서 `.venv/Scripts/python.exe -m tests`를 실행한다.
파일마다 import 시점에 DB를 설정하므로 독립 프로세스가 필요하다.
하나만 고를 때는 `-m tests bank`처럼 이름 일부를 준다. pytest로 대신하지 않는다.

`server/.env`는 운영 DB를 가리킬 수 있다.
직접 실행할 때는 [README](README.md)의 로컬 DB 환경을 먼저 명시한다.

## 계약

- `lecture.preview_source`는 교수 기준 예습 자료의 선택적 JSON이다. 운영 배포 전 nullable 칼럼 준비가 필요하다.
  구형 입력 생략은 기존 값을 보존한다. 학생용 요약에는 내부 보존본·대화 연결·로컬 경로를 넣지 않는다.
  예습 PDF는 해시별 키로 올리고 이전 객체와 해시/복원 정보를 보존한다. 선택 원본과 공유 대화가
  어긋나면 예습 문항 업로드를 보류한다. 기존 대화/학습 기록은 지우지 않는다.

- 문제은행을 교체하거나 공용 문항을 수정하기 전에 `bank_retention`으로 은행 버전과
  사용자 상태를 보관한다. `previous`만 덮어써 여러 버전의 이력을 지우지 않는다.
  문항 ID만으로 동일성을 판단하지 않으며, 확실히 같은 문제의 평가 시각·등급만
  새 학습에 연결한다. 변경·불명확 문항은 원본 보관본에 남기고 임의로 완료 처리하지 않는다.

- 약리학 퀴즈 준비 현황은 `quiz_publication_check`의 공개 응답 검증 기록과 QuizBank의
  성공 업로드 시각을 별도로 조회한다. 새 표는 API 전에 생성하고 RLS를 활성화한다.
  공유 링크 저장 시각으로 출제 완료 시각을 추정하지 않는다. 학생 API에는 원문·개인 대화 주소를 싣지 않는다.
- 새 표·칼럼은 DB 초기화/호환 변경과 코드 배포 순서를 함께 검토한다. 운영 변경 시 DB 준비가 먼저다.
- 라우트 변경 시 `tests/test_route_contract.py`와 호출하는 웹·러너·확장을 확인한다.
- 학생 응답과 관리자 응답을 구분한다. 화면에서 숨기는 것만으로 개인정보가 제거되지는 않는다.
- 기존 퀴즈 간격은 `srs.py`가 계산한다. 웹에 같은 정책을 복제하지 않는다.
- Quiz Bank 정책은 Study Engine이 담당하며 학생 공개는 `open_to_students`를 따른다.
- 사용자 지시(2026-10-16): 신규 문항은 등급(Core·Important·Optional)·심화 여부로 묶지 않고 슬라이드 순서를 기본으로 한다. 선행관계와 같은 개념의 회상방향 간격만 순서 조정에 사용하며 일반·모아풀기에 함께 적용한다.
- 사용자 후속 지시(2026-10-18): 첫 학습은 명시적 선행관계와 같은 개념의 직접 회상을 먼저
  확인한 뒤 대응·기전·응용으로 이어간다. 필요한 뿌리는 관련 세부 문항의 슬라이드 위치로
  당기며, 관련 없는 개념의 흐름은 유지한다. 직접 회상은 기초 연결의 보수적인 대용 기준이고
  문장 키워드로 의학적 선행관계를 새로 만들지 않는다. 명시적 관계와 충돌하는 추론은 생략한다.
  평가 후에는 오답도 다음 연결을 열고 당일 반복을 강제하지 않는다. 은행·기존 학습 기록은 바꾸지 않는다.
- 사용자 후속 지시(2026-10-18, 지혈 전체 순서): 검토된 문항의 선택적 `learning_page`는
  개요 인용·근거 이미지 목록과 구분한 실제 학습 위치다. 해당 문항은 명시적 prerequisites만
  사용하며 같은 개념의 direct를 자동 추가하지 않는다. 기존 은행은 이 필드 없이 종전 동작을
  유지한다. 지혈 91문항은 순서 메타데이터만 교정했고 문항·정답·근거·빌드·학습 기록을 보존했다.
  다른 강의의 구조 점검과 내용 대조 범위는 `work/hemostasis-order-20261018/summary.json`에 기록했다.
- 사용자 후속 지시(2026-10-18, 나머지 23강의 직접 순서 검토): 추가 PDF·모델/CLI 검수 없이
  저장된 문항·정답·검토 자료로 전체 1,961문항을 직접 확인하고 575문항의 순서 메타데이터만
  교정해 운영 반영했다. 기존 내용·근거·검수 판정·빌드·학습 기록과 수정 잔여 횟수는 보존한다.
  문항별 판단과 전후 재현 기록은 `work/remaining23-order-20261018/README.md`에 보관한다.
- 카드 전체 교체 시 관리자의 `card_edit` 판정을 다시 반영한다.
- 파일 본문은 R2 서명 URL로 직접 전송하며 계약의 kind와 Content-Type을 유지한다.
