## 파일 수신 확인의 범위

| 확인 | 이번 방법 | 의미 |
|---|---|---|
| 실제 파일 생성 | 다운로드한 원문 파일을 받음 | 링크/완료 문구만 받았다는 상태와 구별 |
| 내용 확인 | 나온 트리를 함께 보고 뿌리·큰 흐름·원본 근거·범위 확인 | 첫 요청에 세부 출력 항목을 강제하지 않음. 부족한 정보는 후속 확인하며 의학적 완전성 보증으로 쓰지 않음 |
| 원문 보존 | 받은 바이트를 보존하고 SHA256·크기를 기록 | 이후 변환/대조에서 같은 판을 사용 |
| bridge 자동 회수 | 이번 전달 경로에서는 미검증 | 수동 파일 회수 성공을 자동 회수 성공으로 표시하지 않음 |
| bridge 설치/패키지 버전 | 별도 선행 확인 항목으로 유지 | 소스 1.3.20과 로컬 ZIP 1.3.19의 차이는 아직 해결하지 않음 |

현재 bridge는 문제은행 파일 계약을 다루며 뿌리/포인트 파일의 종류별 수신 계약은 없다.
이 시범 파일을 사이트의 “답변 저장·검수 요청”에 넣거나 STUDYEZ_BANK_COMPLETE를 붙이지 않는다.
기존 은행 자동 검수·게시 경로를 사용하지 않고 로컬 검토 자료로만 회수한다.
실제 bridge 자동 회수 확인은 설치/패키지 정합성과 격리된 수신 경로의 구체 계획을 검토한 후 진행한다.
