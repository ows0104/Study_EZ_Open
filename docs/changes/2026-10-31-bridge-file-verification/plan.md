# Bridge 파일 수신 동작 점검 — 구현 계획

## 변경 범위·대상 파일·순서
이 계획은 구현 변경이 없는 진단 계획이다. 먼저 소스와 기존 테스트의 격리 여부를 읽고, 기존 검사만 실행한 후 수신 메타데이터와 raw.md의 지문을 대조한다. 로컬 배포 ZIP의 버전/파일 구성이 현행 소스와 맞는지도 읽기 전용으로 확인한다. report.md에 확인·실패·미확인을 분리한다. 이번 조사에서 기능 보완을 구현하지 않는다.

## 검사 명령과 성공 조건
1. Node: tests/bridge/test_bank_file.cjs, test_bank_download.cjs, test_link_recovery.cjs. 모의 다운로드·완료 확인·전달 계약 검사를 실제 실행하고 수와 실패를 확인한다.
2. 루트 가상환경 pytest: tests/bridge와 tests/runner/test_bank.py의 markdown_file 선택. 저장 원문과 지문 보존 및 변조 거절을 확인한다.
3. server/.venv/Scripts/python.exe -m tests bank_file_storage 및 bank_markdown_file. 각 파일이 별도 프로세스에서 임시 SQLite/로컬 저장소를 사용함을 확인한 뒤 실행한다.
4. 기존 response-file.json별 raw.md 바이트 수/SHA256 및 파일 헤더·실제 ID 수를 비교한다. 성공 이력은 새 운영 왕복의 증거로 쓰지 않는다.
실제 명령·종료 코드·출력과 소스 지문은 report.md에 기록한다. 개발 도구의 build 승인을 테스트 통과나 제품 구현 승인으로 임의 생성하지 않는다.

## 위험·복원·승인할 범위
현재 사용자 요청은 조사·기존 검사 실행 범위에 적용한다. 제품 구현·운영 업로드·게시·확장 재설치/재패키징은 포함하지 않는다. 운영 웹에서 새 파일 전달은 검수·게시 작업을 만들 수 있으므로 이번 진단에서 실행하지 않는다. 실패를 발견하면 근거와 구체 보완안을 먼저 제시한다. 생성한 조사 문서/테스트 임시 파일 이외에는 변경하지 않으므로 제품 복원이 필요하지 않다.
