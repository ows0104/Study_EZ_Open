# Main-Quiz 모아풀기 — 설계

## 요구사항과 수용 기준
- R1 선택: `StudyOverview`에서 `mainQuiz`가 있는 행만 `batch: true`다. 체크·「열린 강의 모두 선택」·막대는 기존 모양 그대로다.
  막대 문구 「오늘 복습 n장」은 행의 `cardProgress.reviewDue` 합이다(Main-Quiz 집계).
- R2 주소: 「모아풀기」는 `/study/mix?l=<subject>/<runId>&l=…`로 간다. 주소만으로 다시 열 수 있다(새로고침·뒤로).
- R3 시작 화면: 고른 강의마다 제목과 「오늘 n문항」(이어 풀 회차면 「남은 n문항」)을 보인다.
  오늘 과제가 없는 강의는 「오늘 과제 없음」으로 보이고 흐름에서 빠진다. 「모아풀기 시작」, 「강의 다시 선택」.
- R4 회차: 시작하면 강의마다 기존 `POST …/sessions`를 보낸다(열린 회차가 있으면 서버가 그 회차를 준다).
  각 회차를 `GET /api/root-learning/sessions/{id}`로 읽는다. 강의 하나라도 시작이 거절되면 그 강의만 빼고 이유를 보인다.
- R5 섞기(2026-11-18 사용자 정정 「병렬처리인데 랜덤」): 아직 끝나지 않은 강의 중 하나를 남은 문항 수에 비례한 확률로 뽑는다.
  오늘 문항 전체를 강의 안 순서는 지킨 채 고르게 섞은 것과 같다.
  한 강의의 과제 순서는 서버가 정한 그대로다. 평가·보류·제외로 그 강의 문항이 끝날 때만 다음 강의를 고른다.
- R6 풀이: 화면은 기존 `RootSolve`를 그대로 쓴다. 제목 줄에는 지금 문항의 강의 제목, 진행은 모든 강의의 합(`문항 k / N`)이다.
  문항 수정·중요도·메모·내 문제 경로는 지금 문항의 강의 것이다.
- R7 되돌리기: 화면 전체에 하나의 행동 스택(강의 key 목록)을 둔다. Z는 맨 위 강의로 바꾸고 그 회차에 `undo`를 보낸다.
  강의 하나일 때와 같이 미리 받은 문항이 있으면 바로 그린다.
- R8 마침: 모든 강의가 끝나면 「오늘 모아풀기를 마쳤어요」와 강의별 「n문항 · 첫 학습 a/b · 회상 가능 c」. 되돌리기·「강의 목록으로」.
  새로고침 전에 오늘 목록을 이미 끝낸 강의(시작 화면 「오늘 목록 마침」)는 섞이지 않지만 마침 화면에는 남는다.
  진행 표시(`문항 k / N`)는 그때 섞는 강의만 센다.
- R9 저장: 쓰기는 기존 `useRootStudyWrites` 한 줄(scope `[계정,"mix"]`)로 순서대로 보낸다.
  유실·충돌 안내와 「같은 요청 다시 저장」·「보관 응답 확인 후 서버 기록 불러오기」는 강의 화면과 같다.
- R10 학습일: 회차가 `학습일` 막힘이면 「오늘 모아풀기 다시 시작」으로 시작 화면에 돌아간다.

## 책임·입출력 계약·오류 상태
- 새 API 없음. 기존 `GET lectures/{s}/{r}`(overview), `POST …/sessions`, `GET sessions/{id}`, `GET sessions/{id}/prepare`,
  `POST sessions/{id}/events`만 쓴다. `test_route_contract`는 그대로다.
- 섞기·되돌리기 스택은 화면 상태다. 새로고침하면 각 강의 회차의 서버 위치에서 다시 섞는다(기록은 서버에 있다).
  새로고침 뒤 Z는 그 뒤에 한 행동부터 돌린다(강의 화면도 새로고침하면 화면 스택을 비운다).
- 미리 받기: 강의마다 `prepare`로 다음 3문항을 받는다. 미리 받은 문항이 없으면 저장을 기다린 뒤 회차를 읽는다(강의 화면과 같다).
- 오류: 한 강의 overview가 404·403이면 그 강의는 「열 수 없음」으로 보이고 빠진다. 모두 빠지면 시작 단추가 꺼진다.

## 호환성과 데이터 보존
- 서버·DB·migration·프롬프트·생성기 변경 없음. 학습 이벤트 형식·복습일·학습률 계산은 그대로다.
- 모아풀기에서 한 평가는 강의 하나 화면에서 한 평가와 같은 이벤트다. 강의별 회차에 그대로 쌓인다.
- 옛 Quiz Bank 모아풀기(`BankSolve` batch, `/api/bank/batch/*`)는 지우지 않는다. 학생 화면에서 그 길로 들어가는 곳만 새 화면으로 바뀐다.
  (`batch`가 11-11부터 모두 false라 이미 들어갈 수 없었다.)
- `RootSolve`·`RootLearning`은 고치지 않는다(다른 진행 중 작업이 고치는 파일). `useRootFrames.ts`는 `warm`을 내보내기만 한다.
