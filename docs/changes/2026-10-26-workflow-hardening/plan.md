# 실행 묶음 — 로컬 구현·자동화 복구 승인

1. 정상 한국어 자동화 초안을 docs/feedback-loop.md 및 기존 사용자 승인 기록과 대조한다.
   전후 설정을 보존한 뒤 자동화 도구로 같은 study-ez 항목만 수정하고 다시 읽어 검증한다.
2. scripts/development.py의 검증 대상과 evidence 형식을 설계한다. 실제 입력 목록과
   컴포넌트별 의존성, 기존 state.json의 호환/마이그레이션 정책을 먼저 확정한다.
3. source 범위·plan hash를 테스트/리뷰에 연결하고 4개 재현 사례를 실패가 아닌 통과로 전환한다.
   설계 변경 중 실행과 다른 컴포넌트의 변경도 회귀 검사한다.
4. server/deploy.ps1과 웹 릴리스 경로에 후보 고정·승인 확인·배포 결과 기록을 연결한다.
   이 구현 단계에서는 원격 호출 대역으로 검사한다. 실제 운영 배포는 별도 중요 승인 대상이다.
5. scripts/maintenance.py와 개발 기록에 사건 수명주기를 추가하고 감지→조사→새 계획→
   승인→검사→배포 기록→관측 복구를 격리 환경에서 한 사이클 재현한다.
6. 최종 릴리스 후보를 별도 구성할 때만 웹/API/러너/계약 검사를 해당 후보에 맞춰 실행한다.

검사: 기존 workflow 8개, 정상 연결 추가 2개, 확인된 결함 4개, 신규 승인/수명주기/배포 대역 검사.
복원: 자동화 원문과 변경 파일 백업, 기존 기록 원문 보존, 새 evidence 형식의 명시적 버전 처리.
운영 DB·문항·자료·러너 실행 상태는 변경하지 않는다. 현재 사용자 발언으로 구현을 승인받았으며 운영 배포 승인은 없다.
