# 예습 대상 매칭 보류 원인 표시 및 장내세균 연결 복구 — 설계

## 요구사항과 수용 기준
계획이 불확정 매칭 때문에 없으면 대상 과목/강의의 매칭 보류 이유를 표시한다. 다른 강의의 경고를 사용하지 않는다. 시간표 읽기 실패/과목 식별 실패는 실제 원인을 표시한다. 근거 없이 자료·시간표 부재로 단정하지 않는다. 261105_02의 명시적 연결 등록 뒤에는 251106_02 PDF를 선택해야 한다.

## 책임·입출력 계약·오류 상태
publish/ahead의 보수적 매칭 기준과 반환 계약은 유지한다. prequeue.resolve의 Target.state/reason에 정확한 사유를 전달한다. 러너 blocked_reason도 같은 강의 사유를 전달해야 한다. 실제 실행 결과는 성공·기존 완료·입력 대기·실패로 구분한다.

## 호환성과 데이터 보존
원본 PDF·시간표·저장 응답·공유 링크·기존 pairs·HOLD/CHOSEN·검수/재시도 이력을 보존한다. 기존 JSON의 한 키만 추가한다. 매칭 임계값과 검수 상한은 유지한다. 다른 세션의 미커밋 변경을 되돌리지 않는다.


## 2026-11-05 현재 사용자 승인 및 범위 확장
사용자: “응, 그 계획대로 연결 복구하고 실패 안내도 수정하고 다른 강의들도 마찬가지로 진행해줘.”
위 단일 강의 제한을 현재 블럭 감염과 면역의 같은 연결 누락 전체로 확장한다. 2026-11-01 검증 upload-plan.json/matching.md에서 확정한 강의만 복구하며, 전용 원본 미확인 10칸은 임의 연결하지 않는다. 기존 명시적 연결과 정상 연결을 보존한다.
중복 작년 원본을 쓰는 동영상 수업은 기존 readiness.packet_sources 계약의 별도 입력 사본/출처 해시로 실행 자리를 분리한다. 원본과 기존 결과는 유지한다. 시간표가 원래 합쳐 둔 실습 교시는 임의 분할하지 않는다.
작업 기록 안에 audit/recover 스크립트를 두고 변경 전 pairs와 원본 해시를 보존한다. 실행은 기존 서버/러너 큐에서 저장 응답이 있는 미완료 강의를 선별한다. 전체/개별 중지·취소·완료·진행 중 상태 및 검수 상한은 유지하고 force는 쓰지 않는다. 새 웹 요청·매칭 기준 완화·운영 코드 배포는 제외한다.
