전송 스키마에서 uniqueItems/minLength/maxLength 제약만 제거하되 모델 프롬프트와 원래 JSON Schema 검증에 그대로 보존한다. 원본/문항/의학 검수/수정 상한은 바꾸지 않는다. 기본 실행은 기존 failed/started/지문 변경을 계속 보류한다. 명시적 유지보수 함수만, 입력 지문 일치·기대 이전 identity·normalize failed만 존재·수정0회·출력 없음·단 한 번의 thread/turn 시작→strict schema HTTP400 error→turn.failed만 있는 전체 로그를 검사한 뒤 기술 복구를 기록한다. 로그와 이전 원장을 별도 보존하고 새 identity·proof hash를 기록한다. 다른 실패/완료/사용량/모델 출력/재복구/불일치는 거부한다. 운영 모델 호출의 비용을 0이라고 추정하지 않는다. 복구는 새 문제 최초 출제나 웹 재호출이 아니다.
