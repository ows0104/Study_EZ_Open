# 자유 노트 — 설계

## 요구사항과 수용 기준
- 화면 `/notes`: 왼쪽 노트 목록(제목·수정 시각, 최근 수정 순, 새 노트 +), 오른쪽 편집기. 좌측 메뉴 「학습」 묶음에 「자유 노트」.
- 편집기는 프로토타입과 같다: 블록 11종(텍스트·제목1–3·글머리·번호·할 일·인용·콜아웃·코드·구분선),
  줄머리 md(`#`,`-`,`1.`,`[]`,`>`,```` ``` ````,`---`), 글 안 md(`**굵게**`,`*기울임*`,`~~취소~~`,`` `코드` ``),
  `/` 메뉴, 글을 고르면 서식 막대(전환·B·i·U·S·코드·글자색 10·배경색 10), 블록 손잡이(추가·끌어 옮기기·삭제·복제·전환), 할 일 체크.
- 속성: 「태그」(칩, + 로 입력, Enter/쉼표로 추가, × 로 삭제, 중복 무시) · 「수정」(마지막 저장 시각).
- 노트 삭제: 목록 항목의 삭제 버튼, 확인 후 삭제.
- 입력 후 잠시 뒤 자동 저장. 저장 실패는 편집기에 「저장 실패 · 다시 시도」로 표시하고 내용은 화면에 남긴다. 다른 노트로 옮기거나 화면을 떠날 때 대기 중인 저장을 먼저 보낸다.
- 붙여넣기는 서식 없는 글로 넣는다. 저장된 HTML은 그릴 때 허용 태그·색 스타일만 남긴다.
- 프로토타입 예시 노트(SEED)는 넣지 않는다. 노트가 없으면 빈 노트 하나를 만들 수 있는 상태로 시작한다.

## 책임·입출력 계약·오류 상태
- 새 표 `user_note`: `id`(32자 PK), `user_id`(64, index), `title`(Text), `tags`(JSON 문자열 목록), `blocks`(JSON 블록 목록),
  `created_at`, `updated_at`. postgres에서 RLS 활성화(서버 역할만 접근).
- API(승인된 StudyEZ 사용자, 본인 노트만):
  - `GET /api/me/notes` → `{notes: [{id,title,tags,updatedAt}]}` 최근 수정 순
  - `POST /api/me/notes` `{title?,tags?,blocks?}` → 노트 전체
  - `GET /api/me/notes/{id}` → `{id,title,tags,blocks,updatedAt}`
  - `PUT /api/me/notes/{id}` `{title,tags,blocks}` → 노트 전체(전체 덮어쓰기, 마지막 저장이 이긴다)
  - `DELETE /api/me/notes/{id}` → `{ok:true}`
- 남의 노트·없는 id는 404. 제한: 제목 200자, 태그 30개×40자(앞뒤 공백 제거·빈 값/중복 제거),
  블록 2,000개, 블록 html 20,000자, 사용자당 노트 500개(초과 409). 블록 종류는 11종 외 422.
- 블록 JSON: `{id, type, html, checked?}` (화면 전용 `rev`는 저장하지 않는다).

## 호환성과 데이터 보존
- 기존 표·응답·학습 기록·은행·출제·러너·확장 계약은 바꾸지 않는다. 새 표 추가뿐이다.
- 운영 반영 순서: 운영 DB에 `user_note` 표 생성(+RLS) → API 배포 → 웹 배포. `init_db`의 `create_all`이 없는 표를 만든다.
- 프로토타입 폴더(`redesign-prototype`)와 그 localStorage 예시는 그대로 둔다. 실제 노트와 연결하지 않는다.
