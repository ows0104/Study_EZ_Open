# 순서 맞추기 판정

학생 복습 퀴즈(Main-Quiz)의 나열 문항 중 **순서가 곧 내용인 문항**을 고른다.
순서형으로 고른 문항은 선지 대신 「단계를 순서대로 놓기」 화면으로 푼다. 아닌 문항은 지금처럼 「해당하는 것 모두 고르기」로 푼다.
문항·정답은 고치지 않는다. 판정만 한다.

입력 `input.json`의 `questions`마다 질문(`question`), 정답(`answer`), 번호 붙은 정답 단위(`units`, 0부터), 해설(`explanation`)이 있다.

## 순서형(ordered: true)
정답 단위들이 하나의 과정을 이루고, 학생이 그 **차례**를 알아야 맞혔다고 할 수 있는 문항.
- 복제주기·생활사·감염 과정·병기·임상 단계처럼 시간 순서로 일어나는 단계
- 전파·침입·이동 경로처럼 앞 단계가 다음 단계로 이어지는 하나의 길
- 반응 연쇄·신호 전달·기전의 차례
- 질문이 「순서대로」, 「높은 순서로」, 「차례로」처럼 순서를 직접 요구하는 문항

## 순서형이 아님(ordered: false)
- 서로 독립된 여러 가지를 나열한 문항: 종류·원인·증상·특징·약물·병원체 목록
- 「경로 두 가지」, 「대표 원생동물 두 가지」처럼 질문에 경로·단계라는 말이 있어도 단위끼리 앞뒤가 없는 문항
- 단위 중 일부만 차례가 있고 나머지는 같은 자리에 있는 문항
- 올바른 차례를 강의 내용으로 확신할 수 없는 문항

헷갈리면 순서형이 아니다. 순서형이 아닌데 순서 화면으로 나오는 것이 더 나쁘다.

## order
순서형이면 `order`에 `units` 번호를 올바른 차례로 모두 쓴다(빠짐·중복 없이 전부).
저장된 단위 순서가 이미 맞으면 0, 1, 2, … 그대로 쓴다. 저장된 순서가 틀렸으면 바로잡은 차례를 쓴다.
순서형이 아니면 `order`는 빈 배열이다.

## basis
순서형이면 왜 차례가 내용인지, 순서형이 아니면 왜 아닌지를 한 줄로 쓴다.

출력은 스키마의 JSON 하나다. 입력의 모든 문항에 판정 한 줄씩. 다른 파일을 만들거나 고치지 않는다.
