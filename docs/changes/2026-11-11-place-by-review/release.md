# Main-Quiz 문항을 지도 관계에 바로 배치 — 배포 준비

사용자 2026-11-11 「지도 직접 배치도 짜줘」. 브랜치 `claude/place-by-review`, 기준 master `20307c71`(#92·#93 병합 뒤).

## 코드 리뷰·검증 결과

### 바뀐 것
- **새 배치 규칙 `review`** (`PLACEMENTS`에 추가, 정책 `review-relations/1`)
  - 새 ledger에 `placement` 표시를 적는다. 표시가 없는 ledger·결과는 이전 규칙(`evidence`·`answered`) 그대로다.
- **문항 검토**
  - 입력에 지도 관계 `map_relations`를 넣는다. 지도 확인에서 supported이고 어떤 목표가 가진 관계만 넣는다.
  - 출력에 `relations: [{relation_id, part: whole|partial, reason}]`을 받는다. 모르는 관계를 적으면 그 단계를 되돌려준다.
- **배치**: 검토 관계를 가진 목표가 후보다. 고르는 순서는 whole 관계 우선 → 답한 component 수 → 지도 순서다.
  - 커버 판정의 근거 행 관계는 배치에 쓰지 않는다.
  - 관계가 없으면 `no-relation`으로 남는다.
- **회상 단위**: 문항은 답한 단위에만 붙는다. 같은 목표의 어느 단위도 답하지 않을 때만 모든 단위가 후보다. 확인됨은 답한 단위만 센다(`recall.summarize(answered)`).
- **보충 단계**: review 규칙에서는 커버 판정이 어느 목표와도 대조하지 않은 문항만 보충 대상이다.
- **결과 검증**
  - 표시가 있으면 반드시 review 규칙이어야 한다.
  - 모든 검토 행에 `relations`가 있고, 그 행은 판정 기록 값이어야 한다.
  - 표시가 없으면 review 규칙을 받지 않는다.

### spec과 다른 점(결정)
- 커버 지시문은 바꾸지 않았다. 옛 규칙으로 이어 하는 실행이 같은 지시문을 쓰기 때문이다.
- 검토가 관계를 적지 않은 문항은 검토 뒤에 다시 보충하지 않는다. `no-relation`으로 보고만 한다.
- spec 「결정할 것」은 권한 기본값으로 진행했다.
  1. 실측을 기다리지 않았다.
  2. 후보 순서는 whole → component 수 → 지도 순서다.
  3. `readiness`는 커버 판정 그대로다.

### 독립 리뷰(하위 에이전트, 코드만 줌)
- **결함 1(높음, 수정)**
  - 문제: 보충 단계가 검토보다 먼저 돌고 커버 판정 기준으로 대상을 고른다. 그래서 이 변경이 살리려는 문항(일부·반대 방향·추론)이 검토 전에 새 목표가 되거나 범위 밖으로 빠졌다.
  - 수정: review 규칙에서는 커버 근거 행이 하나도 없는 문항만 보충한다.
  - 검사: `test_a_question_judged_without_a_relation_waits_for_its_review_not_the_supplement`
- **결함 2(높음, 수정)**
  - 문제: 회상 단위 좁히기를 관계(주장)마다 해서, 다른 단위를 답하는 문항이 다른 관계를 통해 답하지 않은 단위에 붙을 수 있었다.
  - 수정: 목표마다 답한 단위 집합으로 좁힌다.
  - 검사: `test_a_unit_reached_by_another_relation_is_dropped_when_another_unit_is_answered`
- **지적 3(수정)**: 목표가 없는 관계를 검토 입력에서 뺐다. 적어도 배치에 쓰이지 않아 조용히 사라졌기 때문이다.
- **지적 4(남김)**
  - 표시가 있는 결과가 판정 기록 안의 더 옛 검토 행으로 바꿔치기될 수 있다. 최종 검토 행과 묶지 않았다. #92의 근거 확인도 같다.
  - 내용 해시로 묶으면 인용 맞추기 뒤 해시가 달라져 어렵다. 남은 위험으로 둔다.
- **지적 5(남김, 의도)**: review 규칙은 커버 status가 unknown인 목표에도 배치한다.
- 옛 규칙 결과가 바이트까지 같다는 것은 리뷰어도 확인했다(`place` 키 앞자리 상수, `summarize` 기본값, 이유 문자열).
