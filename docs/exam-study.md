# 시험 전 현재 카드로 학습하기

상단 **모아 풀기**에서 과목·강의명을 검색하고 강의를 선택한다. 선택한 강의의 문제를
섞어서 푼다. 선택한 강의의 새 문항을 모두 먼저 평가한 뒤 예정된 복습을 섞어서 한다.
새 카드와 복습이 모두 끝나면 완료한다. 숙련도 점수는 완료 조건이 아니다.
진행 중이던 문항 수 제한은 모아 풀기에서는 해제한다.
평가와 일정은 기존 강의별 상태에 저장하며 같은 탭을 새로고침해도 선택한 순서를 이어간다.
**쉬기**로 중단한 뒤 이어서 학습하거나 강의를 다시 선택할 수 있다. 마지막 평가는 강의를
넘어서도 되돌릴 수 있으며, 완료 뒤 되돌리면 남은 문항이 다시 생긴다.

관리자는 강의 패널 또는 모아 풀기의 **누락 검증·객관식 보강**을 요청할 수 있다.
러너가 Quizgen의 목표·회수 대상 계획처럼, 현재 은행을 보지 않는 별도 폴더에서 원본 PDF의
목표와 독립 회수 포인트를 먼저 추출한다. `coverage/point-plan.json`을 고정한 뒤 각 point_id와 실제 문항을 대조하고, 실제 문항으로
회수되지 않는 출제 포인트와 객관식으로 구별할 가치가 있는 내용을 찾아 추가한다.
각 포인트에 실제 근거 쪽을 붙이며, 대조에서는 고정 포인트 전체와 필요한 원본 근거를 확인한다.
보강 뒤 다시 원본을 대조하고 기존 외부지식 정답 검토도 수행한다.
남은 누락·객관식 기회가 있으면 같은 고정 포인트 계획으로 최대 세 차례 보강·재대조한다.
원본 범위는 강의별 관리자 지정 범위를 우선하며, 낮은 중요도를 자동 제외 근거로 삼지 않는다.

기존 질문·정답·ID와 build ID는 유지하므로 학습·개인 수정 기록이 이어진다. 추가 문항은
새 카드가 된다. 보강본은 전체 구조 검증을 통과해야 적용되며, 실패하면 현재 은행으로
계속 공부할 수 있다. 완료·누락 의심·읽지 못한 쪽은 별도 표시한다. 검사 전 은행을
검증 완료로 표시하지 않으며, 문항이나 원본 파일명이 바뀌면 대조 결과를 만료시킨다.
원본 대조 결과는 AI 검토이며 개념 누락이 전혀 없음을 보증하는 수치는 아니다.

객관식은 `mcq_mode`로 분류한다. `recall_first`는 먼저 인출한 뒤 선지를 공개하고,
`comparison`은 선지를 처음부터 비교한다. 새 출제와 보강은 목적을 명시하며 옛 문항은
기존 회수 방향·발문으로 기본 분류한다. 관리자는 문항 수정에서 분류를 바꿀 수 있다.
누락 검증·보강 시에는 기존·추가 객관식 전체를 모델이 학습 목표로 다시 분류하고,
문항별 근거를 `classification.json`에 기록한다. 유형만 바뀌어도 학습·개인 수정 기록은 이어진다.
선지 공개 상태는 현재 문항 토큰에 저장하며 새로고침해도 유지한다. 선지 보기만으로
정답 열람이나 평가가 기록되지 않는다.

새 은행 생성에도 원본 대조가 기본 적용된다. 로컬에서 `quizbank.run --no-coverage`로
생략할 수 있으나 이때 원본 대조 완료 표시가 붙지 않는다. 보강은 `--existing-bank`로
기존 JSON을 읽으며 원문을 재정리하지 않는다. `coverage.json`과 `coverage/before.json`,
`coverage/additions.json`에 쪽별 판단과 추가분을 보존한다.
보강 모델은 중복을 덜어낸 `coverage/tasks.json`을 읽고, 스키마로 검사할 전체 추가분을 파일로 저장한다.
운영 러너는 같은 보강 요청을 `POST …/bank/runner-audit`로 넣을 수 있다. 러너 토큰이나 관리자 세션이 필요하다.

API·웹·러너를 함께 적용한다. 새 DB 표나 칼럼은 없다. API를 먼저 배포하고 웹을 공개한다.
러너는 매 작업마다 새 `runner bank` 하위 프로세스를 사용한다. 구버전 러너가 보강 요청을
일반 재생성 결과로 올리면 API가 거절하므로 기존 진도를 초기화하지 않는다.
