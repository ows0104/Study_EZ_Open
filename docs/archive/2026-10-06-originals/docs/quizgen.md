# PDF2ANKI — 인계 문서

강의 필기 PDF와 과목 족보 PDF를 시험 대비 Anki 덱으로 바꾸는 파이프라인.
**코드는 정규화·스키마·기계적 오류를, 모델은 학습 목표·문항 선택·의미 판단을 책임진다.**
이 분업이 설계의 고정축이다.

설계 근거는 [quizgen-blueprint.md](../../quizgen-blueprint.md).
이식하면서 바꾼 것과 그 이유는 아래 "설계에서 바뀐 것"에 적었다.

---

## 실행 환경

Python은 PATH에 없다. Anaconda를 직접 부른다. PyMuPDF·genanki·jsonschema는 이미 설치돼 있다.

```bash
PYTHONIOENCODING=utf-8 "$USERPROFILE/anaconda3/python.exe" -m quizgen.<모듈>
```

한글 출력이 깨지므로 `PYTHONIOENCODING=utf-8`을 반드시 붙인다.

## 파이프라인

```
[과목당 1회]
  jokbo.py      족보 PDF 1개 → 강의별 조각 (문항 + 정답 + 이의제기)

[강의마다]  ← run.py 가 이 전부를 한 명령으로 잇는다
  prep.py       필기 PDF → clean.pdf / annotated.pdf / 사이드카
  pack.py       (공용) 토큰 예산·파트 나누기·파일명에서 강의 알아보기.
                예습 파이프라인과 함께 쓴다. 카드 철학은 여기 없다
  assemble.py   → prompt.plan.md, prompt.cards.md, context.*.md
  ① 모델        prompt.plan.md      → plan.json
  review.py     → plan.review.md    ← 사람이 1분 훑고 --approve
  ② 모델        prompt.cards.md     → items.raw.json
  validate.py   → items.checked.json, suspects.json
  reproduce.py  check = solve → judge → apply → items.reproduced.json
                누출 검사(앞면이 답을 흘리는가)는 풀이 **전**에 돈다 — 공짜다
  session.py    `claude -p` 로 이력·설정·도구 없는 세션을 만든다 + 눈가리개 실검사
  build.py      items.reproduced.json → .apkg (재개봉 검증 포함)
                재현 검사 결과가 없거나 재현 불가 카드가 남아 있으면 **덱을 만들지 않는다**
  merge.py      (선택) 같은 강의가 두 파일일 때 한 덱으로. report 는 겹침만 잰다
  prequiz/      **예습 덱** — 별개 파이프라인. 아래 '예습 덱' 절 참고
  runbase.py    (공용) 두 파이프라인의 러너가 같이 쓰는 배관 — 산출물이 있으면
                건너뛰기·원장 기록·하위 프로세스·세션 잇기. **판단은 한 줄도 없다.**
                무엇을 낼지, 무엇을 결함으로 볼지, 어디까지 수선할지는 각자 갖는다
  run.py        위 전부를 한 명령으로. ①② 는 빈 세션(claude -p, 도구 허용)이 채운다.
                ② 는 ① 세션을 이어받아 PDF·사이드카를 다시 읽지 않는다.
                산출물이 있는 단계는 건너뛰므로 끊겨도 같은 명령으로 이어진다.
                재현 불가 카드가 나오면 그 카드만 다시 쓰게 하고 **그 카드만** 다시 검사한다.
                이름·전략·검수자료·장부를 전부 스스로 정한다 (아래).
```

### run.py 가 스스로 정하는 것 — 사람이 손으로 옮겨 적던 네 가지

**① 이름은 파일이 정한다.**
덱 이름은 세 마디다 — `<과목>::<강의명>::<기원>`.

| 마디 | 옵션 | 안 주면 |
|---|---|---|
| 과목 | `--subject` | 그냥 `과목` |
| 강의명 | `--lecture` | **파일제목 원문** (확장자만 뗀다) |
| 기원 | (없음) | `예습` / `강의록` / `기출` — 파이프라인이 정한다 |

강의 ID 는 파일명 앞머리 `[260820_03]` 에서 딴 `p260820_03`. `--deck`·`--id` 를 손으로 줄
일이 없다. 29강을 돌리는 동안 그 손이 틀리는 것이 실제 위험이고, ID 는 guid 의 씨앗이라
**바뀌면 Anki 가 전부 새 노트로 본다.** 덱 이름을 통째로 덮으려면 `--deck`.

강의명 기본값은 `pack.lecture_of` — **파일제목 원문**이다. NFC 정규화와 `::` 치환 말고는
손대지 않는다. 그래서 작년 필기본으로 만든 예습 덱과 올해 필기본으로 만든 복습 덱은
**저절로는 한 노드에 서지 않는다.** 모으려면 양쪽에 `--lecture` 로 같은 값을 준다.

```
병리학                                  ← --subject
└ 종양의 분자생물학(1)                    ← --lecture (양쪽에 같은 값)
   ├ 예습     ← prequiz (작년 필기본)
   ├ 강의록   ← 이 파이프라인 (올해 필기본)
   └ 기출
```

> **한때 `clean_lecture_name` 으로 자동으로 맞췄다.** 날짜·교시·교수·필기자를 떼어
> 양쪽에서 같은 문자열이 나오게 하는 방식이었는데, **2025↔2026 아카이브에서 29강 중
> 20강만 일치했다.** 나머지 9강은 어차피 손으로 줘야 했고, 자동 정제는 그 9강을 조용히
> 다른 노드에 세웠다. 지금은 원문을 그대로 쓰고 노드 합치기를 `--lecture` 에 맡긴다 —
> **틀릴 때 눈에 보인다.** `clean_lecture_name` 자체는 남아 있고 `find_jokbo` 의
> 제목 대조가 쓴다. 거기서는 깎는 것이 덱 정체성과 무관한 검색 보조라 성격이 다르다.

어느 필기본에서 나왔는지는 덱 이름이 아니라 `강의::<lecture_id>` 태그와 `run.config.json`
이 기억한다. guid 씨앗은 `lecture_id` 라 `--lecture` 로 노드를 합쳐도 노트끼리는 안 섞인다.
그래도 조용히 합치지는 않는다 — `run.deck_siblings` 가 같은 노드를 쓰는 다른 강의를 찾아 알린다.

> ⚠ **이미 임포트한 덱이 있으면 이름이 달라진다.** 노트는 guid 로 살아남지만
> Anki 는 옛 이름의 덱에 그대로 둔다. 소아질환(2) 로 확인했다 — 덱 이름만 바뀌고
> guid 88개는 그대로였다. 옛 덱에서 새 덱으로 옮기고 빈 덱을 지우면 된다.

**② 전략은 족보 통계와 강의의 사진 구성이 정한다.** (`assemble.decide_strategy`)
판정은 아래 표의 순서대로 하며, 먼저 맞은 조건이 이긴다.

| 전략 | 조건 | 하는 일 |
|---|---|---|
| 사진 중심 | **1순위:** 제목/파일명이 실습이고, 사진 포함 슬라이드가 10장 이상이면서 전체의 30% 이상 | 사진·조직·육안·영상 판독 목표 우선 · `image_basic` 중심 · 사용 가능한 사진이 충분하면 강의록 카드의 절반 이상을 이미지 카드로 |
| 족보 중심 | **2순위:** 교수 유임이고 반복률 ≥35% | 기출이 물은 목표를 먼저 다 덮고 · 반복 출제는 `importance=core` |
| 필기 중심 | **3순위:** 교수 교체 또는 반복률 <20% → 사용자에게 확인 | `--annotation-evidence` 자동 · 기출은 신호로만 · 올해 필기가 몰린 곳부터 |
| 기본 | **4순위:** 반복률 20~35% / 조각 없음 / 조각의 주인이 다른 강의 | 강의록 구조를 축으로 · 기출·스탬프·필기를 그 위에 얹는다 |

`--strategy 필기|족보|사진|기본` 으로 덮고, 필기 근거만 따로 끄려면 `--no-annotation-evidence`.
교수 교체·낮은 반복률 판정은 대화형 실행에서 `필기 중심으로 만들까요? [Y/n]`으로 묻는다.
야간 실행처럼 stdin이 없는 경우에는 추측하지 않고 멈추며, 아래처럼 한 강의의 전략을 명시해 재개한다.
이미 확인한 2026 병리학 강의는 답을 저장했다. `260820_01·02·03·05` 소아질환은 필기 중심,
그 밖의 당시 확인 대상 8강은 기본이다. 이 목록에 없는 미래 강의는 다시 묻는다.

```powershell
python -m runner watch 병리학 --run-id 260819_05 --strategy 사진 --build --force
```

사진 다수 기준은 한 슬라이드에서 잘게 검출된 도형 수가 아니라, `lecture_figures`가 하나라도 있는
슬라이드의 수와 비율로 계산한다. 현재 실습 6개는 모두 이 기준을 통과한다.

> 이 전략이 서려면 조각 대조가 맞아야 한다. 고치기 전에는 **29강 중 9강이 조각을 못 찾아**
> 통계 없이 조용히 `기본` 으로 떨어졌다. 셋을 고쳤다.
> - **파일명 잡음이 분모를 불렸다.** `[260812_01]`·`(정경천)`·`_정현영v2` 를 떼고 대조한다.
>   `병리학 소개` → `병리학 소개: 과거, 현재, 미래` 가 0.21(탈락)에서 1.00 이 됐다.
> - **자카드만으로는 길이 차이에 진다.** 포함도를 양방향으로 함께 본다 —
>   조각 제목이 더 넓을 때(`유전질환 (1)~(3)` ⊃ `단일유전자질환`)와 더 좁을 때가 둘 다 있다.
> - **실습 강의는 아예 후보에서 빠져 있었다**(`lecture_key == "PRAC"` 를 건너뛰고 있었다).
>   실습 6강이 실습 97문항(반복률 39%·가중치 high)을 통째로 못 쓰고 있었던 셈이다.
>   이제 실습 강의는 PRAC 조각만 상대하고, 조각이 6회 공용이라는 경고를 프롬프트에 단다.

**③ 이미지 접촉 시트를 한자리에 모은다.** `out/_image_check/<파일제목>_image_check.pdf`.
강의마다 폴더를 찾아 들어가야 하면 실제로는 안 보게 된다. 눈검사가 필요 없어지면 `--no-image-check`.

**④ 장부.** 단계마다 시간·비용·토큰을 `usage.jsonl` 에 한 줄씩 적고 끝에 표로 낸다.
`run.report.json` 에 이번 실행과 이 폴더 누적이 함께 남는다.
값은 전부 `claude -p --output-format json` 봉투가 이미 주는 것이라 **재느라 토큰을 더 쓰지 않는다.**
캐시 읽기/쓰기를 입력과 나눠 두었다 — 합치면 ②가 ①을 이어받아 아낀 양이 보이지 않는다.
하위 프로세스(reproduce)는 환경변수 `PDF2ANKI_RUN` 으로 같은 실행 표를 물려받는다.

`disposition.py`(유지·수정·경고유지·삭제 판정)는 아직 없다. 재현 검사 결과가 쌓인 뒤에 붙인다.

## 예습 덱 (prequiz)

복습 덱과 **목적 함수가 다르다.** 파이프라인은 닮았지만 계약·프롬프트·검사가 별개다.

```
복습(quiz)     시험에 나올 수 있는 것        ← quizgen.run
예습(prequiz)  꼭 반드시 알아야 하는 것      ← quizgen.prequiz.run
```

예습의 목적은 수업 중에 「저 단어·약어가 뭐지? 저 기전이 뭐지? 외워야 될 게 너무 많은데?」
로 막히지 않게 하고 「오 이거 어제 외웠던 거다」를 만드는 것이다. 흥미를 유발하고
학습에 장애물이 없게 하는 것이 목표이며, **강의를 따라가는 것은 그 수단이다.**
이 목적은 공유 범용 원칙과 분리된 `quizgen/prompts/profiles/prelecture.md`에 둔다.

```bash
python -m quizgen.prequiz.run "<작년 필기 PDF>" --note <URL 또는 .md>
```

기본 도메인은 한국어 의학 강의용 `medical_ko`다. 다른 분야에서 범용 정책만 쓰려면
`--domain generic`을 준다.

입력은 **작년** 필기본 + 예습 설명본 + 족보다. 예습 시점에 올해 필기는 없다.
출력은 `<과목>::<강의>::예습` 덱 하나. 복습의 `::강의록`·`::기출` 과 형제로 선다.

끊겼으면 폴더만 대면 이어진다:

```bash
python -m quizgen.prequiz.run --resume out/pre_p250825_01
```

**이 한 줄이 덱까지 간다.** 복습 쪽과 같은 수준으로 맞추느라 세 군데서 죽던 것을 고쳤다 —
셋 다 사람이 다른 명령을 손으로 다시 쳐야 끝나던 자리다.

| 죽던 자리 | 고친 방식 |
|---|---|
| `validate` 가 계약 위반(장수·O/X)에 종료코드 2 를 내면 실행이 멈췄다 | `sh(ok=(0,2))` 로 받아 두고 수선 루프가 처리한다 |
| 재현 불가 카드가 나와도 수선 루프가 없어 그대로 덱에 들어갔다 | `repair.md` + `--repair-rounds 2` (기본). 고친 카드만 다시 검사한다 |
| `--skip-reproduce` 를 주면 `items.reproduced.json` 이 안 생기는데 `step` 이 그걸 요구해 죽었다 | 그때는 산출물을 요구하지 않는다 |

수선을 다 쓰고도 장수가 안 맞으면 **덱은 낸다.** 빈손으로 끝내는 것보다 계약을 어긴 덱과
그 사실을 함께 주는 편이 낫다 — 어느 카드를 덜지는 사람이 정할 일이다.
`--allow-size` 를 손으로 붙일 일이 없어졌다.

접촉 시트는 `out/_image_check/` 로 모이고, 실행 표와 누적 비용은 `run.report.json` 에 남는다.

### 축이 바뀌면 따라 바뀌는 것 — 네 자리

| | 복습 | 예습 |
|---|---|---|
| 교수 교체 | 사진 실습·높은 반복률 다음에 사용자에게 필기 중심 여부를 묻는다 | 전략을 안 가른다. `reason=repeated` 를 쓸 수 있는지만 정한다 |
| 족보 | 예측 — 이게 올해 나올 것 같다 | **중심성의 증거** — 여러 해 물었다면 이 단원의 중심이다 |
| `trap` 유형 | 있다 | **없다.** 수업 전날 함정은 장애물을 하나 더 세우는 것이다 |
| 분량 | 상한 없음 (한 강의 77장까지 갔다) | **10~15장이 계약.** `validate` 가 막는다 (2026-09-03 30→20, 10-04 20→15) |

복습은 사용자 전략 우선순위를 따르고, 예습은 꼭 알아야 할 의학 지식의 중심성을 따로 판단한다.

### 재사용한 것과 새로 쓴 것

`prep`·`jokbo`·`session`·`ledger`·`textutil`·`pack`·`reproduce` 는 그대로 쓴다.
빌드도 렌더러(노트 모델·CSS·뒷면 구조·그림 크롭·접촉 시트·재개봉 검증)를 통째로 가져온다.
새로 쓴 것은 `schema`·`prompts`·`assemble`·`validate` 와 노트 조립 루프뿐이다.

> ⚠ **guid 씨앗에 `::pre` 를 붙인다.** guid 는 `(강의 ID, 질문)` 이라, 예습과 복습이
> 같은 용어를 같은 문장으로 물으면 — 용어 카드에서 충분히 일어난다 — Anki 가 한 노트로
> 보고 **한쪽이 다른 쪽을 덮는다.** `tests/quizgen/test_prequiz.py` 가 이걸 지킨다.

### 첫 실측 — 종양의 분자생물학(1), 작년 필기 47장

같은 강의를 예습 설명본 없이 / 있이 두 번 돌렸다.

### 어디서 토큰이 샜나 — 세션 기록을 열어 재 본 것

`~/.claude/projects/.../<session>.jsonl` 을 세어 보면 비용의 정체가 보인다.
`종양의 분자생물학(1)` ①② 세션은 **assistant 턴 44회 · 평균 컨텍스트 127,300토큰 ·
캐시읽기 합계 5,601,231** 이었다. 비용은 사실상 **턴 수 × 컨텍스트 크기**다.

중복 읽기는 없었다 — 모든 파일을 정확히 한 번씩 읽었고, ②가 ①을 이어받아
47쪽 PDF를 다시 읽지 않는 것도 확인됐다. 샌 곳은 다른 데였다.

**① 모델이 쓸 수 없는 도구를 계속 시도했다.** `AUTHOR_TOOLS` 는
`Read·Write·Edit·Glob` 뿐인데, 모델이 `python -m quizgen.prequiz.validate` 를
네 번(Bash 3 · PowerShell 1) 시도해 전부 `This command requires approval` 로 막혔다.
`claude -p` 에는 승인할 사람이 없다.

**② 막히자 검사기 소스를 읽어 규칙을 손으로 흉내 냈다.**
`Grep quizgen` → `Grep RE_POINTS_AT_SOURCE|MAX_Q_CHARS|LEAK_THRESHOLD ...` →
`Read validate.py` → `Read schema.py` → 카드 한 장을 `Edit`. 프롬프트가
"그 밖의 파일을 찾아다니지 마라"라고 한 바로 그 행동이고, **근거 위계가 깨지는 경로다.**
합쳐서 44턴 중 12턴(27%) — 평균 컨텍스트로 환산하면 약 150만 토큰이다.

**③ ② 프롬프트가 ①의 것을 통째로 되풀이했다.** 머리말·철학·계약이 양쪽에 다 실려 있었다.
②는 ①의 세션을 이어받으므로 그 15k 는 이미 컨텍스트에 있고, 다시 실으면
남은 턴마다 따라다닌다.

### 예습 설명본 받아오기

ChatGPT 공유 링크는 본문이 DOM 에 없다. `<script>` 안 RSC 페이로드에 있고
(`__NEXT_DATA__` 가 아닌 App Router 형식) 그 안에서 **JSON 이 두 겹 이스케이프**돼 있다.
`prequiz.run.from_rsc` 가 그걸 푼다. 세 번 헛짚었고 전부 **예외 없이 조용히 실패**했다.

| | 건진 양 |
|---|---|
| DOM 파서만 | 24자 |
| 인용 표식 제거가 표식 *사이의 본문*까지 먹음 | 4,520자 |
| 이스케이프를 한 겹만 풂 (`
` 이 문자 그대로) | 14,735자 |
| **제대로** | **13,986자 · 754줄** |

`tests/quizgen/test_fetch_note.py` 가 세 실패 모드를 전부 잡는다. 형식이 바뀌면 여기가 먼저 깨진다.

### 덱 이름을 올해 강의에 맞추는 문제

예습은 작년 파일로 만드는데 덱은 **올해 강의**에 붙어야 한다. 파일 제목이 해마다
조금씩 달라서(`소아기 특이 질환` vs `소아기 특이 질환 1`) 자동으로는 못 맞춘다 —
**2025↔2026 아카이브에서 정확히 일치하는 것은 29강 중 20강뿐이었다.**
그래서 자동 정제를 걷어내고 `--lecture` 로 명시하게 했다. 기본값은 작년 파일제목 원문이라
안 주면 노드가 갈리는 것이 **바로 보인다** — 조용히 20/29 만 맞던 것보다 낫다.
(`--deck-title` 은 옛 이름으로 그대로 받는다.)

### 명령

한 강의를 통째로 — **인자는 PDF 하나뿐이다.**

```bash
python -m quizgen.run "<필기 PDF>"
```

기본 도메인은 `medical_ko`이며, 범용 실행은 `--domain generic`으로 선택한다.

끊겼으면 폴더만 대면 이어진다 (덱 이름·전략은 `run.config.json` 이 기억한다):

```bash
python -m quizgen.run --resume out/p260820_03
```

단계별로 돌리려면:

```bash
# 과목당 1회
python -m quizgen.jokbo "족보_예시/2026 질병의 병리학적 이해 족보.pdf" -o out/jokbo
python -m quizgen.schema -o out/schema

# 강의마다
python -m quizgen.prep "<필기 PDF>" -o out/lecNN
python -m quizgen.assemble out/lecNN            # --strategy 필기|족보|사진|기본 (기본 auto)
#   → prompt.plan.md 를 모델에게 읽힌다 → plan.json
python -m quizgen.review out/lecNN            # 사람이 훑는다
python -m quizgen.review out/lecNN --approve
#   → prompt.cards.md 를 모델에게 읽힌다 → items.raw.json
python -m quizgen.validate out/lecNN/items.raw.json \
    --prep out/lecNN/prep.json --jokbo "out/jokbo/<조각>.json"
python -m quizgen.reproduce check out/lecNN     # solve → judge → apply 한 번에
#   옵션: --model · --judge-model(기본 sonnet) · --jobs 4(동시 세션) · --only c003,c007
#         --chunk 25 · --retries 1 · --force · --skip-canary
#   풀이는 강한 모델이어야 한다(실제로 푸는 단계). 채점은 의미 비교라 sonnet 으로 충분하다.
#   단계별로 돌리려면 solve / judge / apply
#   수동으로 하려면 prepare / grade 가 프롬프트를 파일로 내보낸다 (새 대화에 붙여넣기)
python -m quizgen.build out/lecNN --deck "병리학::NN 제목" --id "pathNN"
#   입력은 items.reproduced.json 이다. 재현 불가 카드가 남아 있으면 멈춘다.
#   --skip-reproduce (검사 없이) · --allow-defects (결함 카드째 강행) — 둘 다 출력에 남는다
```

다른 의학 지식을 댄 경우다(소아질환(2) 의 RDS 재태주수·태아수종 호발 부위, 병리학 소개의 한국
병리학사 연도·인명 7장 등). **`different` 비율이 높은 강의는 대개 역사·지역 특수 내용이 많은
강의이지 나쁜 강의가 아니다.**

### 24강 일괄 실행에서 실제로 멈춘 것 — 7건 / 24강

배치 안에서 강의가 멈추면 드라이버는 다음 배치로 계속 간다. ①② 산출물이 남으므로
`--resume` 재개는 싸다(실측 $1.7~7.6). 원인은 세 가지였다.

| 원인 | 건수 | 성격 |
|---|---|---|
| **누출 검사 실패** | 4 | 진짜 카드 결함. 아래 참고 |
| API 응답 끊김 | 2 | 일시적. `--resume` 한 줄이면 끝 |
| prep 크래시 (IRT 주석) | 1 | 코드 결함. 고쳤다 |

**누출 검사가 이번 실행의 유일한 실질 실패 유형이다(24강 중 4강, 17%).** 두 부류다.

1. **cloze 로 가린 말이 같은 문장에 맨몸으로 또 나온다.** `{{c1::EGFR}} … Iressa는 EGFR
   tyrosine kinase inhibitor`, `{{c2::47,XXY}} … mosaic(46,XY/47,XXY)`.
   고치는 법은 **두 자리를 다 가리는 것**이다.
   `prompts/cards.md` 에 조항을 넣었는데 **그 뒤에도 나왔다. 지침만으로는 안 막힌다.**
2. **기출 선지를 앞면에 그대로 옮겨 답이 선지 안에 인쇄된다.**
   `전신경화증, 쇼그렌증후군, … 중 B세포 림프종 위험이 가장 큰 질환은?` / 답 `쇼그렌증후군`.
   철학 1조(*기출은 형태가 아니라 지식을 옮긴다*)가 금하는 바로 그 형태인데, 선지를 **떼는**
   대신 **붙여** 와서 반대 방향으로 터졌다. 선지를 떼고 지식을 묻게 고쳤다.

### 누출 수선 — 이제 코드가 한다

위 4건은 전부 사람이 카드 한 장을 고치고 `--resume` 해야 했다. 수선 고리가 *채점 뒤*
`DEFECT_REASONS` 로 갈린 카드만 다시 쓰는데 누출은 풀이 **전**에 걸려서 손이 안 닿았다.
같은 고리를 앞에도 놓았다.

```
기계 검증 → 누출 수선 → 재현 검사 → 수선 → 누출 재확인 → 덱 빌드
```

- **검사 자체는 공짜다.** 결정론적이라 세션도 돈도 안 든다 — 깨끗한 3강에 걸어 0.05초.
  누출이 있을 때만 세션이 뜬다.
- **관문이 둘인 이유.** 뒤의 수선이 카드를 다시 쓰면 누출이 **새로** 생길 수 있다.
  덱에 들어가기 전 마지막으로 한 번 더 본다.
- **뒤쪽 관문은 고친 카드만 다시 검사한다** (`reproduce --only`). 빌드 입력이
  `items.reproduced.json` 이라 거기까지 고쳐 두지 않으면 낡은 질문이 덱으로 간다.
- 실측: 세 강의에 실제로 걸어 **강의당 32~52초 · $0.28~0.89**, 재빌드까지 1~2분.

> ⚠ **고칠 대상은 `items.raw.json` 이다. `items.checked.json` 만 고치면 조용히 되돌아간다.**
> 수선 고리가 `validate()` 로 checked 를 raw 에서 다시 만들기 때문이다. 24강 실행에서
> 손으로 고친 세 장이 정확히 그렇게 되돌아가 **덱까지 흘러 들어갔다** — 재현 검사는
> 통과했고(수정 시점에는 맞았다) 로그도 정상이라 아무 데서도 안 잡혔다.
> 24강 전량에 다시 걸어 찾아냈고, 새 고리로 셋 다 고쳐 **지금은 하드 누출 0** 이다.

> 질문을 다시 쓰면 **그 카드의 guid 가 바뀐다**(씨앗이 `(lecture_id, 질문)`). 이미 임포트한
> 뒤라면 옛 카드가 남으므로 지워야 한다. 임포트 전이면 신경 쓸 것 없다.

### 합치기 — `merge.py`

같은 강의가 두 파일로 있을 때 한 덱으로 합친다. `report` 는 아무것도 쓰지 않고 겹침만 잰다.

```bash
python -m quizgen.merge report out/p260820_01 out/p260820_02
python -m quizgen.merge make   out/p260820_01 out/p260820_02 --id p260820_0102
```

**중복 제거의 절반은 guid 가 이미 한다.** 씨앗이 `(lecture_id, 질문)` 이라 **강의 ID 하나**로
구우면 질문이 같은 카드는 Anki 가 임포트할 때 한 장으로 본다. 모듈이 하는 일은 그 위에서
*질문이 다르지만 같은 것을 묻는* 카드를 골라내는 것이다.

**두 강의를 물리적으로 이어 붙여 한 강의로 만든다.** Media 를 카드마다 갈라 태우는 대신
annotated/clean PDF 를 `insert_pdf` 로 잇고 B 의 쪽번호·그림 ID 를 A 의 쪽수만큼 민다.
그러면 `build.build()` 를 한 줄도 안 고쳐도 접촉 시트·기출 원문·오클루전이 그대로 산다.
순환장애 1×2 로 검증했다 — 그림 크롭이 원본과 **바이트 일치**, 필기 주석 개수·종류·쪽크기 동일,
슬라이드 렌더 차이는 최대 **1/255**(픽셀의 0.085%, 재인코딩 반올림).

**판정은 질문 자카드가 아니라 양방향 포함도 두 개로 한다.** 처음엔 질문 2-gram 자카드
하나로 재려 했는데 실측이 반증했다 — 순환장애 1×2 에서 눈으로 확인한 진짜 중복 6쌍의 값이
0.41~0.88 로 흩어져 **임계값을 어디에 두어도 절반을 놓쳤다.** 한쪽 질문이 길면 자카드가
무너진다(이 문서 "한국어" 절의 그 함정이다). 가른 것은 **답의 양방향 포함도**였다 —
진짜 중복 6쌍은 0.86~1.00, 가짜 2쌍은 **0.00**. 가짜 둘은 O/X 카드와 열거 카드로,
같은 용어를 쓰지만 묻는 것이 다르고 그 차이가 질문이 아니라 답에 나타난다.
그래서 `질문 포함도 ≥0.60 이고 답 포함도 ≥0.80` 이다. 답만으로 판정하지 않는 이유는
답이 짧을 때다 — 서로 다른 질문 둘이 똑같이 "혈전"을 답으로 가질 수 있다.

**그런데 정작 합치려던 `p260820_01`×`p260820_02` 는 겹침이 0 이었다.** qc 0.40 넘는 쌍이
3개뿐이고 셋 다 답 포함도 0(가짜)이다. 1교시는 **선천 기형·malformation·deformation**,
2교시는 **PPROM·조산** 으로 내용이 아예 갈린다(슬라이드 36 대 61). 같은 강의의 다른 필기본이
아니라 **한 강의가 두 교시에 걸쳐 서로 다른 내용을 다룬 것**이다.
새 덱 이름 규칙이 이미 둘을 한 노드에 모으므로 **이 쌍에는 `merge.py` 를 쓰지 않았다.**
모듈은 다음에 진짜 중복본이 나올 때를 위해 남겨 둔다.

`out/jokbo/` 에 과목 전체 족보가 16개 강의로 잘려 있다(필기 490문항 + 실습 97문항).
목차 제목과 본문 헤더가 다를 때(`종양의 정의 및 분류, 암의 역학*` vs `종양의 정의 및 분류`)
섹션을 못 열던 결함을 고쳤다 — 쉼표 앞 토막을 별칭으로 등록한다(`title_aliases`).
그 전에는 21강 문항 15개가 통째로 19-20 섹션에 흡수돼 있었다.
필기 아카이브는 `C:\Users\ows01\SynologyDrive\병리학\필기\2026\` 에 29강 전부 있다.

철학에 세 조항이 추가됐다 — ①기출은 형태가 아니라 지식을 옮긴다 ②열거형은 기원·범주를 지정해
답의 집합을 닫는다 ③이미지 카드의 질문은 그림이 이미 답하는 것(진단명·장기)을 말하지 않는다.
셋 다 사용자가 실제 카드를 짚어 지적한 데서 나왔다.

## 설계에서 바뀐 것과 그 이유

설계 문서를 그대로 이식하지 않았다. 실제 자료가 전제를 여러 개 무너뜨렸다.

- **필기 제거는 어렵지 않다.** 필기 전량이 PDF annotation 객체라 `delete_annot()` 한 번이면 clean 강의록이 나온다.
- **채널 위계는 색이 아니라 구조에서 나온다.** 색 규약은 필기자마다 다르다.
  `페이지 컨텐트 = 강의록 / annotation = 필기`는 어떤 필기본에서도 참이다.
  필기의 연도는 `creationDate`에서, 마커는 반복되는 Stamp `name`에서 얻는다.
  **다만 이것을 「색을 아예 안 본다」로 읽지 마라.** 위계를 정하는 데 안 쓸 뿐,
  2026-09-03에 강의록 자체의 글자색을 `lecture_emphasis` 채널로 붙였다 — 필기자가
  아니라 교수가 칠한 것이라 편 안에서 일관된다. 본문색은 편에서 가장 많이 쓰인 색으로
  정하고, 무채색(각주·출처)과 쪽마다 같은 자리에 반복되는 템플릿을 뺀 나머지를 강조로
  본다. 계약은 필기 `markers`와 같은 급 — 중요도 신호이고 단독 근거가 아니다.
- **Structure·Chunk·Merge 단계를 없앴다.** 강의 하나(36~46장)가 컨텍스트 한 번에 들어간다.
- **`슬라이드 수 + 50` 분량 공식을 버렸다.** 회수 목표 수와 기출 문항 수가 분량을 정한다.
- **`density`·`style` 설정 축을 없앴다.** 근거가 생기기 전에는 설정으로 두지 않는다.

## 걸렸던 것 — 다시 밟지 말 것

**PDF·Read**

- Claude Code의 `Read`는 PDF에서 **텍스트 레이어를 주지 않는다.** 페이지 이미지만 온다.
  그래서 용어 철자는 사이드카에서 가져와야 한다. 이미지에서 옮겨 적으면 오탈자가 카드에 박힌다.
- `Read`는 **1회 25k 토큰**에서 잘린다. 조용히 잘리므로 `assemble.py`가 파트로 나눠 둔다.
  토큰 추정은 한글 음절당 2.0, 그 외 자당 0.7 (실측 25,315자 = 27,898토큰).
- PDF는 한 번에 20쪽까지만 읽힌다.

**PyMuPDF**

- `insert_textbox`는 상자에 안 맞으면 **조용히 실패**하고 음수를 반환한다. `insert_text`(baseline)를 쓴다.
- 클립해서 렌더한 픽스맵의 좌표계는 0 기준이 아니라 `(pix.x, pix.y)`만큼 밀려 있다.
  `set_rect`에는 **장치 좌표**(페이지 좌표 × 배율)를 넘겨야 한다. 0 기준으로 계산하면 엉뚱한 자리를 칠한다.
- 페이지에 `draw_rect`한 것은 **annotation 아래에 깔린다.** 필기를 가리려면 픽스맵에 직접 칠해야 한다.
- 2단 조판을 `(단, y)`로 재정렬하면 두 단에 걸친 **전폭 섹션 제목이 쪼개진다.** 블록 순서를 그대로 쓴다.
- 페이지 크기가 균일하다고 가정하지 마라. 한 파일 안에 540/648/756pt가 섞여 있었다.
- **주석을 지울 때 `for a in list(page.annots())` 는 안전하지 않다.** 미리 리스트로 담아도,
  답글(IRT)이 달린 주석이 하나라도 있으면 앞의 것을 지우는 순간 뒤의 것이 페이지에서 떨어져
  `RuntimeError: Annot is not bound to a page` 로 죽는다. `[260820_01] 소아질환(1)` 이
  그랬다 — 주석 374개 중 IRT 가 달린 것은 **단 하나**였고, 그 한 개 때문에 강의 하나가
  prep 에서 통째로 멈췄다. `delete_annot` 이 **다음 주석을 돌려주므로** 그 사슬을 따라간다:
  `a = page.first_annot; while a: a = page.delete_annot(a)`. `prep.build` 가 이제 그렇게 한다.
- **`insert_pdf` 로 이어 붙여도 필기는 온전하다.** `merge.py` 를 붙이며 실측했다 —
  주석 개수·종류·쪽크기가 그대로이고, 렌더 차이는 최대 1/255(픽셀의 0.085%)로 재인코딩
  반올림뿐이다. 그림 크롭은 원본과 **바이트까지 같다.**

**족보 절단**

- 본문에 제목이 없는 강의의 문항은 **앞 섹션으로 흡수된다.** 슬라이스 두 개가 동시에 오염된다.
  목차 순서로 계산해 `may_contain`에 기록하고, `assemble.py`가 그것으로도 대조한다.
- 정답은 `(섹션, 연도, 번호)`가 아니라 **`(연도, 번호)`로 전역 결합**한다. 정답 구역의 섹션 경계가
  문항 구역과 어긋난다. 이걸 고치니 결합률이 62%→97%가 됐다.
- **답가지(보기)를 문항 밖에 한 번만 인쇄하는 연결형 묶음이 있다.** 머리글이
  `[문항 7,8] 아래 답가지(1-15) 중에서 …` 이고, 공용 답가지가 먼저, 그 답가지를 쓰는 문항이
  나중에 온다. 답가지 조판이 두 가지인데 **평번호(`1.` `2.`)는 문항 시작과 생김새가 똑같다.**
  구분하지 않으면 답가지 15줄이 전부 가짜 문항이 되고 — 실습 2021 에서 17개, 필기에서 40여 개 —
  번호가 겹치는 **진짜 문항의 정답을 훔쳐 간다.** `Barrett 식도` 가 정답 `1` 을 달고 있던 것이
  그거다. 정답이 비는 것보다 나쁘다. 조용히 틀리기 때문이다.
  출제자도 같은 충돌을 겪어서, 번호가 1부터 다시 시작하는 묶음의 정답은 **`R` 을 달아** 찍는다
  (`R7. 3,10`). 앞 문항 번호보다 작아지면 다시 시작한 것으로 보고 `R` 키로 결합한다.
  `[42-43]` 처럼 번호가 이어지는 묶음은 그대로 둔다. `jokbo.Bank` 가 이 상태기계다.
  고친 뒤 실습 정답 결합은 82/97 → **82/82**, 전체는 554/587 → **517/533** 이 됐다
  (분모가 준 것은 가짜 문항 54개가 사라졌기 때문이다). `tests/quizgen/test_jokbo.py` 가 지킨다.
- 문항 번호 구분자가 `.` 이 아니라 `,` 로 찍힌 문항이 하나 있다 (`20, 만성염증에 …`).
  그 문항은 통째로 앞 문항에 흡수된다. **정규식으로 `,` 를 허용하면 안 된다** — `1,000명당 70명`,
  `46,XY/47XXY`, `1, IL-2 등을 분비하여` 가 전부 문항 시작으로 잡힌다. 실측 1건을 살리려고
  10건을 깨는 거래다. 콘솔의 `짝을 못 찾은 정답` 에 `2023-20` 으로 남겨 두는 편이 낫다.

**guid**

- **이미지 카드의 guid 씨앗에 그림이 빠져 있었다.** 씨앗이 `(강의 ID, 정규화한 질문)`
  뿐이라, 질문이 그림을 가리키는 카드끼리 문장이 같으면 guid 가 겹쳤다. Anki 는 나중
  것을 **기존 노트의 수정**으로 처리하므로 한 장이 조용히 사라진다. 28강에서 4장이
  그러고 있었다 — 충수돌기/담낭, 태아 폐 18주/23주, 적색/백색 경색, 침윤/핵다형성.
  넷 다 사진과 답이 다른 **서로 다른 카드**였고 질문 문장만 같았다.
  카드 수를 세지 않으면 드러나지 않는다. `bundle.py` 로 28강을 한데 담다가 잡혔다.
  이제 이미지 카드만 씨앗에 `그림 ID · 가림 상자 · 크롭` 을 덧붙인다 —
  **렌더된 파일명을 결정하는 값과 같은 것**이라, 그것까지 같으면 정말로 같은 카드다.
- **그림이 없는 카드에는 아무것도 덧붙이면 안 된다.** `genanki.guid_for` 는 인자를
  `__` 로 이어 해싱하므로 **빈 문자열을 붙여도 해시가 바뀐다.** 무심코 항상 붙이면
  텍스트 카드 2천여 장의 guid 가 통째로 바뀐다. `tests/quizgen/test_guid.py` 가 이걸 지킨다.

- **씨앗을 늘리는 것으로는 재발을 못 막는다.** 겹칠 수 있는 카드는 언제든 또 나온다
  (같은 질문 문장에 답만 다른 텍스트 카드 두 장이면 지금도 겹친다). 그래서 `build.check_guids`
  가 **덱을 만들기 전에** 센다 — 질문·답·형식·그림까지 같으면 진짜 중복이라 접고,
  하나라도 다르면 `GuidClash` 로 **덱을 만들지 않는다.** 어느 쪽을 버릴지는 코드가
  정할 일이 아니라 겹친 두 장을 보여주고 멈춘다. 재현 검사 관문과 같은 자세다.

> ⚠ **2026-08-22 에 이미지 카드의 guid 가 바뀌었다.** 그전에 임포트한 덱이 있으면
> 이미지 카드가 **중복으로 들어간다** (옛 노트는 옛 guid 로 그대로 남는다).
> 옛 덱을 지우고 다시 넣는 것이 깨끗하다. 텍스트 카드의 guid 는 그대로다.

**한국어**

- **NFD 로 저장된 파일명이 섞여 있다.** Synology 를 거친 것으로 보인다. 자모가 풀린 한글은
  `[가-힣]` 에 하나도 걸리지 않아 **통째로 사라진다.** `[260819_05] … 실습 4 …` 한 강의만
  조각 대조가 조용히 0점이었다. `textutil._strip` 이 이제 NFC 로 정규화하고,
  덱 이름·강의 ID 도 NFC 로 만든다. 한글 파일명을 다룰 때는 항상 먼저 의심할 것.
- 어절 토큰 비교는 조사 때문에 무력하다(`합성` ≠ `합성을`). 유사도는 **글자 2-gram**으로 본다.
- 표를 터미널에 낼 때 `f"{s:<14}"` 로 폭을 맞추면 **한글이 두 칸**이라 어긋난다.
  `unicodedata.east_asian_width` 로 세야 한다 (`ledger._w`).
- `고르시오`·`옳은 것은` 같은 상투어를 빼야 유사도가 정확해진다. 이걸 빼니 족보 반복률의
  거짓 양성이 사라졌다(9번 강의 69%→33%, 실제 반복은 3쌍).

**Anki 템플릿**

- **뒷면의 스크롤 구조는 `<hr id="answer">` 가 전부다.** Anki 는 뒷면을 그린 뒤 `id="answer"` 인
  요소를 찾아 그 자리로 스크롤한다. 그래야 질문이 위로 밀려나고 답이 화면 맨 위에 선다.
  앵커가 없으면 Anki 는 스크롤을 건드리지 않아 **뒷면이 맨 위에서 시작하고 질문이 화면을
  차지한 채 답은 그 아래 남는다.** 네 형식 모두 그 상태였고, 사용자가 "구조가 깨졌다"고
  짚기 전까지 아무도 못 봤다 — 코드는 멀쩡하고 카드도 멀쩡해 보이기 때문이다.
  이미지 카드에서는 앵커가 **그림 뒤**에 온다. cloze 는 붙이지 않는다(빈칸이 문장 안에서
  열리므로 문장이 제자리에 있어야 맞다).
- **경고는 세 층이다**(2026-09-03 관리자 지시). 가르는 축은 「푸는 사람이 지금 할 일이
  있나」이고, `build.py` 의 `WARN_TRUST`·`WARN_MINOR`·`WARN_CHORE` 가 어느 층인지 정한다.
  **카드 겉면에 남는 것은 ①뿐이다** — 노란 상자(`.warn`, 족보 검토·정답 의심도 여기).
  ②(`.minor`)와 ③(`.chore`)은 **접힌 출처 안**으로 가고, 같은 자리에 있어도 색과 크기로
  층이 남는다(② 가 진하고 크다). 나누기 전에는 셋이 한 상자였는데, 실측하면
  「자료 주의」로 뜬 272건 중 **202건(74%)이 ③**이라 노란 상자가 사실상 잔소리 전용이었다.
  새 플래그는 셋 중 하나에 넣어야 카드에 뜬다 — 어디에도 안 넣으면 조용히 안 뜬다
  (`FLAG_LABEL` 은 셋을 합친 것이라 따로 적을 것이 없다). 층을 나눌 자리가 필드가 아니라
  **`warning_of` 안**인 이유는 `Warning` 필드가 하나뿐이기 때문이다 — 필드를 늘리면
  이미 임포트한 덱의 노트 타입이 흔들린다. 그래서 div 를 파이썬 쪽에서 붙이고 템플릿은
  `{{Warning}}` 만 놓는다. 예습도 같은 표·같은 생김새를 쓴다.
- 모델 ID 는 **모델 이름**에서 나온다(`_mid(name)`). 템플릿을 고쳐도 이름이 같으면
  이미 임포트한 덱이 **덮어써진다.** 반대로 강의 ID(`--id`)를 바꾸면 guid 가 전부 바뀌어
  **중복 임포트**가 된다. 템플릿은 마음껏 고치고, 강의 ID 는 건드리지 마라.

**이미지 렌더**

- **image_basic 앞면은 clean.pdf 에서 뜬다.** 필기가 그림을 가리거나 캡션·라벨로 답을
  흘리는 일이 잦다. 좌표는 그대로 쓸 수 있다 — `lecture_figures` 는 애초에 clean 페이지에서
  뽑은 것이고(`prep.figures_of(cp)`) 두 판은 같은 원본의 사본이다.
- **오클루전 앞면은 annotated 에서 떠야 한다.** 가리는 대상이 필기 라벨 자체라
  clean 으로 뜨면 라벨이 사라져 빈 자리를 가리게 된다.
- **오클루전 크롭은 그림 bbox 로만 자르면 안 된다.** 경계에 걸친 필기가 단어 중간에서
  잘려 `gregation`, `혈관 손상 → suben` 같은 조각이 남는다. 읽히지도 않으면서 시선만 끈다.
  걸친 필기·마커를 온전히 품도록 넓힌다(`Media._with_annotations`, 실측 1.3~1.7배).
  단 `media.crop` 이 지정된 경우는 넓히지 않는다 — 모델이 정답 새는 구간을 일부러
  도려낸 것이라 되돌리면 안 된다.

**차단 검사(카나리아)**

- **표현으로 판정하지 마라.** 예전 카나리아는 빈 세션이 `"blocked"` 라고 **말했는지**를 봤다.
  같은 상황을 `file_not_found` 라고 답한 판이 나오자 멀쩡한 실행이 멈췄다(순환장애 2강).
  이제 아무도 알 수 없는 토큰을 파일에 심고 **그 토큰이 답에 나타났는지**만 본다.
  틀리는 방향은 그대로 한쪽이다 — 못 읽었는데 읽었다고 판정될 길은 없다.

**검증기를 새로 만들 때**

- **문장 형태로 "축이 여럿인지"를 재려다 실패했다.** `무엇이며`·`이며,` 를 신호로 넣었더니
  세 덱 257장 중 22장이 걸렸는데 사용자 판정으로 진짜 결함은 **한 장**이었다(정밀도 5%).
  한국어에서 그 연결은 정의와 그 즉각적 귀결을 잇는 가장 흔한 형태이고, 이미지 카드는
  철학이 오히려 "장기·진단·소견을 한 장에서" 물으라고 시킨다 — **자기 철학이 권장하는
  형태를 잡고 있었다.** 깃발을 지우고 길이(`question_too_long`, 120자, cloze 제외)만 남겼다.
  257장 중 2장에 붙는다.
- 교훈: **새 깃발은 반드시 이미 만든 덱 전량에 걸어 보고, 걸린 것을 사람에게 보여 채점받아라.**
  0.8% 에 붙는 깃발은 읽히고, 8% 에 붙는 깃발은 무시된다.
- 새 서식을 넣으면 **기존 검사가 오탐을 내는지** 먼저 본다. 불릿 답을 도입하면서
  `too_many_items` 가 쉼표까지 세어 3줄 답을 항목 7개로 잡던 것을 함께 고쳤다(`count_items`).

**단계 산출물 확인**

- **프롬프트는 커지면 파트로 갈린다.** 그러면 `prompt.cards.md` 는 **아예 생기지 않고**
  `prompt.cards.1of2.md` 가 대신 선다. run.py 가 그 고정 이름으로 산출물을 확인하고
  모델에게도 그 이름을 읽히고 있어서, **갈린 강의에서만** 조립 직후 멈췄다
  (순환장애 두 강의가 여기서 걸렸다. 소아질환(2)·종양1 은 안 갈려서 드러나지 않았다).
  이제 `made("prompt.cards*.md")` 로 확인하고 `prompt_path()` 로 첫 파트를 찾는다.
  파트 1이 나머지를 읽으라는 목록을 달고 있으므로 첫 파트만 지목하면 된다.

**Python 소스 수정**

- `str.replace()`로 소스를 패치하면 이스케이프가 어긋나 **조용히 실패**한다. Edit 도구를 쓴다.

## 카드 품질 — 사용자가 지적한 것

사용자가 실제 카드를 짚어 지적한 사례다. 아래 사례 자체는 설계 기록으로만 남기고,
런타임에는 다른 과목에도 적용되는 원칙만 `quizgen/prompts/core/`와 조건부 어댑터에 둔다.
현재 구성 기준은 [prompt-architecture.md](../../../prompt-architecture.md)를 따른다.

**1. 기출은 형태가 아니라 지식을 옮긴다.**
"~이 아닌 것은?" 같은 부정형은 **선지가 있어야만** 답이 하나로 정해진다.
선지를 떼고 옮기면 절대 풀 수 없는 카드가 된다. 기전을 묻거나 O/X로 세운다.

```
나쁨  Q. 생후 2일에 사망한 아기의 부검에서 볼 수 없는 소견은?   A. 기관지폐이형성증
좋음  Q. BPD가 조직학적으로 성립하려면 어떤 두 과정이 먼저 일어나야 하는가?
      A. 유리질막이 소실되고, type II 폐포세포의 재생이 일어나야 한다
```

**2. 시험 푸는 요령은 카드가 아니다.**
"선지를 먼저 지운다"는 응시 기술이지 의학 지식이 아니다. 같은 통찰을 개념 진술로 바꾼다.

```
나쁨  Q. 어머니가 Rh 양성인 선지를 먼저 지울 수 있는 이유는?
좋음  Q. Rh 부적합이 성립하려면 어머니와 태아의 Rh 형은 각각 어때야 하는가?
```

**3. 어디에 카드를 몰 것인가.**
강의를 균등하게 훑으면 안 된다. 우선순위는 ①여러 해 반복 출제된 기출 주제(각 3~5장)
②`족보`·`중요` 스탬프가 붙은 슬라이드 ③형광펜·밑줄이 덮은 문구 ④올해 필기가 몰린 슬라이드.
표시도 기출도 없는 슬라이드는 목표당 1장을 넘기지 않는다.

**4. 열거보다 변별.** 시험은 5지선다이고 요구하는 능력은 비슷한 것을 가르는 힘이다.
`card_type=list`는 자료가 실제로 번호를 매겨 묶어 제시한 경우에만 쓴다.

**5. 열거형은 개수를 밝히는 것으로 부족하다.** 재현 검사에서 `answer_underspecified` 로
갈리는 카드는 거의 다 "N가지는?" 형태다. 외부 풀이자는 **다른 N개**를 댈 수 있다.
기원·범주를 질문에 지정해 **답의 집합을 닫아야** 재현된다.

```
나쁨  Q. 중간엽 기원 양성종양 다섯 가지는?
좋음  Q. 양성종양 명명 규칙을 근육·섬유모세포·연골·뼈·지방 기원에 각각 적용하면?
```

**6. 이미지 카드의 질문은 그림이 이미 답하는 것을 말하지 않는다.**
조직 사진 앞에서 무슨 조직·무슨 질환인지 알아내는 것이 과제인데,
질문이 "이 NEC 조직 사진에서…"로 시작하면 회수 목표 둘을 앞면이 먼저 답해 버린다.
진단명·장기명·판독 결론을 앞면에서 빼고, 그것 자체를 묻는다.
(단 그림만으로 특정 불가능한 것 — 나이·임상 경과·수치 — 은 질문에 준다.)

**7. 축이 여럿이면 카드도 여럿이다.** 사용자 문장 그대로 —

**8. 답의 항목이 둘 이상이면 줄로 나눈다.** `/` 로 잇지 말고 줄바꿈과 `- ` 로,
범주와 내용은 `—` 가 아니라 **`:`** 로 가른다. 카드는 눈으로 훑는 것이고
훑는 데 걸리는 시간이 회독 수를 정한다.

```
나쁨  벽재성 — 심장 내강 / 대동맥 내강 / 동맥 — 관상동맥 / 대뇌동맥 / …
좋음  - 벽재성: 심장 내강(cardiac chamber), 대동맥 내강

      - 정맥: 하지 정맥, 문맥, 간정맥
```

`build.render_answer` 가 `- ` 줄을 `<ul>` 로 낸다. CSS `white-space: pre-line` 만으로는
**선행 공백이 뭉개지고** 한 항목이 두 줄이 되면 들여쓰기가 무너져 안 된다.

**9. 오클루전은 승인된 핵심 라벨만 가린다.** 후보를 순서대로 집지 말고 승인된
`retrieval_targets`에 직접 속하는 이름 있는 라벨만 고른다. 기본은 한 장에 라벨 하나이며,
같은 목표·같은 축의 라벨만 함께 가릴 수 있다. 남은 라벨이 답을 흘리면 무관한 상자까지
늘리지 말고 crop을 조정하거나 카드를 만들지 않는다. 가린 라벨 자체가 `a`의 답이어야 하며,
기능·기전을 묻고 싶다면 `image_basic` 또는 텍스트 카드가 낫다.

**용어 병기는 자료 안에서 확인된 것만 쓴다.** 원문 표기를 보존하고, 한국어·영어가 모두
제시된 개념은 자료의 주표기를 머리로 둔 `주표기(대응 표기)` 하나로 고정한다. 같은 덱에서
`Down syndrome`·`다운증후군`·`Down 증후군`처럼 섞지 않는다. 자료에 한국어만 있으면 영문을
외부 지식으로 보태지 않고, 영문 원문을 임의 한글 음차로 대체하지 않는다. 오클루전 답에는
가린 원문 라벨을 반드시 남기며, 자료가 제공한 대응 표기는 같은 답 안에 병기할 수 있다.

**10. cloze 로 가린 말이 같은 문장 다른 자리에 맨몸으로 또 나오면 안 된다.**
앞면에서 가려지지 않은 자리가 답을 그대로 읽어 준다.
같은 말이 두 번 필요하면 **두 자리 모두 가린다.**
24강 실행에서 두 번 터졌다(`EGFR`, `47,XXY`). `prompts/cards.md` 에 조항을 넣었지만
**그 뒤에도 나왔다 — 지침만으로는 안 막힌다.** 누출 검사가 잡는 것이 최종 방어선이다.

```
나쁨  ... {{c1::EGFR}} 변이이고, {{c1::Iressa}}는 EGFR tyrosine kinase inhibitor다
좋음  ... {{c1::EGFR}} 변이이고, {{c1::Iressa}}는 {{c1::EGFR}} tyrosine kinase inhibitor다
```

> 위 예시의 번호가 예전에는 `c1`/`c3` 이었다. **2026-09-04 부터 빈칸 번호는 전부 `c1`
> 이다** — 아래 절을 보라.

**11. 1조는 반대 방향으로도 터진다 — 선지를 붙여 오면 답이 인쇄된다.**
1조는 "선지를 떼면 못 푸는 카드가 된다"를 경고했는데, 실제로는 선지를 **떼지 않고 그대로**

## 아직 안 푼 문제

- **이미지 카드의 정답 노출.** 필기자가 슬라이드를 통째로 스크린샷해 붙였기 때문에
  "그림"이 곧 "캡션 포함 슬라이드"인 경우가 많다. 캡션이 픽셀이라 **코드로 감지할 수 없다.**
  `media.crop`(그림 기준 비율)으로 잘라낼 수 있게 열어 뒀지만, 자를 구간은 모델이 정해야 한다.
  `build.py`가 만드는 `*_image_check.pdf`를 **반드시 눈으로 확인**해야 한다.
- **필기 라벨 기반 오클루전의 통과율이 낮다.** 소아질환(2)에서 6장 중 1장만 살았다.
  필기 라벨 대부분이 슬라이드에 이미 있는 내용을 한국어로 옮겨 적은 것이라 원본이 옆에 남으면 답이 샌다.
  필기가 슬라이드에 **없는** 정보를 더한 경우에만 성립한다.
  (핵심 용어를 3~6개 가리라는 지침과 `MAX_LABEL_CHARS` 24 상향을 넣었으나 **아직 실측이 없다** —
  순환장애 두 강의는 그 전에 만들어졌다. 다음 강의에서 통과율을 다시 세어 볼 것.)
- **재현 검사는 "풀리는가"를 재지 "읽히는가"를 재지 않는다.** 종양1의 c004
  (`염증의 4징 중 종양(tumor)과 같은 낱말을 쓰는 것은…`)는 재현 검사를 `same`·confidence
  `high` 로 통과했는데 사용자는 **무슨 말인지 모르겠다**고 했다. 푸는 빈 세션은 의학 지식을
  다 갖춘 채 문장을 몇 번이고 뜯어볼 수 있지만, 회독하는 사람은 지친 상태로 한 번 훑는다.
  빈 세션에 `clear: true/false` 를 함께 내게 하는 안을 검토했으나, 강한 모델은 웬만하면
  "분명하다"고 답할 것 같아 접었다. **가독은 지금 아무 데서도 재지 않는다.**
- **`evidence_type` enum이 두 축을 섞고 있다.** 채널(강의록/필기/기출)과 매체(텍스트/그림)가
  한 enum에 들어 있다. 래스터로 된 텍스트 슬라이드에서 어느 쪽을 쓸지 애매하다.

`run.py` 로 강의 하나를 통째로 돌린 실측 (소아질환(2), 46슬라이드·88장, 최적화 전):

```
① 학습목표      8분   $2.4
② 카드 88장    19분   $4.4
수선 7장        6분   $1.2
재현 검사 ×2    9분   $2.7
                     ─────
               36분   약 $12
```

**장부가 붙은 뒤의 실측 (순환장애 2강, 2026-08-22).** 추정 $7 보다 비쌌다.

| 단계 | 순환장애(1) 73장 | 순환장애(2) 107장 |
|---|---|---|
| ① 학습목표 | 5.4분 $2.96 | 9.5분 $4.86 |
| ② 카드 | 11.3분 $4.33 | 10.5분 $4.77 |
| 풀이 (동시 4·6) | 77초 $0.61 | 1.7분 $0.85 |
| 채점 (sonnet) | 2.0분 $0.78 | 2.3분 $0.64 |
| 수선 1바퀴 | 62초 $0.60 | 74초 $0.42 |
| **합계** | **21분 $9.28** | **25분 $11.54** |

**값의 거의 전부는 ①②이고(각 $9.28 중 $7.29, $11.54 중 $9.63), 그 안에서도 캐시읽기다**
— 1강 426만 · 2강 716만 토큰. 출력은 각 115k·133k 에 불과하다. ②가 ①을 이어받는 구조라
대화가 길어질수록 매 턴 되읽는 양이 붙는다. **줄일 데가 있다면 여기다.**
재현 검사 일습(풀이+채점+수선)은 $1.9~2.0 로 싸고, 결함을 0으로 만들고 있다.

`--jobs` 를 6까지 올려도 풀이는 2분을 넘지 않는다. 벽시계의 주인은 ①②다.

이 아래는 최적화를 붙이기 전 소아질환(2) 의 기록이다.

**최적화 네 가지를 붙인 뒤 강의당 약 20분 · $7 로 봤다 (실측은 위).**

- ② 가 ① 세션을 이어받는다 → PDF·사이드카를 두 번 읽지 않는다
- 재현 검사 세션을 동시에 (`--jobs 4`) → 77장 기준 5분 → **125초**
- 채점은 sonnet (`--judge-model`) → $0.45 → **$0.30**. 푸는 쪽은 강한 모델을 유지한다
- 수선 뒤에는 고친 카드만 재검사 (`--only`) → 전체 $0.77 대신 3장 $0.13

**채점 모델을 바꾸면 판정이 조금 달라진다.** 같은 답을 opus 는 `same 76·partial 1`,
sonnet 은 `same 73·partial 4` 로 봤다. sonnet 이 더 엄하고, 늘어난 셋 다 타당한 판정이었으며
카드 결함으로는 분류되지 않아 헛된 수선이 돌지 않았다. 되돌리려면 `--judge-model opus`.

이 세션(대화) 안에서 손으로 돌리면 값이 2배가 된다 — 매 턴 대화 전체를 다시 읽기 때문이다.
그래서 ①② 를 빈 세션에 맡기는 구조가 비용 구조상으로도 맞다.

## 빈칸 번호는 굽는 자리에서 하나로 모인다 (2026-09-04)

관리자 지시 — *"지금 clozed 카드에 자꾸 c1, c2, c3가 생겨. 나는 clozed가 좋은데
한번에 보였으면 좋겠어."*

Anki 는 **빈칸 번호 하나에 카드 한 장**을 만들고, 각 카드는 나머지 번호의 답을 앞면에
그대로 인쇄한다. 그래서 `c1..c4` 로 나뉜 한 문장이 카드 네 장이 되고, 그 넷 모두
앞면에 답 셋이 적혀 있다.

**얼마나 나고 있었나 — `runs/` 의 `items.checked.json` 85편, cloze 64장.**

    빈칸 번호가 하나  25장
    둘                20장
    셋                15장
    넷                 4장   →  번호가 갈린 것 39장 (61%)

갈린 것 대부분이 **한 축**이었다(`amastigote → promastigote → epimastigote →
trypomastigote`, `Pseudopodia / Cilia / Flagella / Undulating membrane`). 계약에는
「같은 축에 나란히 놓인 항목은 같은 번호로 함께 가린다」가 이미 적혀 있었다.
**지침만으로는 안 막혔다** — 위 10조와 같은 자리다.

그래서 코드가 모은다. `build.collapse_cloze` 가 `{{cN::` 을 전부 `{{c1::` 로 바꾸고,
복습·예습 두 빌드가 노트 필드를 만들 때 그것을 통과시킨다.

**모으는 자리는 굽는 직전 하나다.** `guid` 는 그 위에서 **모델이 낸 글자 그대로**
계산되므로, 이미 나간 덱을 다시 구워도 같은 노트로 들어간다 — 복습 이력이 살아남는다.
`items.checked.json` 에도 모델이 낸 번호가 그대로 남는다.

**이미 임포트한 덱에는 빈 카드가 남는다.** 옛 노트의 `c2..c4` 카드가 갈 곳을 잃기
때문이다. Anki 의 `도구 → 빈 카드` 를 한 번 돌리면 지워진다. **덮어쓰기가 지워 주지
않는다.**

재현 검사는 그 전부터 **모든 빈칸이 함께 가려진 앞면**을 채점하고 있었다
(`reproduce.front_of` 가 번호를 안 보고 전부 `[...]` 로 바꾼다). 즉 **채점한 앞면과
실제로 구워지던 앞면이 달랐다.** 이제 같다.

계약과 프롬프트도 같이 고쳤다 — 번호를 나누지 말고 **축이 다르면 카드를 나눈다.**
축이 다른 것을 한 문장에 몰면 이제 한 카드가 두 축을 함께 묻게 된다.

**아직 안 재 본 것:** 한 축이 4칸 한꺼번에 가려진 카드가 실제로 풀 만한지.
`too_many_clozes`(빈칸 5개 이상)는 그대로 세지만, 그 문턱은 「번호가 갈려 있던 시절」에
정해진 값이라 이 바뀜을 겪지 않았다.
