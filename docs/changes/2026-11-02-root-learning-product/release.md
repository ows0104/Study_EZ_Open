## 남은 채택·활성화 조건

1. 초기 정책 선택은 완료됐다. 사용자 선택은 “학습 결과와 시험일까지 남은 기간에 따라 유동적으로 조정, 하루 경계는 새벽 4시”다. 기본 roots-adaptive/1은 독립 회상과 실제 경과 시간으로 간격을 연장하고, 일부/도움은 줄이고, 실패는 다음 학습일에 재확인한다. 시험 임박 상한을 적용하고 같은 날 반복 성공으로 간격을 늘리지 않는다. 초기 수치·예시는 policy-examples.md에 고정했다. STUDYEZ_ROOT_POLICY를 지정하지 않으면 새 기본을 사용한다. 이전 정책/09시 회차·사건은 스냅샷 그대로 보존하고 새 추천과 분리한다. 정책 선택 대기를 이유로 기능을 막는 상태는 해제했지만 전체/강의별 공개 플래그는 기본 닫힘이며 운영 활성화는 미실행이다.
2. 콜린성 실제 15목표/필수 방향은 후보다. 기존 10묶음/49문항을 자동 변환·채택하거나 의학 답을 수정하지 않았다. 관리자 자료 등록 경로가 준비되었으나 실제 콘텐츠를 검토·채택하여 등록해야 사용 범위가 생긴다. sources 지문은 관리자 제공 검토 묶음의 주장으로 취급하며 구조 검사가 원본 PDF 대조를 인증하지 않는다.
3. 같은 질문의 작성 중 초안은 계정/강의/판/질문별 마지막 로컬 보관값이다. 별개의 탭이 보낸 미확인 요청과 충돌 응답은 요청 ID별로 각각 보존한다. 판 사이에는 명시적 검토 연결과 같은 의미 지문이 함께 있어야 기록을 읽어 이어간다.

따라서 이 기록은 로컬 제품 코드/Build/Test/Review 결과이며 실제 콘텐츠 시범 완료나 운영 배포 준비 전체 완료로 부르지 않는다.

## 운영 순서·승인·복원

운영은 미실행이다. 전체 기능 환경 플래그는 기본 꺼짐이며 강의별 활성 판/검토/허용 계정을 서버에서 함께 검사한다. 운영 반영 전에 선택된 정책의 실제 시범 확인과 실제 콘텐츠 검토, 다른 작업과 분리한 고정 후보를 준비하고 중요한 운영 승인을 받는다.

승인된 후보의 순서: 대상 DB와 복원 가능한 백업 확인 → app.cli init-db로 새 표/RLS 준비 → API → 웹 → 검토된 콘텐츠 비공개 등록 → 대상 계정에 제한 활성화 → 실제 저장/재개·비공개/타 계정 차단·기존 풀이 사후 확인 → 승인된 범위로 공개. 새로운 표만 추가하며 기존 표의 데이터를 이주/삭제하지 않는다.

문제 발생 시 서버 환경 플래그 또는 강의 enabled를 끄고 이전 API/웹 후보로 복원한다. 새 콘텐츠·원래 사건·세션·관리자 공개 이력·브라우저 미확인/충돌 입력은 삭제하지 않는다. 복구 후 같은 요청 ID로 대조한다. 실제 콘텐츠가 문제면 검토된 이전 판을 다시 활성화하되 동일성 미확인 기록을 자동 승계하지 않는다.
