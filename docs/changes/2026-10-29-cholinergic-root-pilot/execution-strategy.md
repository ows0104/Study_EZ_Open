# StudyEZ — 일반 ChatGPT 웹과 Codex CLI의 역할 검토

기준: 2026-10-29 KST. 사용자 요청으로 시범 실행에 앞서 조사했다. 웹은 사용자가 확인한 **일반 ChatGPT 대화**이며 ChatGPT Work로 간주하지 않는다.
상태: 공식 문서·현재 코드에 근거한 분석과 역할 제안. 실제 비교 생성·성능/토큰 벤치마크·설정 변경은 미실행이다.

사용자 후속 설명: “웹은 토큰 소모가 없어. 그리고 PDF 전체를 읽을 수 있는거 같아. 대신 불안정하고
출력 제한이 있는거 같아.” 현재 권고는 이 사용환경을 운영 전제로 반영해 웹의 원본 기반 작성 비중을
높이는 안으로 수정했다. 이를 모든 계정·플랜의 무제한 무료 사용이나 제품 기능의 보편적 보증으로 일반화하지 않는다.

## 판단의 출발점

웹과 CLI는 서로 다른 모델 이름이 아니라 사용 방식이다. 선택 모델·추론 설정·입력 자료·도구·대화 이력과
작업 설계가 달라지면 결과와 사용량도 달라진다. 인터페이스만으로 의학적 정확성·독해력·저비용 우위를 단정하지 않는다.
현재 웹 문제 생성은 사용자 수동 전송, CLI는 저장된 결과의 후처리·검수라는 기존 경계를 유지한다.
이번 제안만으로 자동 웹 접속·최초 CLI 재출제·운영 변경을 실행하지 않는다.

| PDF 전체 흐름 | 전체 첨부와 구조 질문을 함께 제공하기 간편함. 첨부 성공만으로 모든 지면·그림을 읽었다고 보장하지 않음 | 전체 텍스트와 모든 페이지 이미지를 준비할 수 있음. 실제 열람·미확인 쪽을 추적하는 설계가 필요 |

| 코드·파일 연결 | 일반 대화에서 로컬 저장소·검사와의 연결은 추가 전달 과정이 필요 | 파일 쓰기·스키마·참조 검사·전후 비교·재개 기록과 연결하기 적합 |

| 결과 검토 | 사람이 문항과 큰 구조를 읽고 수정 의견을 주기에 편함 | 기계가 처리할 결과와 상세 추적 기록을 보관하기 편함. 별도 사람이 읽을 요약 필요 |
| 실패·반복 | 중단·이어쓰기·버전 차이를 완성 결과 파일과 대조해야 함 | 종료·불완전 출력·재시도·변경 무효화 등을 명시적으로 다룰 수 있지만 잘못 설계하면 반복 호출이 늘어남 |

위 적합성 판단은 제품 작업 방식에 대한 제안이며 특정 모델의 비교 실험 결과가 아니다.

## 실제 프로젝트에서 확인한 차이

- `studyez_llm/codex.py`는 작업용 `blind=False`에서 파일·이미지 도구를 사용할 수 있게 한다. `blind=True`는 도구를 끄고 전달된 프롬프트만 다루는 격리 평가용이다. 이 후자에 PDF 경로만 적어 PDF를 읽었다고 간주하면 안 된다.
- `quizbank/question_first.py`의 원본 독립 추출은 전체 PDF의 페이지별 텍스트와 페이지 이미지를 준비하고 `coverage._call`의 작업용 CLI를 이용한다. `prompts/points.md`는 모든 쪽 이미지를 보도록 지시한다.
- `studyez_llm/pdf.py`는 지면을 이미지로 렌더한다. 렌더 파일의 존재와 모델의 실제 이미지 확인은 다른 사실이므로 확인 기록의 역할을 구별한다.
- `quizbank/web_audit.py`는 원본 쪽별·포인트별 대조 보고를 검사한다. 페이지별 상태가 다 있다는 사실만으로 모든 의학적 판단의 정확성이 증명되지는 않는다.
- `quizbank/session.py`의 도구 없는 구조화 실행은 정리·고정 입력의 평가에 쓰이며, 원본 전체를 새로 읽는 작업과 혼동하지 않는다.
- `studyez_llm/codex.py`와 `telemetry.py`는 입력·캐시 입력·출력·실패 상태·시간을 기록한다. 현재 어댑터는 `cost_usd=None`이며 이를 실제 달러 청구액으로 바꾸지 않는다. 최종 사용량 이벤트가 없는 실패는 0이 아닌 미상이다.
- `scripts/codex_usage.py`는 기록을 집계할 수 있다. 토큰을 계정의 주간 사용률로 직접 환산하지 않는다.

## 토큰·사용량을 판단하는 방법

사용자는 현재 일반 ChatGPT 웹에서 토큰 소모 부담 없이 작업할 수 있다고 설명했다. 따라서 사용자 관점의
CLI 사용량 절약과 전체 작업 안정성을 기준으로 판단한다. 웹에서 비용 부담 없이 원본 기반 작성을 할 수
있다면 그 작업을 CLI로 옮겨 모델 호출을 늘릴 이유는 약해진다. 이는 사용자의 운영 조건에 따른 판단이다.
동일 입력·모델·품질 목표의 기술적인 토큰 수 비교는 수행하지 않았고 CLI가 몇 배 더 싸다고 주장하지 않는다.
일반 Chat과 Work도 구별한다.
공식 문서는 Work와 Codex의 공유 사용량을 설명하지만 그 내용을 일반 Chat의 모든 한도에 그대로 적용하지 않는다.
API 토큰 요금과 ChatGPT 로그인으로 사용하는 CLI의 구독 한도를 같은 비용표로 계산하지 않는다.

줄일 수 있는 중복:

1. PDF 텍스트 추출·렌더·쪽 번호·원본 지문은 일반 코드로 한 번 준비하고 재사용한다. 다른 모델 호출에서 원본이 무료로 재사용된다는 뜻은 아니다.
2. 원본 전체를 읽어야 하는 추출은 유지하되, ID 확인·스키마·집계·학습량 계산 때문에 원본 전체를 모델에 반복 전송하지 않는다.
3. 문제·포인트·트리는 독립 입력을 유지한다. 공유 가능한 것은 원본의 기계적 준비물이며 한 추출의 해석 결과를 다른 추출의 정답으로 넘겨 읽기 비용을 줄이지 않는다.
4. 수정 가능한 범위와 출처가 같을 때만 검증된 결과를 재사용한다. 원본·범위·내용이 바뀐 결과를 그대로 통과시키지 않는다.
5. 긴 은행 전체를 결과 파일과 최종 답변에 중복 출력하지 않는다. 손실 없는 기계적 변환은 코드로 하고 의미 해석이 필요한 경우만 모델을 쓴다.
6. 같은 작업을 오류가 없어질 때까지 반복 호출하지 않는다. 실패·미해결·원문과 기존 횟수를 보존한다.

세 작성 결과는 서로 다른 원본 전용 입력에서 만든 뒤 대조하며, 웹에서 만들었다는 이유로 필수
원본·정답 검수를 생략하지 않는다. 처음의 필수 전체 대조를 유지하고 이후에는 동일 내용·근거·검수 기준의
기존 결과를 재사용하는 범위에서 중복을 줄인다. 일반 코드 실행과 모델을 부르는 Codex CLI 실행은 사용량 측면에서 구별한다.

## 웹의 불안정성과 출력 길이에 대응하는 제안

- PDF 전체를 읽는 입력 범위는 유지하고 결과 출력만 나눈다. 문제를 짧게 출력하려고 강의 맥락까지 잘라 뿌리를 선정하지 않는다.
- 문제·포인트·트리는 서로의 결과를 보지 않는 별도 대화로 작성한다. 세 결과를 한 응답에 몰아 넣어 길이와 자기 대조 문제를 키우지 않는다.
- 결과는 안정적인 ID·근거 쪽을 가진 파일 또는 구간별 출력으로 받는다. 문항 번호만이 아니라 실제 내용과 개수를 대조하고 중복·누락·중단을 구분한다.
- 출력 구간, 마지막 ID, 남은 구간과 완료 표시를 남긴다. 완료 문구만으로 완전성을 통과시키지 않는다. 파일 출력도 누락 검사가 필요하다.
- 이어쓰기는 전체를 다시 생성하지 않고 확인된 미완료 구간을 대상으로 한다. 기존 수동 전송·브라우저 비접속 지침을 유지하며 자동 이어쓰기를 추가하지 않는다.
- CLI 호출 전 일반 코드로 파일·ID·필수 필드·참조·개수·기존 지문을 확인한다. 의미 판단이 필요한 대조에만 모델을 사용한다.
- 평균 4강/평일에 세 독립 결과를 만들면 12개 작성 흐름을 관리하게 된다. 수동 전송·완성 결과 회수의 부담도 중요한 병목으로 보고 출력 계약과 재개 위치를 우선 정한다.

## PDF 전체 읽기의 계약 제안

원본 전체를 텍스트와 지면으로 확인할 수 있게 준비하고 페이지별로 요지·근거·범위 밖·미확인을 기록한다.
색·손글씨·도식·표·작은 글씨가 판단에 중요하면 해당 지면을 충분한 해상도로 다시 확인한다.
기존 검색 결과나 요약에 포함된 부분만 보고 전체 검토를 완료했다고 표시하지 않는다.
미확인 지면이 남으면 그것을 알려주고, 누락 검증의 완료와 구별한다. 기계적 지면 기록 검사는 독해의 보조 근거다.

PDF를 이미지와 함께 다루는 비용은 입력 방식에 따라 달라진다. API의 직접 PDF 입력은 텍스트와 지면
이미지를 함께 처리하는 별도 경로이며, 일반 ChatGPT 웹이나 현재 Codex CLI의 동작으로 그대로 치환하지 않는다.

## 콜린성 시범에서 확인할 항목

이번 턴에는 실행하지 않는다. 역할 배치를 검토한 뒤 기존 시범 범위 안에서 다음을 확인하는 안이다.

- 같은 필기·족보 판, 원본 전용 입력과 결과 파일을 고정한다.
- CLI별 입력·캐시·출력·완료/실패·시간·실제 지면 확인 범위를 기록한다. 확인할 수 없는 웹 토큰은 추정 수치로 채우지 않는다.
- 사용자가 뿌리의 강의 전체 대표성·필기/그림 반영·문제 연결을 검토한다. 서로 다른 작업의 출력 길이를 그대로 효율 비교하지 않는다.
- 웹과 CLI 품질의 직접 비교가 필요하면 같은 작은 과제를 별도 입력으로 비교한다. 1회 결과를 통계적 우위로 일반화하지 않는다.
- 모델 호출을 늘리는 비교 실험은 기존 시범의 자동 필수 단계로 추가하지 않는다.
