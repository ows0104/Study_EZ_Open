# Main-Quiz 오늘 학습 이어 풀기 — 설계

## 요구사항과 수용 기준

- R1 하루 한 흐름: 오늘의 흐름은 같은 사용자·강의·판·학습일·정책의 `root_session` 중 가장 최근 것 하나다(focus 무관).
  `overview_data`의 재개 대상(`sessionId`)은 그 흐름이 끝나지 않았을 때 그 ID다. 배포 전에 만든 오늘 회차가 여럿이면
  가장 최근 것이 흐름이 되고 나머지는 기록으로 남는다.
- R2 칩을 바꾸면 뒷부분만 다시 고른다(`PUT …/focus`): 오늘 흐름이 있고 끝나지 않았으면
  - 앞부분 `tasks[:index]`(푼·넘긴·제외한 자리)는 그대로 둔다. 번호·Z 되돌리기 위치도 그대로다.
  - 지금 자리의 과제가 답을 연 채(평가 전)면 그 과제도 그대로 둔다.
  - 나머지 자리는 「오늘 처음부터 이 칩이었다면」의 계획으로 바꾼다. 오늘(학습일) 답 보기·평가·넘기기·되돌리기
    기록을 뺀 상태로 새 칩의 계획을 내고, 앞부분과 오늘 건드린 과제를 뺀다. 그래서 칩을 껐다 켜면 안 바꾼 것과 같은 목록이 되고
    새 목표 몫도 늘지 않는다. 더 풀기로 늘린 몫(`state.extraGoals`)은 새 목표 몫에 더한다.
  - 끝난 흐름에도 같다. 칩을 줄여 끝났던 흐름은 다시 켜면 남은 것이 돌아온다.
  - 바뀌면 세션 `version`을 올린다(다른 탭·미리 받은 문항은 다시 읽게 된다). 흐름이 없으면 선택만 저장한다(지금과 같음).
  - 설계 중 바꾼 점: 처음에는 「뒷부분의 미학습 새 목표 수」로 몫을 묶으려 했다. 그러면 칩을 껐다 켤 때 목표가 빠지는 경우가 있어
    위 방식으로 바꿨다(release.md).
- R3 더 풀기(`POST …/sessions`): 오늘 흐름이 끝나지 않았으면 재개(지금과 같음). 끝났으면 지금 칩으로 새로 계획한 과제
  (지금 규칙 그대로: 새 목표 몫·복습·미평가·습관 보충)에서 흐름에 이미 있는 과제를 뺀 것을 뒤에 붙이고 재개한다.
  붙일 것이 없으면 409 「오늘 더 풀 과제가 없습니다.」 흐름이 없으면 지금처럼 새로 만든다.
- R4 시작 화면: 응답에 `todayDone`(오늘 흐름에서 지나간 자리 수, 없으면 0)을 더한다. 버튼은
  흐름 진행 중 「오늘 학습 재개」 · 흐름 끝남 「더 풀기」 · 흐름 없음 「오늘 학습 시작」. 배지는 재개면 남은 수, 아니면 붙을 수.
  칩을 바꾸면 남은 수를 다시 읽는다.
- R5 그대로 둘 것: 평가·되돌리기·제외·지도 이벤트와 기록, 요약·진척 분모, 「내 중요도」, 학습일 만료, 풀이 화면.

## 책임·입출력 계약·오류 상태

- `planning.plan(…, new_goals=None)`: `new_goals`가 주어지면 새 목표 몫을 그 수(준비된 미학습 목표 수 이하)로 한다.
  기본값은 지금 동작과 같다.
- 더 풀기는 붙인 계획의 `newGoalQuota`를 `state.extraGoals`에 더한다.
- 뒷부분 교체는 `update root_session … where version = 읽은 version`(평가 저장과 같은 낙관적 잠금). 경합이면 409,
  focus 이벤트는 저장하지 않고 화면은 기존 오류 표시로 다시 불러온다.
- 세션 ID는 처음 만들 때의 값 그대로다(내용이 바뀌어도 ID는 식별자일 뿐).
- 응답 계약 추가: overview `todayDone: number`. 기존 필드 의미 불변(`sessionId`는 끝나지 않은 오늘 흐름).

## 호환성과 데이터 보존

- DB 스키마 변경 없음(`tasks`·`state` JSON). 이벤트·기록 삭제 없음.
- 옛 웹(새 필드 모름)은 `todayDone`을 무시한다. 흐름이 끝났을 때 「오늘 학습 시작」을 누르면 R3대로 이어 붙는다.
- 롤백: 코드 `git revert`. 이어 붙인 흐름은 옛 코드에서도 그냥 긴 회차로 읽힌다(focus 키가 있는 흐름은 옛 재개 조건대로).
