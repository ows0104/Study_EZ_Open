## 범위와 성공 기준
- 앞 단계(`runner/root_front.py`): 검사 실패를 같은 세션에 한 번 되돌려주기, 문제은행을 생성기 접수와 같은 검사로,
  포인트 대조·보완·재대조를 지도·문제은행과 동시에.
- 생성기(`quizbank`): 네트워크가 끊은 호출 1회 자동 재실행(앞 단계 포함), 동시 실행 3→6, 추가 회차 커버 확인 동시.
- 공용(`studyez_llm`): 기계 전체 Codex 동시 실행 한도(8), 네트워크 끊김 판별.
- 바꾸지 않는 것: 지시문, 단계 이름·입력·결과 형식, 서버·DB, 검수·수정 상한, 판정 규칙, 콘텐츠 거절·시간 초과 처리.
- 성공 기준: 새 합성 검사 통과, 기존 quizbank·contracts·runner·studyez_llm·quizgen 회귀가 이 변경 전과 같은 결과.
  실제 시간 단축은 러너 재설치 뒤 다음 강의의 `diag`(아래 release) 수치로 확인한다.

## 근거·미정 사항
- 승인: 위 사용자 요청이 구현 승인이다(개발 루프 「사람에게 묻는 것」에 닿지 않음: 운영 DB·공개 범위·자료 전송 경로 불변).
- 정책 변경 한 가지를 사용자 요청에 근거해 넣었다: 「중단/실패 호출은 자동 반복하지 않는다」에 둘째 예외
  transport-retry/1(네트워크가 끊어 답이 오지 않은 호출만, 단계당 한 번). 원하지 않으면 `Stages._call`·`Front._session`만 되돌리면 된다.
- 미정(이번 범위 밖, 수치 근거가 더 필요): 조립·최종 검증 실패를 문항 단위로 좁히기, 검토 묶음 안 순차(검토→고치기→재검토→커버 재확인) 줄이기,
  normalize(6~8분)를 앞 단계 재대조와 겹치기. 동시 6에서 계정 한도에 닿는지는 실제 실행으로만 알 수 있다.
