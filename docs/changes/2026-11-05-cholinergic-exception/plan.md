# 콜린성 예시 핵심 보완 1회 예외 — 구현 계획

## 변경 범위·대상 파일·순서
1. 이전 결과/원본/ledger와 실행 도구 hash를 새 proof에 고정하고 사용자 예외 승인 및 누적 4번째 교정임을 기록한다.
2. 기존 검증·delta 재생·그림 crop·blind review 도구를 재사용하는 별도 실행기를 작성한다. 한 번의 내용 모델 호출로 승인 범위만 변경하고 정확히 재생한다.
3. 새 전체 원본 대조 및 실제 문항 그림을 첨부한 독립 정답 검수, 별도 최종 의미 대조를 수행한다. 원래 20개 및 3방향의 처리 이력을 유지한다.
4. 구조/자료/호출 상한/변경 범위/독립성/재생 일치 검사를 수행한다(artifact). 공용 roots/source 계약 검사를 수행한다(contracts). 실제 갱신 트리를 새 경로에 만들고 전체 문항/그림/좁은 화면/답 숨김을 확인한다(preview).
5. release.md와 검사·리뷰 증거를 기록하고 읽기 전용 예시만 제공한다. 복원은 새 예시를 채택하지 않고 기존 폴더를 참조하는 방식이며 기존 자료를 덮어쓰지 않는다.

현재 사용자 승인은 위 한정 1회 예외 범위의 구현·동일 자료 전송·재검수를 포함한다. 기존 3차 상한의 초기화나 추가 수정 반복, 운영 배포 승인이 아니다.

## 검사 명령과 성공 조건
artifact: 새 실행기의 check로 hash/범위/재생/계약/호출 증거 검증. contracts: tests/contracts 및 tests/quizbank/test_connection_generate.py. preview: 새 트리의 Playwright 검사를 실행한다. 모든 명령은 scripts/development.py verify로 실제 종료 코드와 지문을 기록한다.

## 위험·복원·승인할 범위
추가 교정 후에도 의심·누락이 남을 수 있다. 실제 검수를 보존하며 예시 준비 수를 보수적으로 집계한다. 새 폴더를 사용하므로 원본 되돌리기가 필요 없다. 승인 범위는 위 지정 예외이며 운영 변경은 없다.
