# 자유 노트 플로팅·강의명·로컬 사진 — 배포 준비

## 코드 리뷰·검증 결과
- `server -m tests test_notes` 통과(격리 sqlite): image 블록은 id만 저장, html(data URL 포함) 버림, id 없음·잘못된 id 422.
- `npm --prefix web run build`(tsc 포함) 통과. 첫 `web` 기록(종료 127)은 npm 경로 오타로 실행 자체가 안 된 것.
- 로컬 미리보기(격리 API 8013 + local_test_data sqlite, 운영 DB 미사용)에서 확인:
  - 캘린더·퀴즈 화면 우측 하단 버튼 → 창 열림, 새 노트, 다시 열면 마지막 노트, 새로고침 뒤 내용 유지. `/notes`에서는 버튼 없음.
  - 이전 Main-Quiz(`QuizPage` 알림)·Main-Quiz 주소(주소의 강의에서 읽기) 모두 「＋강의명」 표시.
  - 커서를 글 가운데 두고(클릭·방향키, 바깥 클릭 뒤 포함) 버튼 → 그 자리에 들어감.
  - 창 안에서 친 `1 v z`·방향키가 window keydown에 닿지 않음. 창 밖 키는 그대로 닿음.
  - 사진 붙여넣기 2400×1200 PNG → 1600×800으로 줄어 표시, 서버 행에는 `{"type":"image","html":"","image":"<id>"}`만(노트 전체 215바이트). 끌어놓기도 동작.
  - IndexedDB를 비우면 「이 기기에 없는 사진」 칸.
  - 휴대폰 폭(375): 아래 75% 시트, 가로 넘침 없음, 어두운 화면. 처음엔 `/notes`의 좁은 화면 `min-height:100vh`가 새어 전체를 덮었다 → 고침.
  - 답·평가 줄(`.quiz-bar`·`.pq-dock`)이 있으면 버튼을 104px·창을 164px 위로 올림(요소를 넣어 계산값 확인).
- 확인 못 한 것: 로컬 DB에 문항이 없어 실제 문항 카드가 있는 풀이 화면에서의 겹침은 눈으로 보지 못함. `/` 메뉴 「사진」의 파일 고르기 창은 자동화로 열 수 없어 미확인.
- 계획과 다른 점: `BankStudy.tsx`는 고치지 않았다. 강의명을 알리지 않는 퀴즈 주소는 창이 `/api/lectures/<과목>/<run>`에서 이름을 읽는다(창을 열었을 때만 1회).
- 커서는 selectionchange 외에 keyup·mouseup·input·blur에서도 기억한다(자동화 입력에서 selectionchange가 오지 않아 바깥 클릭 뒤 옛 자리에 들어가던 것을 고침).

## 배포 대상 버전·순서·데이터 변경
- DB 스키마·migration 없음(blocks는 JSON 열). 기존 노트 형식 그대로.
- 자동 배포 순서(API → 웹)를 따른다. 배포 직후 이미 열려 있던 이전 웹 탭은 사진 블록이 든 노트를 저장하면 422(사진 id 없음)로 저장 실패가 뜰 수 있다 — 새로고침하면 해결.
- 사진은 이 브라우저에만 있다. 다른 기기·사이트 데이터 삭제 시 없음. 블록만 지운 사진은 기기에 남는다(노트를 지우면 그 노트의 사진은 이 기기에서 지움).

## 배포 후 확인·롤백·필요한 사람 승인
- master 병합(=운영 자동 배포)은 사용자 승인 필요. 이번 구현 승인 범위 밖.
- 배포 후: 운영 웹에서 버튼·창·강의명·사진 붙여넣기, 네트워크 PUT 본문에 사진 바이트 없음 확인.
- 롤백: PR revert(웹·API 함께). 이미 사진 블록이 저장된 노트는 이전 서버에서 저장 시 422가 된다 — 읽기는 된다.
