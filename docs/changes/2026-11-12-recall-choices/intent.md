# Main-Quiz 단답·나열 선지 보기

## 문제와 사용자 효과
이번 블록(감염과 면역) Main-Quiz는 대부분 선지 없이 답을 떠올려야 하는 문항이다.
답이 떠오르지 않으면 바로 「답 보기」로 넘어가는 길뿐이고, 선지를 보고 골라 보는 중간 단계가 없다.

2026-11-12, 이 PC에 생성 결과가 있는 4강의(261102_02·261104_03·261110_03·261111_02) 실측:

| 형식 | 문항 | 비율 |
|---|---|---|
| 단답(basic) | 285 | 44.5% |
| 나열(list) | 158 | 24.6% |
| 빈칸(cloze) | 177 | 27.6% |
| OX | 14 | 2.2% |
| 객관식(mcq) | 7 | 1.1% |
| 합계 | 641 | |

- 선지가 있는 문항은 7개, 그중 선지를 숨겼다가 펴는 「기억 확인형」은 2개다.
- 단답·나열 443문항(69.1%)은 `options`가 모두 비어 있다.
- 운영 DB의 게시본과는 대조하지 않았다. 야간 일괄 출제가 도는 중이라 강의 수는 늘어난다.

원하는 효과: 단답·나열 문항에서 먼저 스스로 떠올려 보고, 안 되면 선지를 펴서 골라 본 뒤 답을 확인한다.

## 범위와 성공 기준
- 대상: Main-Quiz 풀이(`RootSolve`)의 단답·나열 문항.
- 선지는 처음에는 보이지 않는다. 사용자가 원할 때만 편다.
- 문항의 질문·정답·형식·판(revision)·학습 기록은 바꾸지 않는다. 선지는 판에 덧붙는 별도 자료다.
- 선지가 없는 문항은 지금과 똑같이 동작한다.
- 이미 공개된 판에도 판을 교체하지 않고 선지를 덧붙일 수 있다.

범위 밖:
- 빈칸·OX·객관식 문항, 옛 Quiz Bank 풀이(`BankSolve`), Pre-Quiz·강의 퀴즈.
- 단답을 객관식으로 바꾸는 형식 변환. 커버 판정·회상 단위가 `answer_units`에 묶여 있어 건드리지 않는다.
- 힌트. Main-Quiz에는 힌트가 없고, 이번 요청에도 없다.
- v4 출제 지시문(`content/prompts/learning-links/v4/`) 수정. 진행 중인 goal-dedupe 작업과 겹친다.

## 근거·미정 사항
사용자 발언(2026-11-12 채팅):
- 「우리 주관식에서 스페이스바 누르면 보기나 힌트 나오는건 없어졌나?」
- 「이번 블록 Main-Quiz를 말하는거야. 단답이나 나열에서도 선지를 주면 좋긴하겠다.」
- 「설계안 써줘」

위 발언은 설계 요청이다. 구현 승인으로 쓰지 않는다. 「좋긴하겠다」는 바람이지 지시가 아니다.

구현 전에 사용자가 정할 것(추천은 spec의 기본값):

| # | 정할 것 | 추천 | 다른 길 |
|---|---|---|---|
| D1 | 스페이스바 | 지금처럼 「답 보기」. 선지는 별도 키 `C`와 버튼 | 선지가 있는 문항은 첫 번째 스페이스바가 선지, 두 번째가 답 |
| D2 | 선지를 보고 맞힌 풀이의 평가 | 지금처럼 네 버튼 자기평가에 맡기고 「선지 봄」만 기록 | Good·Easy를 못 누르게 막기 |
| D3 | 이미 공개된 이번 블록 판 | 선지를 덧붙이는 보강 실행(모델 호출, 따로 승인) | 새로 출제하는 강의부터만 |
| D4 | 대상 문항 | 단답·나열 전부 시도하고 좋은 오답이 없으면 건너뜀 | 중요도 높은 문항만 |

D1을 추천대로 둔 이유: 선지가 붙는 문항이 약 70%라서, 첫 스페이스바가 선지면 대부분의 문항에서 한 번씩 더 눌러야 하고
매번 선지를 보게 되어 스스로 떠올리는 연습이 줄어든다. 사용자가 처음 기대한 동작은 「다른 길」 쪽이다.
