# Main-Quiz 생성 검수·수정 묶음 병렬화 — 설계

## 요구사항과 수용 기준
R1 묶음 모드. 새 ledger는 `batchMode: "parallel/1"`을 갖는다. 표시가 없는 기존 ledger는 순차(지금과 같은 코드 경로·입력).

R2 묶음 실행. 4단계(문항 검수·수정)를 시작할 때 상태(문제은행·충돌·그림·커버리지 행·판정 기록·/4 중요도 근거)를
사본으로 떠서 묶음마다 준다. 각 묶음은 지금과 같은 순서(검수 → 수정 → 재검수 → 되돌리기 → 커버리지 재확인, 최대 FIX_LIMIT)를
자기 사본에서 돈다. 동시 실행은 `BATCH_WORKERS = 3`.
- 묶음 b의 단계 입력은 시작 사본과 b 자신의 진행에만 의존한다. 완료 순서가 달라도 입력 지문이 같다.

R3 합치기(묶음 순서). 문항·그림·중요도 근거는 묶음 문항 것으로, 새 원본 충돌은 묶음 순서대로 덧붙이고,
임상 사실은 시작 사본 기준으로 바뀐 것만 반영한다. 커버리지 재확인 결과는 묶음 순서대로 `_merge_row`로 다시 적용한다.
판정 기록(verdictLedger)·fixes·restated·ledger의 단계 순서도 묶음 순서로 놓는다.

R4 결합 시 순차. 시작 시점에 (a) 둘 이상의 묶음 문항이 인용하는 충돌, 또는 (b) 묶음을 넘는 선행 연결이 있으면
그 실행의 4단계는 순차로 돌고 `ledger.batchPhases`에 이유를 남긴다.

R5 충돌 범위. 병렬 묶음의 수정 입력에 `conflict_scope = {new_conflict_id_prefix, own_conflict_ids}`를 준다.
새 충돌 ID는 접두어(`CF-B<b>-`)로 시작해야 하고, 다시 쓸 수 있는 기존 임상 사실은 own_conflict_ids(시작 시점에
그 묶음 문항이 인용한 충돌)뿐이다. 어기면 그 단계의 수용 검사가 거절하고 같은 세션에 오류를 돌려준다(기존 P6 경로).
수정 지시문(v3/v4 fix.md)에 이 한 문단을 더한다.

R6 묶음을 넘는 중복 그룹. 묶음 b의 커버리지 재확인이 다른 묶음 문항(중복 짝)을 함께 판정했고 그 문항이 그 묶음에서
바뀌어 유지됐다면, 합친 뒤 그 목표들만 `<X>coverage-merge-0` 한 번으로 다시 판정한다.

R7 동시 실행 안전. ledger 변경·저장은 잠금 안에서 한다. 묶음마다 `out/.batches/<b>/material`(공용 material 복사)을
쓰고, 합칠 때 그 파일들을 공용 material에 더한다(그림 파일은 내용 지문 이름). 그림 렌더(PyMuPDF)와 검수용 그림
사본 쓰기는 모듈 잠금으로 한 번에 하나만.

R8 그 밖의 동시 실행(병렬 모드만). 첫 커버리지 조각들과 `map-check-0`을 함께 돌린다. 의학 검토의 40문항 묶음을
동시에 묻고, 결과·요약·사용량은 묶음 순서로 모은다(누락 문항 1회 재질문 규칙 그대로).

R9 실패. 한 묶음이 실패해도 다른 묶음은 끝까지 돌고(이어 만들기에 쓰도록) 첫 실패(묶음 순서)를 올린다.
실패 단계 표시·--resume 규칙은 그대로.

수용 기준(합성 모델):
- 결합 없는 은행에서 병렬 결과의 문서·커버리지·판정·fixes가 순차 결과와 같다.
- 완료 순서를 바꿔도 결과와 ledger 단계 순서가 같다.
- 한 묶음 실패 뒤 이어 만들면 완료 단계는 모델을 다시 부르지 않는다.
- 결합이 있으면 순차로 돌고 이유가 남는다.
- 접두어 밖 새 충돌 ID·남의 충돌 사실 재작성은 거절된다.
- 표시 없는 기존 ledger는 순차로 돈다.

## 책임·입출력 계약·오류 상태
- `quizbank/connection_generate_v3.py`: Stages 잠금·material 인자·단계 순서 정리, 병렬 실행 도구, 의학 묶음 동시 실행, v3 4단계.
- `quizbank/connection_generate_v4.py`: v4 4단계·첫 커버리지 동시 실행.
- `quizbank/connection_visuals.py`: 렌더·사본 쓰기 잠금.
- `studyez_contracts/roots/generation_v3.py`: `check_conflict_scope`(R5), check_fixed에서 ctx에 범위가 있을 때만 적용.
- 지시문: `content/prompts/learning-links/v3/fix.md`, `v4/fix.md`에 R5 문단.
- 오류: 기존과 같다. 수용 검사 실패는 같은 세션에 돌려주고, 단계 실패는 ledger에 failed로 남는다.

## 호환성과 데이터 보존
- 결과 형식·서버 계약·DB 변경 없음. manifest에 `batchPhases`(모드·이유)만 더한다(선택 항목).
- 기존 ledger는 순차. 지시문 해시가 바뀌므로 기존 /3·/4 실행을 새 코드로 이어 만들 때는 기존 규칙대로
  `--resume <이유>`가 한 번 필요하다(완료 단계는 입력 지문이 같으면 재사용).
- 수정 상한·판정 기록·되돌리기·원본 보존 규칙 불변. 묶음 사이 정보 차이(다른 묶음의 수정 결과를 보지 않음)는
  R4 결합 검사로 막는다.
