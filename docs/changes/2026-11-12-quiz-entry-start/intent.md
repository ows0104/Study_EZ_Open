# Main-Quiz 정리 화면 먼저·재개 카드 수·뒤로

## 문제와 사용자 효과
사용자(2026-11-12, 화면 두 장 첨부): 「특정 상황에서 문제 풀기 버튼을 누르면 문제 개수가 안 나와. 왜 그런지 이유를 찾고 해결해줘.
그리고 강의별 풀기에서 복습 퀴즈 버튼을 누르면 자꾸 이 정리 페이지가 잠깐만 보이고 알아서 퀴즈로 바로 넘어가는데,
그러지 말고 항상 이 페이지에 먼저 오도록 설정해줘.」
이어서(같은 날): 「이 정리 페이지에서도 뒤로가기 버튼을 만들어서, 강의 목록에서 왔으면 강의 목록으로,
캘린더에서 왔으면 캘린더로 돌아갈 수 있게 만들어줘.」

원인:
- 개수 없음: 진행 중 회차가 있으면 버튼이 「오늘 학습 재개」가 되고, `RootToday`가 `!info.sessionId`일 때만 배지를 그렸다.
  재개할 회차의 남은 수는 overview에 없어서 숨겼던 것.
- 바로 넘어감: 강의 목록 ▶가 `?start=1`로 열어 첫 불러오기 뒤 `begin()`을 자동 호출했고(정리 화면이 잠깐 보임),
  진행 중 회차는 첫 불러오기에서 바로 문제 화면을 그렸다(2026-11-08 main-quiz-entry-ui 결정).

## 범위와 성공 기준
- 어디서 들어와도(강의 목록 ▶·캘린더·새로고침) 정리 화면이 먼저. 회차 시작·재개는 버튼으로만.
- 「오늘 학습 재개」에도 배지: 진행 중 회차의 남은 문항 수(count − position).
- 정리 화면 왼쪽 위 「뒤로」: 같은 탭 기록이 있으면 들어온 화면으로, 없으면 캘린더(`/`). PreQuiz의 뒤로와 같은 규칙.
- 웹만. 서버·DB·API 변경 없음.

## 근거·미정 사항
- 새로고침도 정리 화면으로 온다(사용자 「항상」). 풀이 중 새로고침 뒤에는 「오늘 학습 재개」 한 번을 더 누른다.
- 저장 재시도(「같은 요청 다시 저장」) 뒤에는 기존처럼 풀던 회차를 다시 그린다(풀이 화면 복구 동작).
