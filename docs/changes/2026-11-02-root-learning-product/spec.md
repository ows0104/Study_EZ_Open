2026-11-02 후속: 사용자의 구체적인 자료 전송 승인 후 [단회 읽기 전용 대조](content-comparison-review.md)를 완료했다. 원본 35쪽과 로컬 69문항에 근거한 목표 후보 15개·방향·문항 충족 범위와 첫 8문항 경로를 확보했다. 후보 표의 각 행을 확정 목표 1개로 저장하거나 8문항 경로를 뿌리 전체로 취급하지 않는다. 부분 회상을 중간 평가에 포함할 때 ‘도움 받아 떠올림’이라는 문구만으로 충분한지는 학습 흐름 검토안에서 결정 대기로 남겼다. 합의된 Spec 채택·의학 검수 통과·Build 승인은 여전히 별도다.

## 1. 첫 제품에서 완성할 경험

1. 학습 현황에서 강의별 뿌리의 미학습·보완 필요·회상 가능과 중요한 미학습을 본다.
2. 오늘 추천을 눌러 준비된 뿌리부터 시작한다. 지도 방문은 선택이다.
3. 머릿속으로 답/이유를 떠올리고 정답을 확인한 뒤 평가하면 다음 질문으로 바로 이동한다.
4. 지도는 현재 위치와 직전 변화만 짧게 보여준다. 지도를 탐색해도 풀이 위치는 유지된다.
5. 오늘 새로 접한 목표와 회상 변화, 남은 중요한 목표를 보고 종료한다. 다시 열면 저장된 위치에서 이어간다.

첫 막대는 명확히 **뿌리 학습 범위**로 표시한다. 전체 세부 범위를 준비하지 않은 상태에서 강의 전체 또는 시험 범위의 학습 완료를 선언하지 않는다. 기존 문제풀이로 이동하는 경로를 유지한다.

## 2. 실제 결과를 제품의 학습 단위로 만드는 방법

2026-11-02 연결 중심 학습 합의는 [전체 Spec S7/S8](../2026-10-27-learner-journey/spec.md#s8-콘텐츠-준비검증학습-연결)을 따른다. 목표 선정 시 구조적 역할과 강의 이해·시험·임상 중요성의 근거를 구분하며 기출이 없더라도 필요한 뼈대 과제를 포함한다. 실제 시험한 관계와 발문이 제공한 관계를 따로 대조한다. 중요도 저장 필드·추천 가중치·기존 Tier 대응은 아직 미정이다. 첫 제품의 뿌리 범위 표시는 유지하고, 세부의 첫 학습은 전체 제품의 요구로 남기며 이 첫 버전만으로 충족했다고 하지 않는다.

수신한 트리의 작용 표적 / 작용 방식 / 장기 반응 / 임상 활용 / 과도한 활성화는 탐색 묶음 후보다. 이를 목표 5개나 고정 선행순서로 저장하지 않는다.

| 단위 | 제안 계약 |
|---|---|
| 탐색 묶음 | 제목·순서·하위 묶음·목표 참조. 자체 진행률 분모는 아님 |
| 목표 | 한 번의 평가로 확인할 수 있는 사실 또는 관계, 답의 범위, 출처, 중요도 근거 |
| 방향 | 주어진 단서·회상할 답/이유·필수 여부. 역방향은 근거가 있을 때만 추가 |
| 과제 | 목표/방향을 실제로 시험하는 질문. 기존 문항 또는 별도 검토된 뿌리 과제 |
| 연결 | 묶음 소속·비교·설명 관계·명시적 선행을 구별. 화면 선을 곧 선수조건으로 쓰지 않음 |

같은 약물이나 이름이 반복된다고 목표를 합치지 않는다. 동일 사실/관계/답 범위면 하나의 목표를 여러 위치에서 참조하고, 묻는 관계가 다르면 별도 목표로 검토한다. 복합 문항은 실제 확인한 방향만 평가한다. 과제의 일부만 맞힌 것을 모든 연결 목표의 성공으로 기록하지 않는다. 첫 버전은 단일 평가로 판정 가능한 과제만 사용하고 복합 묶음의 일괄 성공 처리는 금지하는 안을 권고한다.

콘텐츠 준비는 원본 → 독립 트리·포인트 → 원본과 상호 대조 → 기존 69문항의 실제 질문·답·이유 대조 → 뿌리 과제 묶음 확정 순서다. 대응 ID가 있다는 것만으로 충족으로 보지 않는다. 충분한 기존 문항을 우선 사용하되 빠진 관계는 '과제 준비 전'으로 남긴다. 별도 과제 작성·의학 판정은 허용된 CLI 경로를 따르고 기존 은행 수정 상한을 우회하지 않는다.

대조 산출물은 원본 판/쪽, 목표, 방향, 트리 위치, 문항 판/ID, 실제 시험 범위, 충족/부분/미충족/불명확, 검토 근거를 담는 안이다. 이번 Spec은 이 표의 의학 내용을 채운 결과가 아니다.

## 3. 학습·평가·진행률

추천 버튼: **못 떠올림 / 도움 받아 떠올림 / 스스로 떠올림**. 정답 확인은 '떠올려본 뒤 정답 확인'으로 시도를 포함한다는 설명을 제공한다. 실제 시도 없이 답을 본 경우에는 '답만 보기'로 분리해 첫 학습에 넣지 않는 안이다.

- 시도+정답 확인이 서버에 저장되면 첫 학습을 기록한다. 평가를 아직 하지 않았어도 첫 학습 사실은 남고 회상은 미평가다.
- 평가 전·보류·저장 실패를 실패나 성공으로 치환하지 않는다.
- 선지/지도/해설에서 도움을 받았다면 중간 평가를 안내한다. 자동으로 사용자의 사고 과정을 추정하지 않는다. 도움 표시와 자기평가의 충돌은 높은 등급으로 조용히 통과시키지 않는다.
- 목표의 회상 가능은 준비된 모든 필수 방향의 유효 평가가 도움 없는 회상을 나타낼 때다. 새 방향·내용 변경으로 기준이 달라지면 망각과 별도 사유를 표시한다.
- 묶음의 진행률은 하위의 고유 목표 ID 합집합이다. 선택 확장 과제·반복 횟수·중복 위치는 분모를 늘리지 않는다.
- 시간 경과의 회상 판정은 아래 정책 후보의 선택 후 확정한다. 현재 엔진의 점수·FSRS 유사 곡선을 그대로 승계하지 않는다.

지도에서 답이 되는 노드명은 풀이 중 중립적 위치명으로 표시하고 답 내용을 펼치는 행동은 도움 열람으로 구분하는 안을 권고한다. 자기평가 후 다음 질문은 즉시 표시하되 저장 중 변화는 임시 표시한다. 서버 확인 전 전체 막대·오늘 완료를 확정하지 않는다.

## 4. 추천: 합의를 실행 가능한 규칙으로 좁히는 안

합의: 시간 입력 없음, 새 진도 보호, 필요하면 평소보다 분량 증가, 매일 재계획, 시험 2일 전 첫 학습 목표. 아래 계산은 채택 전 제안이다.

추천 단위는 고유 목표와 방향별 과제이며, 첫 학습 목표 수와 실제 과제 수를 함께 표시한다. 과제가 여러 개 필요한 목표의 부담을 목표 하나로 숨기지 않는다.

- D>0: 준비된 미접촉 목표 U에 대해 ceil(U/D)를 새 목표의 최소 기준으로 삼는다. D는 KST 달력 기준 오늘부터 시험 2일 전까지 포함하며 주말도 센다.
- 앞으로 올 강의의 양을 아는 경우 남은 목표 추정량을 함께 나누되 지금 준비된 U를 넘겨 배정하지 않는다. 초기에는 같은 블록에서 준비된 강의들의 목표 수 중앙값을 사용하고 표본·추정임을 표시한다. 표본이 없으면 추정치를 만들지 않고 준비 범위 기준이라는 한계를 표시한다.
- 급한 복습은 예정일 도래 또는 실패/도움 상태인 필수 방향에서 선정한다. 새 목표 할당과 함께 기본 분량에 포함하고 같은 과제는 중복 배정하지 않는다. 중요도·시험 임박·오래 대기한 순으로 정렬한다.
- 최근 학습량 H는 최근 7개 학습일의 서버 확인된 서로 다른 과제 수 중앙값을 참고하는 안이다. 미접속·자료 대기·오류 날은 0 능력으로 처리하지 않는다. H가 없으면 새 진도+급한 복습만으로 시작한다. H를 상한으로 쓰지 않는다.
- 기본 배정 후 H의 여유가 있을 때만 필요한 일반 보완을 추가한다. 필요 없는 항목으로 수를 채우지 않는다.
- 시험 전날·당일 또는 목표일 경과 후에는 U/D를 사용하지 않는다. 준비된 중요한 미학습과 급한 복습을 먼저, 나머지 미학습을 뒤에 배정하고 실제 남은 수를 표시한다. 전체 첫 학습 달성을 보장한다고 말하지 않는다.
- 시작할 때 오늘의 유한한 과제 목록을 고정한다. 같은 날 실패로 목록을 무한히 늘리지 않는다. 새 자료는 다음 세션 재계획에서 반영하고 진행 중 강제 삽입하지 않는다. 중요한 새 자료는 추가됨을 알린다.

**복습 정책 추천안:** 첫 구현은 방향별 명시적 간격표를 별도 정책 판으로 관리한다. 도움 없는 회상은 다음 날 → 3일 → 7일 → 14일, 실패/도움은 다음 날 재확인, 같은 날 반복 성공은 단계 증가 없음. 예정일이 지나면 마지막 성공은 보존하면서 현재 확인 필요로 표시한다. 이는 검증된 기억 확률이 아닌 보수적 제품 규칙이며, 수치·단계·회상 막대 반영은 사용자 선택이 필요한 주요 결정이다. FSRS는 별도 후속 비교 대상으로 둔다.

하루 집계는 기존 앱과 맞춘 KST 09시를 권고한다. 시험일 D 계산은 달력 날짜, 오늘 활동 집계는 09시 경계라는 차이를 명시한다. 분량 변화는 자료 유입·기준 변경·실제 평가로 나눠 설명한다.

## 5. 콘텐츠·학습 기록의 저장 계약 제안

은행과 별개로 불변 `RootContentRevision`을 저장한다. 강의 키, 원본 지문, 트리/목표/방향/과제, 문항 연결 지문, 검토 상태, 공개 여부를 가진다. 초안·검토 중·준비 완료·공개를 구별하고 수신만으로 준비 완료 처리하지 않는다.

사용자별 `RootLearningEvent`에 event_id, 사용자, 강의, 콘텐츠 판, 목표/방향/과제 판, 사건 종류, 평가, 도움, 서버 시각, 취소 대상 ID를 보존한다. `RootSession`에는 추천 판·순서·현재 과제·확인/평가 단계·서버 revision을 저장한다. 별도 상태 집계는 이벤트로 재계산 가능하게 한다. 식별자만 같다고 판 사이의 학습을 복사하지 않는다.

내용/질문/답/필수 방향이 같고 배치만 바뀐 판은 검토된 동일성 연결표로 이어간다. 내용 변경·개인 수정·연결 불명확은 옛 기록을 보존하고 영향받은 방향만 재확인한다. 다른 강의·목표를 일괄 초기화하지 않는다.

기존 개인 수정/제외는 실제 과제 선택 전에 적용한다. 수정으로 원래 목표 충족이 불명확하면 그 문항의 연결을 미검증으로 두고 다른 준비된 과제를 선택한다. 모든 과제가 제외된 목표는 준비 문제를 표시하고 분모에서 지워 완료율을 올리지 않는다. 새 학습을 기존 BankState에 이중 기록하지 않는다.

## 6. API·저장 실패·권한 제안

서버가 집계·추천·검증·저장의 정본이다. 웹은 표시·탐색·미확인 요청 보관을 맡는다. 신규 `/api/root-learning` 경로로 기존 bank 경로와 분리하는 안이다.

| 요청 | 책임 |
|---|---|
| GET overview, lecture map | 허용된 공개 콘텐츠와 본인 목표별 상태, 준비 불확실성 |
| POST sessions / GET session | 오늘 추천 고정 또는 재개, 콘텐츠/정책 판과 서버 revision |
| POST session/events | 시도+답 확인·평가·보류, event_id로 중복 방지, 기대 revision 검사 |
| POST session/undo | 직전 자기평가 취소 사건 추가, 시도+확인 사실은 유지. 잘못 기록한 첫 학습의 정정은 별도 명시 동작 |
| 관리자 콘텐츠 등록/검토/공개 | draft 보관과 검토된 판 활성화 분리. 기존 bank-response를 사용하지 않음 |

문제 응답에는 정답·해설·답을 노출하는 지도 문자열을 싣지 않는다. 답 확인 요청 뒤에만 답을 반환한다. GET·지도 탐색은 학습 사건을 만들지 않는다.

중복 event_id+동일 본문은 같은 결과를 반환하고 다른 본문이면 충돌을 반환한다. 평가와 상태 revision 갱신은 한 트랜잭션으로 처리한다. 다른 탭의 오래된 revision은 409로 재동기화하며 덮어쓰지 않는다. 네트워크 실패 요청은 동일 ID로 재전달하고 서버 접수 여부를 확인한다.

미확인 요청은 사용자별 로컬 보관함에 두고 서버 확인까지 유지한다. 계정 전환 시 다른 계정으로 재전송하지 않는다. 로컬 보관 불가·저장 실패가 감지되면 추가 평가 누적을 멈추고 현재 과제와 재시도를 유지한다. 완료 화면은 미확인 저장이 없어야 확정한다. 인증·학생 공개·관리자 권한은 기존 경계를 계승한다.

## 7. 이미지와 첫 범위의 관계

이미지 자체로 푸는 과제와 해설 근거 이미지를 계약에서 구별할 수 있게 하되 실제 crop·가림·새 이미지 출제는 첫 Build의 기본 범위에 넣지 않는다. 첫 뿌리에 시각 과제가 필수라면 텍스트로 충족 처리하지 않고 해당 방향을 준비 전으로 표시한다. 그 상태에서는 전체 필수 방향 준비/회상 완료가 될 수 없다. 이미지 기능을 포함하려면 실제 사례의 영역·단서·파일·검수 계약을 확정하고 계획 범위를 명시적으로 갱신한다.

## 8. 수용 조건과 확정할 주요 결정

학습 시도+정답 확인 후 실패해도 첫 학습은 유지, 중복 문항/방향은 목표 범위를 중복 집계하지 않음, 필수 방향 미준비는 회상 완료 불가, 저장 재시도는 한 번만 반영, 취소와 재개는 재현 가능, 기존 은행/개인/제외/학습 이력은 보존되어야 한다. 학습하지 않은 목표를 자료 검증 완료만으로 학습 완료로 바꾸지 않는다.

사용자 검토를 받을 큰 결정은 세 묶음이다: (1) 첫 뿌리 경험과 별도 기록 구조, (2) 세 단계 자기평가·답만 보기·도움 처리, (3) 추천·복습·하루 경계 정책. 실제 목표와 필수 방향은 콘텐츠 대조로 확정한다. 세부 표현의 취향을 전부 인터뷰하지 않고 승인된 방향 안에서 구현 검토한다.

## 2026-11-03 구현 계약 v2 (기존 제안보다 우선)
