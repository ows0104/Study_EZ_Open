# 연결 중심 학습과 구조·시험·임상 중요도 구분

## 문제와 사용자 효과
중요한 사실을 나열한 문제은행을 넘어, 중요한 개념 사이의 연결을 형성하고 실제로 회상하는 학습을 만든다. A→B→C에서 발문이 A→B를 제공하고 C만 물으면 A→B를 안다는 증거가 되지 않는다. 먼저 필요한 연결의 존재를 익히고, 구체적 내용·이유·조건·예외와 잘못된 연결의 구별로 나아간다.

## 범위와 성공 기준
개념도와 연결된 문제로 강의의 뼈대·가지·세부를 구성하고, 강의 자료·필기·족보로 중요도의 근거를 평가한다. 강의 이해에 필요한 뼈대 질문은 기출이 없어도 포함하고, 범위 안 세부도 최소 한 번 학습할 기회를 제공한다. 구조적 역할, 시험 중요성, 임상 중요성을 구분해 순서·반복에 반영한다.

이번 작업은 제품 Intent·합의 Spec·결정 대기·첫 제품 계획의 문서 반영이다. 기존 첫 제품 작업을 대체하지 않으며 운영 프롬프트·문항·코드·DB·학습 기록은 변경하지 않는다.

2026-11-02 후속 요청 “오케이. 그럼 plan 단계로 넘어가볼까?”에 따라 문서 반영에서 Implementation Plan 구체화로 진행한다. 첫 구현 제안은 연결·문항·중요성 근거를 검토할 로컬 콘텐츠 묶음이며, 지도·학습·추천 구현은 기존 root-learning-product 계획과 연결한다. 이번 요청은 계획 작성이며 Build·실제 자료의 추가 모델 실행·운영 반영 승인은 아니다.

후속 Build 승인: “오케이. 그럼 1단계 연결 검토 묶음부터 계획대로 구현해줘. 지금 근데 개념도, 출제포인트 등은 싹 갈아엎어야될 것 같긴해.” A의 로컬 구현을 승인한 발언이다. 기존 트리·포인트의 내용이나 수를 고정하지 않고 새로운 원본 기반 결과를 별도 판으로 받을 수 있게 한다. 실제 콘텐츠 재작성은 이번 도구 구현에 포함하지 않으며 이전 원문·판·기록을 삭제하지 않는다.

## 근거·미정 사항
2026-11-02 KST 현재 채팅: 사용자는 연결 중심 출제와 독립 포인트 대조의 정리에 “어. 좋아. 이걸 반영해줄래?”라고 답하고, “개념도, 연결된 문제를 만들어두고, 족보나 강의 자료를 통해 중요도를 평가”, “꼭 시험에 나오지는 않더라도 이 강의를 이해하기 위한 뼈대 느낌의 질문”, “잎사귀도 한번씩은 훑을 수 있게”를 요청했다.

원칙 반영은 승인된 문서 범위다. 중요도 점수·가중치·추천 공식·저장 필드와 실제 콘텐츠 채택은 아직 정하지 않았다. 기출 없음은 올해 출제되지 않는다는 뜻이 아니며, 임상 중요성에는 구체적 판단·행동과 근거가 필요하다.
