## 배포 대상·데이터 변경
이번에는 운영 배포하지 않는다. 운영 DB·서버·러너·문항·자료·학습 기록·공개 상태는 변경하지 않았다. 이번 수정 파일만 향후 웹 배포 범위다. 현재 web/dist는 다른 작업의 미커밋 변경이 함께 있는 전체 워크스페이스의 검증 산출물이며, 이 작업만의 고정 운영 후보로 제시하지 않는다. 다른 작업의 변경은 되돌리거나 커밋하지 않았다.

## 운영 반영 시 확인·복원·승인
운영 배포가 요청되면 이번 변경과 승인된 기존 변경만 포함하는 소스를 분리하고 고정 웹 후보·contracts 검사·현재 운영 복원 버전을 준비한다. 해당 후보의 중요 승인을 확인한 뒤 기존 웹 배포 절차를 따른다. 운영에서 실제 시간표의 기본 블록, 준비 전 강의, 수동 선택 유지와 복귀 갱신을 읽기 전용으로 확인한다. 로컬 복원은 이번 파일/부분 변경만 대상으로 한다.

## 앞선 조사 보존
사용자의 첫 질문 때는 읽기 전용 조사만 했다. 기존 선택식은 이전 준비 블록 ready=true, 새 블록 date=2026-11-02/ready=false일 때 11월 1일과 2일 모두 이전 블록을 골랐다. 새 블록 ready=true일 때만 11월 2일 새 블록이었다. 당시 운영 HTML 직접 조회는 실패했고, 구현 승인 gate도 ready=false였다. 이후 현재 사용자의 명시적 수정 요청과 주간 기준 확인을 받아 이 작업의 intent/spec/plan과 구현 승인을 갱신했다.
