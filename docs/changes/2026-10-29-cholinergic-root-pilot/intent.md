# 콜린성 약리학(1) 뿌리 시범 검토

## 문제와 사용자 효과

사용자는 첫 시범 강의로 “콜린성 약리학으로 해보자.”라고 선택했다(2026-10-29 KST, 이 채팅).
강의별 뿌리를 원본에서 선정하고 출제 포인트·기존 문제를 대조해, 큰 흐름을 보며 공부할 수 있는지 검토한다.
[사이트 의도](../2026-10-27-site-intent/intent.md)와 [학습자 여정](../2026-10-27-learner-journey/spec.md)을 따른다.

## 범위와 성공 기준

- 첫 자료 확인 대상은 콜린성 약리학(1)(이철환), `261002_01`로 제안한다. (2) `261002_02`는 별도 강의이며 통합하지 않는다.
- 현재 수행 범위는 로컬 파일 탐색·원본/기존 기록 식별과 시범 계획 작성이다. 자료 확인 결과는 [sources.md](sources.md)에 기록한다.
- 다음 실행 후보는 원본 기반 뿌리·관련 출제 포인트의 검토 초안과 기존 문제 대조, 제안 학습 순서다. 기존 문제의 재출제·수정·배포를 포함하지 않는다.
- 사용자는 실제 자료 처리와 구현을 구체 계획 승인 후 진행하도록 했다. 강의 선택을 모든 생성·구현·게시 승인으로 확대하지 않는다.
- 성공은 원본 근거, 독립 추출/기존 문항 색인의 구별, 뿌리별 문제 연결·부족한 지점과 학습 순서를 사용자가 검토할 수 있는 것이다. 기존 기록의 검사 횟수·판정을 변경하지 않는다.

## 근거·미정 사항

- 최초 요청: 필기·족보에서 문제·출제 포인트·개념트리를 만들고 누락과 적절성을 검증하며, 트리로 학습 순서를 구성한다.
- 확인한 로컬 참조 은행은 69문항이다. 기존 출제 포인트는 `web-question-index`, `independent: false`로 표시돼 새 원본 독립 추출의 정본으로 사용할 수 없다.
- 족보 조각은 (1)·(2) 합본이므로 (1)의 필기 근거로 범위를 구별하고 불명확한 항목은 보류한다.
- 뿌리·첫 질문·대조 판정은 아직 원본 전체 검토로 확정하지 않았다. 앞선 화면의 예시는 의학 내용 검증 결과가 아니다.
- 새 앱 구현·DB 변경·운영 조회·로그인·채점·업로드·배포는 현재 범위 밖이다.
- 기존 문항·ID·원본·개인 수정·제외 상태·학습 기록·검수 판정·수정 잔여 횟수는 보존한다.

## 실행 경로 비교 요청

사용자는 앞선 계획에 “오케이.”라고 답한 뒤 웹/CLI의 장단점·토큰·전체 PDF 읽기·코드 연계를 먼저
분석해 기능별 역할을 정하도록 작업 순서를 바꿨다. 추가 확인에서 웹은 일반 ChatGPT 대화라고 답했다.
현재 턴은 이 비교 분석을 우선하며 시범 저작을 실행하지 않는다. 결과와 미확인 사항은
[실행 경로 검토](execution-strategy.md)에 기록한다. 동일한 기존 시범 범위의 동의를 다시 요청하지 않고,
실제 역할 배치가 바뀔 때 범위·계획에 미치는 영향을 구분해 반영한다.

사용자 후속 설명: “그니까 웹은 토큰 소모가 없어. 그리고 PDF 전체를 읽을 수 있는거 같아.
대신 불안정하고 출력 제한이 있는거 같아.” 사용자의 현재 웹 이용 조건을 운영 전제로 반영한다.
원본 기반 문제·포인트·트리 작성은 웹을 우선하고 코드/CLI에서 회수·참조 검사·필수 의미 대조를
담당하는 수정 권고안을 작성한다. 구체 배치는 아직 검토안이며 자동 웹 접속·자료 전송·시범 추출은 실행하지 않는다.

## 2026-10-31 다음 단계

사용자는 bridge 파일 진단 설명 뒤 “오케이. 이제 슬슬 다음 단계로 넘어가자.”라고 요청했다.
[next-step.md](next-step.md)에 뿌리 파일 한 건을 먼저 회수하는 절차와 두 독립 웹 대화용 입력 안내를 작성했다.
현행 bridge에 뿌리/포인트 종류별 수신 계약이 없으므로 첫 시범은 사용자 수동 파일 전달로 진행한다.
수동 회수 확인을 bridge 자동 회수의 검증으로 표시하지 않으며, 최신 패키지/설치 버전과 자동 회수의
실제 동작 확인은 별도 미완료로 유지한다. 이 요청을 앱 구현·패키징·운영 게시 승인으로 확대하지 않는다.
