# Bridge 파일 수신 동작 점검 — 설계

## 요구사항과 수용 기준
파일 수집기의 직접 링크·다운로드 버튼·파일 선택 경로와 강의/버전/문항/내용 지문 검사를 조사한다. 기존 모의 브라우저 검사, 격리 서버 검사, 러너의 원문 보존 검사를 실행한다. 실제 저장된 response-file.json과 raw.md의 바이트 지문을 대조해 과거 수신 근거를 구분한다.

## 책임·입출력 계약·오류 상태
bridge/bank-file.js와 bank-download.js 및 chatgpt-share.js → background.js → web/src/bank/bankBridge.ts → 서버 bank-response → runner/bank_flow가 대상이다. 직접 파일 선택도 자동 수집과 같은 원문 검사를 사용한다. 파일 검사는 전달 구조를 확인하며 원본 대비 의학적 누락/정답성은 증명하지 않는다. 자동 회수 실패·파일 생성 불완전·저장 미확인을 구분한다.

## 호환성과 데이터 보존
운영 인증정보와 server/.env를 읽지 않는다. 서버 검사는 테스트 파일의 임시 SQLite/로컬 저장소를 사용하고 모델·외부 서비스를 호출하지 않는 범위만 실행한다. 기존 원본·은행·학습 기록·수정/검수 상한·runs 기록은 읽기만 한다. 조사 결과는 이 폴더에 기록한다.
