# Map와 독립 출제포인트 추출 지침 정리 — 구현 계획

## 변경 범위·대상 파일·순서
현재 사용자 승인 범위의 지시문 작성만 수행한다. 이전 Concept map 요청문과 quizbank/prompts/points.md, 공통 문항 품질 원칙을 참고하여 content/prompts/learning-links/map-extract.md, point-extract.md를 작성하고 같은 디렉터리 README에 입력 분리와 자동 파이프라인 미연결을 명시한다.

후속 표현 교정은 두 요청문의 반복적인 금지문을 삭제하거나 긍정적인 작성 방향으로 바꾼다. 출력 구조·원본 범위·연결 회상 철학은 유지한다.

출력 구체화: 같은 디렉터리에 Map/포인트 JSON Schema와 비의학 합성 예시를 추가하고, 두 프롬프트에 필드별 작성 규칙과 완전한 예시를 넣는다. README에 버전·스키마·자동 미연결을 명시한다. 개발 기록의 verify_formats.py로 스키마·문서 내 예시·참조/고유 ID/분류 순환·근거 쪽/범위·비정상 입력 거절을 확인한다. 공용 런타임 계약과 생성기/서버/웹은 변경하지 않는다.

후속 간소화는 같은 작성 범위에서 /2 출력으로 정리한다. Map은 개념·관계·짧은 흐름 설명, 포인트는 구체적 목표·근거만 남기고 notes에 중요한 한계를 기록한다. 출처 재고는 입력으로 제공하며 출력에서 재작성시키지 않는다. 형식 예시는 실제 JSON 다운로드 파일 지시와 함께 짧게 유지한다. 스키마·예시·개발용 검증·README를 함께 갱신한다. 자연어 관계의 의미/순환 검토는 후속 의미 검토의 책임임을 명시한다.

## 검사 명령과 성공 조건
prompt-review: verify_formats.py에서 두 JSON Schema의 유효성, 프롬프트 예시 일치, 합성 정상/오류 사례를 검사한다. 원본 독립성·연결 회상·관계와 선행 구분·판정 한계는 수동 검토하고 git diff --check도 실행한다. 실행 코드를 바꾸지 않으므로 모델/서버/웹 통합 검사는 하지 않는다.

## 위험·복원·승인할 범위
현재 채팅의 두 프롬프트 작성 승인을 동일 범위에 적용한다. 실행 코드·모델 호출·출제 재개·운영 배포 없음. 복원은 두 지시문과 안내 변경만 되돌리고 기존 실행 기록은 보존한다. release에 실제 변경과 검증 한계를 남긴다.
