# 예습 cloze 표시를 복습 Quiz Bank 방식에 맞추기 — 설계

## 요구사항과 수용 기준
1. 예습 cloze의 답 공개 전 표시([____]/[힌트])는 그대로 유지한다. 빈칸 번호를 추가하지 않는다.
2. 답 공개 후에는 해당 문장의 빈칸 위치에 정답을 채우고 복습 Quiz Bank처럼 강조한다. 여러 빈칸·같은 번호 반복·여러 줄·강조 문법을 보존한다.
3. 원문의 빈칸별 답과 별도 answer가 다를 수 있으므로 답 단락은 보존한다. 단순 문자열 분리나 정답 단어 검색으로 위치를 추측하지 않는다.
4. 다음 문제로 넘어가거나 다시 풀 때 정답을 숨긴다. 되돌리기는 기존처럼 답이 공개된 상태이며, 어려웠던 문제 목록에서도 문장 안 정답을 확인할 수 있다.
5. 유효한 source_stem이 없는 기존 카드나 원문과 stem이 맞지 않는 카드는 기존 질문·답 표시로 안전하게 돌아간다. 원문 확보를 위한 재출제·재업로드는 하지 않는다.
6. basic/OX 및 복습 퀴즈 동작, 예습 완료 기준과 학습 기록은 유지한다.

## 책임·입출력 계약·오류 상태
서버는 저장된 source_stem의 cloze를 해석해 reveal 응답에 선택적 clozeParts를 추가한다. 형식은 {text: string, blank?: true}의 순서 있는 배열이며, blank인 부분의 text는 정답이다. 예습의 유효한 cloze에만 제공하며 undo도 같은 reveal 경로를 사용한다. 이미 답을 제공하는 본인별 missed/extraMissed 응답에도 같은 정보를 추가해 완료 화면 재방문을 지원한다. 일반 텍스트와 빈칸 답을 별도 요소로 보내므로 구분자가 포함된 정답도 위치를 잃지 않는다.
첫 문항 목록·미리 불러오는 슬라이드 응답에는 원문이나 빈칸 정답을 추가하지 않는다. 웹은 reveal 전 stem만 사용하고, reveal 후 현재 itemId에 해당하는 clozeParts만 사용한다. 미공개 정답을 브라우저에 먼저 보내 CSS로 감추는 방식은 사용하지 않는다.
서버에서 원문을 가린 결과와 현재 stem의 일치 여부를 확인하고, 불일치·문법 오류 시 추가 필드를 생략한다. quizgen/runner 모듈은 서버에 import하지 않는다. API 실패와 재시도 처리는 기존 흐름을 유지한다.

## 호환성과 데이터 보존
API의 추가 필드는 선택적이다. 새 웹+기존 서버, 기존 웹+새 서버 조합은 기존 표시로 동작한다. DB 스키마 변경, 문항 내용 교정, 학습 기록 변경, 덱 재생성은 없다. 원본·개인 수정·제외 문항·검수 이력을 보존한다.
새 사용자 행동이나 수집 이벤트가 없는 표시 변경이므로 이용현황 카탈로그는 변경하지 않는다.
